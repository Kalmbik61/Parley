# Spec: встроенный PTY-терминал (v1)

## Архитектура

```
node-pty (spawn `claude`) ──raw bytes──▶ @xterm/headless (VT-парсер, движок VS Code
        ▲                                 без DOM, держит экранный буфер)
        │ input, resize                          │ буфер (строки/ячейки/стили)
        │                                        ▼
   фокус-роутер Ink ◀────────────── рендер буфера в правую панель Ink
```

- Спавнится **немодифицированный официальный бинарь `claude` из PATH** — это
  юридическая граница проекта (см. PROMPT.md, Key Principles). Никаких обёрток над
  API, никаких токенов.
- На каждую пачку данных из PTY: скормить @xterm/headless → забрать изменённые строки
  буфера → перерисовать правую панель. Дифф по строкам, не полный ререндер.
- `claude --resume <sessionId>` запускается с `cwd` из меты сессии.

## Обязательные механики

1. **Resize**: на ресайз терминала пересчитать cols/rows правой панели и synchronously
   прокинуть в ОБА места: `pty.resize(cols, rows)` и `terminal.resize(cols, rows)`.
2. **Фокус**: когда правая панель активна — ВЕСЬ ввод (включая стрелки, Ctrl-комбо,
   Esc) идёт в PTY. Escape hatch по умолчанию `Ctrl+Q` (конфигурируемо) возвращает
   фокус спискам; не должен конфликтовать с биндингами Claude Code.
3. **Alt-screen**: Claude Code использует alt-screen/полноэкранные перерисовки —
   @xterm/headless обрабатывает это сам, рендерить всегда текущий буфер.
4. **Мышь**: если PTY включает mouse reporting — транслировать события мыши Ink
   (если панель в фокусе) в escape-последовательности PTY. В v1 допустимо отложить,
   но зафиксировать ограничение в README.
5. **Scrollback**: буфер @xterm/headless с настраиваемым scrollback; прокрутка
   в режиме «просмотра» (когда PTY в alt-screen — прокрутку отдаёт сам claude).
6. **Lifecycle**: детект завершения/краша процесса, статус в панели, действие
   «перезапустить»; один активный PTY на сессию; закрытие PTY при выходе из TUI —
   аккуратно (SIGHUP), не убивая пользовательские данные.

## Ограничения и риски

- Параллельные PTY-сессии жгут лимиты подписки (5-часовое окно + недельный потолок) —
  при запуске второго+ параллельного агента показать предупреждение, не блокировать.
- Для непрерывной автономии подписка не подходит — это забота v3, вне объёма.
- Перф: если рендер буфера в Ink не вытянет — запасной вариант tmux/zellij как
  подложка (зафиксированное решение из хендоффа), но сначала померить.

## Тесты

- Интеграционный тест — против **stub-бинаря** (маленький node-скрипт, рисующий в
  stdout управляющие последовательности): spawn → write → resize → teardown.
- Реальный `claude` в автотестах не запускать никогда (лимиты + недетерминизм).
