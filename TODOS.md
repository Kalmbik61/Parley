## 3. Ревью и правки человека

Всё про «Изменения», диффы, заметки и вкладки: здесь человек читает и правит работу
агента.

- **Фантомные пустые строки в диффе нового и удалённого файла** (приёмка fix-live,
  D2). Новый файл `a\nb\n` показывает удалённую пустую «1 −» и лишнюю пустую «3+»,
  хотя в заголовке секции и в «Changes» `+2 −0`. У удалённого — лишние «N+1 −» и
  «1+». Причина — Monaco: сравнение с пустым документом ставит его единственную
  пустую строку против содержимого одной заменой. Решение, как у VS Code и GitHub:
  секция добавленного или удалённого файла — один read-only редактор с построчной
  подсветкой «+» или «−», без диффа против пустого. Вместе с этим — привязка заметок
  к такой секции: сторона `modified` у нового, `original` у удалённого.
- **Заметка к строке внутри свёрнутого неизменённого региона диффа не видна** до
  развёртки региона (`review/DiffTab.tsx`, кусок 8.4b).
- **«Изменения» и дифф не видят правок worktree не агентом.** Поводы обновления
  (спека 11.1): открытие, `works.changed`, выход сессии из `working`, Refresh. Правка
  файла или коммит человеком (скриптом) без работы агента видны только после
  Refresh. Идея — слежение за файлами worktree (или папки проекта у сессии без
  worktree) с тем же дросселем 2 с (`review/use-changes.ts`).
- **Метка корня у одноимённых вкладок — только внутри одной группы.** fix-live (D5)
  ищет совпадения по вкладкам группы (`files/store.ts`, `layout/TabStrip.tsx`). Если
  `src/app.ts` из S01 и из S02 разнести по разным сплит-панелям, заголовки и вопросы о
  несохранённом файле теряют `· S02`. Подсказка вкладки корень показывает всегда.
  Искать совпадения по всем группам работы.
- **Отказ записи заметок держит закрытие окна один раз.** Второе закрытие проходит,
  заметка теряется. Человек видел тост, но вопроса «закрыть всё равно» для заметок нет
  (fix-final-c).
- **Commit worktree, где изменён только подмодуль,** — общий тост отказа
  `git commit`, а не «нечего коммитить», как у папки проекта (fix-final-c; подмодули
  исключены из `add`, спека 10.8). Выровнять в core.
- **Числа неотслеживаемых — процесс git на файл.** `core/work/worktree.ts` считает
  числа у первых 500 неотслеживаемых (`uncountedUntracked` — остальные). Но 500
  процессов на обновление «Изменений» — это ≈0,7 с CPU, не чаще раза в 2 с. Начинать с
  кэша чисел по (путь, mtime, size) между обновлениями.

## 4. Хост, сессии и координация — надёжность

**Отложено 2026-09-29 на следующую неделю** (решение пользователя: бережём недельный лимит
подписки). Для минимума в первую очередь нужны четыре пункта: отмена `wait_for` (комнаты
ждут через него), `works-index.lock` после падения, errno запуска node-pty, запуск
`pending`-сессии из окна. Окружение login-оболочки (в том числе `PATH`) для собранного
`.app` сделано вместе с Codex (README, «Собрать `harnas.app`»); открыта только живая
проверка из Finder (прогон 2).

- **node-pty теряет errno запуска.** `posix_spawnp failed.` одинаков для EACCES у
  `spawn-helper` без `+x` (так был сломан собранный `.app` до 168b200), ENOENT и
  прочего (`src/unix/pty.cc` node-pty). Хосту — проверять режим `spawn-helper` и
  доступность программы до `pty.spawn`, причину писать в `host.log` и в ответ.
- **Хост не откатывает запись упавшей сессии.** `sessions-service.create` пишет
  запись в карту до запуска и при сбое (нет бинарника, worktree не создан, PTY не
  поднялся) её не откатывает, а ответ об ошибке id не несёт — окно запись убрать
  не может. Итог: не запущенная сессия-сирота на каждый сбой и на каждый «Retry»
  диалога «New session or room» (её убирает «Delete» в меню строки). Варианты:
  откат записи в `create` или id записи в ответе об ошибке.
- **Усилие при `resume` у Claude.** Модель и усилие теперь хранятся в
  `WorkSession` (`spawn_session` иначе не передал бы выбор хосту), но `resumeArgs`
  Claude их не несёт: модель Claude Code при `--resume` берёт из сессии сам,
  усилие по документации не восстанавливает. Решить: передавать `--effort` из
  карты при `resume`, если провайдер его принимает (у Codex `resume` восстанавливает
  всё из треда).
- **Закрыть сессию, чья папка worktree исчезла мимо хоста.** `worktrees.discard` у
  такой сессии отвечает `internal`: git не находит worktree. Из окна пункт скрыт, но
  агент может его вызвать. Нужно своё решение: `git worktree prune`, `branch -D` ветки
  сессии и `closed` в карте (fix-8).
- **autoLaunch и интерактивный `sessions.create` (проверить).**
  `autoLaunchCandidates` (`host/sessions/auto-launch.ts`) отличает сессии только по
  `parent !== null` и полагается на то, что `sessions.create` сам зовёт `launch()`
  синхронно. Если наблюдатель карты когда-нибудь обгонит этот путь,
  `attachWorktreePlan` перепишет бриф уже стартовавшей сессии. Первый старт это не
  задевает: `readBrief` бриф повторно не читает. Но `sessions.resume` подставит новый
  текст. На практике не видели (ревью fix-guide).
- **`pending`-сессию при выключенном autoLaunch из окна не запустить.** В меню строки у
  `pending` есть только Stop. Resume бывает у `exited`, `done`, `failed`
  (`sidebar/SessionRowMenu.tsx`, `RESUMABLE`/`STOPPABLE`). Сессия, которую агент
  породил при `autoLaunch: false`, ждёт без пути запуска из окна (сверка README
  2026-09-28). Нужен пункт запуска у `pending`.
- **Порог тишины не перечитывается после `settings.set`.** `activity-service` читает
  `silenceThresholdMs` один раз на старте хоста (кусок 1.5). Нужен сигнал «настройки
  изменились» от `methods/settings.ts`.
- **Копия замка `host.pid.stale.<pid>` не подбирается.** Если хост унёс живой замок
  соседа и не смог его вернуть (`acquirePidLock` в `host/src/host.ts`), копия остаётся
  рядом с `host.pid`. Следующий старт её не смотрит и не убирает.
- **`works-index.lock` не снимается по устареванию** (остаток приёмки координации
  v3). Сначала решить: порог устаревания лока или «ошибка, не отбор» из спецификации
  координации.
- **Наблюдатель дома хоста видит userData окна.** `HARNAS_HOME/desktop/electron`
  (кэши Chromium окна) лежит внутри дома. Рекурсивный наблюдатель хоста получает сотни
  событий на каждый старт окна: фильтр их отбрасывает, но CPU тратится (fix-tests2).
  Начинать с исключения `desktop/` из наблюдения или с переноса userData окна из дома.
- **Предел 1 МБ — на весь `layouts.json`, а не на раскладку работы.**
  `main/layout-store.ts` меряет файл целиком, с отступами `JSON.stringify(…, null, 2)`:
  много работ с большими раскладками упираются в предел все вместе. Нужен предел на
  одну раскладку и запись без отступов.
- **`wait_for` не отменяется вместе с вызовом MCP.** Пробросить сигнал отмены
  (`extra.signal` обработчика MCP) в `waitForMap`: отменённый `wait_for` должен
  закрывать `fs.watch` и `setInterval` сразу, а не по своему таймауту. Сейчас клиент
  отваливается по своему таймауту, а watcher и таймер живут до 30 минут и копятся по
  числу отмен. С чего начать: `packages/core/src/mcp/tools.ts` (`waitFor`, обработчик
  `CallToolRequestSchema` получает `extra`), `packages/core/src/mcp/watch-map.ts`
  (`waitForMap`: добавить `signal`, снимать `stop()` по `abort`).

## 13. Встроенный браузер и превью

Всё здесь упирается в CSP окна и схемы протоколов (спека 12.2 и 15.2). Поэтому один
заход.

- **Идеи из Orca** (сравнение 2026-09-28, `docs/specs/2026-09-28-desktop-browser-vs-orca.md`).
  Код Orca — MIT, переносить только самодостаточные куски с записью в `NOTICE` (спека
  1.2). Брать:
  - настоящий ввод для `browser:focus` и `window.open` —
    `browser-route-guest-popup-gesture.ts`. Закрывает остаточный риск самофокуса
    страницы (спека 12.2; разбор — К1 сравнения);
  - темп вкладок от страницы (4 за 2 с) и фоновую вкладку по ⌘-клику;
  - пределы масштаба 58–249 % и процент на экране;
  - ограду данных страницы в блоке Design Mode для агента;
  - понятные ошибки загрузки (localhost: «сервер не запущен?», Try HTTPS, Copy URL) и
    уведомления об отказах сайту в разрешениях;
  - контекстное меню страницы, ⌘R и ⌘⇧R (перезагрузка без кэша);
  - Design Mode: несколько отметок с комментариями одним блоком, роль, имя и соседний
    текст элемента, рисование на снимке (стрелка, рамка, текст) — в изолированном мире,
    с пометкой «данные страницы»;
  - эмуляцию размеров экрана (`enableDeviceEmulation`), историю адресов с подсказками;
  - самоподписанный https на localhost и полку загрузок — только с правкой спеки 12.2
    и 15.2.

  Не брать:
  - управление браузером агентом (CDP);
  - импорт куков и подмену UA;
  - авто-разрешения;
  - автосохранение загрузок;
  - `file:` во вкладке;
  - окна-попапы;
  - удалённые страницы.
- **Локальный HTML во вкладке браузера.** Через `session.protocol.handle('file', …)`
  раздела браузера с проверкой `realpath` корня на каждый запрос. Образец — их схема
  `orca-preview://`, но строже `file:`. Сейчас `file:` во встроенный браузер не
  пускается вовсе (спека 12.2).
- **Превью PDF не рисует картинки JPX и JBIG2.** pdf.js идёт с `useWasm: false`
  (`files/preview/PdfPreview.tsx`, кусок 7.5). Декодеры этих форматов — WebAssembly, а
  CSP окна без `'wasm-unsafe-eval'` (спека 15.2), и ослаблять её ради превью не стали.
  Такие картинки и цветовые профили ICC pdf.js пропускает, текст и прочее рисуется
  (fix-7.5). Начинать с запасного JS-декодера pdf.js (`wasmUrl`) или с CSP только для
  воркера pdf.js.

## 14. Свой агентский цикл для API-провайдеров (исследование)

- **Что:** для моделей без подписочного CLI (GLM по ключу, локальные) — свой цикл
  агента на открытом ядре. Кандидат: `badlogic/pi-mono`, пакеты `pi-agent-core` и
  `pi-ai`, MIT, TypeScript.
- **Почему отложено:** все три целевых провайдера дают подписку только через свой
  немодифицированный CLI. Свой цикл нужен лишь для pay-as-you-go, и по объёму это
  отдельный продукт.
- **С чего начать:** спайк — насколько `pi-agent-core` пригоден как фундамент и что из
  `packages/core` (карта, MCP) переносится без изменений.
- **Зависит от:** решения пользователя платить по API.
