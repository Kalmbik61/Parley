## Сплит главной области на две живые панели

- **Что:** `O`/`X` открывают вторую панель с другим агентом рядом, `Tab` обходит обе.
- **Почему отложено:** одна панель выбрана осознанно (вложенность сессий в работу,
  быстрое переключение через сайдбар). Сплит требует нескольких живых буферов,
  раскладки, ресайза каждой панели и правил уведомлений при двух агентах.
  Уточнение 2026-09-09: панель треда (`docs/specs/2026-09-08-agent-conversation-design.md`,
  раздел 6, задача C) строит ту же механику раскладки — вторая область справа,
  сжатие панели, ресайз PTY под новую ширину, правая граница в `routeMouse`,
  порог колонок для дока. После C остаются только второй живой PTY и фокус.
- **С чего начать:** `docs/specs/2026-09-02-coordination-tui-design.md`, раздел 2.5
  (заготовка), `packages/tui/src/pty/use-agent-pty.ts` (один активный PTY);
  после задачи C — раскладка дока треда в `app.tsx` как готовый второй столбец.
- **Зависит от:** TUI v2 (сайдбар, `use-selection.ts`) должен быть реализован.

## Фоновый сервер и detach/reattach

- **Что:** как у herdr: панели живут в фоновом процессе, клиент подключается и
  отключается, агенты переживают закрытие терминала и SSH.
- **Почему отложено:** транскрипт хранит сам Claude, после перезапуска сессии
  возобновляются через `--resume`; сервер — отдельная архитектура (сокет, протокол,
  восстановление экрана).
- **С чего начать:** `docs/specs/2026-09-05-tui-v2-design.md`, раздел 5.4 (живость
  по pid) как первый шаг; herdr `docs/session-state.mdx` как референс.
- **Зависит от:** TUI v2.

## Свой агентский цикл для API-провайдеров

- **Что:** для моделей без подписочного CLI (GLM по ключу, локальные) — свой цикл
  агента на открытом ядре (кандидат: `badlogic/pi-mono`, пакеты `pi-agent-core`,
  `pi-ai`, MIT, TypeScript).
- **Почему отложено:** все три целевых провайдера дают подписку только через свой
  немодифицированный CLI; свой цикл нужен лишь для pay-as-you-go и это отдельный
  продукт по объёму.
- **С чего начать:** спайк: насколько `pi-agent-core` пригоден как фундамент и что из
  `packages/core` (карта, MCP) переносится без изменений.
- **Зависит от:** решения пользователя платить по API.

## Skill-файл харнесса для агента

- **Что:** команда `harnas-core skill install`, кладущая `.claude/skills/harnas/SKILL.md`
  в проект: описание работ, карты, MCP-инструментов и правила «подсессия вместо
  субагента для длинных подзадач».
- **Почему отложено:** ревью плана 2026-09-06 (решение D1) срезало его из объёма:
  Claude Code читает skills только из `.claude/skills/` проекта, `~/.claude/skills/`

  `harnas` и ничего не может сделать с картой. Системная вставка и `read_guide`
  закрывают сессии из харнесса; skill нужен только для сессий «мимо».
- **С чего начать:** `docs/specs/2026-09-06-agent-guidance-plan.md`, задача A
  (`core/work/guide.ts` как источник текста); `packages/core/src/cli.ts`.
- **Зависит от:** задача A плана (гид как текст).

## `wait_for` не отменяется вместе с вызовом MCP

- **Что:** пробросить сигнал отмены вызова (`extra.signal` обработчика MCP) в
  `waitForMap`, чтобы отменённый `wait_for` закрывал `fs.watch` и `setInterval`
  сразу, а не по своему таймауту.
- **Почему отложено:** найдено внешним голосом инженерного ревью 2026-09-09
  спецификации разговора агентов. Критичность упала после решения D16 (сторож
  канала карту не пишет, `wait_for` тоже, письма не теряются), осталась утечка
  ресурсов в существующем коде: клиент отвалился по своему таймауту, а watcher и
  таймер живут до 30 минут; при повторных вызовах их накапливается по числу
  отмен. На одного пользователя с несколькими сессиями незаметно.
- **С чего начать:** `packages/core/src/mcp/tools.ts` (`waitFor`, обработчик
  `CallToolRequestSchema` получает `extra`), `packages/core/src/mcp/watch-map.ts`
  (`waitForMap` — добавить `signal`, снимать `stop()` по `abort`).
- **Зависит от:** ничего. Приоритет P3.

## Хвосты приёмки TUI v2 (2026-09-05)

- **`prefix c` из режима навигации не выходит из него**: сессия создаётся и
  подключается, но набранный сразу текст пропадает до `Esc`. У `Enter` по `new`
  режим снимается, у `c` нет. Унифицировать. `packages/tui/src/use-actions.ts`.
- **Переключение `prefix j/k` видит новую сессию только после события watcher**:
  до этого `order` состоит из одной сессии. Заметно лишь в тестах, но стоит подавать
  свежую карту в сайдбар сразу после создания.
- **`events.test.ts` «на изменение журнала отдаёт id сессии»**: один раз упал на
  таймауте fs.watch, в трёх повторных прогонах и двух приёмках стабилен. Если
  повторится — заменить fs.watch на опрос с условием в тесте.
- **`.omc/project-memory.json` попал в коммит `f19e42a`**: файл переписывает сам
  OMC, к продукту не относится. История не переписывалась.
