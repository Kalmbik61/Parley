## 3. Ревью и правки человека

Всё про «Изменения», диффы, заметки и вкладки: здесь человек читает и правит работу
агента.

- **Фантомные пустые строки в диффе нового и удалённого файла** (приёмка fix-live,
  D2). Новый файл `a\nb\n` показывает удалённую пустую «1 −» и лишнюю пустую «3+»,
  хотя в заголовке секции и в «Changes» `+2 −0`. У удалённого — лишние «N+1 −» и
  «1+». Причина — Monaco: сравнение с пустым документом ставит его единственную
  пустую строку против содержимого одной заменой. Решение, как у VS Code и GitHub:
  секция добавленного или удалённого файла — один read-only редактор с построчной
  подсветкой «+» или «−», без диффа против пустого. Вместе с этим — привязка заметок
  к такой секции: сторона `modified` у нового, `original` у удалённого.
- **Заметка к строке внутри свёрнутого неизменённого региона диффа не видна** до
  развёртки региона (`review/DiffTab.tsx`, кусок 8.4b).
- **«Изменения» и дифф не видят правок worktree не агентом.** Поводы обновления
  (спека 11.1): открытие, `works.changed`, выход сессии из `working`, Refresh. Правка
  файла или коммит человеком (скриптом) без работы агента видны только после
  Refresh. Идея — слежение за файлами worktree (или папки проекта у сессии без
  worktree) с тем же дросселем 2 с (`review/use-changes.ts`).
- **Метка корня у одноимённых вкладок — только внутри одной группы.** fix-live (D5)
  ищет совпадения по вкладкам группы (`files/store.ts`, `layout/TabStrip.tsx`). Если
  `src/app.ts` из S01 и из S02 разнести по разным сплит-панелям, заголовки и вопросы о
  несохранённом файле теряют `· S02`. Подсказка вкладки корень показывает всегда.
  Искать совпадения по всем группам работы.
- **Отказ записи заметок держит закрытие окна один раз.** Второе закрытие проходит,
  заметка теряется. Человек видел тост, но вопроса «закрыть всё равно» для заметок нет
  (fix-final-c).
- **Commit worktree, где изменён только подмодуль,** — общий тост отказа
  `git commit`, а не «нечего коммитить», как у папки проекта (fix-final-c; подмодули
  исключены из `add`, спека 10.8). Выровнять в core.
- **Числа неотслеживаемых — процесс git на файл.** `core/work/worktree.ts` считает
  числа у первых 500 неотслеживаемых (`uncountedUntracked` — остальные). Но 500
  процессов на обновление «Изменений» — это ≈0,7 с CPU, не чаще раза в 2 с. Начинать с
  кэша чисел по (путь, mtime, size) между обновлениями.

## 4. Хост, сессии и координация — надёжность

**Отложено 2026-09-29 на следующую неделю** (решение пользователя: бережём недельный лимит
подписки). Для минимума в первую очередь нужны четыре пункта: отмена `wait_for` (комнаты
ждут через него), `works-index.lock` после падения, errno запуска node-pty, запуск
`pending`-сессии из окна. Окружение login-оболочки (в том числе `PATH`) для собранного
`.app` сделано вместе с Codex (README, «Environment of the window»); открыта только живая
проверка из Finder (прогон 2).

- **node-pty теряет errno запуска.** `posix_spawnp failed.` одинаков для EACCES у
  `spawn-helper` без `+x` (так был сломан собранный `.app` до 168b200), ENOENT и
  прочего (`src/unix/pty.cc` node-pty). Хосту — проверять режим `spawn-helper` и
  доступность программы до `pty.spawn`, причину писать в `host.log` и в ответ.
- **Хост не откатывает запись упавшей сессии.** `sessions-service.create` пишет
  запись в карту до запуска и при сбое (нет бинарника, worktree не создан, PTY не
  поднялся) её не откатывает, а ответ об ошибке id не несёт — окно запись убрать
  не может. Итог: не запущенная сессия-сирота на каждый сбой и на каждый «Retry»
  диалога «New session or room» (её убирает «Delete» в меню строки). Варианты:
  откат записи в `create` или id записи в ответе об ошибке.
- **Усилие при `resume` у Claude.** Модель и усилие теперь хранятся в
  `WorkSession` (`spawn_session` иначе не передал бы выбор хосту), но `resumeArgs`
  Claude их не несёт: модель Claude Code при `--resume` берёт из сессии сам,
  усилие по документации не восстанавливает. Решить: передавать `--effort` из
  карты при `resume`, если провайдер его принимает (у Codex `resume` восстанавливает
  всё из треда).
- **Закрыть сессию, чья папка worktree исчезла мимо хоста.** `worktrees.discard` у
  такой сессии отвечает `internal`: git не находит worktree. Из окна пункт скрыт, но
  агент может его вызвать. Нужно своё решение: `git worktree prune`, `branch -D` ветки
  сессии и `closed` в карте (fix-8).
- **autoLaunch и интерактивный `sessions.create` (проверить).**
  `autoLaunchCandidates` (`host/sessions/auto-launch.ts`) отличает сессии только по
  `parent !== null` и полагается на то, что `sessions.create` сам зовёт `launch()`
  синхронно. Если наблюдатель карты когда-нибудь обгонит этот путь,
  `attachWorktreePlan` перепишет бриф уже стартовавшей сессии. Первый старт это не
  задевает: `readBrief` бриф повторно не читает. Но `sessions.resume` подставит новый
  текст. На практике не видели (ревью fix-guide).
- **`pending`-сессию при выключенном autoLaunch из окна не запустить.** В меню строки у
  `pending` есть только Stop. Resume бывает у `exited`, `done`, `failed`
  (`sidebar/SessionRowMenu.tsx`, `RESUMABLE`/`STOPPABLE`). Сессия, которую агент
  породил при `autoLaunch: false`, ждёт без пути запуска из окна (сверка README
  2026-09-28). Нужен пункт запуска у `pending`.
- **Порог тишины не перечитывается после `settings.set`.** `activity-service` читает
  `silenceThresholdMs` один раз на старте хоста (кусок 1.5). Нужен сигнал «настройки
  изменились» от `methods/settings.ts`.
- **Копия замка `host.pid.stale.<pid>` не подбирается.** Если хост унёс живой замок
  соседа и не смог его вернуть (`acquirePidLock` в `host/src/host.ts`), копия остаётся
  рядом с `host.pid`. Следующий старт её не смотрит и не убирает.
- **`works-index.lock` не снимается по устареванию** (остаток приёмки координации
  v3). Сначала решить: порог устаревания лока или «ошибка, не отбор» из спецификации
  координации.
- **Наблюдатель дома хоста видит userData окна.** `PARLEY_HOME/desktop/electron`
  (кэши Chromium окна) лежит внутри дома. Рекурсивный наблюдатель хоста получает сотни
  событий на каждый старт окна: фильтр их отбрасывает, но CPU тратится (fix-tests2).
  Начинать с исключения `desktop/` из наблюдения или с переноса userData окна из дома.
- **Предел 1 МБ — на весь `layouts.json`, а не на раскладку работы.**
  `main/layout-store.ts` меряет файл целиком, с отступами `JSON.stringify(…, null, 2)`:
  много работ с большими раскладками упираются в предел все вместе. Нужен предел на
  одну раскладку и запись без отступов.
- **`wait_for` не отменяется вместе с вызовом MCP.** Пробросить сигнал отмены
  (`extra.signal` обработчика MCP) в `waitForMap`: отменённый `wait_for` должен
  закрывать `fs.watch` и `setInterval` сразу, а не по своему таймауту. Сейчас клиент
  отваливается по своему таймауту, а watcher и таймер живут до 30 минут и копятся по
  числу отмен. С чего начать: `packages/core/src/mcp/tools.ts` (`waitFor`, обработчик
  `CallToolRequestSchema` получает `extra`), `packages/core/src/mcp/watch-map.ts`
  (`waitForMap`: добавить `signal`, снимать `stop()` по `abort`).

- **Релизный workflow ещё не прогонялся на GitHub.** `release.yml` проверен вычиткой, тестами
  (`release-workflows.test.ts`, `release-scripts.test.ts`) и локальной сборкой теми же командами,
  но кнопка «Run workflow» появляется в Actions, только когда файл лежит в master. Больше всего
  на GitHub ещё не видели шаги `Upload the files to the draft release` (`gh release upload` после
  `--publish never`) и `Check the tagged commit is in master` (`fetch-depth: 0` даёт `origin/master`;
  сам шаг тест выполняет на настоящем git-репозитории). Порядок:
  слить ветку в master → Actions → Release → Run workflow (`dry_run` по умолчанию включён,
  собранное остаётся в артефактах прогона) → тег `v0.1.0`; публикует `publish-release` после
  проверки файлов. Заодно живая проверка скачанной сборки (к прогону 2, «Собранный
  `Parley.app` из Finder»): dmg → Applications → «Open Anyway»; запуск на машине без node в
  `PATH` — хост поднимается встроенным node; приложение в каталоге с пробелом; Intel-сборка на
  настоящем Intel-маке — её собирали и проверяли только на arm64.
- **Релиз: что осталось после ревью релизного workflow.**
  - права: `build-mac` получает `contents: write` и в пробном прогоне (GitHub не даёт задать права
    задачи по условию), хотя токен берёт только шаг загрузки. Чтобы у сборки права записи не было
    вовсе, разделить её на задачу сборки (чтение, артефакты Actions) и задачу выкладки (запись,
    `gh release upload`). Подводный камень — имя артефакта при «Re-run failed jobs»: у частично
    перезапущенного прогона другой `run_attempt`;
  - коммит тега: `create-release` проверяет, что он лежит в master, но не что CI на нём зелёный.
    Нужны `checks: read` у задачи и опрос check-runs коммита (или environment с ручным одобрением у
    `publish-release`);
  - действия закреплены по SHA на мажоре v4 (`ALLOWED_ACTIONS` в `release-workflows.test.ts`);
    обновлять осознанно, SHA — `git ls-remote --tags <репозиторий> <тег>`, у аннотированного тега
    строка с `^{}`;
  - Intel: `scripts/release/verify-packaged-apps.sh` запускает встроенный node x64 под Rosetta, если
    она есть на раннере; нет — предупреждение, и x64 проверен только по файлам.
- **Linux** (x64 и arm64, AppImage и deb). Решение 2026-09-30: клавиши — Ctrl+Shift+буква, на
  macOS остаётся ⌘.
  - клавиши: реестр `shared/keybindings.ts` описан акселераторами `CmdOrCtrl+…`, а обработчики
    окна (`renderer/keys/handler.ts`, терминал, палитра) ждут `metaKey`, подписи ⌘ зашиты в

## 17. Голосовой ввод

- **Что:** голосовой ввод, как в Claude и Codex.
  - Кнопка микрофона → запись → человек говорит → останавливает → текст расшифровки встаёт
    в поле ввода.
  - Где кнопка: поле комнаты, ввод в терминал сессии (как вставка), диалог «New session or
    room».
  - Текст сам не отправляется: отправляет человек.
  - Во время записи видно, что она идёт, и громкость; запись можно отменить.
- **Через кого распознавать.** Через одного из подключённых провайдеров. В настройках
  человек выбирает «Transcription provider» из тех, кто умеет распознавать речь.
- **Решить до начала.**
  - Рамка проекта. Запросов к API Anthropic и OpenAI с токенами подписки нет и не будет.
    Варианты:
    - распознавание через сам CLI провайдера, если он это умеет;
    - через API провайдера по отдельному ключу, который человек сам вводит в настройках.
      Хранить ключ — в `safeStorage` Electron, не в открытом виде.
  - Кто что умеет — проверить на день работы:
    - у Anthropic открытого API распознавания речи, похоже, нет;
    - у OpenAI есть transcriptions API;
    - GLM — проверить;
    - Claude Code и Codex CLI — есть ли у них свой голосовой ввод и можно ли им
      воспользоваться.
  - Запасной путь без сети — локальное распознавание: macOS Speech framework или
    whisper.cpp.
  - Разрешение на микрофон в macOS: `NSMicrophoneUsageDescription` в Info.plist и
    `systemPreferences.askForMediaAccess('microphone')`. Без подписи Apple разрешение может
    сбрасываться после обновления.
  - Язык распознавания: авто или из настроек; русский и английский.
- **С чего начать:** спайк по провайдерам и рамке, потом план. Окно — по-английски, тексты —
  в `shared/strings.ts`.
- **Источник:** просьба пользователя 2026-10-01.

## 18. Окно без терминала: лента разговора поверх CLI

- **Что:** сессия в окне выглядит как разговор, а не как терминал — как режим Code в Claude
  Desktop.
  - Агент тот же: официальный интерактивный CLI провайдера (`claude`, `codex`, остальные) в
    PTY под логином человека. Терминал скрыт, а не убран: переключатель «Terminal»
    показывает его в любой момент.
  - Лента: сообщения, вызовы инструментов и диффы — из журнала сессии, только на чтение
    (`~/.claude/projects/*.jsonl`, у Codex — `~/.codex/sessions`).
  - Поле ввода внизу, текст уходит в PTY (`pty.send`).
  - Запрос разрешения — карточка с кнопками. Жмёт человек, окно передаёт его выбор клавишами
    в PTY (`pty.input`). Автоответов нет.
- **Решение (пользователь, 2026-10-01).** Запускаем тот же CLI в скрытом терминале, визуал
  показываем в своём окне. Parley не предлагает вход через Claude и ничего не продаёт: всё в
  рамках того, что дают CLI Claude Code, Codex и остальных провайдеров.
- **Не выбрано: машинный режим.** Хост запускает `claude -p --input-format stream-json
  --output-format stream-json` (у Codex — `codex app-server`), окно рисует поток само.
  `claude -p` — это Agent SDK через CLI, а про Agent SDK сказано: без одобрения Anthropic
  нельзя предлагать вход claude.ai и лимиты подписки в своём продукте, иначе API-ключ.
  Возвращаться только после ответа Anthropic. Правила OpenAI для `codex app-server` не
  сверялись.
- **Рамка** (сверено 2026-10-01: `code.claude.com/docs/en/legal-and-compliance` и
  `…/agent-sdk/overview`; политика меняется, перед началом перечитать):
  - запускать немодифицированный Claude Code в своём продукте можно на условиях раздела
    «Can customers offer Claude Code in their products?»: принять Commercial Terms, не
    трогать бинарь и его способы входа, не платить за человека и не посредничать — каждый
    входит сам, в том числе подпиской;
  - следствие для ленты: вход, доверие папке и всё, чего в ленте нет, не прятать — терминал
    открывается сам или сессия помечается «нужен ты»;
  - имя Claude Code — только простым текстом; лента в своём облике, не под Claude Code.
- **Что уже есть:**
  - ввод из окна: `pty.send` и `pty.input` (`packages/protocol/src/methods.ts`,
    `renderer/terminal/send.ts`);
  - состояние `blocked` по хукам `PermissionRequest` и `Notification`
    (`packages/core/src/work/activity.ts`). Журнал хуков хранит stdin хука целиком;
    `EventRecord` с 0.2.0 берёт из него имя события, тип уведомления и поля субагентов
    (`agent_id`, `agent_type`, `background_tasks`, `transcript_path`); живые субагенты —
    `LiveMetrics.tasks`, описание — из `meta.json` субагента
    (`host/activity/subagent-meta.ts`), участник комнаты показывает «Subagent: …»;
  - чтение журнала сессии (`packages/core/src/jsonl.ts`, `adapter-v1.ts`). `SessionRecord`
    берёт первый текст и имена инструментов, остальное лежит в `raw`;
  - связь сессии с журналом и слежение за ним (`packages/host/src/activity/log-index.ts`),
    экран PTY (`packages/host/src/pty/screen.ts`).
- **Чего нет:** разбора событий и записей журнала в блоки ленты (текст, вызов инструмента,
  его результат, дифф), события ленты в протоколе хоста, экрана ленты в окне, карточек
  разрешения и вопроса агента с ответом через хук.
- **Разведка 2026-10-01 сделана:** `docs/research/2026-10-01-chat-view-spike.md`, стенд и
  улики рядом, в папке с тем же именем. Главное: Claude Code отдаёт ленте всё хуками — текст
  ответа по мере вывода (`MessageDisplay`), вызовы и результаты инструментов с диффами,
  запрос разрешения, конец хода; на запрос разрешения и на вопрос агента окно отвечает
  решением хука, без клавиш, а диалог в терминале при этом остаётся живым. Клавиши нужны
  для смены режима (`Shift+Tab`, `/plan`), прерывания и меню — слать после тишины экрана и
  сверять результат по экрану. Только экран: доверие папке, вход, меню `/model` и настроек,
  отказ по Esc (хука `Stop` не будет). Журнал — история и диффы, не живая лента: текст ответа
  попадает в него после `Stop`.
- **Решено делать (2026-10-01), план:** `docs/specs/2026-10-01-chat-view-plan.md` — пять
  кусков: core (модель ленты и нормализаторы), host и protocol (HTTP-приёмник хуков,
  ожидание решений, служба ленты), окно (лента, поле ввода, переключатель Chat/Terminal),
  карточки и режим, E2E и документы. Субагенты — чьи, сколько и зачем — в ленте, в строке
  сессии и у участника комнаты (решение 13 плана, проверено на стенде). Потом — Codex (хуков
  у него нет, состояние идёт из заголовка окна, уведомлений и `notify`, прогон 10) и
  остальные провайдеры.
- **Источник:** вопрос пользователя 2026-10-01 («как в Claude Desktop, без терминала»).
