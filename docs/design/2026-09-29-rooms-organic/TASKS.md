## 3. Данные: ведущий и решение
- core: `Room.lead`, `Room.proposal`, `Proposal`; `parseMap` с подстановкой; операции хранилища: `addMember` (одна комната на сессию, системное сообщение), `setProposal` (замена, `rev + 1`), `resolveProposal` (accept → `decision` от ведущего + системное; return → письмо человека ведущему).
- protocol: `rooms.create.lead`, `rooms.addMember`, `rooms.resolveProposal`, `sessions.create.model/effort`; `providers.list` — `models`, `effort`; всё в `hello.methods`.
- host: методы и проброс `model`/`effort` через реестр провайдеров.
- **Готово:** юнит-тесты core, protocol, host; карта v2 без новых полей читается; устаревший `proposalId` → `conflict`.

## 6. Вкладка комнаты
- `RoomPanel` / `RoomHeader`: шапка, лента участников, блок `Decisions`, сообщения с чипами, строка ожидания по `readBy`, карточка решения с потоком возврата.
- `Composer`: contentEditable, меню упоминаний §2.3, сериализация в `@s02` и `to[]`, черновик на комнату, Enter / Shift+Enter, вставка текстом.
- Прочтение через 1.2 с (`mail.markRead`); прокрутка вниз при открытии и новом сообщении.
- **Готово:** тесты `Composer` (условия меню, клавиши, сериализация, `to: []` без упоминаний) и `RoomPanel` (Accept и Return зовут `rooms.resolveProposal` с нужными полями).

- `NewSessionOrRoomDialog` (§1.5) вместо `NewSessionDialog` и `CreateRoomDialog`: ⌘T, карточка, палитра, меню карточки.
- `MergeRoomDialog` (§1.6); перетаскивание в сайдбаре §2.5 рядом с существующим переносом в раскладку.
- **Готово:** 1 агент → один `sessions.create`, без `rooms.create`; 3 агента → три `sessions.create` и `rooms.create` с `lead`; сессия на сессию → диалог; сессия на комнату → `rooms.addMember`; чужая работа — бросок запрещён.
