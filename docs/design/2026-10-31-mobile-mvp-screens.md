## 1. Принципы облика

«Нативно отлично» (§11.3) значит: системные элементы и системное поведение, а не перенос окна Parley.

1. **Системные компоненты.** Native tabs, native stack с крупными заголовками и свайпом назад, сгруппированные
   списки (`insetGrouped`), системные листы (sheet) с ручкой, системные алерты только для разрушительных действий,
   контекстные меню вместо самодельных поповеров. На iOS 26 — Liquid Glass у панели вкладок, панели навигации и
   нижней панели действий (`expo-glass-effect`); на iOS 17–25 — системный материал `.bar` (запасной вариант).
2. **Решение — главное действие.** Человек берёт телефон, чтобы ответить. Кнопки решения крупные (высота 50 pt),
   внизу экрана, в зоне большого пальца. Опасное действие — не по умолчанию и не там, куда палец попадает случайно.
3. **Ничего не обещать, чего не знаем.** Пока нет соединения, решения недоступны, а на экране — последний снимок с
   отметкой времени. Неподтверждённый ответ не выдаётся за принятый (§11.4).
4. **Цвет — не единственный носитель смысла.** Каждое состояние сессии — точка цвета **и** символ или слово.
5. **Мало текста.** Одна строка причины, одна строка «чем занят». Длинное — по тапу.
6. **Тексты интерфейса — английские** (как в окне), документ — русский.

## 2. Данные, на которых стоят экраны

Экраны Works и Session спроектированы только на полях, которые есть у телефона в этапе A. Чего нет — в открытых
вопросах (раздел 14), а не в макетах.

| Источник | Что даёт экрану |
|---|---|
| Проекция снимка работ (S7 §7.3, V1 + A1b) | снимок: `revision`, работы в порядке сайдбара; работа: `projectPath`, `id`, `title`, `status`, счётчики писем, **`swarms`**; сессия: `id`, `label`, `provider`, `model`, `role`, `parent`, **`createdBy`**, `lifecycle`, `result`, `stuck`, последнее событие `{event, at}`, `startedAt`, `resultAt`; комната: `id`, `title`, `members`, `lead`, **`ownerId`**, `mode`, `archived`, `proposal` (`id`, `kind`, `from`, `text`, `rev`, `at`), счётчики `{total, unread}`; рой: `id`, `tag`, `creator`, `queen`, `members [{sessionId, role, n, handedAt}]`, `status`, `createdAt`, `endedAt`, `seenAt` |
| `activity.snapshot` / `activity.changed` | `activity` (`working` / `blocked` / `unseen` / `idle`), `need` (`approval` / `question` / `limit` / вход и др., `detail`, `resetsAt`), `subagents`, `waitingFor`, `turnEndedAt`, `lastEventAt` |
| `feed.snapshot {ref, scope:'attention'}` | ждущие карточки `permission` / `question` / `plan` и последний ответ модели |
| `@parley/core/card-gist` | краткое описание карточки: `run` (команда), `tool` (инструмент и путь), `fetch` (URL), `question` (первая строка), `plan` |
| `@parley/core/attention`, `session-state` | `sessionAttention` → `needs-you` / `unseen` / `working` / `idle` / `off`; порядок как в сайдбаре окна; `needsYouCount` |
| `@parley/core/stuck` `needReason` | одна строка причины «нужен ты» (`Waiting for your approval: …`, `Asked you a question in its terminal`, лимит с временем сброса) |
| `rooms.mail`, `context.messages`, `context.letter` | письма человеку: список и текст |
| `providers.list`, `roles.list` (решение человека: запуск в MVP) | провайдеры, модели и уровни усилия, готовность провайдера, роли — для листа New session (8.4) |
| hello моста, `bridge.status` | `host` (`starting` / `online` / `offline` / `incompatible`), `epoch`, `minClient`, `hostName`, версии |
| супервизор `remote-client` (§10.2) | `idle` / `connecting` / `handshaking` / `ready` / `waiting` / `offline` / `blocked` |

**Поля проекции** — по черновику S7 после подтверждения человеком (2026-10-31, `f6a36d8d`): у комнаты есть
`title`, `members` и `lead`, у сессии — `parent`, у работы — `projectPath`. Этого хватает на названия комнат
(вопрос В1 закрыт) и на секции проектов.

**Обязательные поля для команд** (раздел 8.2; решение ведущего s-174, m-2034, в задаче A1b): у сессии
`createdBy`, у комнаты `ownerId`, у работы `swarms` без текстов (`objective`, `result`, `failure`, `expiredAt`,
`addedAt` не передаются; `seenAt` передаётся — m-2038). Без них телефон не может построить дерево, как окно: по одному `parent` комнаты
и рои не встают под своего владельца.

## 3. Карта навигации

```
Запуск
 ├─ нет хостов ───────────────▶ Welcome ─▶ Scanner ─▶ Device name ─▶ Handshake ─▶ SAS ─▶ Paired ─▶ Notifications ─▶ Inbox
 │                                 ▲                       ▲
 │  parley://pair?… (камера iOS) ──┴─ Confirm link ────────┘
 │
 └─ есть хост ─▶ Tabs ────────────────────────────────────────────────────────────────────────────────
                 │
                 ├─ Inbox (вкладка 1, бейдж = needsYouCount)
                 │    ├─ карточка разрешения ── Allow / Deny прямо в строке (без «Always»)
                 │    ├─ вопрос / план / сессия без карточки ─▶ Session
                 │    ├─ решение комнаты ─▶ Decision ─▶ (sheet) Return for rework
                 │    ├─ письмо ─▶ Letter
                 │    └─ кнопка ✉ в панели навигации ─▶ Letters ─▶ Letter
                 │
                 ├─ Works (вкладка 2): секции по проектам
                 │    ├─ «+» ─▶ New session / New room (sheet, 8.4) ─▶ Session или Work
                 │    └─ Work: карточки команд (главная сессия → её сессии, комнаты, рои) ─▶ Session
                 │            ├─ шапка команды, комната, рой — свернуть / развернуть
                 │            ├─ «N more under …» ─▶ Session этой сессии (секция Team)
                 │            └─ строка решения комнаты ─▶ Decision
                 │
                 └─ Settings (вкладка 3)
                      ├─ Host ─▶ Rename (sheet), Remove from this phone (alert)
                      ├─ Pair another Mac ─▶ Scanner …
                      ├─ Notifications
                      └─ Diagnostics

Push (тап) ─▶ хост по data.route ─▶ подключение ─▶ Inbox; неизвестный route ─▶ Settings → Macs
Переключатель хоста — меню в заголовке Inbox и Works (только когда хостов ≥ 2).
```

Правила:
- Паринг — модальный поток (full-screen cover) поверх вкладок; при первом запуске вкладок за ним нет.
- Session, Decision, Letter, Letters, Host — push в стек своей вкладки, свайп назад работает везде.
- Return for rework и Rename — системный sheet средней высоты (`detents: medium, large`), с клавиатурой.
- Переход Inbox → Session сохраняет позицию списка Inbox; возврат по свайпу.
- Глубокие ссылки: `parley://pair?…` (паринг) и маршрут push. Других ссылок в этапе A нет.

## 4. Плашка подключения (A14, §11.2 п. 8)

Плашка — одна строка под панелью навигации на всех экранах вкладок и стека (`ConnectionBanner`). Она не
перекрывает контент, а сдвигает его; появляется и уходит пружиной (Reanimated, `damping 20, stiffness 220`).
Состояние `ready` при `host: online` плашки не показывает.

| Состояние | Откуда | Иконка | Текст | Вторая строка / действие | Решения | Цвет |
|---|---|---|---|---|---|---|
| Холодный старт | супервизор `connecting`/`handshaking`, снимка ещё нет | `ProgressView` | Connecting… | — (экран — скелет, раздел 5) | нет | нейтральный |
| Переподключение | `connecting`/`handshaking`/`waiting` при прошлом снимке | `arrow.triangle.2.circlepath` (вращение) | Updating… | Last updated 2 min ago | нет | нейтральный |
| Ждём отступ долго (> 30 с) | `waiting` | `arrow.triangle.2.circlepath` | Updating… | Retrying in 12 s · **Retry** | нет | нейтральный |
| Нет сети | супервизор `offline` (NetInfo + `/v1/health`) | `wifi.slash` | No internet connection | Last updated 2 min ago | нет | нейтральный |
| Relay недоступен | сокет к relay не открывается, `ready` от relay нет за 10 с | `antenna.radiowaves.left.and.right.slash` | Can't reach relay | relay.example.com · **Retry** | нет | предупреждение |
| Мак не в сети | relay `host_offline` | `desktopcomputer` + `zzz` | Mac offline | Your Mac is asleep or Parley is closed | нет | предупреждение |
| Хост запускается | `bridge.status host:'starting'` | `ProgressView` | Mac is starting… | — | нет | нейтральный |
| Хост не запущен | `bridge.status host:'offline'` | `exclamationmark.triangle` | Parley isn't running on your Mac | Open Parley on your Mac | нет | предупреждение |
| Не узнаёт телефон | relay `unknown_device` / `unknown_route` | `questionmark.circle` | This Mac does not recognize this phone | **Pair again** · **Remove** | нет | предупреждение |
| Отозван | `session.closing revoked` / `reset` (только внутри Noise) | — | экран на весь контент, раздел 11.4 | **Pair again** · **Remove** | нет | — |
| Нужна новая версия телефона | `minClient` > версии приложения | — | экран «Update required», раздел 11.5 | — | нет | — |
| Нужна новая версия Мака | `host:'incompatible'` или `protocol` клиента больше | — | экран «Update Parley on your Mac», раздел 11.5 | — | нет | — |

- Плашка «Updating…» не мигает на коротких разрывах: показывается, только если переподключение длится дольше
  1,5 с. Иначе пользователь видит её на каждом возврате в приложение.
- Тап по плашке открывает Settings → Diagnostics текущего хоста.
- Состояния «Не узнаёт телефон», «Отозван» и обе «Update» — `blocked` супервизора: выход только по действию
  человека. Неаутентифицированный сигнал relay ничего не стирает (рамка п. 12): кнопка **Remove** спрашивает
  подтверждение.
- Пока плашка видна, кнопки решений на экране выключены, а над ними подпись «Reconnecting — actions are paused».

## 5. Общие состояния экранов

| Состояние | Как выглядит | Где |
|---|---|---|
| Загрузка, данных нет | скелет строк (3–5 серых плашек, мерцание `opacity 0.4↔0.7`, 1,2 с; при Reduce Motion — без мерцания) | Inbox, Works, Work, Session, Letters, Letter, Decision |

| Потянуть для обновления | системный `refreshControl`, триггер подключения (§10.2) и перечитывания | Inbox, Works, Work, Session, Letters |

### 6.2 Scanner

- Полноэкранный вид камеры, рамка 260×260 pt со скруглением 24 и затемнением вокруг, подпись «Point at the QR code
  on your Mac». Кнопка **Cancel** слева сверху, фонарик `flashlight.off.fill` справа.
- Код распознан → haptic `impact(light)`, рамка подсвечивается акцентом на 200 мс → экран имени.

| Состояние | Что видно |
|---|---|
| Разрешение камеры не спрошено | системный запрос (текст `NSCameraUsageDescription`: «Parley uses the camera only to scan the pairing code on your Mac.») |
| Камера запрещена | `camera.fill` с перечёркиванием (`video.slash`), «Camera access is off», **Open Settings** |
| Не тот QR (`bad_qr`) | плашка внизу: «This isn't a Parley pairing code», сканирование продолжается |
| Симулятор без камеры | то же, что «запрещена», плюс **Paste link** (только dev-сборка) |

### 6.3 Confirm link — вход по `parley://pair?…`

Ссылку могла открыть любая страница (§14 спеки), поэтому этот экран пропустить нельзя (приёмка A14, кейс).

```
  [exclamationmark.shield]
  Pair with a Mac?
  Continue only if you just scanned
  the code on your Mac.
  [ Continue ]        (borderedProminent)
  [ Cancel ]          (plain)
```

- Нет жеста «свайп вниз = Continue»: лист открывается как full-screen, свайп вниз — только отмена.

### 6.4 Device name

- Сгруппированный список: поле `Name` с именем модели по умолчанию («iPhone 16 Pro»), подпись «Your Mac shows this
  name when it asks to allow this phone.» Предел — 40 знаков.
- **Continue** в правом верхнем углу и кнопка внизу; Return на клавиатуре — то же.

### 6.5 Handshake и SAS

- Сначала «Connecting to your Mac…» со спиннером (relay `pair`, msg1, msg2). Таймауты — §10.2.
- После верного msg2 — экран SAS. Код показывается **только** после верного msg2 (§7.4).

```
┌───────────────────────────────┐
│ Cancel                        │
│                               │
│     Check your Mac            │
│                               │
│        123 456                │  ← SF Mono, 48 pt, моноширинные цифры, группы по 3
│                               │
│  Your Mac shows the same code.│
│  Click "Codes match — Allow"  │
│  there.                       │
│                               │
│  [ProgressView] Waiting for   │
│  your Mac…              1:54  │
└───────────────────────────────┘
```

- Haptic `impact(medium)` в момент появления кода — телефон в руке «щёлкает», внимание на экран.
- Таймер — оставшиеся из 120 с ожидания решения на Маке. В последние 10 с цифры `systemOrange`.
- VoiceOver читает код по цифрам: «1 2 3, 4 5 6» (`accessibilityLabel` с пробелами).
- Нет кнопки «коды совпадают» на телефоне: решает только Мак.

| Итог | Экран |
|---|---|
| `credentials` пришли | Paired (6.6) |
| `denied` | `xmark.octagon` «Your Mac denied this phone», **Try again** (новый QR) |
| `timeout` (120 с) | `clock.badge.exclamationmark` «Your Mac didn't answer in time», **Try again** |
| `offer_closed` | `qrcode` с перечёркиванием «This code was already used», «Make a new code on your Mac: Pair a device.», **Scan again**. Если на Маке при этом виден код — это попытка чужого телефона: на Маке нажмите Deny (подпись мелким текстом) |
| relay недоступен | «Can't reach relay», адрес relay из QR, **Try again** |

| «Нужен ты» без карточки (Codex, `blocked` без события) | `hand.raised` | label, работа, `needReason` | — | Session («Answer at your Mac») |
| Лимит / вход | `hourglass` / `person.badge.key` | label, работа, `needReason` (с временем сброса) | — | Session |
| Решение комнаты | `checkmark.seal` | комната, работа, первая строка решения | **Review ›** | Decision |
| Письмо человеку | `envelope` | «Greta → you», работа, первая строка | — | Letter |

- «Always» в Inbox нет никогда: только на экране сессии, где видно всё правило (§11.2 п. 4).
- Под работой у карточки сессии — строка происхождения (9): `↰ Greta › # iOS app: stage A`, `footnote`
  `secondaryLabel`, без ссылок (тап по карточке и так ведёт в сессию). У главной сессии строки нет.
- Allow в строке — для быстрых разрешений; полный вход карточки и последний ответ модели — на Session. Allow в строке —
  под Face ID, как на экране сессии (раздел 12a); Deny — без запроса.
- Свайп строки влево — нет (случайный свайп в списке решений опасен).
- Контекстное меню (долгое нажатие): Open session, Open work, Copy command (только `run`).

## 8. Works и Work (A15, §11.2 п. 3)

Редизайн по замечаниям человека к прототипу (2026-10-31): Works делится по проектам, а экран работы — по
связям сессий, как сайдбар окна (спека окна `2026-09-29-desktop-rooms-organic-design.md` §1.2, §2.7). Общего
потока всех сессий нет: это сотни строк, а поток того, что ждёт человека, уже есть — Inbox. Поля для группировки
есть в проекции V1 (раздел 2): `projectPath` у работы, `parent` у сессии, `members` и `lead` у комнаты.

### 8.1 Works — проекты и работы

Секции — проекты, как заголовки проектов в сайдбаре: цветная точка проекта, имя, число работ. Внутри — работы.
Порядок секций и работ — по самому срочному внутри (ранг внимания §2.7 окна: «нужен ты» 4, `unseen` 3, `working`
2, `idle` 1, законченные 0), при равенстве — проекты по имени, работы в порядке сайдбара.

```
│ Works                         │
│ ● codex-bridge  1             │  ← заголовок проекта: точка цвета проекта, имя, число работ
│ ┌───────────────────────────┐ │
│ │ ● Codex bridge        2 › │ │  ← точка = внимание работы, капсула = сколько ждут тебя
│ │   3 sessions · idle       │ │
│ ├───────────────────────────┤ │
│ │   Done (2)              › │ │  ← работы status: done свёрнуты внутри проекта
│ └───────────────────────────┘ │
│ ● parley  2                   │
│ ┌───────────────────────────┐ │
│ │ ● Improvements   ✉1  5  › │ │
│ │   9 sessions · 2 rooms ·  │ │
│ │   2 working               │ │
│ ├───────────────────────────┤ │
│ │ ● Rooms organic         › │ │
│ │   2 sessions · 1 room ·   │ │
│ │   idle                    │ │
│ ├───────────────────────────┤ │
│ │   Done (3)              › │ │
│ └───────────────────────────┘ │
```

- Вторая строка собирается из проекции: число незакрытых сессий, число комнат и роёв (если есть), число `working`
  или «idle».
- Капсула справа — сколько в работе ждут человека: сессии `needs-you` плюс комнаты с решением (капсула
  `systemOrange`). Рядом `envelope` с числом непрочитанных писем человеку.
- Работы `done` — строка «Done (N)» в конце своего проекта; `archived` в этапе A не показываются.
- Имя проекта — последняя часть `projectPath`. Цвет проекта выводится из пути, как в окне
  (`desktop/src/renderer/lib/project-color.ts`: FNV-1a от `projectPath` по трём ступеням палитры): один проект —
  один цвет на Маке и на телефоне, нового поля не нужно.
- Секции проектов не сворачиваются: проектов обычно мало, а свёрнутая секция прячет ждущее.
- Пусто: `square.stack.3d.up` «No works yet», «Create a work on your Mac.»

### 8.2 Work — команды: главная сессия и всё, что она запустила

Вторая правка человека к прототипу (2026-10-31): одних отступов мало, должно быть явно видно, что подсессии,
комнаты и рои относятся к одной главной сессии. Экран повторяет дерево сайдбара окна
(`desktop/src/renderer/sidebar/sort.ts#cardRows`) и показывает его тремя средствами сразу: карточка команды,
линии дерева и контейнеры для комнат и роёв.

**Дерево — как в окне.**
- **Главная сессия** — сессия верхнего уровня (у неё нет показанного создателя).
- Под сессией по порядку: **комнаты, которыми она владеет** (`Room.ownerId`), **рои, которые она завела**
  (`WorkSwarm.creator`), **сессии, которые она создала** (`WorkSession.createdBy`), и так рекурсивно.
- **Участники комнаты** показаны внутри комнаты, **участники роя** — внутри роя; отдельными строками они не
  повторяются. Владелец комнаты — строка дерева, даже если он сам в ней участвует (правило окна).
- Комната без владельца и рой без показанного создателя — свои команды верхнего уровня.
- Сессия, чей создатель не показан строкой (закрыт и спрятан, стоит участником комнаты), — тоже верхний уровень.

**Команда = карточка.** Каждая главная сессия со всем, что под ней, — отдельная карточка `insetGrouped`. Граница
карточки и есть «это одна команда». Одиночные сессии без подчинённых, стоящие подряд, делят одну общую карточку,
чтобы список не дробился на десятки карточек.

**Шапка команды** — строка главной сессии, крупнее остальных:
- аватар 36 pt — первая буква имени на заливке акцента, в углу значок состояния (рука, точка, галочка);
- имя (`headline`, 18 pt) и строка «чем занят» (до двух строк);
- строка команды акцентом: `arrow.turn.down.right` **Team · 14 agents · 1 room · 1 swarm** — сколько всего под
  ней (участники комнат и роёв входят в число агентов);
- справа капсула «ждут тебя» по всей команде и кнопка свернуть / развернуть (44×44, шеврон поворачивается);
- тап по шапке — экран Session главной сессии; тап по шеврону — свернуть, haptic `selection`;
- свёрнутая команда — шапка и строка мини-значков прямых подчинённых: точки сессий, `checkmark.seal` / `number`
  комнат, статичная иконка «соты» роёв (14 pt, условный рой, как значок карточки в окне);
- **по умолчанию** команда развёрнута, если внутри кто-то работает, ждёт или закончил ход (ранг ≥ 2), иначе
  свёрнута. Ручной выбор держится до перезапуска приложения.

**Линии дерева** — как `TreeGuides` окна: ствол 1,5 pt идёт из-под значка (аватара) родителя вниз, проходит строки
между ними и скруглённым углом (радиус 10) поворачивает к значку ребёнка или к краю контейнера комнаты / роя.
Несколько детей дают «├», у последнего ствол заканчивается углом. Цвет — `separator` посильнее: `rgba(60,60,67,.30)`
в светлой теме, `rgba(235,235,245,.26)` в тёмной. Отступ уровня — 28 pt, ствол — по центру колонки значка (36 pt).

**Комната — контейнер.** Скруглённый блок (радиус 14) на фоне `surface2`, при ждущем решении — `tintSoft` с
тонкой обводкой акцентом:
- шапка: `checkmark.seal` акцентом при решении, иначе `number` (`#`); название до двух строк; ниже капсула
  **Decision** или `3 new`, затем `Room · 4 agents · lead <label>` (у свёрнутой — точки участников);
- **строка решения** `p-03 · rev 2 …  Review ›` → Decision — видна и у свёрнутой комнаты;
- участники — компактные строки внутри блока, у ведущего `★`;
- по умолчанию развёрнута, если ждёт решение или участник ждёт человека.

**Рой — контейнер, облик — как в окне** (третья правка человека: «рой бери из готовых вариантов дизайна, как в
Парли»). Строка роя повторяет `SwarmRow` окна (`desktop/src/renderer/sidebar/SwarmRow.tsx`, `lib/swarm-view.ts`;
спека роя v1 §7.1, §7.5), в том же блоке, что комната:
- **иконка** — живая «соты из капель» окна (`components/swarm-comb.ts`), 24 pt: ячеек столько, сколько трутней и
  проверяющих (до семи), полные — сдавшие, несдавшие — медовые капли кружат вокруг сот; сдача — капля летит в свою
  ячейку и перетекает в шестиугольник; `collecting` — свет обходит соты; `done` — оборот света, волна и искры, потом
  статичный кадр; `failed` / `cancelled` — серые «засахаренные» соты. На тёмной теме — ореол, на светлой — тёмная
  кромка мёда. Анимированы не больше трёх иконок на экране, ~12 кадров в секунду; при Reduce Motion — статичный кадр и
  вспышка яркости 300 мс вместо реакции;
- **первая строка** — **Swarm** `[Research]` (тег — `secondaryLabel`);
- **вторая строка** — точки по одной на трутня и проверяющего (залита — сдал, акцент — упал, контур — работает или
  ждёт), счётчик `3/6` (сдавшие из всех, королева не считается; до первого трутня — `…`), знак конца (✓ готов,
  ⚠ сбой, ✕ отменён), таймер `12:07` от `createdAt` до `endedAt` или сейчас (раз в секунду, только у идущего роя);
- **раскрытый рой** — участники под тонкой линией: 👑 **Queen**, **Drone 1…N** по номеру, **Verifier**; справа слово
  состояния, как в окне: у королевы `cutting the task…` / `waiting for hand-ins…` / `collecting…` / `handed in ✓`, у
  трутня `reading…`, у проверяющего `verifying…`, у всех `waiting`, `handed in ✓`, `failed`, `closed`. Сдавшие и
  закрытые — приглушены, у работающего точка пульсирует. Тап по участнику — его экран Session;
- **законченный рой** — в раскрытом виде блок **Result**. Текста итога и причины сбоя в проекции нет (тексты — этап
  B, В11), поэтому на телефоне — «The queen's summary is on your Mac»;
- **видимость** — как в окне (`isSwarmShown`): идущий рой виден всегда, законченный `done` / `failed` — пока человек не
  посмотрел итог (`seenAt` в проекции), отменённый и просмотренные — только при раскрытом «Closed (N)»;
- **по умолчанию свёрнут**, как в окне; раскрывается сам, только если участник роя ждёт человека.

Иконка роя — не SF Symbol: в приложении это порт `swarm-comb.ts` (поле расстояний и свет по пикселям). Для React
Native — шейдер `react-native-skia` (`RuntimeEffect` на SkSL с тем же полем расстояний) с тем же API `set` / `frame`;
выбор библиотеки — за A15 (вопрос В12). Запасной вариант без анимации — статичные кадры по состояниям.

**Глубина.** На экране работы — три уровня (главная сессия и два под ней). Глубже строки не рисуются: у последней
показанной сессии появляется ссылка `arrow.turn.down.right` **1 more under Push-tests ›**, она открывает экран
Session этой сессии, где дерево продолжается в секции Team (раздел 9).

### 8.3 Состояния Works и Work

Загрузка (скелет) · пусто · список · переподключение / офлайн (прошлый снимок + плашка) · новая эпоха (снимок
целиком заменяется без анимации строк, чтобы не «прыгало» 300 строк) · работа исчезла из снимка, пока открыт
Work → «This work is no longer on your Mac» и возврат к Works.

Состояния группировки на экране Work:
- команда развёрнута / свёрнута; комната и рой развёрнуты / свёрнуты (по умолчанию — по правилам 8.2, затем ручной
  выбор);
- решение комнаты принято или возвращено (здесь или на Маке) — строка решения уходит, фон контейнера гаснет,
  команда опускается по рангу при следующем снимке; если человек её не трогал, комната сворачивается;
- участник вышел из комнаты или комнату архивировали — его строка возвращается в дерево по `createdBy`;
- трутень сдал — точка заливается, счётчик растёт, в иконке капля летит в свою ячейку; все сдали — `collecting`
  (свет обходит соты, королева `collecting…`); рой закончен — знак конца ✓ / ⚠ / ✕, таймер встаёт, иконка
  проигрывает «готово» или сереет, в раскрытом рое — блок Result;
- дерево глубже трёх уровней — ссылка «N more under …» вместо строк;
- новая сессия в снимке — встаёт на место по порядку без анимации сдвига всего списка (fade 150 мс самой строки).

### 8.4 New session / New room — запуск с телефона

Решение человека 2026-10-31 (решение 5, спека §4.2 «Запуск с телефона», §11.2 п. 9, §11.4, §12; `b47befcb`):
телефон в MVP заводит сессии и комнаты и пишет письмо в комнату (`sessions.create`, `rooms.create`, `rooms.send`,
`providers.list`, `roles.list`). На Маке один переключатель «Allow creating sessions and rooms from the phone»,
**по умолчанию включён**. Face ID — перед каждым запуском и каждой отправкой (12a). Хост — власть: правила параметров,
известные проекты и работы, лимиты.

**Вход.** Кнопка `plus` в панели навигации Works (воркспейс по умолчанию — первый активный) и экрана воркспейса (этот
воркспейс). Кнопка есть, **только если методы есть в hello моста**: переключатель на Маке выключен — кнопки нет.
Без связи кнопка выключена. Лист — системный sheet на большую высоту; сверху сегменты **Session | Room**. Свайп вниз
с введённым текстом спрашивает «Discard this draft?».

**New session.**

```
│ Cancel        New session         │
│ [  Session  |  Room  ]            │
│ WORKSPACE                         │
│ │ Improvements                ⌄ │ │  ← существующие неархивные работы из проекции, по проектам
│ AGENT                             │

│ │ Role                   None ⌄ │ │  ← roles.list
```

- Уходит `sessions.create {projectPath, workId, provider, label, task, parent: null, model, role?, worktree}`.
  Усилия, `agent` и облегчённого запуска на телефоне нет: хост отвечает на них `bad_request` (4.2). Модель и усилие
  по умолчанию — настройки Мака.
- После ответа `{ref}` — лист закрывается, тост «Session started», экран новой сессии.

**New room.**

```
│ Cancel          New room          │
│ [  Session  |  Room  ]            │
│ WORKSPACE     Improvements      ⌄ │
│ ROOM NAME   [What the agents will discuss] │  ← обязателен, 1–128
│ MODE   [ Free | Checklist | Verified ]     │  ← autonomous — только на Маке
│ MEMBERS · ★ LEAD                  │
│ │ ◉ Greta            feature-lead ★│ │  ← сессии этой работы (живые, не участники роёв)
│ │ ◉ Astra-browser    architect   ☆│ │
│ │ ○ Changelog-writer writer       │ │
│ NEW AGENTS                        │
│ │ [ Claude | Codex ]   ☆   ⊗     │ │  ← новые агенты: провайдер, модель, роль
│ ╭ ⊕ New agent ╮                   │
├───────────────────────────────────┤
│   Room with 3 agents in Improvements │
│ [ (faceid) Create room          ] │
```

- Участники — сессии этой работы: отмеченные существующие и новые агенты. Новые запускаются тихо
  (`sessions.create` с пустой задачей), затем `rooms.create {title, members, lead, quiet: true, mode}`. Ведущий — звезда
  у отмеченного участника; без выбора — первый. `autonomous`, рецепты и `origin` с телефона закрыты (хост:

- Подсказки режимов: Free — «The lead brings you a decision when the agents agree»; Checklist — «The lead proposes a
  plan of items; you accept it, then the room works through it»; Verified — «Like Checklist, and a verifier checks

- **Шаг 2 — первое письмо** (`rooms.send`, задача тихой комнаты). Тот же лист: `checkmark.circle.fill` «Room created»,

  тост «Write the task in the room on your Mac».
- После отправки — экран воркспейса, комната развёрнута в своей команде.

|---|---|

| Офлайн | `plus` выключен; открытый лист — кнопка выключена, «Reconnecting — actions are paused» |

### 9.1 Карточки

- **Разрешение.** Иконка и заголовок по `card-gist`: `Run a command` / `Edit a file` / `Fetch a page` / `Use <tool>`.
  Вход карточки целиком (моно, `footnote`, горизонтальная прокрутка у длинных строк). Кнопки: **Deny**
  (`bordered`), **Allow** (`borderedProminent`), над ними — **Allow and don't ask again** (`bordered`, во всю
  ширину) **только** при непустом `permission_suggestions` (приёмка A15, кейс); под ней мелко «Adds the rule:
  Bash(pnpm lint:*)». Перед «Always» нет алерта: правило видно на кнопке.
  **Allow** и **Allow and don't ask again** — под Face ID (раздел 12a): на кнопке слева значок `faceid` (или
  `lock.fill`, когда биометрия не настроена), пока настройка включена. **Deny** — без запроса.
- **Вопрос.** Для каждого вопроса — `header` (капсула), текст, варианты как строки сгруппированного списка с
  описанием второй строкой. Один выбор — галочка `checkmark`; `multiSelect` — `checkmark.circle.fill` /
  `circle`. Поле «Other» — свой ответ (≤ предела `FEED_DECISION_ANSWER_LIMIT`). Кнопка **Send answer** внизу
  активна, когда на каждый вопрос есть ответ.
- **План.** Текст плана — Markdown во всю ширину, прокрутка. Внизу две кнопки, слова как в окне: **Approve,
  auto-accept edits** (`borderedProminent`) и **Approve, approve each edit** (`bordered`), обе под Face ID, со значком
  `faceid` (12a, В13). Вариант «отклонить»
  в CLI — ответ в терминале: ниже ссылка-подпись «To keep planning, answer at your Mac».
- **Нет карточки при `blocked`** (Codex, экран без события) → карточка
  `[desktopcomputer] Answer at your Mac` с `needReason` и строкой «This request can only be answered in the
  terminal on your Mac.»
- **Лимит / вход** — информационная карточка: `hourglass` «Usage limit · resets at 14:30» или `person.badge.key`
  «Signed out of Claude» и «Answer at your Mac». Действий нет.

Список «ключ — значение», моно для значений, долгое нажатие — Copy: Relay (адрес), State (`ready` / …), RTT (по
последнему `ping`), Last connected, Host (`online` / …), Epoch, Bridge version, Host version, Stage (A), Device ID
(первые 8 знаков). Кнопка **Reconnect**.

### 11.4 Removed from this Mac — отозван или сброс

Только по `session.closing {reason:'revoked' | 'reset'}` внутри Noise. Экран на месте контента вкладки, вкладки
видны (можно перейти к другому хосту в Settings):

```
  [desktopcomputer.trianglebadge.exclamationmark]
  Removed from Evgeniy's MacBook Pro
  This Mac no longer allows this phone.
  [ Pair again ]     (borderedProminent)
  [ Remove ]         (plain, destructive)
```

Haptic `notification(error)` один раз при появлении.

### 11.5 Update required

- **Телефон старше** (`minClient` > версии): `arrow.down.app` «Update Parley on your phone», «Your Mac needs
  version 1.2 or later.», кнопка **Open App Store** (в Personal Team-сборке — без кнопки, «Install the new build
  from Xcode»).
- **Мак старше** (`host:'incompatible'` или `protocol` клиента больше): `desktopcomputer` «Update Parley on your
  Mac», «This phone needs a newer Parley on your Mac.»
- Оба — `blocked`: прошлого снимка не показываем, решения невозможны.

### 11.6 Безопасность: «Require Face ID to allow»

Секция **Security** над уведомлениями, одна строка:
- `faceid` **Require Face ID to allow** — переключатель, **по умолчанию включён** (решение 6). На iPhone с Touch ID —
  «Require Touch ID to allow» и `touchid` (`supportedAuthenticationTypesAsync`). Биометрия не настроена — подпись
  второй строкой «Face ID isn't set up — your passcode is used», значок `lock.fill`.
- Подпись под секцией: включено — «Parley asks for Face ID before Allow and Accept. Deny, Return for rework, answers
  and viewing never ask.»; выключено — «Allow and Accept are sent without Face ID. Anyone holding this unlocked
  iPhone can approve.»
- **Выключение — само под Face ID**: иначе чужие руки сначала выключат защиту, потом одобрят. Включение — сразу.
- Настройка локальная (Keychain/SecureStore приложения), мост и хост о ней не знают.

## 12a. Face ID на одобрение (решение 6, спека §11.4)

Защита от чужих рук на разблокированном телефоне, а не граница доступа: проверка только на телефоне, мост и хост о ней
не знают.

| Действие | Face ID |
|---|---|
| Allow разрешения — на экране сессии и прямо в Inbox | да |
| Allow and don't ask again («Always») | да |
| Start session, Create room, первое письмо в комнату (8.4; `rooms.send` — каждая отправка) | да |
| Accept решения комнаты (`rooms.resolveProposal` с `accept`) | да |
| Выключить «Require Face ID to allow» в Settings | да |
| Одобрение плана — оба варианта: «Approve, auto-accept edits» и «Approve, approve each edit» (В13) | да |
| Deny, Return for rework, ответ на вопрос, отказ от плана и отзыв на него (они — в терминале на Маке), просмотр | нет |

**Поток.**
1. Тап по Allow / Accept → кнопки выключаются, вызов **ещё не уходит**.
2. `LocalAuthentication.authenticateAsync({ promptMessage, disableDeviceFallback: false })`. Системный запрос
   Face ID поверх экрана — своего оформления нет. `promptMessage` (виден при коде и Touch ID): «Confirm to allow» /
   «Confirm to approve the plan» / «Confirm to accept the decision» / «Confirm to turn off Face ID for approvals».
3. Успех → вызов уходит; дальше всё как раньше: спиннер, итог `applied` / `already answered` / `conflict` / `lost`.
4. **Отмена** (свайп, «Cancel», уход из приложения) → вызова нет, карточка или решение на месте, кнопки снова
   доступны; тост «Face ID cancelled — nothing was sent» (2 с). Haptic приложения нет — системный уже был.
5. **Лицо не узнано** → системный алерт «Face Not Recognized»: **Try Face ID Again** / **Enter Passcode** /
   **Cancel**. Код устройства — системный экран «Enter iPhone Passcode» с той же причиной. Успех кода = успех Face ID.
6. **Биометрия не настроена** (`isEnrolledAsync` → false) → сразу системный экран кода устройства.
7. Между запросом и ответом карточку могли закрыть на Маке: перечитывание 10.3 продолжается; если карточки нет —
   после успеха Face ID вызов не уходит, показывается «Answered at your Mac».

**Детали.**
- `NSFaceIDUsageDescription`: «Parley uses Face ID to confirm approvals.» Первый запрос iOS — системное
  разрешение на Face ID; отказ → дальше только код устройства.
- Пока системный запрос на экране, приложение в `AppState: inactive`, не `background`: супервизор подключения (§10.2)
  не считает это уходом в фон и не рвёт соединение.
- Соединения нет (плашка «Updating…») — кнопки выключены, Face ID не спрашивается: спрашивать ради вызова, который не
  уйдёт, нельзя.
- Face ID спрашивается на каждое одобрение, без «окна доверия» на N секунд (`LAContext.touchIDAuthenticationAllowableReuseDuration` = 0):
  иначе второе одобрение после первого прошло бы без проверки.

## 14. Открытые вопросы к человеку

- **В1. Название комнаты в проекции** — закрыт: `title` есть в проекции V1 (S7 после подтверждения).
- **В2. Строка «чем занят» без текстов.** В проекции нет `summary`, поэтому строка сессии строится из активности
  («Working · 2 subagents», «Idle · 20 min ago»). Нужен ли телефону короткий итог сессии — например первая строка
  `summary` до 120 знаков? Это +~10 КБ сырыми на 350 сессий. По умолчанию — нет, хватает активности.
- **В3. Письма и счётчик в этапе A.** Телефон не умеет `mail.markRead` (этап B), поэтому прочитанное на телефоне
  письмо остаётся в бейдже и push-счётчике, пока его не прочтут на Маке. Варианты: (а) так и оставить, письмо
  уходит в Inbox вниз с отметкой «Opened on this phone» — по умолчанию; (б) перенести `mail.markRead` в этап A.
- **В4. Комната без решения.** В этапе A у телефона нет ленты комнаты: тап по такой комнате ничего не открывает.
  Достаточно ли этого, или нужен экран комнаты только для чтения (`context.messages` по комнате)? С `rooms.send` в этапе A —
  см. В17.
- **В5. Переключатель уведомлений.** Выключить push можно двумя способами: (а) телефон шлёт
  `push.register {apnsToken: null}` и мост перестаёт слать — честно и экономно, по умолчанию; (б) только скрывать
  на телефоне. (а) требует, чтобы `push.register` с `null` значил «не слать», — так и в A16.
- **В6. Порядок и отбор работ.** Работы `done` свёрнуты, `archived` не показываются, закрытые сессии свёрнуты
  (V2 S7 на уровне экрана). Нужен ли фильтр V3 «только работы с активностью за 7 дней»? Для него у работы нужно
  время последней активности (`updatedAt`) — в проекции V1 его нет.
- **В7. Allow прямо в Inbox.** Макет даёт Allow / Deny разрешения прямо в строке Inbox (без «Always»). Это
  быстро, но человек видит только краткое описание (команду в 2 строки). Альтернатива — только переход на Session.
  По умолчанию — в строке, команда целиком по тапу.
- **В8. Акцент.** Терракотовый акцент Parley (`#C67139`) на белом даёт 3,6:1 — мало для текста. Макеты берут
  затемнённый `#A8531E` (5,4:1) в светлой теме и `#E08A52` в тёмной. Подходит ли, или акцентом iOS-приложения
  оставить системный синий?
- **В9. Биометрия** — решено человеком (решение 6, 2026-10-31): Face ID перед Allow и Accept, запасной путь — код
  устройства, настройка «Require Face ID to allow» включена по умолчанию (раздел 12a).
- **В10. Вид команд на экране работы.** Макет по умолчанию — **Team cards**: карточка на главную сессию, шапка с
  аватаром, линии и контейнеры комнат и роёв. Альтернатива **Tree lines only** — то же одним списком, как карточка
  сайдбара (переключатель в прототипе). По умолчанию — Team cards: граница команды видна без чтения линий.
- **В11. Итог и видимость законченного роя** — решено ведущим (m-2038): `seenAt` роя входит в проекцию, телефон
  прячет просмотренные законченные рои по правилу окна `isSwarmShown`; `failure` и `result` — тексты, остаются на
  этап B (статус и так говорит `failed` / `cancelled`).
- **В12. Иконка роя в React Native.** Порт `swarm-comb.ts` требует рисования по пикселям: `react-native-skia`
  (новая зависимость, шейдер SkSL) или статичные кадры без анимации. Решение — за A15 и ведущим.
- **В13. Face ID на одобрение плана** — решено человеком (2026-10-31, спека §11.4, `8b1a9d1f`): Face ID на любом
  одобрении плана, и с `auto-accept`, и без; отказ от плана и отзыв на него Face ID не спрашивают.
- **В14. Телефон без кода-пароля.** Если на iPhone нет ни Face ID, ни кода, `authenticateAsync` не может ничего
  спросить (`passcode_not_set`). Варианты: (а) одобрения идут без проверки, в Settings предупреждение «This iPhone has
  no passcode — approvals are not protected»; (б) Allow и Accept недоступны, пока не задан код. Предложение — (а):
  без кода телефон и так открыт любому.
- **В15. Задача комнаты с телефона** — решено (решение 5, `b47befcb`): `rooms.send` в этапе A, письмо в комнату,
  в том числе первое — задача тихой комнаты; Face ID на каждую отправку.
- **В16. Что ещё из диалога окна** — решено там же: режимы комнаты на телефоне — `free`, `checklist`, `verified`;
  `autonomous`, рецепты и `origin` — только окно; усилия, `agent` и облегчённого запуска с телефона нет.
- **В17. Экран комнаты.** `rooms.send` теперь в этапе A, а читать ленту комнаты позволяет `context.messages`. Нужен ли
  в MVP экран комнаты с лентой и полем письма (тогда закрывается и В4), или письмо в комнату пока только первое — из
  листа New room?

## 18. Dynamic Type и VoiceOver

**Dynamic Type.**
- Все тексты — стили раздела 17.2, проверка до `AX5` (accessibility sizes).
- Начиная с `accessibility1`: строки списка переходят в вертикальную раскладку (бейдж и `role · model` под
  текстом, а не справа); кнопки Deny / Allow встают друг под другом во всю ширину (Allow сверху).
- Команды и код не переносятся по словам, прокручиваются по горизонтали; размер — как `footnote` с масштабом.
- Код SAS при `AX3+` переносится на две строки «123» / «456», не уменьшается.
- Нижняя панель действий не закрывает контент: контент получает нижний отступ по её реальной высоте.

**VoiceOver.**
- Строка Inbox — один элемент: «Permission. Mobile-D1-designer, Улучшайзинг. Run a command: pnpm lint. 2 minutes
  ago.» Кнопки Allow / Deny — отдельные элементы и `accessibilityActions` строки («Allow», «Deny»), чтобы ответить
  без поиска кнопки.
- Точка состояния не читается отдельно: состояние входит в метку строки («Needs you», «Working»).
- Плашка подключения — `accessibilityLiveRegion` / `announceForAccessibility` при смене (не чаще раза в 5 с),
  кнопки плашки — отдельные элементы.
- Код SAS — по цифрам; таймер — `accessibilityLabel` «1 minute 54 seconds left», обновление не объявляется.
- Итоги решений («Allowed», «Already answered at your Mac») объявляются `announceForAccessibility`.
- Выключенные кнопки — `accessibilityState.disabled` и подсказка «Reconnecting — actions are paused».
- Лист New session: агенты — группы с заголовком «Agent 1, lead»; звезда — кнопка «Make lead»; итог запуска
  объявляется «Session started» / «Room created».
- Кнопки под Face ID: `accessibilityLabel` «Allow», `accessibilityHint` «Requires Face ID»; отмена Face ID
  объявляется «Face ID cancelled, nothing was sent».
- Заголовки секций — `accessibilityRole="header"`, чтобы ротор «Заголовки» работал.
- Увеличенный контраст (`Increase Contrast`): системные цвета подстраиваются сами; у `tint` — вариант `#8C4519` /
  `#F09A62`.
