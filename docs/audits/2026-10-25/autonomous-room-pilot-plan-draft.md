# Пилот автономной комнаты — черновик плана (редакция 4 после рецензий m-469, m-471, m-483 и сверки с кодом стопки; к рецензии критика до Go)

Основание: решение p-09 (§11 п. 2 плана этапа 1), ответ 6 человека (эталонная задача — экран с графиком, анимацией, связанными данными и намеренными ловушками, одна комната), провайдеры по p-06.

**Редакция 4 (сверка с кодом стопки f25fb26e, 2026-10-25).** Инструмент `propose_decision` принимает замороженные входы спецификаций **путями** (`inputs: string[]`, `validateAutonomousDraft`); blob каждого пути хост замораживает сам по голове базовой ветки полигона (`main`) в момент предложения (`freezeChecks` в `attempts-endpoint.ts`: путь обязан быть файлом на этой голове, иначе `bad-input`). Аргументы плана ограничены 64 КиБ (`planTool`), а текст плана (цель, заголовки, объём и критерии пунктов) вместе с текстом карточки решения — 10 000 символов (`PLAN_TEXT_MAX`). Черновик редакции 3 (137 КБ, 968 пар путь/blob) этим правилам не отвечал: валидатор ядра отвергает объекты во входах (`invalid autonomous check`). Исправление: шлюз типов стал скриптом `scripts/typecheck.mjs` с манифестом контрольных сумм `vendor/typescript/SHA256SUMS` (коммиты полигона `fd2a235`, `7970974`), замороженных входов 11 на каждую проверку (99 записей), JSON черновика ≈ 10 КБ; карточка Go — не длиннее 6000 символов (валидатор ядра из сборки стопки: при тексте 7000 проходит, 8000 — отказ). Старый файл сохранён как `pilot-plan-draft.v3.json` только для сравнения.

## Полигон

`~/parley-pilot/chart-screen` — одноразовый git-репозиторий вне Parley, без устанавливаемых зависимостей: TypeScript исполняется Node 22 с `--experimental-strip-types`, тесты — `node:test`, шлюз типов — vendored компилятор TypeScript 5.9.3 (`vendor/typescript`, строгий `tsconfig.json`, `--noEmit`). Так проверки работают в песочнице запускателя и в клонах попыток без `pnpm install` (установка из клона писала бы в хранилище pnpm вне разрешённых корней). **Отступление от текста p-09, которое выносится в карточку Go:** вместо «Vite + TypeScript» — Node + vendored tsc; сборки бандла нет, её роль играет дымовой снимок `dist/screen.html` (три кадра перехода, настоящие SVG-узлы через `createElementNS`), который человек открывает в браузере при финальной приёмке. Экран собирается через переданный документ (`MinimalDocument` с `createElement` и `createElementNS`), проверяется документом-заглушкой `test/fake-dom.ts`, который различает пространства имён и сериализует разметку.

Базовый коммит (baseSha для Go): `7970974ece8b592309361967875388ef2e2d2afe` (голова `main` полигона; хост берёт blob'ы входов с головы `main` в момент предложения, поэтому до Go в `main` полигона ничего не коммитить). Заготовки модулей бросают `not implemented`; на заготовках: typecheck проходит (контракты типизированы), тесты падают — data 0/6, chart 0/4, anim 0/4, screen 1/5 (проходит только страж «нет глобалов»), smoke 0/1. Эталонное решение ведущего (вне полигона, не раскрывается) проходит typecheck и 20/20 тестов — спецификации выполнимы.

## Пункты плана (owner и verifier = ENGINE)

1. **Данные и связи** (`src/data/series.ts`, `src/data/catalog.ts`). Критерии: (а) `parseDate` принимает ISO и `DD.MM.YYYY`, отвергает мусор и несуществующие даты; (б) `linkSeries` даёт ряды в порядке каталога, `unknown` в конце только при наличии записей вне каталога, точки отсортированы, одинаковые даты суммируются, вход не мутируется; (в) `monthlyTotals` и `formatMonth` по UTC. Проверка: `ck-data` = `node --experimental-strip-types --test test/data.test.ts`. Качественный критерий (проверяющий): реализация без побочных эффектов и без изменения сигнатур из заголовка модуля.
2. **Геометрия графика** (`src/chart/path.ts`), after [1]. Критерии: (а) `scaleLinear` с экстраполяцией и вырожденным доменом; (б) `ticks` — красивые шаги, границы покрыты, не больше `count + 1`; (в) `linePath` — точный формат `d`, округление до 2 знаков без лишних нулей, ось Y вниз. Проверка: `ck-chart` = `… test/chart.test.ts`. Качественный: чистые функции, без DOM.
3. **Анимация** (`src/anim/tween.ts`), независимый. Критерии: (а) `easeInOutCubic` с зажимом и монотонностью; (б) `tween` с нулевой длительностью; (в) `resample`/`morph` для рядов разной длины, детерминированные кадры, правило пустого ряда. Проверка: `ck-anim` = `… test/anim.test.ts`. Качественный: ни таймеров, ни `Date.now`.
4. **Экран** (`src/screen/render.ts`), after [2, 3]. Критерии: (а) заголовок с названием региона и месяцем первой точки; (б) `svg` и `path` созданы через `createElementNS(SVG_NS, …)`, `d` равен `linePath` текущего кадра; (в) легенда по всем рядам с `aria-current` и цветом; (г) `frameAt` — промежуточный кадр на 250 мс равен независимо вычисленной интерполяции пересэмплированных рядов по `easeInOutCubic`, не совпадает ни с началом, ни с концом; (д) дымовой снимок `dist/screen.html` с тремя кадрами настоящего SVG. Проверки: `ck-screen` = `… test/screen.test.ts`, `ck-smoke` = `… test/smoke.test.ts`. Качественные (проверяющий): экран переиспользует `formatMonth` (пункт 1), `linePath` (пункт 2) и `morph` (пункт 3), а не копирует их; документ только параметром, глобалов нет (страж в тесте).

Шлюз типов: у каждого пункта N спецификация `ck-types-N` = `node scripts/typecheck.mjs` (одна команда на весь проект; заготовки других пунктов типизированы, поэтому шлюз проходит с первого пункта). Скрипт сверяет каждый файл `vendor/typescript/**` с манифестом `vendor/typescript/SHA256SUMS` (правка, лишний или недостающий файл — отказ кодом 2), отказывает при `@ts-nocheck`/`@ts-ignore`/`@ts-expect-error` в `src/` без учёта регистра (рецензия m-483: компилятор понижает регистр имён прагм, `// @TS-NOCHECK` отключает проверку файла — проверено на vendored tsc 5.9.3: без директивы TS2322/код 2, с директивой любого регистра — код 0 у tsc, отказ шлюза кодом 2), затем запускает vendored `tsc --noEmit -p tsconfig.json` тем же Node (`process.execPath`) и возвращает его код. Замороженные входы **каждой** из 9 проверок одинаковы — 11 путей: `package.json`, `tsconfig.json`, `scripts/typecheck.mjs`, `vendor/typescript/SHA256SUMS`, `test/node-env.d.ts`, `test/fake-dom.ts` и пять `test/*.test.ts`; так исполнитель одного пункта не может тронуть тесты другого и не может ослабить шлюз (скрипт и манифест заморожены, перечислять 104 файла компилятора не нужно). `cwd` = корень клона, `timeoutMs` = 120000. **Команды и окружение (рецензия m-471):** запускатель не наследует PATH хоста и ищет голую команду только в `spec.env.PATH` или `/usr/bin:/bin`, где Node нет; поэтому `argv[0]` — абсолютный путь `/Users/kalmbik61/.nvm/versions/node/v22.23.3/bin/node` (Node 22.23.3 этой машины), `env` = `{ PATH: '/Users/kalmbik61/.nvm/versions/node/v22.23.3/bin:/usr/bin:/bin' }`; проверено запуском шлюза типов и тестов под `env -i` с этим PATH. Спецификации порождаются скриптом ведущего (`make-pilot-draft.sh <полигон>` печатает массив `checks`, каждый путь проверяется как файл на HEAD полигона): 9 проверок (`ck-data/chart/anim/screen`, `ck-types-1..4`, `ck-smoke`). Проверено на копиях полигона: заготовки — шлюз проходит (код 0); подделка `lib.es5.d.ts`, лишний файл в `vendor`, `@ts-nocheck` в `src` — отказ кодом 2; ошибка типов — код tsc; эталонное решение — шлюз проходит, 20/20 тестов, `dist/screen.html` записан. Черновик целиком (`pilot-plan-draft.json`, 9994 байта в каноническом JSON) прошёл `validateAutonomousDraft` из сборки стопки на карте с автономной комнатой; все 11 путей — blob на `7970974`.

Покрытие: каждый критерий → соответствующий `ck-*` плюс `ck-types-N` пункта; качественные критерии → `verifier`.

## Намеренные ловушки (не раскрывать исполнителям)

- смешанные форматы дат и запись региона `east` вне каталога (пункт 1);
- точный формат `d` и правило округления (`12.50` → `12.5`), вырожденный домен (пункт 2);
- ряды разной длины в `morph`, зажим `t`, пустой ряд (пункт 3);
- экран обязан использовать `formatMonth` из модуля пункта 1, `linePath` на кадре `frameAt`, а не на исходных точках, и `morph` пункта 3 (пункт 4 зависит от помощников пунктов 1–3 — сценарий «экран A зависит от помощника B»); переиспользование проверяет проверяющий по diff;
- `svg`/`path` через `createElement` проходят только по виду, но не по пространству имён — страж в `test/screen.test.ts` и `test/smoke.test.ts`;
- промежуточный кадр: «скачок» в конце перехода не проходит независимое ожидание на 250 мс;
- `test/*` заморожены: правка теста ломает квитанцию (`frozen-inputs-changed`);
- подмена vendored компилятора, лишний `.d.ts` в `vendor` или подавление проверки типов директивой — отказ шлюза (`scripts/typecheck.mjs` и манифест заморожены).

## Финальная приёмка снимка (рецензия m-471)

`dist/screen.html`, который пишет `ck-smoke`, живёт в одноразовом checkout проверки и удаляется запускателем вместе с ним; доказательством проверки остаётся вердикт и хвост вывода. Файл для человека получается документированным шагом после `verified` пункта 4 (и перед принятием завершения): ведущий снаружи песочницы выполняет в полигоне `git worktree add <tmp> <зеркало ветки интеграции на verifiedHead>` и `npm run test:smoke` в этом дереве, затем человек открывает `<tmp>/dist/screen.html` в браузере; путь и SHA записываются в отчёт пилота. Продуктовый код для этого не меняется.
