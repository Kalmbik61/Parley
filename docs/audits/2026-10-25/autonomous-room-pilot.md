## 3. Находки

Нумерация — по заметкам наблюдения; у каждой — доказательство и предложение. Три находки (1, 2, 7) напрямую вызвали потери попыток.

1. **Формула хэшей манифеста не дана агенту.** `attempt_submit` требует `submissionKey` и `manifest.hash` по каноническому JSON Parley (`sha: null` участвует); формулы нет в брифе, описании инструмента и гайде; движок пересчитывает `hash` сам при квитанции. Все три исполнителя получили отказ; at-0003 не сдалась вовсе. → Задача 14 (p-15): хэши считает хост, поля необязательны, идемпотентность по тождественному содержимому; реализована s-20, принята критиком (m-586), в стопке с `b975adb4` (итог на 2026-10-26).
2. **Режим разрешений автономных Claude-сессий.** `--permission-mode acceptEdits` перекрывает `defaultMode: auto` человека, а правил allow на инструменты сервера parley в файле настроек нет → первый же вызов `attempt_status`/`attempt_verify`/`check_inbox` ждёт человека; простой 9 минут у проверяющего интеграции. → Задача 11 (p-13): `--permission-mode auto` + `permissions.allow: mcp__parley`; коммит a6c37f11, рецензия снята; живая приёмка не проводилась (часть 2, итог на 2026-10-26).
3. **Ведущий комнаты — критик.** Окно позволило назначить ведущим любого участника; предложение Go исходило от критика, «pilot-lead» получил бриф исполнителя. Разделение «критик рецензирует карточку до предложения» не состоялось. → UX создания автономной комнаты (подсказка о роли ведущего); в спеку графа/карточек.
4. **Обход шлюза типов директивой в верхнем регистре** (`// @TS-NOCHECK`) — слабость полигона в прогоне на `fd2a235`; исправлено в `7970974` после Go. Не продуктовый дефект.
5. **Служебные каталоги инструментов в захвате.** Захваты at-0001 (9f36f56) и at-0002 (5d52783) содержат по 8 файлов `.omc/`, `.omx/` (хуки Claude Code / OMC / OMX пишут в cwd клона); движок исключает только `.parley-tmp`. Одинаковые пути с разным содержимым в двух попытках → add/add-конфликт при слиянии второй (не случился только потому, что at-0001 истекла). → Движок: список исключений захвата (`.omc`, `.omx`, `.claude`, `.codex`, `.agents`) по механизму `.parley-tmp` или `.git/info/exclude` в клоне попытки; полигону — `.gitignore`. Также `main` полигона получил эти каталоги коммитом 7970974 (мой `git add -A` в проекте, где живёт хост другого дома) — убрать после пилота.
6. **Клон интеграции содержит `.omc`/`.omx`** — следствие п. 5 (приходят из захватов); `clean -fdx` перед слиянием это не трогает, потому что файлы отслеживаемые.
7. **Сторож `minutesPerAttempt` считает ожидание в очередях.** 30 минут попытки включают очередь прогонов (по одному на хост), ожидание проверяющего и интеграции; at-0001 истекла через 26 минут после квитанции. Усилено находкой 8. → Варианты: сторож только для стадии исполнителя плюс отдельный предел ожидания; или бюджет ≥ 60 минут для пилотов с реальными проверяющими; записать в план этапа 2.
8. **Проверяющий без `attempt_verify`.** s-08 (Claude) сдал вердикт текстом «PASS» в комнату; качественный критерий остался без машинного вердикта, попытка ждала до истечения. Причины-кандидаты: запрос разрешения на `mcp__parley__attempt_verify` в acceptEdits (у s-08 в журнале acceptEdits → auto и «waiting for your input»); бриф проверяющего недостаточно императивен. → Задача 11 устраняет первую причину-кандидата (по исходникам, вживую не проверено); вторая — бриф проверяющего: «вердикт — только `attempt_verify`, текст не считается» — не сделана (отдельная правка `brief.ts`, этап 2).
9. **Служебные строки «is back / waiting for the human» воспринимаются человеком как шум** (m-501). → показывать свёрнуто или в карточке сессии; UX.
10. **Указатели «New messages» при пустом inbox** — наблюдалось у ведущего в основном доме и записано критиком пилота в backlog дома пилота. Дефект канала уведомлений, не автономной комнаты.
11. **Лимит доставок писем пространства** (400 в час) исчерпан в комнате из 4–5 участников за ~3 часа активной координации; широковещательные письма ведущего отказаны. → пересмотреть учёт доставок (служебные строки Parley тоже считаются?) или значение по умолчанию.

## 5. Часть 2 — не продолжался

Продолжение на новой сборке планировалось так: пересборка desktop из головы стопки с задачами 11, 13, 14 → перезапуск дома пилота → «Продолжить» → третья попытка пункта 1, затем пункты 2 и 4 → `verified` пункта 4 → внешний дымовой снимок → предложение завершения → приёмка человеком.

Фактически: сборка головы `b975adb4` подготовлена (2026-10-25, ~14:30Z), хост дома пилота остановлен человеком в 14:58Z, новая сборка не запускалась. 2026-10-26 в 19:48Z человек решил продолжение не проводить («давай без пилота», m-706); решение p-17 зафиксировало: продолжение отменено, живая приёмка задач 11 и 13 не проводилась, стопка идёт в PR с явной оговоркой об этом. Побочно: 26.10 с 03:45Z до 16:01Z сессия ведущего стояла по недельному лимиту Claude — тот же риск, который вчера грозил верификаторам пилота (Claude sonnet, провайдер верификаторов зашит в `packages/host/src/host.ts:377`).

**Что не проверено вживую** (переносится в описание PR как «Not verified live»): запуск и resume автономной Claude-сессии в режиме `auto` с allow на сервер Parley без единого запроса разрешения; Codex-сессия с worktree на новой сборке: `add`/`commit` при запуске, `pack-refs` + resume + повторный коммит, извещение `git-connectivity-failed` после выхода/удаления сессии; реальная сдача манифеста без хэшей через MCP на собранном приложении (задача 14). Первые реальные сессии на master станут первой живой проверкой; это не приёмка, уже пройденная.

**Задача 15 (p-18, 2026-10-26).** При слиянии `origin/master` (285ed9e2, PR #108 «host-owned map») в ветку PR обнаружился семантический конфликт: сессии с каналом агента исполняют инструменты Parley в хосте через `/agent/tools`, где нет канала агента, нужного `attempt_*` для HTTP-вызова `/agent/attempts`. Исправление — канал попыток внутри хоста (`McpContext.attempts`, `perform` у endpoint попыток) — выполнено задачей 15 (s-20, `f96f9325`, рецензия критика m-846 без замечаний); автоматические наборы этот разрыв не ловили, так как тесты инструментов дают канал, а цикл движка тестируется мимо инструментов.

## 6. Оценка и следующие шаги

Что движок показал в наблюдавшихся операциях первого прогона: квитанции сдачи at-0001/at-0002 с захватом в `engine.git`, прогоны замороженных проверок, кандидат интеграции и слияние at-0002 в ветку интеграции, остановка плана по истечению попытки и продолжение с новой попыткой после «Продолжить», без потери состояния. Это и есть основа оценки; полного цикла до `verified` и завершения на реальных агентах не было, поэтому оценка по p-09 неполная.

Чем объясняются потери прогона: прямые потери попыток вызвали находки 1 (формула хэшей; закрыта задачей 14 по исходникам и автопроверкам) и 2 (режим разрешений; закрыта задачей 11 по исходникам, вживую не проверено); истечению at-0001 способствовала находка 7 (сторож `minutesPerAttempt` считает ожидание очередей) — не закрыта; находка 8 закрыта лишь в части причины-кандидата с разрешениями, бриф проверяющего не правился. Не закрыты и остаются рисками: 5–6 (служебные каталоги `.omc`/`.omx` в захвате → add/add-конфликт при слиянии второй попытки с теми же путями), 7, 8 (бриф), 9–11 (шум служебных строк и дребезг детектора лимита, пустые указатели «New messages», лимит доставок). Задача 13 закрывает не находку пилота, а требование человека m-518 (git без вопросов у Codex). Задача 15 закрывает конфликт со слиянием master, не наблюдение пилота.

Для судьбы режима (p-13 ч. 4): движок в наблюдавшихся операциях состояние не терял и останавливался корректно; дефекты лежали и на границе «агент ↔ канал» (1, 2, 8), и в самом движке (5–7); решение о режиме остаётся за человеком. Дальше: PR стопки в master (p-17) с разделом «Not verified live»; находки 5–8 и 9–11 — отдельные поручения этапа 2; уборка `main` полигона (`.omc/.parley` в коммите 7970974).
