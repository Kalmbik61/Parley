# Ревью критика: A37a (`sessions.resume` с телефона)

Дата: 2026-11-03. Критик: независимый субагент Opus ведущего s-174 (лимит сессий работы исчерпан), только чтение.
Предмет: `5ffde83a` (s-221), влит как `6382c642` в `feat/mobile-device-run`. Текст перенесён ведущим без изменений по
существу.

**Вердикт: блокеров 0, major 1, minor 4.** Граница записи сделана правильно: переключатель, правило параметров,
проверка проекта и работы, лимит и журнал моста. `phone.action` не уходит. Серьёзное замечание одно: хост не
проверяет, что будит именно спящую сессию.

## Major

**M1. Хост будит сессию в любом состоянии, кроме `closed`, а не только `sleeping`.**
- **Где.**
  - `host/src/methods/sessions.ts:86-87` — `launch(ref,'resume')` без проверки состояния.
  - `sessions-service.ts:779-784` — обход, только если сессия уже запускается или её PTY живёт в этом хосте.
  - `sessions-service.ts:842-848` — отсекаются только `closed` и архивная работа.
  - `server.ts:322-324` — для роли `remote` проверяется только `workKnown`.
- **Почему.** Спека §4.2 (правки 19): телефон будит сессию с `lifecycle: 'sleeping'`, а хост — власть. Окно
  ограничивает это только в интерфейсе (`canResume`, `desktop/src/renderer/terminal/send.ts:43-50`). Остров проверяет
  на хосте: `assistant/actions.ts:80`, будит только `sleeping`. Бывают `active` без PTY этого хоста
  (`sessions-service.ts:1931`) и `pending` с живым процессом из терминала (`core/src/work/liveness.ts:155-158`).
- **Сценарий.** Телефон по устаревшему снимку или по Retry шлёт `sessions.resume`:
  - для `active` без PTY — второй `claude --resume <тот же id>` в том же worktree, два агента пишут в один транскрипт;
  - для `pending` (терминал или отложенная сессия автономного движка, `autonomous-engine.ts:392-407`) — запуск с
    `by:'human'` раньше движка.
- **Исправление.** Для роли `remote` требовать `lifecycle === 'sleeping'` по свежему `readMap`, иначе
  `HostError('conflict', 'session is not asleep')`. Тест: `active`, `pending`, `closed` с телефона → `conflict`,
  обработчик не вызван.

## Minor

- **m1. Неизвестная и закрытая сессии приходят телефону как `internal`.** `sessions-service.ts:837,843` бросают
  обычный `Error`; `server.ts:454-457` превращает его в `internal` и пишет в лог хоста «обработчик метода упал».
  Исправление: для `remote` проверять наличие сессии до обработчика (`bad_request`), закрытую — `conflict`.
- **m2. Пробуждение в архивной работе даёт уведомление на Маке.** `workKnown` пропускает архивную работу
  (`host.ts:969`). Дальше `HostError('conflict')` (`sessions-service.ts:846-847`) и `host.notice 'launch-failed'`
  (`:1275-1279`), а окно показывает уведомление (`desktop/src/renderer/attention/notify.ts:126,275`). Исправление:
  для `remote` проверять, что работа открыта, до обработчика, сразу `conflict`, без рассылки.
- **m3. Цель в журнале неоднозначна.** `dispatch.ts:134-142` (`targetOf`) берёт только `ref.sessionId`, а
  `describeParams` (`:95-105`) пропускает вложенные объекты. Номера сессий повторяются между работами. Исправление:
  писать в `detail` `workId` и хэш `projectPath`; то же у `pty.send`.
- **m4. Пробелы в тестах.** Нет пробуждения Codex с доверием к папке с телефона, нет «архивная работа → `conflict`»,
  «закрытая сессия → ошибка» и «не спит → отказ» для роли `remote`.

**К A37b.** В `remote-client/src/rpc.ts:17-25` (`MUTATING_METHODS`) нет `sessions.resume`: таймаут 15 с при сроке
моста 30 с, телефон покажет timeout, пока запуск ещё идёт.

## Проверено и верно

- **Переключатель:**
  - `sessions.resume` стоит в `REMOTE_SWITCHED_METHODS` (`server.ts:94-99`);
  - при выключенном переключателе метода нет в `hello.methods` (`:230`), вызов получает `unknown_method` (`:257-265`);
  - сокеты `remote` закрываются при смене настройки (`host.ts:943-948`).
- **Правило параметров** (`allowlist.ts:321-331`): только `ref`, в нём ровно три непустые строки. Применяется в мосте
  (`dispatch.ts:412`) и на хосте (`server.ts:367`).
- **Цель:** известный проект и работа (`server.ts:323-324`), иначе `bad_request` до обработчика.
- **Особые случаи:**
  - живая сессия этого хоста — `repairLive`, второго процесса нет;
  - сессия, ждущая карточку, — карточка не дублируется (`consents-service.ts:314-323,371-388`);
  - участник автономной комнаты — то же, что в окне.
- **Путь удержания:**
  - доверие к папке у Codex (`sessions-service.ts:866-901`);
  - `project-mcp` у Claude (`:906-933`) с `requestedBy.source: 'resume'`;
  - живой тест через роль `remote` показывает карточку.
- **Мост:**
  - метод в `MUTATING_METHODS` (`limits.ts:27-28`), лимит 30 в минуту;
  - журнал `call` ok/err;
  - склейки и повторов нет;
  - `phone.action` нет.
