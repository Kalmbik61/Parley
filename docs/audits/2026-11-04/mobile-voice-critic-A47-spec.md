# Критик A47: спека «Телефон: кнопка микрофона» (docs/specs/2026-11-04-mobile-voice-input-design.md, 9a03890d)

Критик — s-250 (Opus). Текст из его отчёта записал лид s-174: у роли критика нет права писать файлы.

## Вердикт

В таком виде спеку отдавать исполнителю нельзя. Три блокера:

1. **Защита от сервера Apple.** Гарантия «звук не уходит с телефона» держится на поведении, которое документация
   Apple прямо не обещает. Единственная настоящая проверка в заплатке стоит на пути, который проходится не при каждом
   старте.
2. **Ключ микрофона.** `NSMicrophoneUsageDescription` не попадёт в Info.plist ни при каком порядке плагинов: на первом
   тапе приложение упадёт.
3. **Гонка вызовов.** Нативные `start`/`abort`/`stop` библиотеки асинхронны и не упорядочены. Отмена во время старта
   или переключение поля оставляет микрофон включённым, а интерфейс показывает «готово».

Остальное решается правками спеки: выбор языка, обработка `nomatch`/`no-speech`, уход с экрана без размонтирования,
кнопка Start session, приёмка на устройстве.

Верны: выбор библиотеки, заплатка pnpm (pnpm 9.12.3, ключ `pnpm.patchedDependencies`), перенос `insert.ts`, сборка
текста для iOS 18 и объём задачи в целом.

## Блокеры

### B1. Защита от сервера Apple: правка 2 проходится не всегда, правка 1 по документации ничего не гарантирует

- **Где:** спека §2.2, правки 1–2; `ExpoSpeechRecognitionModule.swift:189–205`; `ExpoSpeechRecognizer.swift:577–590`.
- **Документация Apple.**
  - Справка `SFSpeechRecognitionRequest.requiresOnDeviceRecognition` (developer.apple.com, JSON справки): «The request
    only honors this setting if the SFSpeechRecognizer (supportsOnDeviceRecognition) property is also true».
  - Справка `supportsOnDeviceRecognition`: «If supportsOnDeviceRecognition is false, the SFSpeechRecognizer requires
    a network in order to recognize speech».

  Документация не говорит, что задача упадёт; она говорит, что флаг не учитывается. Утверждение спеки «задача Apple
  падает с ошибкой, а не идёт на сервер» ничем не подтверждено. Правка 1 полезна только как подстраховка.
- **Почему правка 2 не всегда срабатывает.** Она стоит «после `resolveLocale` и до создания распознавателя», то есть
  внутри `if self.speechRecognizer == nil || currentLocale != options.lang` (строка 189). При повторном старте на том
  же языке распознаватель берётся из кэша, и проверки нет.
- **Сценарий.**
  1. Первая диктовка на `ru-RU` прошла, распознаватель закэширован.
  2. Человек выключил диктовку для этого языка или удалил её ресурсы. `supportsOnDeviceRecognition` стал `false`.
  3. Проверка в JS идёт только при возврате на передний план (§2.3), поэтому при переходе по экранам без ухода в фон
     её нет.
  4. Следующий `start` на том же языке пропускает правку 2. Остаётся правка 1, а её Apple, по документации, не
     учитывает.
- **Исправить.**
  - Проверку делать в `ExpoSpeechRecognizer.startRecognizer`, до `prepareRequest` и до `prepareMicrophoneRecognition`,
    на том экземпляре `recognizer`, который реально запускается:
    `if options.requiresOnDeviceRecognition && !recognizer.supportsOnDeviceRecognition { errorHandler(...language-not-supported...); reset(andEmitEnd: true); return }`.
  - Правку 1 оставить подстраховкой.
  - Текст §2.2 переписать по документации.
  - `patch.test.ts` должен проверять, что проверка стоит в `startRecognizer`.
  - В §6 добавить проверку на устройстве (M7).

### B2. `NSMicrophoneUsageDescription` удаляется при любом порядке плагинов: падение на первом тапе

- **Где:**
  - спека §2.4;
  - `packages/mobile/app.config.ts:58` (`microphonePermission: false`);
  - `expo-speech-recognition/app.plugin.js` — пишет в статический `config.ios.infoPlist`, без мода;
  - `expo-camera/plugin/build/withCamera.js:23` — `createPermissionsPlugin` → мод `withInfoPlist`;
  - `@expo/config-plugins/build/ios/Permissions.js:43–45` — `=== false` → `delete infoPlist[permission]`;
  - `withIosBaseMods.js:262–282` — статический `ios.infoPlist` вливается в `modResults` при чтении, до цепочки модов;
  - `withMod.js:84–95` — действие мода выполняется, затем `nextMod`.
- **Сценарий.**
  1. Плагин speech-recognition меняет только статический объект. Базовый мод вливает этот объект в Info.plist при
     чтении, то есть раньше всех модов.
  2. Затем выполняется мод expo-camera и удаляет ключ микрофона, потому что `microphonePermission === false`.
  3. Порядок в `plugins` ничего не решает: у плагина speech-recognition нет мода, после которого можно было бы
     встать.

  Сейчас в `ios/Parley/Info.plist` есть только `NSCameraUsageDescription` (строка 56). Первый тап вызывает
  `requestRecordPermission` без ключа, и iOS завершает приложение (TCC).
- **Исправить.**
  - У `expo-camera` заменить `microphonePermission: false` тем же текстом про микрофон. Камера звук не пишет, ключ —
    только текст запроса.
  - Другой вариант — свой `withInfoPlist` в `app.config.ts`, зарегистрированный раньше camera. Это хрупко.
  - Объяснение в §2.4 исправить. Проверка §6 «оба ключа в Info.plist» верна, её оставить.

### B3. Гонка нативных `start`/`abort`/`stop`: невидимая запись

- **Где:**
  - спека §4 («Номер попытки»), §3.1 (таблица, «другое поле: отменить ту, начать эту»), §6.4 («отмена во время
    `starting`»);
  - `ExpoSpeechRecognitionModule.swift:180–273` — `start` синхронный `Function`, работа идёт в `Task {}` с несколькими
    `await` (`getLocale`, `init`, `hasPermissionToRecord`), затем ещё один `Task` в `ExpoSpeechRecognizer.start:142`;
  - `:366–386` — у `stop` и `abort` тоже свои `Task {}`; при `speechRecognizer == nil` они просто шлют `end`;
  - `ExpoSpeechRecognizer.swift:156–177, 210–211` — `startRecognizer` начинает с `reset`, а `reset` шлёт `end`, если
    задача была.
- **Сценарий 1: отмена во время старта.**
  1. Первый тап: JS вызвал `start`, человек сразу жмёт Cancel (или Send, или поле размонтировалось) → `abort()`.
  2. Неструктурированные `Task` не упорядочены, а у `start` больше `await`, поэтому `abort` обычно выполняется первым:
     шлёт `aborted` и `end`. JS переходит в `idle`.
  3. Затем доходит очередь до `startRecognizer`, и микрофон включается в `continuous` без конца.

  На iPhone горит оранжевая точка, а полоски и кнопки стоп нет. Номер попытки лишь заставляет JS игнорировать
  результаты, микрофон он не выключает.
- **Сценарий 2: переключение поля.** Идёт запись в поле комнаты, человек тапает микрофон другого поля: `abort()` и
  сразу `start()`. Возможны оба порядка.
  - (а) `reset` от `abort` выполняется после `startRecognizer` новой попытки и убивает её.
  - (б) `reset` внутри `startRecognizer` гасит старую задачу и шлёт `end` уже после `start` новой.

  События не несут номера попытки, и JS примет чужой `end`/`aborted` за свой.
- **Сценарий 3.** `stop()` во время `starting`: `task == nil` → `reset(andEmitEnd: true)` → `end`, а запись потом всё
  равно стартует.
- **Исправить.** В §4 описать протокол:
  - нативная сторона «занята» от вызова `start` до своего `end`;
  - новый `start` — только после `end` прежней попытки;
  - отмена или стоп во время `starting` ставят флаг; когда придёт событие `start`, вызвать `abort()` или `stop()`;
    переход `starting → recording` назначить именно на это событие;
  - до `end` все события относятся к прежней попытке;
  - у каждого ожидания `end` свой таймаут: после ошибки `init` распознавателя (строки 263–271) приходит только `error`,
    без `end`.

  В §6.4 добавить тесты поддельного движка с реальным порядком событий:
  - «`start` приходит после `abort`» → вызван `abort`, фаза не `idle` до `end`;
  - «второе поле стартует только после `end` первого»;
  - «`error` без `end`» → таймаут.

## Major

### M1. `isRecognitionAvailable()` проверяет не тот распознаватель

- **Где:** спека §2.3 «Проверка», §3.1, третья причина; `ExpoSpeechRecognitionModule.swift:361–364`
  (`SFSpeechRecognizer()` — язык по умолчанию).
- **Сценарий.** Это та же ошибка, которую спека сама нашла у `supportsOnDeviceRecognition`. Если по `Locale.current`
  распознаватель не создаётся (сочетание языка и региона без распознавателя), функция вернёт `false`. Кнопка покажет
  «Dictation isn't available on this iPhone right now», хотя `ru-RU` работает.
- **Исправить.** Либо четвёртая правка `isRecognitionAvailable(lang?)` по образцу правки 3. Либо не звать эту функцию,
  а полагаться на `supportsOnDeviceRecognition(lang)` и проверку `isAvailable` в `startRecognizer:218` (она даёт
  `service-not-allowed`).

### M2. `pickLocale`, шаг 3: «первый по алфавиту» выбирает вариант без распознавания на устройстве

- **Где:** спека §2.3, шаг 3.
- **Сценарий.**
  - Английский интерфейс и регион Россия или Германия дают `languageTag` `en-RU`/`en-DE`. Шаги 1–2 не находят
    совпадения, а шаг 3 даёт `en-AE`: он первый по алфавиту среди `en-*` в `SFSpeechRecognizer.supportedLocales()`.
    Для `en-AE` распознавания на устройстве, скорее всего, нет. Кнопка «недоступна», хотя `en-US` установлен.
  - Так же `de-RU` → `de-AT`.
  - `zh-Hant` с регионом HK → `zh-HK`, а это кантонский.

  Верно функция работает для русского с регионом US/DE (`ru-US` → `ru-RU`), для `en-GB` и для `zh-Hans-CN` → `zh-CN`.
- **Исправить.**
  - Шаг 3: сначала `<lang>-<LANG>` (`de-DE`, `fr-FR`, `ru-RU`, `ja-JP`), затем короткий список предпочтений: `en-US`,
    `es-ES`, `pt-BR`, `zh-CN` для `Hans`, `zh-TW` для `Hant`.
  - Из кандидатов брать первого, у кого `supportsOnDeviceRecognition(tag)` вернул `true`.
  - Добавить тесты `en-RU`, `de-RU`, `zh-Hant-US`.

### M3. «device/keyboard locale» сведено к первому языку устройства — решает человек

- **Где:** спека §2.3, §8.
- **Сценарий.** Интерфейс iPhone на английском, а человек диктует по-русски (рабочий язык этого пространства —
  русский). Микрофон распознаёт русскую речь как английскую, и без экрана настроек этого не исправить. Язык клавиатуры
  из JS действительно не прочитать. Но человек назвал его явно, а спека молча его выбросила.
- **Исправить.** Вопрос человеку через лида: «Язык — первый язык устройства. При английском интерфейсе русская
  диктовка не заработает. Так годится?» Если нет, есть два варианта:
  - (а) в заплатке отдавать язык текущей клавиатуры (`UITextInputMode`) — это выходит за «ровно три правки»;
  - (б) перебирать предпочитаемые языки и выбирать между ними долгим нажатием — по сути это настройка.

  Сейчас отличие от требования не названо открытым вопросом.

### M4. `nomatch`, `no-speech` и `interrupted` посреди записи: преждевременный конец и потеря текста

- **Где:**
  - спека §3.4;
  - `ExpoSpeechRecognitionModule.swift:502–517` — `nomatch` на пустом результате, который обход для iOS 18 считает
    финальным, если предыдущего финального не было;
  - `:581` — код 1110 → `no-speech`;
  - `ExpoSpeechRecognizer.swift:968–975` — любая ошибка → `reset` → `end`;
  - `:743–747` — прерывание → `interrupted` + `end`.
- **Сценарий 1.** iOS 18, `continuous`. Первый «финальный» кусок пришёл с непустым `speechDuration` и пустым текстом
  (кашель, шум). Посреди записи приходит `nomatch`, хотя распознавание идёт дальше. Таблица §3.4 даёт тост «No speech
  detected». Если хранилище сочтёт это концом попытки, оно уйдёт в `idle` при включённом микрофоне. Если не сочтёт,
  тост всё равно ложный.
- **Сценарий 2.** Полторы минуты диктовки, потом звонок (`interrupted`), `no-speech` или другая ошибка после
  нескольких собранных кусков. По таблице запись выбрасывается, и собранный текст теряется.
- **Исправить.**
  - `nomatch` и пустые результаты не завершают попытку.
  - «No speech detected» решается только на `end`, если сборка пуста.
  - На `end`, который вызван не нашим `abort`, вставлять собранные куски, если они есть: в том числе после
    `interrupted`, `no-speech` и таймаута 10 с.
  - Тесты на оба сценария.

### M5. Экран ушёл из виду, но не размонтирован: запись продолжается невидимо

- **Где:** спека §3.3 («Экран закрыт во время записи — `abort()`»); `src/app/_layout.tsx:38–47` (Stack: `new` —
  модальный экран, `md` — экран поверх); переходы room → session внутри вкладки.
- **Сценарий.**
  - Идёт запись в поле комнаты. Человек тапает ссылку в ленте (`md`) или агента (экран сессии). Прежний экран
    остаётся смонтированным, `abort` не вызывается, микрофон пишет, а полоски не видно.
  - New session открыт модально поверх сессии, и `Composer` сессии под ним смонтирован.
- **Исправить.**
  - Отменять запись при потере фокуса экрана (`useFocusEffect` или `navigation.addListener('blur')`), а не только при
    размонтировании.
  - Распознавание при уходе с экрана идёт по правилу «поле исчезло».
  - Если один экран смонтирован дважды (тот же `session:<ref>` в стеке), снятие цели удаляет её, только если это тот же
    объект — как `register` в окне (`dictation-store.ts`, `register`).

### M6. New session: кнопка «Start session» не завершает запись

- **Где:** спека §4 («⬆ и `chat.send()` сначала зовут `finishBeforeSend`»); `src/app/new.tsx:437` (`submit`); в окне
  `sidebar/NewWorkComposer.tsx:401` зовёт `finishBeforeSend('new-workspace')` перед отправкой.
- **Сценарий.** Человек диктует задачу и жмёт «Start session». Сессия стартует с задачей без продиктованного текста,
  экран закрывается, расшифровка уходит в буфер. Это отличие от окна, хотя §1 обещает «как в окне».
- **Исправить.** `submit` в `new.tsx` сначала зовёт `finishBeforeSend('new-session-task')`. Тест в §6.4.

### M7. Приёмка: на устройстве не проверяются ни защита приватности, ни края сборки текста

- **Где:** спека §6, список «На iPhone».
- **Сценарий.**
  - Авиарежим доказывает только, что выбранный язык работает на устройстве. Что язык без распознавания на устройстве
    не уходит на сервер (B1), он не проверяет.
  - «Две фразы с паузой» не ловят ни дубль последнего куска после «пауза → стоп», ни потерю хвоста при «стоп посреди
    фразы».
  - Сборка §3.3 опирается на комментарий библиотеки о пустом нативном финале
    (`ExpoSpeechRecognitionModule.swift:50–55`), а не на проверку.
- **Исправить.**
  - Дев-флаг (например, `PARLEY_MOBILE_DEV_VOICE_LANG`), чтобы на iPhone запустить `start` с языком без распознавания
    на устройстве и увидеть `language-not-supported` без записи: оранжевая точка не загорается.
  - Добавить в «Not verified»:
    - «фраза, пауза, стоп» — текст ровно один раз;
    - «стоп посреди фразы» — хвост на месте;
    - звонок посреди записи;
    - уход в фон;
    - iOS 17 и iOS 18+ отдельно: сборка текста на них разная (`ExpoSpeechRecognitionModule.swift:459`).
  - Вместе с B3 — тесты порядка событий движка.

## Minor

- **m1. `restricted`.**
  - Alert «Open Settings» из §2.4 при `restricted` бесполезен: это ограничения Экранного времени или MDM
    (`EXSpeechRecognitionPermissionRequester.swift:46–51`). Нужен свой текст без кнопки Settings.
  - Стартует ли запись сама после выдачи разрешений на первом тапе? Спека не говорит. В окне — да
    (`dictation-store.ts`, `begin`).
- **m2. Сопоставление ошибок.**
  - Ошибка создания распознавателя приходит как `not-allowed` без `end` (`ExpoSpeechRecognitionModule.swift:263–271`),
    и по §3.4 человек увидит Alert о разрешениях.
  - `service-not-allowed` (коды 102/201: «Siri or Dictation is disabled», ресурсы не установлены;
    `isAvailable == false`) должен вести в состояние «недоступно» с причиной, а не к «Dictation failed».
  - `audio-capture` — это ещё и код 203, смена маршрута и неизвестные ошибки (`:550, :578, :606`). Поэтому «Microphone
    is busy» часто вводит в заблуждение.
- **m3. Аудиосессия не освобождается.** Библиотека ставит `playAndRecord/measurement` и
  `setActive(true, .notifyOthersOnDeactivation)` (`ExpoSpeechRecognizer.swift:625–632`), но нигде не делает
  `setActive(false)`. Музыка или подкаст человека после диктовки не продолжатся. После `end` звать
  `setAudioSessionActiveIOS(false, { notifyOthersOnDeactivation: true })`.
- **m4. Каретка.**
  - В §3.3 «последнее значение `onSelectionChange`» — на момент старта или вставки?
  - Клавиатура во время записи не убирается: в RN `Pressable` не снимает фокус, у New session
    `keyboardShouldPersistTaps="handled"` (`new.tsx:249`). Значит, человек может печатать, и индекс со старта устареет.
  - Брать каретку в момент вставки и ограничивать её длиной текста. `setSelection` звать после того, как отрисуется
    новое `value`.
- **m5. Таймаут 10 с.** После таймаута звать `abort()`, чтобы микрофон гарантированно выключился, и вставлять уже
  собранные куски (M4).
- **m6. Фаза `starting`.** Её нет в таблице §3.1. Что показывает кнопка и что делает тап? Таймер и предел 2 минуты
  считать от события `start`, а не от тапа.
- **m7. Ширина на iPhone SE (375 pt).**
  - Строка комнаты: `@` 36 + микрофон 44 + ⬆ 44 + три промежутка по 8. Поле ≈195 pt, текста ≈163 pt
    (`room.tsx:582–584`).
  - Подсказка «Write to everyone · type @ to mention an agent» (`room/model.ts:55`) переносится.
  - Нужен снимок SE и крупного Dynamic Type.
  - Порядок над строкой (ReplyPlate, счётчик 16 КБ, полоска записи) не задан. Сказано «там же, где счётчик» — а если
    видны оба?
- **m8. Буфер обмена вместо черновика.**
  - Черновики уже живут в хранилище приложения по ключу (`feed/outbox.ts:43–44`, `draftOf`/`setDraft`). Если поле
    сессии или комнаты исчезло, текст можно дописать в черновик этого ключа. Так он не потеряется и не уйдёт через
    Универсальный буфер на Mac или iPad.
  - С буфером обмена утверждение §5 «расшифровка нигде не хранится» неточно.
  - Буфер оставить для New session.
- **m9. VoiceOver.**
  - Кнопке «Dictate» нужен hint.
  - «Недоступно» нельзя помечать `disabled`, иначе тап не дойдёт.
  - Объявления VoiceOver из динамика (`defaultToSpeaker`) попадут в микрофон и в текст. Это внести в «Not verified».
- **m10. Место `finishBeforeSend` в сессии.** У спящей сессии ⬆ идёт в `askResumeAndSend(chat.composed)` мимо
  `chat.send` (`session/[ref].tsx:598`). Поэтому `finishBeforeSend` звать в обработчике ⬆ у `Composer`, а не в
  `chat.send`.

## Проверено и верно

- `volumechange` — от −2 до 10 (`ExpoSpeechRecognizer.swift:714–719`).
- `getSupportedLocales` на iOS отдаёт `supportedLocales()`, `locales` и `installedLocales` одинаковы (`:393–403`).
- `stop` даёт последний результат, `abort` — без результата (`ExpoSpeechRecognizer.swift:156–177`). После `reset`
  результат не уходит (`:950–953`).
- Пробел спереди у кусков iOS 18 (`:469–471`) и пустой финальный `result` (`:502–526`): `assembleTranscript` с
  обрезкой и пропуском пустых корректен.
- Путь `audioSource` и прочие пути идут через тот же `prepareRequest`.
- Сетевых вызовов в `ios/*.swift` нет; `import AppTrackingTransparency` не используется.
- `requestPermissionsAsync` спрашивает сначала распознавание, потом микрофон; `canAskAgain` верен для смешанных
  состояний.
- Сходство с окном по §1 подтверждается `dictation-store.ts` и `insert.ts`: стоп, вставка с пробелом, Cancel,
  2 минуты, одна запись, `finishBeforeSend`, буфер при исчезнувшей цели. Исключение — M6.
