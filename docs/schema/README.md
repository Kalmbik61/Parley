## Файлы

- `schema-report.json` — какие поля какого типа встречаются у каждого типа записи, с частотой.
- `index.json` — сырой вывод прототипа-экспортёра, по строке на **файл** (не на сессию — см. ниже).

## Что вычищено

Прогон `node tools/scrub-export.mjs claude-export docs/schema`:

- `/Users/<имя>` и слаг `-Users-<имя>-…` → `<user>`;
- сэмплы полей со свободным текстом (`lastPrompt`, `result`, `customTitle`, `aiTitle`,
  `content`, `summary`, `description`, …) → `<redacted>`;
- любой строковый сэмпл длиннее 40 символов или с пробелами → `<redacted:string len=N>`;
- uuid внутри сэмплов → `<uuid>`;
- сегменты имён полей, содержащие `/` (мапы с путями в ключах) → `<key>`.

Числа (`seen`, `count`, `kinds`) и структура полей сохранены полностью — ради них снимок и нужен.

## Как перепроверить после апдейта Claude Code

```bash
node tools/claude-export.mjs --full
node tools/scrub-export.mjs claude-export docs/schema
git diff docs/schema/schema-report.json
```

Непустой diff по `schema-report.json` = формат поехал, нужен новый адаптер схемы.

## Известные искажения `index.json`

Прототип писался под гипотезу «1 файл = 1 сессия», которая на реальных данных неверна.
Поэтому в `index.json`:

- 335 строк ≠ 335 сессий. Настоящих сессий 47, остальное — 253 файла субагентов и 35
  журналов workflow;
- `sessionId` повторяется (48 уникальных на 335 строк): файлы субагентов несут
  `sessionId` **родительской** сессии;
- `project` берётся как имя родительского каталога, поэтому у субагентов там
  `wf_<id>` или `subagents` вместо слага проекта;
- `summary` всегда `null`: записей `type:"summary"` в этой версии нет вообще;
- `subsessionCount` у файлов субагентов = 1 (артефакт: все записи сайдчейновые,
  якорь не находится, всё падает в одну группу `orphan`).

Разбор расхождений и итоговая модель — в `.ralph/specs/data-layer.md`.
