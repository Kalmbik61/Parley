## 1. Зачем и что решено

### 1.1 Вопрос человека

Человек хотел применить в Parley мод `jev-skill-suggestion`: не грузить агентам все скиллы сразу,
а выбирать нужный через навигатор.

### 1.2 Что показал разбор мода

Мод — плагин Claude Code с функциональными хуками (ранний доступ, из claude-code-templates). Он
прячет от модели список скиллов и на каждый промпт вставляет целиком `SKILL.md` одного выбранного
скилла. Выбор по рецепту TypeSafe — два запроса к их модели Jev. Без ключа работает запасной
путь: один вызов маленькой модели Claude Code, без проверки «нужен ли скилл» и без перепроверки
тройки.

На машине разработки мод включён глобально: 86 скиллов переведены в `user-invocable-only`,
`disableBundledSkills: true`, ключа нет. Замер по 62 транскриптам (381 вставка), 2026-10-02:

- **Контекст.** Мод прячет список из 112 скиллов, это около 30 000 знаков. Взамен он вставляет
  в медиане около 28 000 знаков на сессию: `SKILL.md` в медиане занимает 8,8 тыс. знаков, у gstack
  до 80 тыс. Выигрыша нет.
- **Точность.** По ручной оценке последних 40 выборов, примерно половина мимо. Один и тот же
  стартовый промпт работы w-0010 в четырёх агентах дал четыре разных скилла.
- **Parley.** Мод срабатывает на стартовый промпт работы и на указатель «New messages…». На
  «вместе с GPT» он вставляет скиллы OMC (`ccg`, `ask`, `ultrawork`), и те ведут агента в обход
  инструментов Parley.
- **Субагенты** не видят 78 скрытых скиллов: мод работает только в главном разговоре.
- **Codex** мод не покрывает.

Из чего состоит список Claude на этой машине: скиллы плагинов — 17,5 тыс. знаков, claude.ai —
10,2 тыс., свои и проекта — 2,3 тыс. Одни имена заняли бы около 2,8 тыс.

### 1.3 Ответ

Роутер — сама модель сессии. Человек пишет на любом языке, модель его понимает и решает, какой
скилл нужен. Parley даёт ей две вещи:

1. **Короткий список.** В родном списке остаются имена, а описания отдаёт `find_skill`. У Claude
   это переменная бюджета в окружении агента, у Codex — один флаг `-c` (раздел 2). Сокращение
   включается только вместе с навигатором и только там, где путь загрузки подтверждён.
2. **Справочник.** Инструмент `find_skill` MCP-сервера `parley` по запросу отдаёт описания
   подходящих скиллов, модель выбирает и загружает скилл родным способом своего CLI.

В комнате скилл для каждой части работы называет ведущий.

Решения:

- каждый агент находит только скиллы своего CLI. Ведущий может искать скиллы участника (`for`);
- поиск локальный, по словам: без сети, без расхода лимита, без хука на каждый промпт;
- своего формата и каталога скиллов нет, источник — родные `SKILL.md`, как в
  [спеке Capabilities](2026-10-02-capabilities-design.md);
- правила CLI не обходим: скилл, спрятанный человеком, навигатор не показывает;
- переключатель в настройках Parley, по умолчанию выключен (раздел 6).

### 1.4 Чего не делаем

- Хук на каждый промпт со вставкой скилла, как у jev. Это противоречит решению из разбора OMC:
  «не брать хуки на каждый промпт».
- Отдельную модель для выбора (эмбеддинги, Haiku) и побочные вызовы модели сессии.
- Скиллы чужого CLI: Codex-агент не берёт скилл Claude. Отдать скилл второму агенту — это
  «дать второму» в панели Capabilities.
- Свой формат, каталог и маркетплейс скиллов.
- Запись в `~/.claude/settings.json`, `~/.codex/config.toml` и в файлы мода jev.
- Показ в окне, какой скилл взял агент. Позже, если понадобится.

## 2. Что видит агент

Сокращение списка включается вместе с навигатором. Отдельного выключателя «навигатор без
сокращения» в окне нет; нужен он только тестам (внутренний рубильник `claudeSkillRoute.catalogReady`
в `packages/core/src/work/skill-reduction.ts`, по умолчанию `true`).

### 2.1 Claude: имена вместо полного списка

Claude Code сам держит каталог скиллов в бюджете: `окно контекста × 4 × skillListingBudgetFraction`
(по умолчанию 0,01), а переменная `SLASH_COMMAND_TOOL_CHAR_BUDGET` главнее. Значение
`skillListingBudgetFraction: 0` схема настроек отвергает, поэтому оно не используется.

Что делает Parley, когда навигатор включён и сокращение разрешено:

- кладёт `SLASH_COMMAND_TOOL_CHAR_BUDGET=1` в окружение процесса агента (`CLAUDE_SKILL_BUDGET_ENV`).
  В каталоге остаются имена, а описания Claude Code оставляет только встроенным скиллам;
- выключает мод jev записью `enabledPlugins` в файле настроек сессии. Точный id берётся из
  места установки (плагин-папка в `skills/` конфигурации Claude или проекта и запись реестра
  `plugins/installed_plugins.json`), id не угадывается. Мод не установлен — выключать нечего.
  Прочитать место установки не удалось, либо мод установлен, а файла настроек в шаблоне нет —
  список остаётся полным.

Список не сокращается, если у сессии нативная роль Claude (`--agent`: у неё свой набор
инструментов, Skill и `find_skill` не гарантированы) или в шаблоне нет `{mcpConfig}`
(сервер `parley` не дойдёт до агента). Об этом сессия получает предупреждение
«Skill navigator availability is unverified for this launch; the full native skill list remains enabled.»

**Что модель может загрузить.** Это знает сам Claude Code: он пишет в транскрипт сессии вложение
`skill_listing` с полем `names` — теми именами, что показал модели, с учётом `skillOverrides`,
`disable-model-invocation`, включённости плагинов и скиллов claude.ai. Поле полное и при
сокращённом списке. Parley читает его так (`packages/core/src/skills/claude-listing.ts`):

- берётся имена из последнего полного вложения (`isInitial` не `false`) и поздние добавки
  (`isInitial: false`) после него;
- транскрипт ищется только как `<корень истории>/<папка проекта>/<uuid сессии>.jsonl` среди
  настоящих папок, открывается без следования симлинкам; у большого файла читаются окна по
  4 МиБ в начале и в конце;
- описания берутся из `SKILL.md` на диске. Имя без файла возвращается без описания. Скилл,
  который есть на диске, но не назван в списке движка, не возвращается: его модель не загрузит.

Транскрипта или вложения ещё нет (сессия не сделала первый запрос) — `find_skill` отвечает
пустым списком с причиной и при следующем вызове читает заново, без кеша. Для участника комнаты
(`for`) берётся его транскрипт.

### 2.2 Codex: каталог убирается, имена уходят в описание инструмента

Бюджет каталога Codex: 2 % окна, потолок настроенного бюджета 10 000 токенов (0.160 то же, что
0.156). `skills.max_context_tokens=1` выкидывает строки целиком, «только имён» так не получить.
Рабочий путь — `-c skills.include_instructions=false`: каталог убирается целиком.

Что делает Parley, когда навигатор включён и шаблон Codex пропускает подстановку `{skillCatalog}`:

- ставит в запуск и возобновление пару `-c skills.include_instructions=false`;
- имена доступных скиллов выводит в описание `find_skill` (до 3000 знаков, дальше хвост
  «… and N more (find_skill finds them)»);
- сокращает при запуске, только если путь загрузки подтверждён: бинарь Codex найден, а шаблон
  состоит из известных частей (допустимы только `skills.config` и `project_root_markers` сверх
  встроенных флагов). Иначе список остаётся полным, а запуск несёт то же предупреждение, что и у
  Claude.

Каталог для `find_skill` строится позже, при первом обращении, из родного состава Codex:
запросы `skills/list`, `config/read` и `configRequirements/read` к самому Codex. Ответ с ошибкой,
чужой папкой или непустыми управляемыми требованиями путь не подтверждает: `find_skill` отвечает
пустым списком с причиной, а в описании инструмента стоит «Your native skill list is removed and
its names could not be read». Список при этом уже убран — запуск этого не знает; это записано как
ограничение (раздел 7).

**Подмена `args` в `~/.parley/providers.json`.** Запись `codex` со своими `args` целиком заменяет
встроенный шаблон. Без `{skillCatalog}` флаг не доходит, список остаётся полным, а запуск
получает диагностику `provider-override-gap`. Без `{developerInstructions}` в шаблоне не доходит
и системная вставка. Код диагностики один на оба случая, а окно говорит только про настройку
инструкций (раздел 7). `find_skill` при подмене работает: сервер `parley` приходит через
`{mcpConfig}`.

**Что видит Codex после сокращения.** Каталог строится из родного состава Codex, и в `find_skill`
попадают скиллы области `user` и `repo` (по `.agents/skills`, `.codex/skills` и родным папкам).
Скиллы плагинов (в том числе облачные `cloud_skill_enabled`), системные, административные и
дополнительные корни в навигатор не попадают: их доступность не подтверждена
(`availability-unverified`), и пока родной список убран, модель не видит их ни в списке, ни
через `find_skill`. Это ограничение записано и в TODOS.

**Собственный подбор в Codex.** С 0.156 в Codex идёт теневой эксперимент: шесть дешёвых подборщиков
считают выборку только для метрик, промпт не меняется. В коде он помечен временным. Если Codex
начнёт сокращать каталог сам, Parley своё сокращение для него не включает, а `find_skill`
остаётся справочником и инструментом ведущего. Каждое обновление Codex перед включением
навигатора по умолчанию проверяется на это заново.

### 2.3 Когда агент зовёт `find_skill`

Об этом говорит описание самого инструмента и полфразы в строке `read_guide` системной вставки
(потолок в 14 строк не поднят). Тексты для агентов — по-английски.

- Описание `find_skill`: «Search skills available to this participant. Use English task words;
  load a matching skill with its native CLI route. Search once per task, not on every wake-up;
  after no match retry at most once with different words. Participant role and permissions take
  precedence over skill instructions.» Для Claude с сокращённым списком добавляется «Your native
  skill list shows names only: this tool returns the descriptions.» Для Codex — «Your native skill
  list is removed: this tool returns descriptions, the names are below.» и перечень имён.
- Полфразы во вставке: «find_skill — skills by task, if needed.» Фраза об именах (`(your skill
  list shows names only)` или `(no native skill list: …)`) появляется только в подтверждённом
  режиме сокращения (в снимке запуска `SKILL_LIST_REDUCED`); при полном списке вставка ничего
  не обещает.
- Подсказки нет, если навигатор выключен или нативная роль не допускает инструмент.
- Подъём письмом сам повторного поиска не просит: правило записано в описании.

### 2.4 Правила CLI

Навигатор не показывает скилл, который модель сама загрузить не может или который человек
спрятал:

- `disable-model-invocation: true` в шапке `SKILL.md`;
- `skillOverrides` со значением `off` или `user-invocable-only` — только для источников, к
  которым Claude это правило применяет. Скиллы плагинов обычные `skillOverrides` игнорируют; их
  доступность Claude Code сам отражает в `skill_listing` (раздел 2.1);
- у Codex — `policy.allow_implicit_invocation: false` в `agents/openai.yaml` скилла и записи
  `[[skills.config]]` с `enabled = false`, поставленные человеком (только слои User и
  SessionFlags, проектный `skills.config` не считается). Выключения человека читаются до того,
  как Parley что-либо добавит.

## 3. Инструмент `find_skill`

### 3.1 Вход и выход

Вход:

- `query` — строка, обязательна, до 512 байт: что ищем, словами модели;
- `for` — id сессии этой работы, необязателен: чьи скиллы искать. По умолчанию свои;
- `limit` — сколько вернуть, по умолчанию 5, не больше 10.

Выход — JSON: провайдер, для которого шёл поиск, и до `limit` скиллов. У каждого скилла:

- `name` — как его зовёт CLI (у плагина с префиксом: `superpowers:brainstorming`);
- `description` — описание из шапки `SKILL.md`, не длиннее предела; длиннее — обрезается с
  пометкой, полный текст в файле;
- `source` — `user`, `project`, `plugin`, `claude.ai`, `system`, `admin` или `extra`;
- `load` — как загрузить: у Claude — «Use the Skill tool with "<имя>".», у Codex — «Read <путь>.»

Ответ целиком не больше 8 КиБ. Что не влезло, названо числом `omitted`, а не пропало молча.
Если у сессии нет каталога, возвращается пустой список и `reason`.

Ничего не нашлось — пустой список и фраза. Первый пустой поиск подряд: «No skill matched: work
without one, or try other words once». Второй подряд: «No skill matched again: do not search for
this task any more, work without a skill». Находка сбрасывает счёт. Пустой `query`, слишком длинный
запрос, `for` не из этой работы — ошибка. Закрытая сессия в `for` допустима: это только чтение.
Аннотации — `READS`.

### 3.2 Индекс

Индекс собирается из родных мест провайдера и живёт в процессе MCP-сервера до конца сессии (не
общий и не глобальный). Для `for` он строится лениво, отдельно на пару «провайдер, папка сессии»
с учётом настроек этого контекста. Проектные источники берутся из рабочей папки участника
(включая worktree), а не ведущего. Если её worktree удалён, возвращается явный пустой результат
с причиной: поиск не подменяется каталогом основной копии.

Источники Claude: `$CLAUDE_CONFIG_DIR/skills` (по умолчанию `~/.claude/skills`), `.claude/skills`
рабочей папки сессии и `.claude/commands/**/*.md` с родными вложенными именами. Простое имя
скилла берётся по папке, а не по декоративному `name:` в шапке. Плагины, их включённость и
скрытие учитываются отдельно; перечисление установленных плагинов само по себе доступности
не доказывает (раздел 2.1: доступность — по списку самого Claude Code).

Источники Codex: папки конфигурации `.codex/skills`, `.agents/skills` от рабочей папки до корня
проекта по родным меткам, устаревшая `$CODEX_HOME/skills`, `$HOME/.agents/skills`, встроенные
системные, административные, плагины и дополнительные корни. Подтверждены родным составом Codex
только `user` и `repo`; остальные корни дают `availability-unverified` и в автоматический поиск
не попадают. Пределы обхода: глубина 6, до 2000 папок и 20 000 записей на корень.

Файл `SKILL.md` читается целиком, до 65 536 байт включительно, строго как UTF-8. Разбирается
только начальная шапка между строками `---` (BOM и CRLF допустимы); тело не возвращается и не
индексируется. YAML разбирает общий разборщик (`yaml@2.9.1`, с пределом на ссылки), TOML
настроек и политик — `smol-toml@1.9.0`. Отсутствующая шапка отличается от битой. Ошибки несут
только безопасный код и позицию, без строк исходника. Нечитаемый корень, битая ссылка и превышение
пределов — частичная диагностика, а не успешный пустой источник. Неизвестная политика или
доступность — недоступно, причина `availability-unverified`; фильтр применяется до поиска.

Код — общий модуль `packages/core/src/skills/`. Сканер подсказок поля ввода
(`packages/core/src/capabilities/`) переиспользует его; второго обхода папок нет. Запись каталога
несёт источник, путь, описание и доступность модели с причиной. Панель Capabilities показывает и
скрытые записи, а `find_skill` — только доступные. Refresh панели уже построенный индекс сессии
не меняет: новые файлы видны после следующего запуска или возобновления.

Идентичность записи — `(провайдер, realpath полного документа)`, а не имя или папка. Одноимённые
файлы Codex сохраняются; симлинки на один файл схлопываются. Порядок записей выбирает родной
порядок CLI, а не поиск.

### 3.3 Поиск

BM25 по словам имени и описания; имя весит втрое больше описания. Слова в нижнем регистре,
разбиение по небуквенным знакам, имя ещё и по `-`, `_`, `:`. Английские стоп-слова выбрасываются,
окончания срезаются (`-s`, `-es`, `-ing`, `-ed`), основы уточнены для пар write/writing,
debugging/debug, planning/plan: на запрос «write an implementation plan» первым идёт
`superpowers:writing-plans`. Возвращаются скиллы с ненулевым весом, при равенстве — по имени, затем
по пути документа побайтным сравнением. Результат детерминирован.

Запрос на другом языке ничего не найдёт: модель сформулирует его заново, подсказка об этом в
описании инструмента. Человеку подстраиваться не нужно.

### 3.4 Размер

Пределы в байтах после экранирования (`packages/core/src/work/context-budget.ts`): запрос
`find_skill` — 512, ответ — 8 192, сам `read_guide` — 65 536. Вставка по-прежнему не длиннее
14 строк, а стабильная часть правил — 4 096 байт.

## 5. Соседи

- **Мод jev.** Выключается только в сессиях Parley и только записью `enabledPlugins` в файле
  настроек сессии (раздел 2.1). Не применяются `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=0`,
  `disableAllHooks`, безопасный режим и `setup restore` как запасной путь: хуки Parley
  (`report`, конец хода, `statusLine`) должны остаться живыми. Живая проверка этого — часть P32.
- **Скиллы, спрятанные модом jev.** Его настройка переводит скиллы в `user-invocable-only`. Модель
  такой скилл загрузить не может, поэтому навигатор его не показывает. На машине разработки
  таких 78, включая gstack. **Совет человеку: перед включением навигатора выполнить
  `/jev-skill-suggestion:setup restore`.** Скиллы вернутся модели везде, мод в обычных сессиях
  продолжит работать как прежде. Это личная настройка человека, Parley её не трогает.
- **Субагенты Claude.** Переменная бюджета лежит в окружении процесса, но как сокращённый
  список виден субагентам и доступны ли им Skill и `find_skill`, не проверено. Без доказанного
  пути загрузки для нативной роли список не сокращается.
- **Скилл `parley`.** При сокращённом списке его описание может ужаться; путь к гиду ведёт
  через `read_guide`.
- **Запущенные сессии.** Переключатель действует на новые и возобновлённые сессии: бюджет,
  выключение jev и `-c` задаются при запуске.
- **Бюджет работы (P37).** `find_skill` ничего не запускает и в счёт запусков и писем не входит.
- **Адаптеры запуска.** Если будет выполнен план провайдерных адаптеров, запускные части
  навигатора (переменная бюджета, выключение jev, флаги Codex, файл настроек сессии) станут
  возможностями адаптера семейства, а не проверками по id провайдера.

## 6. Включение

- В `ParleyConfig` — `skillNavigator: boolean`, переменная `PARLEY_SKILL_NAVIGATOR`
  (читается и прежнее имя), по умолчанию `false`. В окне — Settings → Agents, переключатель
  «Skill navigator» с подсказкой «Applies to new and resumed sessions.»
- Выключено — всё как до навигатора: инструмента `find_skill` в списке сервера нет, переменной
  бюджета, выключения jev и `-c` нет, `argv`, окружение и настройки не меняются.
- Включено по умолчанию — отдельное решение после живой проверки (раздел 8).
- Навигатор не зависит от `agentSkills`: тот управляет установкой встроенных скиллов в проект,
  а инструменты MCP и общий каталог имеют свой переключатель.

### 6.1 Один снимок настройки на запуск

Запуск читает `skillNavigator` один раз; это значение определяет `argv`, настройки Claude,
подсказку в слое и окружение MCP-сервера (`PARLEY_SKILL_NAVIGATOR=1|0`, при сокращении ещё
`PARLEY_SKILL_LIST_REDUCED=1`). Сервер не перечитывает глобальный файл независимо от уже
запущенного агента: переключение посреди работы не может оставить короткий список без
`find_skill`.

У включённого навигатора файл `--settings` строится для сессии: `settings/<id сессии>.json`
каталога работы (при выключенном остаётся общий `settings.json`). В него входят хуки Parley,
HTTP-хуки ленты и `statusLine` базового файла; запись `enabledPlugins` добавляется только при
сокращении и только для найденного мода jev. Запись идёт без следования симлинкам и без
перезаписи жёстких ссылок.

## 7. Ошибки и ограничения

- Будущая версия Claude Code перестала понимать переменную бюджета — список снова полный.
  `find_skill` работает, теряется только экономия. Ловит проверка размера списка (раздел 8).
- jev не выключился — он прячет и список имён, и вставляет свой выбор. В транскрипте видны
  вставки мода; ловит та же проверка.
- Индекс пуст — `find_skill` отвечает пустым списком, сессия работает; нечитаемое, частичное и
  неизвестное даёт причину, а не «скиллов нет».
- Подмена `args` Codex без `{skillCatalog}` — полный список и `provider-override-gap`; без
  `{developerInstructions}` — нет и системной вставки. Окно показывает одно уведомление на хост:
  текст говорит про инструкции, даже если не хватает только `{skillCatalog}`, и при двух
  недостающих подстановках показан один раз (хвост записан в TODOS).
- Codex после сокращения не видит скиллов плагинов, системных, административных и
  дополнительных корней (раздел 2.2).
- Если Codex не подтвердил родной состав (ошибка, управляемые требования), список у него уже
  убран, а `find_skill` пуст с причиной. Запуск проверяет только бинарь и шаблон, поэтому
  в такой сессии агент остаётся без списка и без описаний. Хвост записан в TODOS.
- Нативная роль Claude без подтверждённых Skill и `find_skill` — список полный, предупреждение.
- Сессия на провайдере, которого навигатор не знает (сейчас всё, кроме `claude` и `codex`), —
  `find_skill` отвечает пустым списком с причиной «This provider has no verified native skill route.»

## 10. GLM — семейство Claude Code

В master с версии 0.5.0 GLM — сессия Claude Code (запись `glm` с `family: 'claude'`, окружение
собирает хост). Навигатор работает у GLM тем же механизмом, что у Claude, без отдельных правил.
**Проверено тестами, живьём — нет:** живая проба на GLM будет отдельно (раздел 9 её не касался).

Что сделано:

- **Семейство вместо id.** Сокращение списка (`SLASH_COMMAND_TOOL_CHAR_BUDGET=1` в окружении
  процесса, выключение jev через `enabledPlugins` в файле настроек сессии) и `find_skill`
  выбираются по `isClaudeCode`, а не по `entry.id === 'claude'`. Навигатор у GLM больше не
  отключён в `work/launch.ts`. Роли, канал, `--disallowedTools` и прочее, не связанное с
  навигатором, остались на прежних проверках.
- **`find_skill` у GLM** — тот же каталог, что у Claude: имена из вложения `skill_listing`
  транскрипта сессии (`~/.claude/projects`, GLM пишет их туда же), описания из `SKILL.md`. Для
  провайдера вне семейства Claude Code и не Codex ответ прежний: «no verified native skill route».
  В ответе `provider` — провайдер самой сессии (`glm`), `load` — «Use the Skill tool with …».
- **Файл настроек сессии** один: `workSettings` с провайдером `glm` пишет модель Z.ai, токен хуков
  `PARLEY_HOOK_CAPABILITY`, HTTP-хуки ленты и `statusLine`, а `enabledPlugins` добавляется к ним.
  Без навигатора GLM остаётся на `settings-glm.json`, как в master.
- **Окружение.** Переменная бюджета идёт в `plan.env`, а хост срезает у GLM только `ANTHROPIC_*`,
  `CLAUDE_CODE_USE_*` и перечень входов (`providerLaunchEnv`): бюджет доходит до процесса, значение
  не перекрывается. Без неё бюджет считается от окна модели (у GLM 1M, около 40 000 знаков), и список
  может не сокращаться вовсе.
- **Строка во вставке** о `find_skill` доходит до GLM через `--append-system-prompt`, как до Claude.
- **Конфигурация Claude.** Хост срезает у GLM `CLAUDE_CONFIG_DIR`, поэтому мод jev ищется в
  `~/.claude`, даже если у человека задана другая папка.

Что остаётся:

- **Скиллы claude.ai** приходят синхронизацией аккаунта. GLM входит ключом Z.ai, а лишний трафик у
  него выключен, поэтому есть ли они в сессии GLM, не подтверждено; каталог берётся из вложения
  транскрипта, так что в него попадает только то, что Claude Code реально перечислил.
- **Описание скилла на диске** для GLM-участника, у которого ведущий на Claude держит
  `CLAUDE_CONFIG_DIR`, читается из папки ведущего: каталог имён берётся из транскрипта и от этого не
  зависит, а вот описания могут не найтись.
- **Живая проверка:** список скиллов GLM с переменной бюджета и без; выключение jev; `for` от
  ведущего на Claude к участнику на GLM и обратно.
- В спеке PARLEY.md описания встроенного GLM тоже устареют (см. её раздел о фактической реализации).

После слияния в основной копии master и в worktree `parley-md` останутся неотслеживаемые старые
копии этой спеки: из-за них `git pull` упрётся в файл с тем же путём. Удалять их — только с
согласия человека (запись в TODOS).
