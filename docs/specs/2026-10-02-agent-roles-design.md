## 1. Зачем

1. **Роль понимает только Claude.** `spawn_session(agent)` проверяет файл
   `.claude/agents/<имя>.md` проекта или пользователя и передаёт `claude --agent`.
   Codex с ролью не запускается (`provider codex does not accept agents`), а `label` —
   просто подпись.
2. **Нативные роли Codex Parley не видит.** Codex грузит роли сам (крейт `agent-roles`,
   папка `agents/` каждого слоя конфига). На машине разработки в `~/.codex/agents/` их
   18 — от oh-my-codex, с `developer_instructions`, моделью и усилием.
3. **Встроенных ролей нет.** Каждый ведущий придумывает промпты сам; модель под задачу
   никто не подбирает; рецензент может править код, потому что «только чтение»
   держится лишь на просьбе в тексте.
4. **Рецептам комнат** (следующий подпроект) нужен каталог ролей, из которого
   собирается состав.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Откуда роли | Встроенные роли Parley и нативные роли каждого CLI |
| Нативные роли | Только в своём CLI: роль Claude — в Claude, роль Codex — в Codex, ровно как её описал CLI |
| Что во встроенной роли | Текст, провайдер по умолчанию, уровень модели, усилие, признак «только чтение» |
| Доставка встроенной роли | Текст — блоком роли в слое Parley; модель и усилие — существующими флагами; «только чтение» — нативными запретами CLI. В проект ничего не пишется |
| Имя роли | Всегда с источником: `builtin:reviewer`, `claude:obsidian-manager`, `codex:architect` |
| Роль у сессии | Необязательна. Задаётся при создании и не меняется. Без роли или если роль пропала — умолчания провайдера |
| Что сильнее | Явный выбор человека или агента → роль → умолчание провайдера. Умолчания роли в карту не пишутся, а вычисляются при запуске |
| Окно | Выбор роли в каждой строке агента диалога «New session or room»; чип роли и замок «только чтение» |
| Инструменты агентов | `role` у `spawn_session`, новый `list_roles`, роль в `get_map` |
| Тексты ролей | Свои, по-английски; из OMC и oh-my-codex ничего не переносится дословно и не пересказывается близко к тексту |

## 3. Встроенные роли

### 3.1 Запись

Встроенная роль — запись в коде core (новый модуль ролей):

| Поле | Что это |
|---|---|
| `id` | Короткое имя: `reviewer`. Стабильно между версиями |
| `name` | Подпись по-английски: `Reviewer` |
| `description` | Одна строка по-английски — для окна и `list_roles` |
| `prompt` | Текст роли по-английски (раздел 3.4) |
| `provider` | Провайдер по умолчанию: `claude` или `codex` |
| `tier` | Уровень модели: `strong`, `standard`, `light` |
| `effort` | `low`, `medium`, `high` |
| `readOnly` | Признак «только чтение» |

### 3.2 Уровни моделей

| Уровень | Claude | Codex |
|---|---|---|
| `strong` | `opus` | `gpt-6-astra` |
| `standard` | `sonnet` | `gpt-6.1-sol` |
| `light` | `haiku` | `gpt-6-luna` |

Значения — из списков `provider-models.ts`. Страница моделей Codex описывает Astra как
самую способную, 6.1 Sol — как почти Astra дешевле, Luna — как самую экономную.

### 3.3 Стартовый набор

| Роль | Что делает | Провайдер | Уровень | Усилие | Только чтение |
|---|---|---|---|---|---|
| `planner` | Разбирает задачу, задаёт вопросы человеку, пишет план с шагами и критериями приёмки | claude | strong | high | да |
| `architect` | Границы, интерфейсы, компромиссы; советует, опираясь на код | claude | strong | high | да |
| `critic` | Ищет дыры в плане или решении: риски, пропуски, противоречия | codex | strong | high | да |
| `executor` | Делает свою часть плана в своём worktree, с тестами | claude | standard | medium | нет |
| `reviewer` | Ревью диффа: ошибки, регрессии, недостающие тесты; каждое замечание с файлом и строкой | codex | strong | high | да |
| `verifier` | Проверяет критерии приёмки: тесты, сборка, линтер; ответ «прошло / не прошло» с доказательствами. Код не правит, но «только чтения» нет: тестам нужна запись | codex | standard | medium | нет |
| `debugger` | Находит и воспроизводит причину сбоя, чинит минимально | claude | strong | high | нет |
| `researcher` | Разведка кода и документации, ответы со ссылками | claude | light | low | да |

Рецензенты (`critic`, `reviewer`, `verifier`) по умолчанию на Codex: чужая модель лучше
находит ошибки в работе Claude. Провайдера, модель и усилие человек меняет в диалоге.

### 3.4 Тексты

- По-английски, свои; не длиннее 40 строк каждый.
- Одно строение у всех: кто ты и зачем; как работать; границы (что нельзя — у ролей
  «только чтение» в том числе запись через shell); что сдать в `report` (артефакты,
  форма); когда звать ведущего или человека.
- Текст роли не повторяет встроенные правила Parley и гид: про `get_map`, `report`,
  письма и комнаты агент уже знает из слоя.
- Перед релизом человек просматривает тексты всех восьми ролей.

## 4. Нативные роли

### 4.1 Claude

- Папки — как сейчас: `.claude/agents/*.md` проекта, затем `~/.claude/agents/*.md`
  (`agentDirs`, `listAgents`, `assertAgent`). Имя — `claude:<имя файла без .md>`.
- Для списка окно и `list_roles` читают из файла только frontmatter `description`.
  Остальное содержимое Parley не читает: промпт, инструменты и модель применяет сам
  Claude Code по `--agent`.
- Агенты из плагинов (`plugin:agent`) — позже, через снимок спеки Capabilities.

### 4.2 Codex

- Папки — те же, что читает сам Codex: `<проект>/.codex/agents/*.toml`, затем
  `~/.codex/agents/*.toml`. При одинаковом имени побеждает проектная, как у Codex.
  Имя — `codex:<name из файла или имя файла>`.
- Из файла берутся `description`, `developer_instructions`, `model`,
  `model_reasoning_effort`, `sandbox_mode`. Остальные ключи пропускаются.
- Файл не разбирается или имя не проходит `^[\w.-]+$` — роль в список не попадает,
  причина пишется в `host.log`.
- Таблицы `[agents.<имя>]` с `config_file` из `~/.codex/config.toml` — позже, через
  снимок спеки Capabilities.
- Разбор TOML — небольшой зависимостью core без своих зависимостей (например,
  `smol-toml`); выбор и лицензия — в плане. Своя разборка не годится: в
  `developer_instructions` многострочные строки `"""`.

## 5. Запуск

### 5.1 Роль в карте

У сессии новое поле `role: { source: 'builtin' | 'claude' | 'codex', name: string } | null`.
Прежнее поле `agent` при чтении карты становится `role: { source: 'claude', name }`;
новые записи пишут только `role`. Роль задаётся при создании сессии и не меняется.

### 5.2 Блок роли в слое Parley

Порядок слоя (спека PARLEY.md, раздел 3.1) с ролью:

1. встроенные правила Parley;
2. строка моста — только у Codex;
3. **блок роли**;
4. плейбук рецепта — только ведущему, если есть;
5. бриф тихой сессии;
6. PARLEY.md;
7. память проекта — если есть.

Навигатор не входит в текст роли: общий `find_skill` ищет скиллы CLI выбранной
сессии из её рабочей папки. Скилл не меняет роль, модель, усилие и запреты записи.
У нативной роли Claude с урезанными инструментами проверяется доступность Skill
и `mcp__parley__find_skill`; без неё список не сокращается, предупреждение остаётся.
Список ролей (`list_roles`) и поиск скиллов (`find_skill`) остаются разными инструментами.

Блок роли начинается строкой `Your role in this workspace: <name> (<источник>:<имя>).`,
дальше — текст встроенной роли или `developer_instructions` нативной роли Codex. У
нативной роли Claude блока нет: её промпт применяет сам Claude. Текст роли длиннее 32 КБ
обрезается по строке со строкой-меткой, как PARLEY.md.

### 5.3 Флаги по видам роли

| | Встроенная роль | Нативная роль Claude | Нативная роль Codex |
|---|---|---|---|
| Текст | блок роли в слое | `--agent <имя>` — как сейчас; слой Parley дописывается (проверено, приложение) | блок роли в слое |
| Модель | уровень роли → модель провайдера сессии: `--model` / `-m` | из файла агента, её применяет Claude | `model` из файла → `-m` |
| Усилие | `--effort` / `model_reasoning_effort` | из файла агента | `model_reasoning_effort` из файла, как задан (в том числе `xhigh`) |
| Только чтение | Claude — новая подстановка `{disallowedTools}` (Edit, Write, NotebookEdit); Codex — новая подстановка `{sandbox}`: `-c sandbox_mode="read-only"` | как задано в файле агента (`tools`, `disallowedTools`) | `sandbox_mode` из файла → `{sandbox}` |

- `{disallowedTools}` стоит в `args` и `resumeArgs` Claude, `{sandbox}` — в
  `CODEX_CONFIG_FLAGS`, то есть при запуске и `resume`. Пустая подстановка выбрасывает
  пару. Точная форма аргументов `--disallowedTools` (несколько элементов argv или один)
  проверяется живьём.
- Модель и усилие при `resume` не передаются, как и сейчас: оба CLI восстанавливают их
  из разговора.

### 5.4 Что сильнее и что пишется в карту

- Явный выбор (поле диалога, которое человек поменял, или `model` / `effort` у
  `spawn_session`) записывается в сессию и сильнее роли.
- Умолчания роли (модель по уровню, усилие) в сессию не пишутся: они вычисляются при
  каждом запуске. Без роли или если роль пропала — умолчания провайдера.
- Провайдер: встроенная роль подставляет свой, если провайдер не выбран; нативная роль
  привязана к своему CLI.
- У нативной роли Claude модель выставляет Claude Code по файлу агента. Что сильнее —
  явный `--model` или поле `model` агента, — проверяется живьём; итог пишется в README.

### 5.5 Файлы нативных ролей и `resume`

Файлы нативных ролей перечитываются при каждом запуске и `resume`: правка файла
действует со следующего запуска. Текст роли в слое при `resume` доходит до модели, как
и весь слой, только после сжатия контекста (спека PARLEY.md, раздел 3.4).

### 5.6 Роль пропала

Файл нативной роли удалён или испорчен, встроенную роль убрали в новой версии —
сессия запускается без роли, на умолчаниях провайдера (явный выбор человека
сохраняется). Хост пишет в `host.log` и один раз за жизнь хоста на сессию показывает
уведомление `role-missing`.

### 5.7 «Только чтение»

- **Codex:** `sandbox_mode="read-only"` держит песочница. Запись возможна только по
  одобрению человека: у сессий Parley стоит `-a on-request`.
- **Claude:** `--disallowedTools` убирает Edit, Write и NotebookEdit. Bash остаётся —
  запрет писать через shell стоит в тексте роли, и это пишется в README. Герметичная
  песочница у Claude — вне объёма.
- **Нельзя обеспечить — не запускаем.** Если в шаблоне провайдера нет нужной подстановки
  (подмена в `~/.parley/providers.json`: на машине разработки это запись `codex` от
  2026-09-25 и запись `glm` на шаблонах Claude без `{disallowedTools}`), сессия с ролью
  «только чтение» не создаётся: `spawn_session` и окно получают понятную ошибку с
  названием подмены. Молча запускать с правом записи нельзя.
- **Текст роли некуда доставить — тоже не запускаем.** Если в шаблоне нет канала слоя
  (`{systemPrompt}` или `{developerInstructions}`), а у нативной роли Claude — `{agent}`,
  роль осталась бы одной подписью. Такая сессия с ролью не создаётся, ошибка та же. Нет
  подстановок модели или усилия — действует то, что задано в подмене, умолчания роли
  молча не применяются.
- Инструменты Parley у таких ролей работают: `report`, `send_message` и конец хода идут
  через MCP-сервер, хуки и `notify`, а не через запись агента в файлы. У Codex это
  проверяется живьём.

## 6. Окно

**Диалог «New session or room».** У каждой строки агента — выбор роли:
- группы: `No role` (по умолчанию), `Parley` (встроенные), `Claude` и `Codex`
  (нативные, что нашлись в проекте и у пользователя);
- у роли — описание в одну строку и замок, если она только для чтения;
- встроенная роль подставляет в строку провайдера, модель и усилие. Поля остаются
  изменяемыми; в `sessions.create` уходят только поля, которые человек поменял, и
  `role`;
- нативная роль переключает провайдера строки на свой CLI и закрывает его выбор;
- без роли строка ведёт себя как сейчас.

**Где роль видна.** Чип роли на строке сессии в сайдбаре и у участника комнаты
(`Reviewer`; у нативной — значок её CLI). Замок у ролей «только чтение» — в чипе и в
шапке терминала сессии.

`sessions.create` в протоколе получает необязательное поле `role`.

## 7. Инструменты агентов

- **`spawn_session`** — новый необязательный `role`: `builtin:<id>`, `claude:<имя>`,
  `codex:<имя>`.
  - Провайдер не указан — берётся из роли.
  - Нативная роль чужого CLI — ошибка.
  - Неизвестная роль — ошибка со списком ролей, доступных для провайдера.
  - Роль «только чтение» без нужной подстановки в шаблоне — ошибка (5.7).
  - Прежний `agent` работает как `claude:<имя>`; заданы оба — ошибка.
- **`list_roles`** — новый инструмент: роли, доступные в проекте, с источником,
  описанием, провайдером, моделью и усилием по умолчанию и признаком «только чтение».
- **`get_map`** — у каждой сессии `role`.
- **Гид** (`read_guide`, тема `tools`) — раздел о ролях: что это, как выбрать, что
  значит «только чтение».

## 8. Граничные случаи

| Случай | Поведение |
|---|---|
| Роль с тем же именем в разных источниках (`builtin:architect` и `codex:architect` от oh-my-codex) | Разные роли: имя всегда с источником |
| Одно имя в проектной и пользовательской папке Codex | Побеждает проектная |
| Битый TOML или недопустимое имя нативной роли | Роли нет в списке, причина — в `host.log`; у существующей сессии — `role-missing` и запуск на умолчаниях |
| Текст роли длиннее 32 КБ | Обрезка по строке со строкой-меткой |
| Подмена провайдера без подстановок роли | Нет канала текста роли или подстановки «только чтения» — роль не создаётся (5.7); нет подстановок модели и усилия — действует подмена |
| Агент Claude с урезанным `tools` без `mcp__parley__*` | Прежнее предупреждение `spawn_session` остаётся |
| Роль у встроенной записи GLM | Нет: у неё нет ни канала слоя, ни флагов. Подмена `glm` на шаблонах Claude принимает встроенные роли без «только чтения»; модель по уровню для неё не подбирается (у GLM свои модели), нативные роли Claude ей в v1 не предлагаются |
| Весь слой длиннее предела аргумента | Сборщик слоя проверяет окончательный argv после экранирования; `session-layer-too-large` до запуска, как в спеке PARLEY.md, 3.3 |

## 9. Тесты

**core (vitest):**
- каталог: восемь ролей, уникальные стабильные `id`, все поля, английские тексты
  (`english-text.test.ts`), текст не длиннее 40 строк;
- уровень → модель для Claude и Codex;
- приоритет «явный выбор → роль → умолчание»; умолчания роли не пишутся в карту;
- карта: прежнее `agent` читается как `role` Claude;
- место блока роли в полном слое; у нативной роли Claude блока нет;
- доступность Skill/find_skill у урезанной роли; скилл не меняет ограничения роли;
- флаги «только чтения» при запуске и `resume` у обоих провайдеров; пустые подстановки
  выпадают;
- нативные роли: поиск в проекте и у пользователя, столкновение имён, разбор TOML
  (многострочный `developer_instructions`, лишние ключи, битый файл, недопустимое имя);
- `role-missing`: запуск на умолчаниях, явный выбор сохраняется;
- `spawn_session`: `role` без провайдера, чужой CLI, неизвестная роль, `agent` и `role`
  вместе, отказ «только чтение» без подстановки;
- `list_roles`: состав и поля.

**host:** запуск с ролью каждого вида; `role-missing` один раз; отказ «только чтение» при
подмене без подстановки.

**окно:** группы выбора роли; подстановка значений встроенной роли и отправка только
изменённых полей; закрытый выбор провайдера у нативной роли; чип и замок.

**Живые проверки:**
- `builtin:reviewer` у Claude: Edit и Write недоступны, инструменты Parley работают;
  точная форма `--disallowedTools`;
- `builtin:reviewer` у Codex: запись просит одобрения; `report`, `send_message` и конец
  хода доходят; после `resume` «только чтение» держится (на машине разработки — после
  того, как человек уберёт или обновит запись `codex` в `providers.json`);
- роль из `~/.codex/agents` меняет модель и усилие, `developer_instructions` видны в
  `codex debug prompt-input`;
- нативная роль Claude: кто сильнее — явный `--model` или `model` агента.

## 10. Зависимости и порядок

- Роли Codex и блок роли в слое опираются на подстановку `{developerInstructions}` и
  сборку слоя из спеки PARLEY.md: реализация после неё или в том же релизе.
- TOML-разборщик общий с настройками скиллов Codex; YAML frontmatter общий со
  скиллами и рецептами. Выбор версий и лицензий — этап 0 единого плана.
- Роли не требуют готовой панели Capabilities или включённого навигатора. Каталог
  и слой реализуются раньше; точная очередь — этапы 1–5 единого плана.

## 11. Вне объёма

- Смена роли у существующей сессии.
- Свои роли проекта в формате Parley: свои роли человек заводит нативно.
- Правка встроенных ролей.
- Агенты из плагинов Claude и таблицы `[agents.*]` из `config.toml` Codex — через
  снимок Capabilities, позже.
- Нативные роли в чужом CLI.
- Роли у встроенной записи GLM.
- Роли `designer`, `writer`, `security-reviewer` — добавятся потом.
- Рецепты комнат — следующий подпроект.
- Герметичное «только чтение» у Claude (песочница).
