## 1. Зачем

Пользователь, 2026-10-17:
- «Есть другие люди, которые предпочитают работать на других моделях. Но им очень нравится наш интерфейс
  и возможности, что даёт Parley. Хотелось бы, чтобы у них была такая возможность — добавить любой свой
  провайдер.»
- Kimi, MiniMax, Qwen и другие, «возможно, закрытые решения».
- Следствие, ради которого это затевалось изначально: в одной комнате работают модели разных вендоров — паритет
  мнений над одной задачей, а не только популярные модели.
- «Самое важное — знать и понимать, что изменения, которые мы вносим, добавляя своих вендоров, не мешают и не
  ломают работу CLI Claude Code.»

Сейчас из коробки есть Claude, Codex и GLM. GLM — это Claude Code на адресе Z.ai, и он зашит в код
(`packages/core/src/providers.ts`, запись `glm`; окружение — `packages/host/src/sessions/provider-env.ts`).
`providers.json` позволяет добавить свой CLI, но не адрес, ключ и модели для Claude Code: поля `family`, `env`,
`secret`, `runner` из него запрещены (`providers.ts`, проверка около строки 962), и это правильно — файл
правится руками и не доверенный.

## 2. Цели, не-цели, анти-цели

**Цели**
- Любой человек сам подключает своего провайдера из окна Parley, без правки кода и без новой версии Parley.
- Подключённый провайдер — полноценный участник: сессии, комнаты, MCP Parley, вид Chat, меню модели.
- Готовые пресеты для известных вендоров и «Свой адрес» для всего остального (прокси, корпоративная, локальная
  модель).
- Обычный Claude Code — в Parley и в терминале вне Parley — ничего не замечает. И это проверяется тестами, а не
  верой (раздел 6).

**Не-цели**
- Перевод протоколов внутри Parley. Модель без Anthropic-совместимого адреса человек подключает через свой прокси
  (LiteLLM, claude-code-router и т.п.) и вписывает адрес прокси.
- Codex, opencode, Qwen Code, Kimi CLI как движки своих провайдеров. Только Claude Code. (`providers.json` для
  своих CLI остаётся как есть.)
- Перевод GLM на новую схему — отдельной задачей потом (раздел 7, решение К3).
- Fallback-цепочки, ротация ключей, автообнаружение моделей, смена провайдера посреди сессии (исследование,
  раздел 7: это нужно системам со своим циклом агента, у Parley сессия — внешний процесс).
- Лимиты и квоты своих провайдеров в строке статуса.
- Подтягивание плагинов Claude Code (раздел 5.4).

**Анти-цели** (провал, даже если всё остальное работает)
- Своя сессия разлогинила, перенастроила или сменила модель обычному Claude Code.
- Ключ своего провайдера попал куда-либо, кроме `secrets.json` Parley и окружения процесса этой сессии: в
  `~/.claude/settings.json`, окружение хоста, логи, транскрипт, `providers.json`.
- Обычная сессия Claude получила адрес, ключ или модели своего провайдера.

## 3. Решения (приняты пользователем в диалоге 2026-10-17)

1. **Только Claude Code.** Свой провайдер = Claude Code с другим адресом (`ANTHROPIC_BASE_URL`), ключом и картой
   моделей. «Через Claude Code можно ставить прокси… выбирать, какая модель отвечает за Sonnet, какая за Haiku,
   какая за Opus. Вместо них указываем ту модель, которую в прокси выбирают.»
2. **Карта моделей по слотам:** вместо Opus, вместо Sonnet, вместо Haiku, субагенты.
3. **Вход:** «+» в конце сегментов строки статуса открывает Settings сразу на разделе Providers.
4. **Раздел Providers в нынешнем диалоге Settings** — пункт левого меню (диалог 46rem, меню слева: Appearance,
   Terminal, Agents, Notifications, Browser, Voice, Assistant — `components/settings/SettingsDialog.tsx`).
5. **Провайдеры в разделе — пилюлями**, как в диалоге New session; под пилюлями форма выбранного.
6. **Форма** (принята по макету): шаг 1 — выбор вендора из пресетов или «Свой адрес»; шаг 2 — название, адрес,
   API key, модели по слотам, «Одна модель на все слоты», «Проверить», «Сохранить», «Удалить провайдера».
7. **Значки.** У известных вендоров — их значок; пока значков нет или с ними сложно — значок Parley
   (`docs/media/brand/parley-icon.svg`). Вендорские значки добавятся потом.
8. **Изоляция — отдельная папка настроек Claude Code на каждого своего провайдера в доме Parley:**
   `~/.parley/providers/<id>/` (через `CLAUDE_CONFIG_DIR`). Вход и выход, настройки, выбор модели, история,
   память — свои у каждого провайдера.
9. **Галочка при сохранении — подтянуть уже настроенное из Claude Code** симлинками, а не копиями, чтобы не
   поддерживать копии: CLAUDE.md, навыки, агенты. Остальное, в том числе навыки Codex, — через `find_skill`
   («всё остальное у нас решается через find skills»).
10. **Предостережение о ссылках.** Правка подтянутого (правила CLAUDE.md, навык, агент) в сессии своего
    провайдера меняет основной Claude Code. Поэтому агент обязан сначала сказать об этом человеку и предложить
    скопировать то, что тот хочет менять, и править уже копию: «нужно говорить человеку, что нужно скопировать…
    скилл и так далее, всё, что он хочет, и потом тут уже менять… Как-то так нужно себя предостеречь».
    Устройство — 5.8.

## 4. Что видит человек

### 4.1 Строка статуса
- Слева, как сейчас, Claude, Codex, GLM, найденные CLI из `providers.json`; за ними — свои провайдеры (значок +
  имя), подключённый — opacity 1, неподключённый — приглушён (правило из
  `docs/specs/2026-10-02-providers-connect-design.md`, раздел 3.1).
- В конце — кнопка «+» (имя для экранных чтецов: «Add provider»). Клик — Settings на разделе Providers с
  открытым шагом выбора вендора.
- Клик по сегменту своего провайдера — Settings на разделе Providers с выбранной его пилюлей.
- «Подключён» для своего провайдера = найден `claude` нужной версии **и** сохранён ключ (как у GLM). Ключ не
  обязателен, если адрес — локальный прокси без ключа; тогда «подключён» = найден `claude` (раздел 8).

### 4.2 Settings → Providers
- Пункт меню **Providers** — после Agents.
- Сверху пилюли: Claude Code, Codex, GLM, свои провайдеры, «+ Add provider» (пунктир). У каждой — значок, имя,
  точка «подключён».
- Пилюли Claude Code, Codex, GLM открывают то, что сейчас показывает их карточка (`ProviderCard`): инструкцию
  или ключ GLM. Их поведение не меняется.
- Под пилюлями — форма выбранного своего провайдера или шаг выбора вендора для «+ Add provider».

### 4.3 Форма
**Шаг 1 — кого подключаем.** Плитки: Kimi, MiniMax, Qwen, DeepSeek, OpenRouter, «Свой адрес». На плитке —
значок, имя, строка про оплату («подписка или токены»). У «Своего адреса» — значок Parley.

**Шаг 2 — поля.**
- Название в Parley (по умолчанию — имя пресета). Из него делается `id`.
- Адрес — Anthropic-совместимый. Пресет подставляет, человек может поправить (у Kimi и Qwen адрес зависит от
  тарифа и региона — пресет даёт выбор, раздел 5.6).
- API key — поле пароля; после сохранения «Key ••••a1b2», «Replace», «Remove», как у GLM.
- Модели: вместо Opus, вместо Sonnet, вместо Haiku, субагенты. Пресет заполняет. «Одна модель на все слоты».
  У «Своего адреса» поля пустые; сохранить можно, только когда заполнены все слоты (или «Одна на все»): пустой
  слот роняет субагентов и фоновые задачи (исследование, раздел 3, прямо у Kimi).
- Галочка «Подтянуть из Claude Code: CLAUDE.md, навыки, агенты». Подпись под ней: это ссылки — правка в этой
  сессии меняет оригинал, который видит и обычный Claude; чтобы поменять что-то только у этого провайдера,
  попросите агента сначала сделать копию (5.8).
- Строка про папку: «Свои настройки Claude Code: `~/.parley/providers/<id>/` — вход, история и память отдельно от
  обычного Claude.»
- «Проверить» — короткое тестовое сообщение на адрес с ключом и моделью слота Sonnet, как `providers.check` у GLM;
  итог строкой под формой («проверено в 9:30» или причина с HTTP-статусом).
- «Сохранить», «Удалить провайдера» (с подтверждением).

### 4.4 Сессии, комнаты, Chat
- Свои провайдеры появляются пилюлями в диалоге New session и при добавлении агента в комнату, как GLM.
- Меню модели в New session и в Chat показывает **настоящие имена** моделей провайдера, а не «Opus/Sonnet».
- Вид Chat, лента хуков, карточки разрешений, подсказки ввода — как у Claude и GLM (это тот же Claude Code).
- Значок провайдера везде, где сейчас `AgentIcon` (карточки, сайдбар, вкладки): вендорский значок пресета или
  значок Parley.

## 5. Как это устроено (решено)

### 5.1 Запуск
Сессия своего провайдера запускает тот же `claude`, что и обычная сессия Claude, с той же раскладкой аргументов
(сессия, MCP-конфиг Parley, `--settings`, хуки, гид), и отличается только окружением процесса:
- `CLAUDE_CONFIG_DIR=~/.parley/providers/<id>/`;
- `ANTHROPIC_BASE_URL` — адрес;
- ключ — в переменной, которую требует пресет (`ANTHROPIC_AUTH_TOKEN` по умолчанию; у некоторых вендоров
  `ANTHROPIC_API_KEY` — исследование, раздел 3);
- `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`,
  `CLAUDE_CODE_SUBAGENT_MODEL` — карта слотов (и прочие слоты, которые знает установленный Claude Code, например
  `ANTHROPIC_DEFAULT_FABLE_MODEL`, — тем же значением, что Opus);
- `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1` и прочее из окружения пресета, как у GLM сейчас.

### 5.2 Обобщить механизм GLM, а не заводить новый
`providerLaunchEnv` (`provider-env.ts`) у GLM вычищает унаследованные `ANTHROPIC_*`, `CLAUDE_CODE_USE_*` и список
селекторов, затем кладёт своё окружение и ключ. Свои провайдеры идут тем же путём. Отличие одно: GLM вычищает
`CLAUDE_CONFIG_DIR` и живёт в `~/.claude`, а свой провайдер, наоборот, получает свою папку. Признак «секрет
провайдера» (`runner.secret`, сейчас тип `'zai'`, `packages/core/src/secrets.ts`) расширяется до ключа на каждого
своего провайдера в том же `secrets.json` (права 0600).

### 5.3 Где хранится описание провайдера
Не в `providers.json`: он правится руками, и доверенные поля из него запрещены. Описание своих провайдеров
пишет хост по команде окна в отдельный файл дома Parley; ключа в нём нет. Формат и имя файла — решение
строителя (раздел 8).

### 5.4 Папка провайдера и галочка «подтянуть»
- `~/.parley/providers/<id>/` создаёт хост при сохранении. Первый запуск Claude Code в пустой папке не должен
  показывать онбординг (выбор темы, вход): хост заранее кладёт в неё то, что для этого нужно (у Qwen прямо
  требуется `hasCompletedOnboarding` — исследование, раздел 3). Что именно — проверить на установленной версии.
- Галочка включена → ссылки из папки провайдера на настройки Claude Code человека (`~/.claude`, при
  `CLAUDE_CONFIG_DIR` у хоста — его папка), **поштучно** (К14):
  - `CLAUDE.md` — ссылка на файл;
  - `skills/` и `agents/` — настоящие папки провайдера, а в них — ссылка на каждый навык и каждого агента
    оригинала. Записи с точкой в начале (`.trash`, `.DS_Store`) пропускаются.
- Ссылки сверяются **перед каждым запуском**: у нового навыка или агента оригинала появляется ссылка, висячая
  ссылка убирается. Настоящие файлы и папки провайдера — копии и то, что создано в его сессиях, — не
  трогаются никогда. Копия с тем же именем, что у оригинала, побеждает: ссылка поверх неё не ставится.
  Зачем поштучно: можно скопировать один навык, не разрывая остальные, а новый навык из сессии Kimi остаётся у
  Kimi и не попадает в основной Claude Code.
- Галочка выключена → ссылки убираются, копии остаются.
- Не подтягиваются: файл настроек, вход, история, память, плагины, **серверы MCP** (К16). Плагины ссылкой не
  перенести: какие из них включены, записано в файле настроек, а его мы как раз не делим. Серверы MCP уровня
  пользователя Claude Code хранит в `.claude.json` той же папки, рядом со входом, поэтому они и так свои у
  каждого провайдера. MCP Parley сессия получает флагом запуска, как сейчас. `.mcp.json` и `.claude/` проекта
  общие у всех сессий workspace, как и сейчас.
- Удаление провайдера удаляет ключ и описание. Папку с историей — по отдельному выбору в подтверждении
  (по умолчанию оставить), чтобы не потерять транскрипты молча.

### 5.5 Значки
Своя папка значков рядом с `assets/providers/` (`AgentIcon.tsx` ищет значок по id провайдера, иначе — буква).
Для своих провайдеров: значок пресета; нет его или «Свой адрес» — значок Parley вместо буквы. Чьи это знаки и
откуда файлы — записать в `NOTICE`, как сейчас для Claude и Codex.

### 5.6 Где свой провайдер обязан работать как Claude
«Полноценный участник» (раздел 2) в первой версии — это всё, что сейчас работает у GLM:
- запуск, возобновление (`resume`), вид Chat и лента хуков;
- история и транскрипты — **из папки провайдера**, а не из `~/.claude/projects` (лента Chat, связывание по
  `session-id`, учёт токенов `usage-ledger`);
- комнаты, MCP Parley, `find_skill`, каталог ролей — с папкой провайдера по правилу `claudeConfigDirFor`;
- меню модели и effort.

Значит, каждое место, которое сейчас узнаёт семейство Claude Code по встроенному id (`isClaudeCode` по строке
смотрит только в `PROVIDERS`; `feed-view.ts` сверяет `claude|glm|codex`; `claudeConfigDirFor` решает по
`secret === 'zai'`; MCP-сервер ядра `core/src/mcp/tools.ts` сам грузит провайдеров в отдельном процессе),
переходит на запись реестра: `family: 'claude'` и папка настроек этой записи. Это сквозная правка, и она входит в
работу, а не откладывается.

### 5.7 Пресеты
Данные, а не код: адрес (или выбор из нескольких по тарифу и региону), переменная ключа, модели по слотам с
подписями, размер контекста (`[1m]`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`), обязательное thinking/effort, ссылка
«Get a key». Стартовый набор — Kimi, MiniMax, Qwen, DeepSeek, OpenRouter; значения — из исследования, раздел 3,
и **сверяются с официальными страницами вендоров в момент реализации** (у Kimi расходятся `api.kimi.com/coding/` и
`api.kimi.ai/coding/`, у Qwen хост зависит от региона и тарифа, имена моделей быстро устаревают).

### 5.8 Предостережение агенту о ссылках (решение 10)
**Почему без него нельзя.** В коде Claude Code 2.1.302 запись файла инструментом (Write/Edit) через
файл-ссылку не идёт. Инструмент отвечает агенту: «Refusing to write through symlink: … Resolve the symlink and
pass the real target path explicitly». То есть он сам отправляет агента править оригинал. Файлы внутри папки
навыка-ссылки пишутся без вопросов. Значит, без правила правка уйдёт в основной Claude Code молча.
Навыки-ссылки и агенты-ссылки Claude Code загружает: папки навыков отбираются по
`isDirectory() || isSymbolicLink()`, поиск `.md` агентов идёт по ссылкам. Каталоги Parley тоже идут по ссылкам:
`core/src/skills/claude.ts` (`isDirectory` со `stat` ссылки; ограничение `containment` только у плагинов и
claude.ai, не у навыков пользователя) и `core/src/roles/claude.ts`.

**Где.** Отдельный блок системного слоя Parley (`--append-system-prompt`), рядом с `bridge` у Codex и правилом
браузера. Блок есть только у сессий своего провайдера с включённой галочкой. Не в файлах:
- `CLAUDE.md` провайдера и есть ссылка: запись туда меняет оригинал;
- `AGENTS.md` Claude Code не читает;
- `PARLEY.md` — правила проекта для всех провайдеров, и лежит он в репозитории человека.

Слой приходит при каждом запуске и возобновлении, агент его не правит.

**Текст** (агенту — по-английски, как вся вставка; `{dir}` — папка провайдера, `{source}` — папка настроек
Claude Code человека):

> This session runs on a custom provider whose Claude Code settings folder is {dir}, not ~/.claude.
> {dir}/CLAUDE.md and the symlinked entries in {dir}/skills and {dir}/agents point to the human's main Claude Code
> settings ({source}): an edit through the link or at the real path changes the main Claude Code too. Before
> changing any of them, tell the human so and ask whether the change is for both or only for this provider.
> Only for this provider: first replace the link with a copy — copy the original to a temporary name next to the
> link, delete the link itself (rm without -r and without a trailing slash), rename the copy to the link's name —
> then edit the copy; Parley keeps copies and does not relink them. Put new skills and agents in {dir}: they stay
> with this provider. MCP servers and settings of this provider are already its own.

**Человеку** — подпись под галочкой (4.3) и абзац в README. Копию делает агент с согласия человека, кнопки в
окне в первой версии нет (К15).

## 6. Не сломать Claude Code — что гарантируем и как узнаём

Пользователь хочет **знать**, а не надеяться. Поэтому каждое обещание ниже закрывается автоматической проверкой.

| Обещание | Как узнаём |
|---|---|
| Обычная сессия Claude не получает адрес, ключ, модели и `CLAUDE_CONFIG_DIR` своего провайдера | Тест окружения запуска: при сохранённых своих провайдерах окружение сессии `claude` совпадает с окружением без них |
| Сессия своего провайдера не видит `ANTHROPIC_*` хоста и `~/.claude/settings.json` пользователя | Тест `providerLaunchEnv` на «грязном» окружении хоста (как у GLM) + проверка, что `CLAUDE_CONFIG_DIR` указывает в `~/.parley/providers/<id>/` |
| Ничего из Parley не пишет в `~/.claude` | Тест на временном доме: после сохранения, проверки, запуска и удаления своего провайдера содержимое `~/.claude` (кроме файлов, которые меняет сам обычный Claude) байт в байт прежнее |
| `/logout`, `/login`, `/model` в сессии своего провайдера не трогают вход и настройки обычного Claude | Проверено по коду Claude Code 2.1.302 (раздел 6.1). В тестах Parley — что `CLAUDE_CONFIG_DIR` своего провайдера задан, а `CLAUDE_SECURESTORAGE_CONFIG_DIR` вычищен из окружения (иначе записи входа снова сольются). Живая проба `/logout` в своей сессии — при реализации и при подъёме `minVersion` |
| Ключ не утекает | Тест: ключа нет в описании провайдера, в логах хоста, в аргументах процесса, в ответах `providers.list` (только маска) |
| Обновление Claude Code не ломает схему молча | `minVersion` у своих провайдеров, как у GLM (`2.1.287`); живая проба повторяется при подъёме минимальной версии |

### 6.1 Проверено: отдельная папка действительно изолирует (Claude Code 2.1.302, 2026-10-17)
Поиск по собранному бинарю `~/.local/share/claude/versions/2.1.302` (имена функций минифицированы):
- **Вход.** Имя записи в связке ключей macOS: `Claude Code<OAUTH_FILE_SUFFIX>-credentials`, а если задан
  `CLAUDE_CONFIG_DIR` — с хвостом `-<первые 8 символов sha256 пути папки>`. Переменная
  `CLAUDE_SECURESTORAGE_CONFIG_DIR`, если задана, перекрывает это правило. Значит, `/login` и `/logout` в сессии
  своего провайдера работают со своей записью, а запись обычного Claude (без хвоста) не трогают — при условии,
  что `CLAUDE_SECURESTORAGE_CONFIG_DIR` в окружении сессии нет (у GLM он уже вычищается, `provider-env.ts`).
- **Настройки и состояние.** `globalConfig = join(<папка> || ~, '.claude.json')`,
  `userSettings = join(<папка> || ~/.claude, 'settings.json')`. С `CLAUDE_CONFIG_DIR` оба файла лежат в папке
  провайдера, значит `/model` и прочие записи пользовательских настроек остаются в ней.
- **Не изолируется и не должно:** настройки проекта (`.claude/settings.json`, `.claude/settings.local.json` в
  папке workspace) — общие у всех сессий этого workspace, как и сейчас у Claude, GLM и Codex.

**Если будущая версия это сломает** (решение К9): Parley не запускает своих провайдеров на версии ниже
`minVersion`, а `minVersion` поднимается только после повторной пробы по этому разделу.

Отдельно о том, что **не** защищено и почему это нормально: симлинки на CLAUDE.md, навыки и агентов — общие по
замыслу. Правка в сессии своего провайдера меняет оригинал. Поэтому агент сначала спрашивает человека и
предлагает копию (5.8), а человеку об этом говорит подпись под галочкой. Тест (задача 9 плана) проверяет: копия
по шагам правила и новый навык в папке провайдера оставляют `~/.claude` побайтно прежним.

### 6.2 Проба первого запуска (Claude Code 2.1.303, 2026-10-19)
Интерактивный `claude` в tmux, чистое окружение (`env -i`), пустая `CLAUDE_CONFIG_DIR`, пустая папка-проект,
`ANTHROPIC_BASE_URL=https://example.invalid`, `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1`. Установлена 2.1.303
(новее 2.1.302 из 6.1). Аргументы раннера GLM (`--settings`, `--strict-mcp-config`, `--model`, `--effort`)
экраны не меняют; `--permission-mode` в них нет.

**Экраны без посева, по порядку** (вход не спрашивают ни с `ANTHROPIC_AUTH_TOKEN`, ни с `ANTHROPIC_API_KEY=Yes`):
1. выбор темы; 2. только с `ANTHROPIC_API_KEY`: «Detected a custom API key… use this key?» (по умолчанию
выбрано «No (recommended)» — тогда после него встаёт экран входа Anthropic); 3. «Security notes» (Enter);
4. «Accessing workspace… Is this a project you trust?» (по умолчанию «No, exit»); 5. поле ввода (плюс неблокирующая
плашка «Auto mode is now default»).

**Что пишется.** После шагов 1–3 в `$D/.claude.json`: `hasCompletedOnboarding: true`, `lastOnboardingVersion`;
после 4: `projects[<cwd>].hasTrustDialogAccepted: true`; после 2 «Yes»: `customApiKeyResponses.approved` =
`[последние 20 символов ключа]` (короткий ключ — целиком). Тема уходит не в `.claude.json`, а в
`$D/settings.json` (`{"theme":"dark"}`).

**Минимальный посев** (проверено: bearer — сразу поле ввода, ни одного экрана):
```json
{ "hasCompletedOnboarding": true, "projects": { "<cwd>": { "hasTrustDialogAccepted": true } } }
```
- Достаточно одного `hasCompletedOnboarding`, чтобы пропали тема и «Security notes»; `settings.json` с темой не нужен,
  `lastOnboardingVersion` не нужен.
- Для `auth: 'api-key'` добавляется `"customApiKeyResponses": { "approved": ["<последние 20 символов ключа>"], "rejected": [] }`.
  Без него сессия висит на вопросе про ключ. Это фрагмент ключа в файле папки провайдера: пишется только туда
  (никогда в `~/.claude`), в логи и ответы протокола не попадает. Пишет его хост перед каждым запуском сессии
  с `auth: 'api-key'` (`approved` = ровно `[хвост текущего ключа]`); при `auth: 'bearer'`, удалении ключа и
  удалении провайдера поле `customApiKeyResponses` из `.claude.json` провайдера убирается (К17).
- Зависит от cwd: только `projects[<cwd>].hasTrustDialogAccepted` (ключ — полный путь сессии). Доверие,
  записанное для родительской папки, действует и на вложенную (проверено: вложенная папка запустилась без вопроса).
- Посев делается один раз и только если `.claude.json` провайдера ещё нет или поля не заданы: существующие поля
  не перезаписываются (слияние), файл остальное Claude Code ведёт сам.

**Доверие к папке.** Parley сам доверие не выставляет (в `packages/core` и `packages/host` нет
`hasTrustDialogAccepted`, `--dangerously-*`, `--permission-mode`). Обычный Claude вопроса не видит, потому что
cwd уже принят в `~/.claude.json` пользователя (без `CLAUDE_CONFIG_DIR`; с ней — `$CLAUDE_CONFIG_DIR/.claude.json`,
см. `host/src/capabilities/claude.ts`). Папка провайдера — другая `CLAUDE_CONFIG_DIR`, поэтому для неё вопрос
появился бы заново в каждой рабочей папке и «подвесил» бы сессию в Chat. **Решение: перенос нужен.** Перед запуском
сессии своего провайдера: если в `.claude.json` пользователя (чтение, без записи туда) для cwd сессии или его
родителя `hasTrustDialogAccepted === true`, записать `projects[<cwd>].hasTrustDialogAccepted: true` в
`.claude.json` провайдера — слиянием (перечитать файл прямо перед записью, остальные поля не трогать) и атомарно
(tmp + `rename`), даже если у провайдера уже идёт другая сессия (К18). Если пользователь не доверял папке в
обычном Claude, не доверяем и мы: сессия покажет тот же вопрос, что показал бы обычный Claude.

## 7. Мои решения (не обсуждались — проверь при чтении)

- **К1. Пункт Providers — после Agents** в левом меню Settings.
- **К2. Плагины не подтягиваются** в первой версии.
- **К3. GLM не трогаем:** остаётся на общей `~/.claude`, как сейчас. Перевод на отдельную папку — потом,
  отдельной задачей, чтобы у тех, кто им уже пользуется, ничего не поменялось незаметно.
- **К4. Галочка «Подтянуть» включена по умолчанию** — человек пришёл с привычными правилами и навыками.
- **К5. Сохранить нельзя с пустым слотом модели** (или «Одна на все»).
- **К6. Удаление провайдера по умолчанию оставляет его папку** с историей; удалить и её — отдельный выбор.
- **К7. «Проверить» шлёт сообщение на модель слота Sonnet.**
- **К8. Галочка «Из Codex» из макета убрана**: навыки Codex и прочее доступны через `find_skill`.
- **К9. Защита от будущих версий Claude Code** — `minVersion` и повторная проба раздела 6.1 перед её подъёмом.
- **К10. Меню модели** показывает модели слотов настоящими именами без повторов; выбор уходит в `--model <id>`
  (как у GLM); «Default» — без флага, то есть модель слота Sonnet. Моделей вне слотов в первой версии нет.
  `[1m]` и обязательное thinking/effort — данные пресета; у «Своего адреса» — уровни effort как у Claude.
- **К11. Ключ — ровно в одной переменной**, которую называет пресет (по умолчанию `ANTHROPIC_AUTH_TOKEN`);
  особые случаи вроде `ANTHROPIC_API_KEY=""` у OpenRouter — тоже данные пресета.
  `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1` — у всех своих провайдеров, как у GLM; проверяется живой пробой
  на каждом пресете.
- **К12. Онбординг.** Хост заранее заполняет папку так, чтобы онбординга не было. Если новая версия Claude Code
  поменяла формат и онбординг всё же показался, человек один раз проходит его в терминале сессии; это
  допустимо, но не должно случаться на поддерживаемой `minVersion`.
- **К13. Денег Parley не считает**: `usage-ledger` хранит только токены («Токены — не деньги…», шапка
  `core/src/work/usage-ledger.ts`), поэтому цен чужих моделей не нужно. Токены своих провайдеров
  считаются так же, как у GLM, из транскриптов в папке провайдера.
- **К14. Ссылки поштучно, а не на папки целиком** (5.4): иначе нельзя скопировать один навык, а новый навык из
  сессии своего провайдера попадал бы в основной Claude Code. Цена — сверка ссылок перед каждым запуском.
- **К15. Копию делает агент по правилу из 5.8, с согласия человека;** кнопки «сделать копию» в окне в первой
  версии нет.
- **К16. Серверы MCP основного Claude Code не переносятся:** они в `.claude.json`, а его мы не делим, потому что
  там же вход. MCP, добавленный в сессии своего провайдера, остаётся у него. Перенос копией при создании — потом,
  если попросят.
- **К17. Режим `api-key` хранит хвост ключа в `.claude.json` папки провайдера** (6.2): так Claude Code сам
  запоминает «Yes» на вопрос о ключе, иначе сессия висит. Это 20 последних символов, не ключ целиком, в папке
  0700 в доме Parley; полный ключ по-прежнему только в `secrets.json` и в окружении процесса. Обходы через
  `apiKeyHelper` или `ANTHROPIC_CUSTOM_HEADERS` меняют заголовки запросов (уходят оба, Bearer и x-api-key) —
  отвергнуты. Все пресеты — Bearer, так что хвост появляется только у «Своего адреса» с выбранным x-api-key.
- **К18. Доверие к папке переносится и при живой сессии того же провайдера** (6.2): правило плана «только без
  живой сессии» оставило бы вторую сессию провайдера в новой папке висеть на вопросе доверия. Гонка с записью
  самого Claude Code возможна только внутри `.claude.json` провайдера (не `~/.claude`); проигрыш гонки — тот же
  вопрос доверия, что и без переноса.

## 8. Оставлено строителю
