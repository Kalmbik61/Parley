## Как гонять

- **Один кусок — один прогон Workflow** (1–2 задачи). Агентам `model: 'sonnet'`.
- **Между кусками — стоп.** Итог показывается человеку, человек читает диф, потом
  коммит. Каждый коммит зелёный сам по себе.
- **Перед стартом этапа** его файл сверяется с кодом прошлых этапов. Имена и типы из
  блоков «Интерфейсы» могли сдвинуться — план правится до кода, а не после.
- **Хостовые куски этапа 1 идут строго по порядку:** все они добавляют строку в
  `packages/host/src/methods/index.ts`. Цепочка окна (1.9 → 1.10 → 1.11) идёт
  параллельно цепочке хоста — это разные пакеты (карта ниже).

## Как отмечать сделанное

- Кусок сделан, когда отмечены `[x]` все пункты его «Приёмки», прогоны зелёные и
  есть коммит.
- Тогда же отмечается его строка в «Прогрессе» ниже, с хешем коммита:
  `- [x] 1.3 Хост: процесс, сокет, рукопожатие — 3c742de`.
- Пункт приёмки, который сознательно не выполнен, не отмечается, а получает
  приписку `— отложено: <почему>` и строку в `TODOS.md`.

## Правила проверки

Из опыта прошлых прогонов:

- **Фаза проверки** — две линзы с разными углами. Каждой сказано исходить из того,
  что дефект есть.
- **У линз разные имена временных файлов.** В одном рабочем дереве они видят файлы
  друг друга и принимают их за постороннее вмешательство.
- **Проверяющий сверяет код с планом** и ошибку самого плана структурно не видит.
  Диф всё равно читает человек.
- **Границы — инвариантом по диапазону,** а не одним числом.
- **`tsc -p tsconfig.json` в пакете не видит тестов** (`exclude` в tsconfig).
  «tsc чисто» не значит «типы в тестах целы».
- **Настоящий `claude` в автотестах не запускается никогда** — только stub через
  `HARNAS_CLAUDE_BIN`.

## Сквозные ограничения

Каждый кусок молча включает эти требования. Значения — из спеки.

- **Стек.** Node ≥ 20, pnpm 9, ESM (`"type": "module"`). Новые пакеты наследуют
  `tsconfig.base.json` со строгими флагами (`exactOptionalPropertyTypes`,
  `noUncheckedIndexedAccess`, `verbatimModuleSyntax`).
- **Юридическая рамка** (спека 9.1):
  - запускаются только немодифицированные `claude` и `codex` из PATH;
  - `~/.claude/.credentials.json`, `~/.codex/auth.json` и Keychain
    `Claude Code-credentials` не читаются;
  - в `~/.claude` и `~/.claude.json` ничего не пишется; хуки — только через
    `--settings`;
  - запросов к API Anthropic и OpenAI нет, скрытых запусков нет;
  - хост не передаёт `--dangerously-load-development-channels`;
  - `--dangerously-skip-permissions` — только явным выбором пользователя.
- **Хост.** Каталог `~/.harnas/host/` (0700): `host.sock` (0600), `host.token` (0600),
  `host.pid`, `host.log`. Сетевых портов нет. `HARNAS_HOME` переносит всё.
- **Числа:**
  - прокрутка снимка экрана — 5 000 строк;
  - пачка `pty.output` — 16 мс;
  - хост уходит через 5 минут без живых сессий и без окон;
  - `resumeRate` — 6 подъёмов в час;
  - указатель без хода — предупреждение через 10 с;
  - `messageRate` — 20 писем в час;
  - `silenceThresholdMs` — 30 000;
  - Enter после текста указателя — через 500 мс.
- **Тексты указателя:**
  - `Новые письма (N). Вызови check_inbox.`
  - `Новые письма (N) в r-01 «<title>». Вызови check_inbox.`
- **Worktree.** Путь `<worktreeRoot>/<имя проекта>-<хеш6>/<w-id>-<S03>`, ветка
  `harnas/<w-id>/<s03>`, `worktreeRoot` по умолчанию `~/harnas/worktrees`.
- **Окно.** `contextIsolation`, `sandbox`, без `nodeIntegration`; CSP без удалённых
  скриптов; markdown без сырого HTML; телеметрии и автообновления нет.
- **TUI заморожен.** Правки в нём — только чтобы собираться с новым core, плюс
  аренда в куске 1.4. Новых видов нет.
- **Стиль.** Комментарии в коде — по-русски, «почему», а не «что», в манере соседних
  файлов. Коммиты — `feat(host): …`, `feat(desktop): …`, `feat(core): …`, тело
  по-русски, трейлер `Co-Authored-By`.

## На что смотреть на ревью

Входы и условия, которые спека подразумевает, но легко пропустить. Тест на каждый
лежит в куске, который владеет кодом.

1. **Второй запуск приложения.** Второй экземпляр фокусирует первое окно, хост
   остаётся один (1.9; второй хост не стартует — 1.3).
2. **Остатки упавшего хоста.** Если лежат `host.sock` и `host.pid`, окно поднимает
   новый хост, а не висит (1.3, 1.9).
3. **Поток на десятки мегабайт** (агент вывел большой файл). Память хоста ограничена
   снимком, медленное окно получает `pty.resync`, а не растущую очередь (1.6).
4. **Кириллица, эмодзи, вставка текста.** Флаг черновика и указатель не рвут
   многобайтные символы (1.6, 1.8).
5. **Карту пишут трое: TUI, хост и MCP-серверы агентов.** Таймаут `map.lock` не
   роняет хост: он шлёт `host.notice` и повторяет на следующем событии (1.4).
6. **Длинный путь сокета.** Путь unix-сокета длиннее 103 байт (например, длинный
   `HARNAS_HOME`) даёт понятную ошибку при старте. Тесты берут короткие пути в
   `/tmp` (1.3).
