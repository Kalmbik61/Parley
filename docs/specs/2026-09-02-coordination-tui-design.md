# Координация: дизайн TUI (режим «работы»)

> **Частично заменён** документом `docs/specs/2026-09-05-tui-v2-design.md`
> (2026-09-05): раскладка, режимы левой колонки, панель ДЕТАЛИ, клавиши и
> `Ctrl+Q` как возврат фокуса больше не действуют. В силе остаются диалоги
> 4.3–4.5, строка статуса (5), глифы и правила усечения (6.1–6.4), сортировка
> сессий и виртуализация (6.5–6.6), решения раздела 10.

Дата: 2026-09-02. Основание: `docs/specs/2026-09-02-coordination-design.md` (v3),
`.ralph/specs/ui.md`, `.ralph/specs/pty.md`, текущий код `packages/tui`.
Кода здесь нет — только макеты и правила, по которым он будет писаться.

Исходные принципы, которые дизайн не нарушает:

- правая панель принадлежит агенту целиком: ни оверлеев, ни диалогов поверх неё;
  всё новое живёт в левой колонке и в строке статуса;
- stock Ink 5, перерисовка по событиям watcher;
- существующий режим «все сессии» не меняется ни в чём, кроме общих для
  обоих режимов вещей: подсветка выбранной строки фоном (6.2) и строка
  статуса (5);
- все хоткеи харнесса действуют только когда фокус на списках — пока фокус
  в терминале, весь ввод уходит агенту (как сейчас).

## 1. Режимы левой колонки

Левая колонка получает два режима, переключаемых клавишей `w`:

| Режим | Верхняя панель | Нижняя панель |
|---|---|---|
| «все сессии» (текущий) | SESSIONS — плоский список историй | SUBSESSIONS выбранной сессии |
| «работы» (новый) | РАБОТЫ — проекты → работы → сессии | ДЕТАЛИ выбранной сессии |

Режим запоминается на время процесса. Диалоги (раздел 4) временно замещают
нижнюю панель — правая колонка при этом не трогается.

Ниже колонка добавляется **строка статуса** (1 строка, всю ширину терминала) —
единственное место уведомлений. На 80×24 она отнимает одну строку у панелей;
это осознанная цена (см. раздел 5).

## 2. Макеты: режим «работы»

### 2.1 80×24

Левая колонка на 80 колонках упирается в минимум: 30 колонок с рамкой,
26 знаков полезного текста. Ряд сессии двухэтажный: статус и label сверху,
провайдер и модель — второй строкой (серым, полужирным — 6.1). Токены на
этой ширине уходят в панель ДЕТАЛИ (правила усечения — раздел 6.4).

Выбранный ряд выделяется серым фоном на всю ширину (обе строки), стрелки `❯`
больше нет. В text-макетах фон условно обозначен `▌` на левом краю строки.

```text
┌────────────────────────────┬─────────────────────────────────────────────────┐
│ РАБОТЫ (3)                 │ бэкенд                                          │
│ ~/dev/shop ─────────────── │ Codex GPT-5.2                                   │
│ ▾ Авторизация        ●2 ▤1 │                                                 │
│   ✓ план               12м │   (экран живого агента — панель целиком его,    │
│     Claude Opus            │    весь ввод уходит агенту;                     │
│▌  ● бэкенд          32м ▤1 │    Ctrl+Q возвращает фокус спискам)             │
│▌    Codex GPT-5.2          │                                                 │
│     ● ревью             3м │                                                 │
│       Claude Opus          │                                                 │
│   ◌ тесты                — │                                                 │
│     Claude                 │                                                 │
│ ▸ Платежи               ●1 │                                                 │
├────────────────────────────┤                                                 │
│ ДЕТАЛИ — бэкенд            │                                                 │
│ Codex GPT-5.2              │                                                 │
│ ● active · 32м             │                                                 │
│ Реализовать шаги 1–3 пла…  │                                                 │
│ ↑1.2к ↓845 ⇄50к/3.0к       │                                                 │
│ ▤ план 09:41 «жду мигр…»   │                                                 │
│ арт: — · суб: 2            │                                                 │
│ ист: ◌ 09:12 → ● 09:14     │                                                 │
└────────────────────────────┴─────────────────────────────────────────────────┘
 ⚑ Cx: pending «тесты» в «Авторизация» · Enter на ◌ — запустить      w · Ctrl+Q
```

Легенда:

- `~/dev/shop ───` — заголовок проекта (dim, не выбирается): хвост пути проекта.
- `▾ Авторизация  ●2 ▤1` — строка работы: раскрыта (`▾`) / свёрнута (`▸`);
  хвост — счётчик активных сессий и непрочитанных сообщений работы.
- Ряд сессии — две строки: `статус → label → хвост (длительность, ▤N)` и под
  ней `Провайдер Модель`. Дочерняя (`ревью`, порождена `бэкенд`) — доп. отступ.
- `▌` — условное обозначение серого фона выбранного ряда (реально это фон,
  никакого глифа в колонке нет).
- `◌ тесты — / Claude` — pending: модели ещё нет, вторая строка — провайдер.
- Заголовок правой панели — та же пара строк: имя сессии, под ним провайдер
  и модель серым (вместо прежнего `TERMINAL — …`).
- ДЕТАЛИ — раздел 3. Строка статуса — раздел 5.

### 2.3 Ряд сессии: две строки и приоритет частей

Ряд сессии — две строки:

```
строка 1: [отступ] [статус 1] [label/task…]        [длительность] [токены] [▤N]
строка 2: [отступ]  Провайдер Модель               ← bright black + bold
```

- Строка 2 не отбрасывается ни на какой ширине — это основной идентификатор
  «кто работает»; при нехватке места усекается с `…`. У pending без известной
  модели — только провайдер (`Claude`).
- Инлайн-бейджи `Cl/Cx/GL` и модели в строке 1 не используются: провайдер и
  модель читаются из строки 2. Имя модели — по таблице нормализации
  (`Opus`, `GPT-5.2`, `GLM 5.3`); неизвестное — сырое, усечённое.
- Приоритет отбрасывания в строке 1: токены → длительность; `▤N` и значок
  статуса не отбрасываются никогда. Минимум label — 4 знака, дальше `…`.
- Порядок частей строки 1 исправлен 2026-09-02: было `[токены] [длительность]`,
  стало как в макетах 2.1, 2.2 и 6.6 — длительность перед токенами.
- Цена двухэтажности: на 80×24 в окно помещается ~5 сессий. Компенсация —
  свёртка работ (`←→`) и липкие заголовки (6.6). Виртуализация считает окно
  в строках, но ряд не рвётся: обе строки либо видны, либо нет.

**Вариант Б (рассмотрен и отклонён):** однострочный ряд с инлайн-бейджами
(`Cl Opus план`) — первая редакция этого документа. Отклонён 2026-09-02:
двухэтажный ряд освобождает строку 1 под label и метрики и читается лучше.

### 2.4 Дерево против отступов

Два варианта показа «кто породил»:

Вариант А — чистые отступы (80×24), глиф `└` только там, где ширина ≥ 36:

```text
▌  ● бэкенд          32м ▤1       ▌  ● бэкенд               32м 1.2к/845 ▤1
▌    Codex GPT-5.2                ▌    Codex GPT-5.2
     ● ревью             3м            └ ● ревью                   3м 640/95
       Claude Opus                         Claude Opus
```

Вариант Б — полные ветки `│ ├ └` на любой ширине:

```text
▌  ● бэкенд          32м ▤1
▌    Codex GPT-5.2
   ├ ● ревью             3м
   │   Claude Opus
   └ ◌ тесты              —
       Claude
```

**Рекомендация: вариант А.** На 26 знаках каждый глиф ветки — минус знак
label; глубина дерева на практике 1–2 уровня (агент порождает исполнителей),
и отступа достаточно. Полные ветки к тому же требуют вертикальных соединителей
через строки чужих поддеревьев — лишняя логика без выигрыша в чтении.

### 2.5 Сплит правой области — ОТЛОЖЕНО

> Решение 2026-09-02: сплит вне объёма v3 (спецификация, раздел 10). Клавиши
> `O`/`X` в этой версии не реализуются, Tab обходит одну терминальную панель.
> Раздел сохранён как заготовка для следующей фазы.

Правая область делится вертикально на две терминальные панели — два живых
агента бок о бок; в каждой пользователь вводит запросы и шлёт файлы своему
агенту (вставка путей и текста идёт через уже поддержанный bracketed paste;
своих файловых механик харнесс не добавляет — вопрос №13).

```text
┌────────────────┬────────────────────────────┬────────────────────────────┐
│ РАБОТЫ (3)     │ бэкенд                     │ тесты                      │
│ …              │ Codex GPT-5.2              │ Claude Opus                │
│                │                            │                            │
│                │ (агент A — весь ввод его,  │ (агент B — весь ввод его,  │
│                │  когда панель в фокусе)    │  когда панель в фокусе)    │
└────────────────┴────────────────────────────┴────────────────────────────┘
```

Правила:

- `O` на выбранной сессии — открыть её во **второй** панели (создаёт сплит).
  `Enter` — как раньше, в активной (последней фокусной) терминальной панели.
- `X` (фокус на списках) — закрыть вторую панель: PTY продолжает жить в фоне,
  сессия в списке остаётся `●`; вернуть — снова `O`.
- `Tab` обходит: списки (верх → низ) → терминал A → терминал B → списки.
  `Ctrl+Q` из любого терминала возвращает фокус спискам.
- Заголовок каждой панели — имя сессии, под ним провайдер и модель (серым,
  полужирным): та же пара строк, что в списке.
- Сплит доступен, только когда каждой панели достаётся ≥ 50 колонок (на 80×24
  недоступен); иначе `O` пишет причину в строку статуса.
- Два живых агента — двойной расход лимитов подписки; существующее
  предупреждение о параллельных сессиях сохраняется.

## 3. Панель ДЕТАЛИ

Замещает SUBSESSIONS в режиме «работы». Показывает выбранную сессию; если
выбрана работа — сводку работы (заголовок, цель, счётчики, последние события).

Порядок секций (фиксированный): ЗАДАЧА → СТАТУС → ТОКЕНЫ → СВОДКА → ВХОДЯЩИЕ →
АРТЕФАКТЫ → СУБАГЕНТЫ → ИСТОРИЯ. Панель фокусируется по Tab, `↑↓/jk` листают
содержимое окном (та же виртуализация, что в списках). На 80×24 панель
однострочно-компактна (макет 2.1), на 120×40 — секционна (макет 2.2).
Сразу под заголовком панели — провайдер и модель (серым, полужирным): та же
пара строк, что в списке и в заголовках терминальных панелей.

Правила:

- СТАТУС: глиф + статус + длительность; для `◐ idle` добавляется «молчит 14м»
  (от последней записи в логе), для `○ exited` и `✓`/`✗` — время выхода и код
  (`код 0` / `сигнал 9`).
- СВОДКА: `summary` из карты; помечается источник — `progress: «…»` (агент, не
  финал), без пометки (report done/failed), `авто: «…»` (summarySource=auto).
  Если резюме нет — `(отчёта нет)`, для exited добавляется подсказка `s — дозаказать`.
- ВХОДЯЩИЕ: непрочитанные первыми, `▤ <label отправителя> <чч:мм> «текст…»`.
  Прочитанные — dim, без `▤`, показываются последние 5; исходящие не
  показываются (решение №10).
- АРТЕФАКТЫ: `kind: path` относительно корня проекта, path усекается слева
  (`…works/w-0042/artifacts/plan.md` — важен хвост).
- СУБАГЕНТЫ: те же строки, что в SUBSESSIONS сейчас (task · длительность · модель).
- ИСТОРИЯ: цепочка `глиф чч:мм → глиф чч:мм`; на узкой ширине — только последние
  2 перехода, полностью — прокруткой.

Секции, отличающиеся от макета 2.2, — для `◐ idle` и `○ exited`
(фрагменты секционной раскладки 120×40, 41 знак):

```text
│ СТАТУС   ◐ idle · 41м · молчит 14м        │

│ СТАТУС   ○ exited 14:02 · 52м · код 0     │
│ СВОДКА   (отчёта нет — s дозаказать)      │
│ ВХОДЯЩИЕ ▤ план 10:02 «проверь линте…»    │
│          план 09:41 «жду миграции…»       │  ← прочитанные: dim, до 5
```

На 80×24 то же в компактной строке: `◐ idle · 41м · молчит 14м`,
`○ exited · 52м · код 0`.

## 4. Диалоги

Все диалоги живут на месте нижней левой панели (правая колонка не трогается,
даже если пуста — иначе поведение зависело бы от состояния агента). Диалог
модален для левой колонки: `↑↓/Tab` ходят по полям, `Enter` — следующее поле /
подтвердить, `Esc` — закрыть без изменений. Глобальные клавиши списков на время
диалога не действуют. Открыть диалог можно только из фокуса списков — если
пользователь печатает в терминале, ничто не выпрыгивает (уведомления копятся
в строке статуса).

### 4.1 Новая работа — `N`

```text
26 знаков (80×24)              41 знак (120×40)
┌──────────────────────────┐   ┌─────────────────────────────────────────┐
│ НОВАЯ РАБОТА             │   │ НОВАЯ РАБОТА · ~/dev/shop               │
│ Проект: ~/dev/shop       │   │ Заголовок: Авторизация▌                 │
│ Заголовок: Авторизация▌  │   │ Цель:                                   │
│ Цель:                    │   │   Логин по e-mail, сессии, миграции     │
│  Логин по e-mail, сесси… │   │                                         │
│ Enter — создать · Esc    │   │ Enter — создать · Esc — отмена          │
└──────────────────────────┘   └─────────────────────────────────────────┘
```

Проект — всегда cwd запуска харнесса, в диалоге не выбирается.

### 4.2 Новая сессия в работе — `n`

```text
┌──────────────────────────┐   ┌─────────────────────────────────────────┐
│ СЕССИЯ · Авторизация     │   │ НОВАЯ СЕССИЯ · Авторизация              │
│ Провайдер: ‹ Codex ›     │   │ Провайдер: ‹ Codex ›   (←→ по реестру)  │
│ Роль: тесты▌             │   │ Роль:      тесты▌                       │
│ Задача:                  │   │ Задача:                                 │
│  Прогнать e2e после ша…  │   │   Прогнать e2e после шагов 1–3          │
│ Enter — создать · Esc    │   │ Enter — создать (pending) · Esc         │
└──────────────────────────┘   └─────────────────────────────────────────┘
```

- Провайдер — селектор `‹ ›` (←/→) по реестру; недоступные в PATH показываются
  dim с пометкой `нет в PATH` и не выбираются.
- «Создать» даёт `pending`-запись. Бриф собирает харнесс по тому же шаблону,
  что и для порождённых агентом сессий (работа, роль, задача, три правила);
  пользователь вводит только роль и задачу. Запуск — отдельным подтверждением
  (4.3).

### 4.3 Запуск pending — `Enter` на `◌`

```text
┌──────────────────────────┐   ┌─────────────────────────────────────────┐
│ ЗАПУСК ◌ тесты (Cl)      │   │ ЗАПУСК ◌ тесты (Claude)                 │
│ бриф: briefs/s-04.md     │   │ бриф: .harnas/…/briefs/s-04.md          │
│ ▏Работа: Авторизация     │   │ ▏Работа: Авторизация — логин по e-mail  │
│ ▏Задача: прогнать e2e    │   │ ▏Роль: тесты · Задача: прогнать e2e     │
│ ▏Контекст: s-02 (резюме) │   │ ▏Контекст: s-02 бэкенд (резюме + арт.)  │
│ Enter — запустить · Esc  │   │ ▏Правила: get_map · send_message · rep… │
└──────────────────────────┘   │ Enter — запустить · Esc — позже         │
                               └─────────────────────────────────────────┘
```

Тело — первые строки брифа из `briefs/<id>.md` (`▏` — цитата, прокрутка `↑↓`).
Правка брифа из TUI не предусмотрена: диалог показывает путь, пользователь
правит файл своим редактором, при `Enter` файл перечитывается с диска.

### 4.4 Возобновление — `Enter` на `○`, `✓`, `✗`

```text
┌──────────────────────────┐   ┌─────────────────────────────────────────┐
│ ВОЗОБНОВИТЬ ○ бэкенд     │   │ ВОЗОБНОВИТЬ ○ бэкенд (Codex)            │
│ codex resume 7fa0e1…     │   │ codex resume 7fa0e1ee-cc7b…             │
│ вышел 14:02 · без отчёта │   │ вышел 14:02, код 0 · отчёта не было     │
│ резюме: нет (s — заказ)  │   │ резюме: нет — s закажет авто-резюме     │
│ Enter — возобновить · Esc│   │ Enter — возобновить · Esc               │
└──────────────────────────┘   └─────────────────────────────────────────┘
```

Id сессии в карте не меняется (`exited → active`), правая панель открывает
PTY с `resumeArgs`. Тот же диалог открывается для завершённых сессий (`✓`/`✗`):
переход `done/failed → active` записывается в историю, прежнее резюме остаётся
в карте до нового `report`, а строка «без отчёта» заменяется на
`резюме: «…» (будет перезаписано)`. Код выхода показывается здесь и в ДЕТАЛЯХ,
глиф для краша и штатного выхода один.

### 4.5 Дозаказ резюме — `s` на `○` exited

```text
┌──────────────────────────┐   ┌─────────────────────────────────────────┐
│ РЕЗЮМЕ ДЛЯ ○ бэкенд      │   │ ДОЗАКАЗ РЕЗЮМЕ ○ бэкенд                 │
│ claude -p по транскрипту │   │ Один вызов claude -p по транскрипту     │
│ запишется как «авто»     │   │ провайдера. Результат — summary с       │
│                          │   │ пометкой «авто» (summarySource=auto).   │
│ Enter — заказать · Esc   │   │ Enter — заказать · Esc                  │
└──────────────────────────┘   └─────────────────────────────────────────┘
```

Пока задача выполняется, в СВОДКЕ деталей — `авто-резюме: считается…`;
готовый результат приходит через watcher карты и отмечается в строке статуса.
Другой индикации нет. Для Codex транскрипт извлекает адаптер core, резюме
тем же вызовом `claude -p`.

## 5. Уведомления и строка статуса

Единственный канал уведомлений — строка статуса (нижняя строка терминала,
вне рамок, всю ширину). Ничего не мигает и не выпрыгивает: пользователь может
в этот момент печатать в правой панели.

Формат: `⚑[N] <последнее событие> · <подсказка действия>    <постоянные подсказки>`

- `⚑N` — счётчик непросмотренных событий (bold yellow); событие считается
  просмотренным, когда фокус побывал на строке-источнике в списках. События
  без строки-источника (предупреждение о лимитах) гаснут при следующем
  нажатии клавиши в списках.
- Показывается только последнее событие; предыдущие не теряются — их следы
  видны в списках (значки статусов, `▤N`).
- Постоянный хвост справа: `w · Ctrl+Q` (короткая шпаргалка режима).

События и их строки:

| Событие | Строка (пример, 80 кол.) |
|---|---|
| Агент породил pending | `⚑ Cx: pending «тесты» в «Авторизация» · Enter на ◌ — запустить` |
| Новое сообщение | `⚑ ▤ план → бэкенд: «жду миграции…»` |
| Сессия вышла без отчёта | `⚑ ○ бэкенд вышла без отчёта · Enter — возобновить, s — резюме` |
| 2-я параллельная сессия провайдера | `⚑ Cx: уже есть активная сессия — лимиты подписки общие` |
| Готово авто-резюме | `⚑ авто-резюме для «бэкенд» готово` |

Предупреждение о параллельных агентах сейчас рисуется в правой панели над
экраном (app.tsx). Оно переезжает в строку статуса в **обоих** режимах:
единый канал уведомлений, правая панель больше ничем не перекрывается.

## 6. Правила отображения

### 6.1 Значки статусов и прочие глифы

Каждому Unicode-глифу — ASCII-запасной (включается `HARNAS_ASCII=1` или при
терминале без Unicode). Цвет никогда не единственный носитель смысла: все
статусы различимы глифом в монохроме.

| Смысл | Unicode | ASCII | Цвет (16 ANSI) |
|---|---|---|---|
| pending | `◌` | `.` | dim |
| active | `●` | `*` | green |
| idle | `◐` | `~` | yellow |
| exited (без отчёта) | `○` | `!` | yellow |
| done | `✓` | `+` | green |
| failed | `✗` | `x` | red |
| непрочитанные `▤N` | `▤` | `@` | magenta bold |
| работа раскрыта / свёрнута | `▾` / `▸` | `v` / `>` | по строке |
| выбор ряда | серый фон всей строки | reverse video | bg bright black, текст не меняется |
| маркер выбора при уровне цвета 0 | `›` | `>` | нет — жёлоб слева, только когда цвета совсем нет (тема, 4.3) |
| провайдер+модель (строка 2) | текст | текст | bright black + bold |
| дочерняя сессия (≥36 зн.) | `└` | `` ` `` | dim |
| уведомление | `⚑` | `!` | yellow bold |
| селектор в диалоге | `‹ ›` | `< >` | cyan |
| цитата брифа | `▏` | `|` | dim |
| усечение | `…` | `~` | — |
| токены вход/выход | `↑` `↓` | `i` `o` | dim |
| кэш чтение/запись | `⇄` | `c` | dim |

### 6.2 Цветовая карта (роли темы)

Цвет больше не приходит именем ANSI — им управляет тема
(`2026-09-22-tui-theme-design.md`), а роль лишь переводится в конкретный цвет
по уровню терминала.

| Смысл | Роль | Где |
|---|---|---|
| активная зона | `border.active` | рамки сайдбара, панели, оверлея и треда; неактивная берёт `border.idle` |
| выбранный ряд | `bg.selection` | обе строки ряда, во всех списках и режимах |
| плашка `new` | `bg.badge` + `fg.badge` | кнопка под курсором; слот не общий с подсветкой ряда (тема, 3.2) |
| фон зон | `bg.sidebar`, `bg.panel`, `bg.status`, `bg.overlay` | построчная заливка, от 256 цветов (тема, 5.1) |
| зона агента | `bg.agent` + `fg.default` | ячейки PTY, которым гость не задал фон и цвет (тема, 5.3) |
| внимание | `status.warn` | `⚑` в строке статуса, точка `blocked` |
| ошибка | `status.fail` | точка `failed` |
| непрочитанное | `status.unseen` | точка непрочитанного в компактной строке |
| мета | `fg.muted` | время, токены, заголовки проектов, `pending`, прочитанные, точки `working`, `idle`, `exited` |
| живое / успех | — | цвета сегодня нет: `✓ done` рисуется без него, `●` уходит в `fg.muted` |
| провайдер, группы, сообщения | — | `Cl/Cx/GL`, заголовки workflow и `▤` сегодня не окрашены |

Две последние строки таблицы стоят без роли не по недосмотру. Три роли
объявлены в `packages/tui/src/theme/roles.ts`, проверены тестами роли и
контраста и не применены ни одним компонентом: `fg.accent` (пурпурный),
`fg.second` (второстепенный текст) и `status.live` (зелёный). Проверено грепом
по `packages/tui/src`: вне `theme/` и тестов их не зовёт никто.

Видно и почему. Перенос цвета на роли (тема, раздел 8, кусок 3) держал
обещание «кадр знак в знак»: все эти места сегодня либо `dim`, либо вовсе без
цвета, поэтому ушли к `fg.muted` и к пустым пропсам, а не к своим ролям. Туда
же смотрит `statusColor` в `glyphs.ts` — функция, по которой писалась прежняя
редакция этой таблицы: её не зовёт ни один компонент, только собственный тест,
а цвета точек на самом деле задаёт `dotColor` в `components/activity-dot.tsx`.
То есть зелёного в интерфейсе нет с тех пор, как появилась компактная строка, —
тема лишь сделала расхождение видимым. Задача заведена в `TODOS.md`.

Три уровня цвета (тема, 4.1): truecolor и 256 цветов красят ролями из палитры
темы и заливают фон зон (сайдбар, панель, оверлеи, строка статуса); шестнадцать
цветов отдают прежние имена ANSI и заливки не делают; ноль цветов не отдаёт
ничего — весь смысл несут глифы (6.1).

При нуле выбранная строка списка помечается маркером в колонке слева — жёлобом
шириной в один знак (`›`, в ASCII `>`), потому что на этом уровне фон и inverse
снимаются вместе с цветом, и залитый или инвертированный ряд ничем не отличался
бы от остальных.

Монохром: выбор = маркер в жёлобе (не reverse video — тот остаётся только на
шестнадцати цветах, тема 4.2); статус = глиф; непрочитанное = `▤N` (глиф);
активная панель = яркая рамка против dim у неактивной (цвет пропадает, разница
яркости остаётся — этого достаточно; заголовка у панели нет).

### 6.3 Токены и длительность

- Числа: 0–999 как есть; дальше `к` и `М`, одна десятичная до 10: `1.2к`,
  `45к`, `1.1М`.
- Полная форма (ДЕТАЛИ): `↑<вход> ↓<выход> · кэш чт <cacheRead> зп <cacheWrite>`.
- Строка списка (ширина ≥ 36): `<вход>/<выход>` без глифов — `1.2к/845`.
  Кэш в строку списка не выводится никогда: он на порядки больше и читается
  как шум; полные четыре счётчика — всегда в ДЕТАЛЯХ.
- `metrics: null` (сессия ещё не привязана к логам) → `—` на месте токенов и
  длительности.
- Длительность и относительное время — существующие `formatDuration` /
  `formatRelative` (`45с / 12м / 1ч 4м / 3д 2ч`), без изменений.

### 6.4 Усечение

- Однострочное усечение с `…` (ASCII `~`) — существующий `truncate`.
- Приоритет отбрасывания в строке сессии — раздел 2.3; label не короче 4 знаков.
- Заголовок работы: усекается до хвоста-агрегата; агрегат (`●2 ◌1 ▤1`) не
  отбрасывается — на самой узкой ширине сокращается до одной суммы `▤N`,
  затем `●N`.
- Пути артефактов усекаются слева (важен хвост имени файла).
- Заголовок проекта: хвост пути (`…/dev/shop`), усечение слева.
- Многострочные поля (задача, сводка) в ДЕТАЛЯХ: до 2 строк на 80×24,
  до 3 на 120×40, дальше `…` (полностью — прокруткой панели).

### 6.5 Сортировка

- Проекты: по `updatedAt` самой свежей работы, убыв.
- Работы в проекте: `active` выше `done`; внутри — по `updatedAt` убыв.
  `archived` не показываются; `done` при старте свёрнуты.
- Сессии проекта вне работ в режиме «работы» не показываются — только в режиме
  «все сессии». Работы других проектов из глобального индекса показываются;
  `Enter` по их сессиям запускает PTY с cwd того проекта.
- Сессии в работе: порядок дерева — корни по `createdAt` возр., дети под
  родителем по `createdAt` возр. Карта — план работы: стабильный порядок
  важнее свежести, строки не скачут при событиях (в отличие от режима
  «все сессии», где сортировка по свежести остаётся как есть).
- ВХОДЯЩИЕ в деталях: непрочитанные первыми, внутри — по времени убыв.

### 6.6 Много сессий (20+) и виртуализация

Окно видимых строк — существующий `visibleWindow`. Дополнительно в режиме работ:

- заголовок работы (и проекта) «липнет»: рисуется над окном, если первая
  видимая сессия — из середины работы (приём как у workflow-групп в
  `subsession-list.tsx`);
- число сессий `(N)` у свёрнутой работы стоит сразу за заголовком (макеты 2.2
  и раздел 7), у липкого заголовка развёрнутой — у правого края, за агрегатом
  (макет ниже): у развёрнутой работы место за заголовком не занято, а справа
  число читается вместе с агрегатом;
- на границах окна — строки `… N выше` / `… N ниже` (dim);
- `←/→` (или `h/l`) сворачивают/разворачивают выбранную работу — единственный
  инструмент навигации по работе с 20+ сессиями без прокрутки через все.

```text
│ РАБОТЫ (1)                 │
│ ~/dev/shop ─────────────── │
│ ▾ Миграция БД      ●3 (24) │   ← липкий заголовок работы
│   … 9 выше                 │
│   ✓ шаг 7            1ч 2м │
│     Claude Opus            │
│▌  ● шаг 8              41м │
│▌    Codex GPT-5.2          │
│   … 14 ниже                │
```

## 8. Клавиши

Существующие — без изменений; новые помечены. «Списки» = фокус на любой левой
панели; в терминале с живым агентом действует только Ctrl+Q (как сейчас).

| Клавиша | Где действует | Действие | Статус |
|---|---|---|---|
| `↑↓` / `j k` | списки, детали, диалоги | навигация / прокрутка / поля | есть |
| `Tab` | списки | панели по кругу: верх → низ → терминал | есть |
| `Tab` | диалог | следующее поле | новая (в диалоге) |
| `Enter` | SESSIONS | открыть сессию справа | есть |
| `Enter` | РАБОТЫ: `◌` | диалог запуска pending (4.3) | новая |
| `Enter` | РАБОТЫ: `○` | диалог возобновления (4.4) | новая |
| `Enter` | РАБОТЫ: `●`/`◐` | attach к PTY сессии справа; если PTY не у харнесса (запущена вне TUI) — правая панель показывает «запущена вне харнесса», детали доступны | новая |
| `Enter` | РАБОТЫ: `✓`/`✗` | диалог возобновления (4.4), переход `done/failed → active` | новая |
| `Enter` | РАБОТЫ: работа | свернуть/развернуть | новая |
| `n` | SESSIONS | новая сессия провайдера (как сейчас) | есть |
| `n` | РАБОТЫ | диалог «новая сессия в работе» (4.2) | новая (то же n) |
| `N` | РАБОТЫ | диалог «новая работа» (4.1) | новая |
| `w` | списки | режим: все сессии ↔ работы | новая |
| `s` | РАБОТЫ: `○` | диалог «дозаказ резюме» (4.5) | новая |
| `←→` / `h l` | РАБОТЫ | свернуть/развернуть работу | новая |
| `p` | списки | фильтр провайдера (в работах — по сессиям) | есть |
| `r` | списки | ре-скан | есть |
| `R` | списки | перезапуск завершившегося агента справа | есть |
| `Esc` | диалог | закрыть диалог | новая (в диалоге) |
| `q` / `Ctrl+C` | списки | выход | есть |
| `Ctrl+Q` | терминал | фокус спискам | есть |

Конфликты и разборы:

- `n` перегружена по режиму, но смысл один — «новая сессия»; в работах она
  просто проходит через `pending` и диалог. Не конфликт, а уточнение.
- `N` против `n` — то же различие регистра, что уже принято для `r`/`R`.
- `R` (перезапуск правой панели) и возобновление exited по `Enter` — разные
  вещи: `R` работает с активной панелью независимо от списка, оставлена как есть.
- `Enter` в работах перегружен по статусу строки — таблица выше фиксирует все
  ветки; на pending/exited/done/failed всегда диалог, тихого запуска нет.
- `w` не конфликтует с `HARNAS_ESCAPE_KEY=w`: та — Ctrl+W и живёт в терминале.
- `h l` заняты под работу с деревом — конфликтов нет (`j k` уже навигация).
- `O`/`X` зарезервированы под сплит (2.5, отложено) и в этой версии не заняты.
- `p` в режиме работ фильтрует строки сессий; работы и проекты остаются
  видимыми, пустые — с пометкой `фильтр: Cx`.

## 9. Схема переходов

```text
                 w                          w
   [ВСЕ СЕССИИ] ─────────▶ [РАБОТЫ] ─────────▶ [ВСЕ СЕССИИ] …
        │                     │
        │ Enter               │ Enter — по статусу выбранной строки:
        ▼                     ├─ работа ─────▶ свернуть/развернуть
   PTY справа                 ├─ ◌ pending ──▶ ДИАЛОГ запуска ──Enter──▶ active, PTY справа
   (resume)                   ├─ ○ exited ───▶ ДИАЛОГ возобновления ──▶ active, PTY справа
                              ├─ ● / ◐ ──────▶ attach к живому PTY справа
                              └─ ✓ / ✗ ──────▶ ДИАЛОГ возобновления ──▶ active, PTY справа

   n (в работах) ──▶ ДИАЛОГ новой сессии ──▶ ◌ pending в списке ──▶ (Enter — запуск)
   N ────────────────▶ ДИАЛОГ новой работы ──▶ пустая работа в списке
   s (на ○) ─────────▶ ДИАЛОГ дозаказа ──▶ «считается…» ──watcher──▶ СВОДКА: авто

   Все диалоги: на месте нижней левой панели; Esc — назад без изменений.
   Правая панель во всех переходах не перерисовывается ничем, кроме своего PTY.
   События карты (watcher) ──▶ строка статуса ⚑ + значки в списках; фокус не крадут.
```

## 10. Вопросы к спецификации и принятые решения

Вопросы первой редакции этого документа и решения по ним (2026-09-02). Все
решения внесены в разделы выше и в спецификацию (раздел 11).

| № | Вопрос | Решение |
|---|---|---|
| 1 | Правка брифа до запуска | Из TUI не правится: диалог показывает путь, правка своим редактором, при `Enter` файл перечитывается |
| 2 | Сессии проекта вне работ | Только в режиме «все сессии»; группы «вне работ» нет |
| 3 | `archived` и `done` работы | `archived` скрыты совсем; `done` при старте свёрнуты |
| 4 | `p`-фильтр в работах | Работы не прятать; пустые помечать `фильтр: Cx` |
| 5 | Attach к сессии, запущенной вне TUI | Правая панель показывает «запущена вне харнесса», attach невозможен, детали доступны |
| 6 | Сколько молчит `idle` | Только в ДЕТАЛЯХ: `◐ idle · молчит 14м` |
| 7 | Индикация дозаказа; не-Claude транскрипты | СВОДКА и строка статуса достаточно; для Codex транскрипт извлекает адаптер core, резюме тем же `claude -p` |
| 8 | Предупреждение о параллельных агентах | В строку статуса в обоих режимах |
| 9 | Работы других проектов | Показывать все из индекса; `Enter` запускает с cwd проекта работы; в диалоге «новая работа» проект не выбирается |
| 10 | Сообщения в ДЕТАЛЯХ | Непрочитанные плюс последние 5 прочитанных; исходящие не показывать |
| 11 | Код выхода `exited` | Глиф один; код выхода в ДЕТАЛЯХ и в диалоге возобновления |
| 12 | Журнал уведомлений | Нет; следы событий в списках достаточны |
| 13 | Отправка файлов агенту | Только вставка; файлового пикера нет |
| 14 | Сплит правой области | Отложен, вне объёма v3 (раздел 2.5) |
| — | `Enter` на `✓`/`✗` | Диалог возобновления, переход `done/failed → active` добавлен в спецификацию |
