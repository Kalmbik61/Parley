# Расход токенов комнаты и сессии — дизайн

Дата: 2026-10-14. Статус: согласовано в диалоге (зачем: беречь лимиты, сравнивать самому, показывать
другим, видеть, куда уходят токены; проценты лимита не показываем — они есть внизу окна; «токены
комнаты» — расход участника с момента входа; уровни — комната и одна сессия в Chat, внутри итога
комнаты разбивка по провайдерам; поделиться — кнопкой Copy; подход A — срез логов по времени в хосте;
история участия — журнал в карте). Основание: код `origin/master` 76795c7 (v0.12.1), учёт токенов P36
(`core/src/work/usage-ledger.ts`), спека архива комнат `2026-10-08-archive-rooms-projects-design.md`
(3.5).

---

## 1. Зачем

- Хост уже считает токены каждой сессии по логам провайдеров (P36): вход без кэша, выход, чтение и
  запись кэша, источник, свежесть, полнота. В окне они видны только в подсказке строки сессии в
  сайдбаре (`SessionRow.tsx`, `formatMetricsLine`). Сколько ушло на комнату, не видно нигде.
- Сумма по нескольким разговорам без двойного счёта (`sumUsage`) написана, но не подключена. Поле
  `UsageAttribution.roomId` всегда `null`: сессия бывает в разных комнатах, и делить её расход нечем.
- Человеку нужно: понимать, сколько съела комната (беречь лимит подписки), самому сравнивать
  агентов и провайдеров, показывать другим, сколько потрачено, и видеть, куда уходят токены.

## 2. Решения

1. **Итог комнаты** — значок в шапке комнаты и поповер: общий итог, разбивка по провайдерам,
   разбивка по сессиям, кнопка Copy.
2. **Токены комнаты — расход участника с момента входа** в неё и до ухода (или до архивации). Работа
   сессии до комнаты и после ухода в итог комнаты не входит.
3. **Chat** — значок с расходом одной сессии за всю её жизнь (комнаты у Chat нет). Ничего нового не
   считается: это `LiveMetrics.usage`.
4. **Токены, не деньги и не процент лимита.** Проценты остаются в строке лимитов внизу окна.
   Правила P36 сохраняются: неизвестное — `?`, а не `0`; неполное помечено; нативные id и пути логов
   в окно не уходят.
5. **Журнал участия в карте** (`Room.memberLog`): кто, когда вошёл и вышел. Сегодня уход из комнаты
   (`leaveOtherRooms`) следа не оставляет, и бывший участник выпал бы из итога. Старые комнаты без
   журнала восстанавливаются по ленте и помечаются.
6. **Подсчёт — в хосте, по меткам времени в логах** (подход A). Сессия целиком внутри окна берёт
   готовый итог; сессия, выходящая за окно, перечитывается со срезом по времени.
7. **Поделиться — Copy**: таблица Markdown в буфер. CSV и другие форматы — вне объёма.

## 3. Что видит человек (окно)

### 3.1 Значок в шапке комнаты

`RoomHeader` получает слот `usageChip` рядом с `modeControl`, `recipeChip` и `historyMenu`. Значок —
кнопка `↑1.2M ↓84k`: вход без кэша и выход итога комнаты, тем же форматом, что `formatMetricsLine`
(`formatTokens`).

- Итог неполный — перед числами `≥` (`≥ ↑1.2M ↓84k`).
- Число неизвестно — `?`.
- Ответа ещё нет — `…`; хост ответил ошибкой — `—` с подсказкой «Usage unavailable».
- Хост без метода `rooms.usage` (окно новее хоста) — значка нет.
- Окно 800×500: значок не сжимается, обрезается название комнаты (как сейчас).

### 3.2 Поповер

```
Token usage · since each member joined                 [Copy]
─────────────────────────────────────────────────────────────
Total        In 1.2M   Out 84k   Cache read 9.1M   write ?
  Claude     In 600k   Out 40k   Cache read 6.0M   write 210k
  GLM        In 300k   Out 20k   Cache read 1.1M   write 100k
  Codex      In 300k   Out 24k   Cache read 2.0M   write ?
─────────────────────────────────────────────────────────────
S01 Planner · lead · Claude   In 500k  Out 30k
S03 Backend · GLM             In 300k  Out 20k
S04 Tests · Codex             In 300k  Out 24k   partial
S06 Docs · Claude             In 100k  Out 10k   left 11:40
S05 Review · Claude           n/a — log not found
S07 · Claude                  not started
─────────────────────────────────────────────────────────────
Tokens, not money or plan limit. Providers count tokens differently.
Updated 12:03
```

- Колонки: `In` — вход без кэша (`input`), `Out`, `Cache read`, `Cache write`. Полный вход
  (`totalInput`) не показывается и ни с чем не складывается (контракт P36).
- Провайдеры — по `session.provider`, подпись из `providers.list` (её уже получает `RoomBody`).
  Строка провайдера есть, только если у него есть участники; все участники одного провайдера —
  строк провайдеров нет вовсе (они повторили бы Total).
- Строка сессии: `sessionRowLabel`, пометка `lead` у ведущего, провайдер, цифры, пометки:
  - `partial` — нижняя граница (P36 или срез, см. 5.3);
  - `snapshot` / `stale` — цифры не из живого лога (как в `formatMetricsLine`);
  - `left HH:MM` — участник уже вышел из комнаты;
  - `shared with r-02` — только старые карты, где сессия числилась в двух комнатах сразу (5.5);
  - `n/a — log not found` / `n/a — session deleted` — посчитать нечем, итог комнаты `partial`;
  - `not started` — сессию ни разу не запускали, в сумме это ноль, полноту итога не портит.
- Порядок сессий: ведущий, затем текущие участники в порядке `members`, затем вышедшие по времени
  ухода.
- Старая комната без журнала (4.3) — строка под таблицей: «Membership before usage tracking is
  partly reconstructed».
- Список сессий прокручивается; длинные названия обрезаются многоточием.

### 3.3 Copy

Кнопка кладёт в буфер таблицу Markdown с теми же числами и пометками, что в поповере (форматированными
`formatTokens`, не точными):

```markdown
**Room “Payment refactor” (r-03) — token usage**
Since each member joined · 2026-10-14 12:03

| | In | Out | Cache read | Cache write |
|---|---:|---:|---:|---:|
| **Total** (partial) | 1.2M | 84k | 9.1M | ? |
| Claude | 600k | 40k | 6.0M | 210k |
| GLM | 300k | 20k | 1.1M | 100k |
| Codex | 300k | 24k | 2.0M | ? |
| S01 Planner · lead · Claude | 500k | 30k | 5.2M | 180k |
| S04 Tests · Codex (partial) | 300k | 24k | 2.0M | ? |
| S05 Review · Claude (n/a — log not found) | ? | ? | ? | ? |

```

Пометки строк идут в скобках после подписи: `partial`, `snapshot`, `stale`, `left HH:MM`, `shared with
r-XX`, `n/a — …`, `not started`; у неполного итога — `(partial)` после **Total**. После копирования —
тост «Copied».

### 3.4 Chat

В `ChatToolbar` — значок того же вида `↑500k ↓30k` по `LiveMetrics.usage` открытой сессии. Поповер:
In / Out / Cache read / Cache write, источник и пометки (`snapshot`, `stale`, `partial`), строка про
токены и лимит. Без Copy. У хоста без `usage` значок показывает `tokensIn`/`tokensOut`, как строка
сайдбара.

### 3.5 Тексты

Все тексты окна — английские, в `shared/strings.ts` (`S.usage.*`): заголовок, колонки, пометки,
примечания, «Copied», «Usage unavailable». Комментарии, тесты и спека — по-русски.

## 4. Журнал участия (core, карта)

### 4.1 Поле

```ts
interface RoomMembership {
  /** Id сессии; человек в журнал не пишется. */
  session: string;
  /** Вход: создание комнаты для создателя и начальных участников, иначе момент `addMember`. */
  from: string;
  /** Уход (`leaveOtherRooms`); `null` — участник до сих пор в комнате. */
  to: string | null;
}

interface Room {
  // …
  /** Журнал участия; нет поля — комната создана до журнала (4.3). */
  memberLog?: RoomMembership[];
}
```

Повторный вход той же сессии — новая запись. `parseMap` проверяет поле, если оно есть (массив
записей с непустым `session`, ISO-строкой `from`, `to` — ISO-строка или `null`), и не подставляет его,
если нет: отсутствие и есть признак старой комнаты. Битое поле убирается — комната читается как
старая (4.3), а карта не становится нечитаемой из-за журнала.

### 4.2 Кто пишет

- `addRoom(map, init, at)` — записи `{ session, from: at, to: null }` для создателя-сессии и каждого
  из `init.members`.
- `addMember(map, roomId, sessionId, at)` (и `addMemberByLead` через него) — запись входа, если
  сессии нет среди открытых записей этой комнаты.
- `leaveOtherRooms(map, sessionId, exceptRoomId, at)` — новый необязательный параметр `at`; закрывает
  открытые записи этой сессии в остальных комнатах (`to: at`). Вызывающие (`rooms-service.ts`,
  `mcp/tools.ts`, `addMember`) передают то же `at`, что и при создании комнаты или входе.
- У комнаты без `memberLog` (старая) новые записи не заводятся — её история восстанавливается
  всегда одинаково (4.3), смешивать два источника не нужно.
- Архивация и Reopen журнал не трогают: окно режется архивом при подсчёте (5.1).

### 4.3 Старые комнаты: восстановление

Комната без `memberLog` восстанавливается при подсчёте, карта не переписывается:

- создатель-сессия и текущие `members` без строки входа — с `room.createdAt`;
- строка ленты комнаты `from: system` с текстом ровно `${sessionMention(id)} joined the room` —
  вход в момент `at` строки (текст строит та же функция, что и `addMember`; сравнение точное);
- выход сессии — её ближайший по времени вход в другую комнату той же работы (правило одной
  комнаты), если он позже входа сюда; иначе выхода нет. Вход в другую комнату берётся из её журнала,
  если он есть (так видны и начальные участники новых комнат, у которых строки «joined» нет), иначе
  по тем же правилам восстановления;
- ушедший начальный участник или создатель, которого заменил `human`, не восстанавливается — поэтому
  у таких комнат примечание из 3.2.

## 5. Окно участника и подсчёт (core)

### 5.1 Окна

Окна участника — его записи журнала, у каждой `[from, to ?? конец]`, где конец — `archivedAt` у
архивной комнаты, иначе «сейчас». Запись, начавшаяся после `archivedAt`, пустая. Время в архиве до
Reopen у вернувшейся комнаты считается (журнал его не различает) — 7.

### 5.2 Целиком или срезом

Для каждого участника:

1. **Сессия ни разу не запускалась** (нет `providerSessionId`) — `not started`.
2. **Сессии нет в карте** (удалена) — `n/a`, причина `deleted`.
3. **Целиком внутри окна** — у участника одно окно, и вся активность сессии внутри него: начало
   активности не раньше `from`, конец не позже `to` (или окно открыто). Активность — по индексу лога
   (`startedAt`, `endedAt`), без лога — по карте (`startedAt`, `endedAt`). Итог — тот же, что
   выбирает `selectUsage` для `LiveMetrics` (живой индекс с потомками или снимок из карты). Это
   обычный случай для агентов, запущенных под комнату. Лог уже есть, а ответов модели в нём ещё нет —
   ноль, а не `n/a`.
4. **Иначе — срез** (ведущий с историей, приглашённая старая сессия, повторный вход, выход). Нужен лог;
   его нет — `n/a`, причина `log-missing`.

### 5.3 Срез учёта по окнам

`createUsageLedger` получает необязательные окна: `{ windows?: Array<{ from: string; to: string | null }> }`.
Без окон поведение прежнее.

- **Разовая запись** (`delta`, Claude и надстройки): учитывается, если её `at` внутри хотя бы одного
  окна. Запись без `at` при заданных окнах не учитывается, итог `partial`.
- **Накопительная нить** (`cumulative`, Codex): вклад окна — значение последнего наблюдения не позже
  `to` минус значение последнего наблюдения раньше `from` (нет такого — база ноль). Сброс (`reset`)
  внутри окна закрывает период так же, как сейчас: вклад закрытого периода считается от базы окна,
  следующих — от нуля. Спад без сброса — `partial`, как сейчас. Поле, неизвестное у базы или у
  конца, — неизвестно. Наблюдение без `at` — `partial`.
- **Потомки**: подагенты Claude (`subagents/*.jsonl`) и порождённые треды Codex режутся теми же
  окнами; сложение — `withDescendants`, как без окон.
- `observedAt` среза — время последнего учтённого наблюдения.
- В окна не попала ни одна запись, а записи с usage в логе есть — расход в окнах известен и равен
  нулю по тем полям, которые лог сообщает (у Codex `Cache write` остаётся `?`). Лог без единой записи
  с usage — неизвестно, как и без среза.

Функции индекса, которые строят учёт (`session-index.ts`, `codex/index-session.ts`), получают те же
окна параметром и отдают только `UsageSummary` — остальной индекс при срезе не нужен.

### 5.4 Итог комнаты

Чистая функция ядра `roomUsage(map, roomId, resolve, now)`: `resolve` по участнику и его окнам отдаёт
итог (5.2) — хост подставляет индекс логов и чтение со срезом, тесты — свои данные.

- Итог участника с несколькими окнами — один срез по всем окнам (повторный вход не дублирует).
- Один разговор у двух участников (две записи карты с одним `providerSessionId`) — в итоге он
  считается один раз (`sumUsage` берёт более свежее наблюдение), строки обоих остаются. Окна двух
  записей не объединяются: случай редкий, а итог всё равно без двойного счёта.
- `total` — `sumUsage` по всем участникам со статусом `counted`; `byProvider` — `sumUsage` по
  участникам каждого провайдера. Участник `n/a` делает `total` и итог своего провайдера `partial`;
  `not started` — нет.

### 5.5 `shared with`

В новых картах сессия в каждый момент в одной комнате, пересечений нет. В старых картах (решение 4
спеки комнат) сессия могла числиться в нескольких комнатах: если её окна здесь и в другой комнате
пересекаются по времени, у строки пометка `shared with r-XX`, и расход за пересечение входит в итоги
обеих комнат.

## 6. Хост и протокол

### 6.1 `rooms.usage`

```ts
'rooms.usage': { projectPath: string; workId: string; roomId: string }
// ответ
interface RoomUsage {
  roomId: string;
  computedAt: string;
  /** Комната без журнала участия: история восстановлена (4.3). */
  reconstructed: boolean;
  total: UsageTotal;
  byProvider: Array<{ provider: string; total: UsageTotal }>;
  members: RoomUsageMember[];
}
interface RoomUsageMember {
  sessionId: string;
  /** `null` — сессии уже нет в карте. */
  provider: string | null;
  lead: boolean;
  /** Окна участия, уже обрезанные архивом. */
  periods: Array<{ from: string; to: string | null }>;
  /** Участник сейчас в комнате. */
  current: boolean;
  status: 'counted' | 'not-started' | 'unavailable';
  reason: 'log-missing' | 'deleted' | null;
  method: 'whole-session' | 'sliced' | null;
  /** Публичная часть итога (P36): без `binding`, `epoch`, нативных id и путей. */
  usage: UsageSummary | null;
  sharedWith: string[];
}
```

Схема — в `protocol/src/methods.ts`, обработчик — `host/src/methods/rooms.ts`, расчёт — новый
`host/src/rooms/room-usage.ts` поверх `roomUsage` ядра и `LogIndex`.

### 6.2 Кэш и нагрузка

- Путь «целиком» (5.2, п. 3) берёт готовый итог из `LogIndex` — без чтения файлов.
- Срез читает файл лога участника (и его потомков) целиком. Результат кэшируется по ключу
  `(файл, размер, mtime, окна)`; повторный запрос без новых записей в логе файл не читает. Кэш —
  LRU на 64 записи, в памяти хоста.
- Одновременные запросы одной комнаты склеиваются в один расчёт.
- В плане — замер среза на самом большом реальном логе ведущего. Если дорого — дочитывание хвоста с
  сохранённым состоянием учёта (сейчас не делаем).

### 6.3 Когда окно спрашивает

Только пока вкладка комнаты активна (`RoomBody.active`): при открытии и активации, при изменении
состава или архива комнаты, и при изменении `LiveMetrics` её участников — но не чаще раза в 10 секунд.
Неактивные вкладки не спрашивают. Открытый поповер показывает последний ответ и «Updated HH:MM».

## 7. Граничные случаи

- Комната вернулась из архива: время в архиве входит в окно. Если агентов остановили при архивации,
  расхода там нет; если нет — он посчитается. Делить по строкам «archived/reopened» не стали (вне
  объёма).
- Сессию перепривязали к другому разговору (`providerSessionId` сменился): считается текущий
  разговор; снимок чужого разговора не берётся (как в `metricsFor`).
- Лог провайдера удалён (Claude по умолчанию чистит старые логи): путь «целиком» берёт снимок из
  карты; срез без лога — `n/a`.
- Часы: время записей лога и время карты пишутся разными процессами; допуск `EPOCH_TOLERANCE_MS`
  при сравнении с границами окна не применяется — граница проходит точно по времени записи.
- GLM и прочие надстройки Claude читаются как Claude (`logFamily`), в разбивке — отдельной строкой
  по `session.provider`.

## 8. Тесты

- **core, журнал**: `addRoom` пишет создателя и участников; `addMember` — вход, повторный вход — новая
  запись; `leaveOtherRooms` закрывает открытые записи с переданным `at`; `parseMap` — карта без поля,
  с полем, с битым полем.
- **core, восстановление**: текущие участники с `createdAt`; вход по строке «joined»; выход по входу
  в другую комнату; создатель-сессия.
- **core, срез учёта**: `delta` внутри, снаружи, на границе, без `at`; `cumulative` с базой до окна,
  без базы, со сбросом внутри окна, со спадом без сброса; несколько окон; потомки Claude и Codex;
  без окон — прежние результаты (существующие тесты не меняются).
- **core, `roomUsage`**: путь «целиком» и срез; `not started`, `deleted`, `log-missing`;
  `byProvider`; один разговор у двух участников; `shared with` в старой карте; `reconstructed`.
- **host**: сервис `rooms.usage` на логах-образцах (`fixtures`): ведущий с историей до комнаты
  (срез), агент, запущенный под комнату (целиком), вышедший участник, кэш (второй вызов файл не
  читает).
- **desktop**: формат значка (`≥`, `?`, `…`, `—`), Markdown для Copy, поповер; значок Chat у хоста с
  `usage` и без. E2E при 800×500 с длинными названиями комнаты и сессий, при масштабе экрана 1 и 2.

## 9. Порядок

1. core: журнал участия — тип, `parseMap`, `addRoom` / `addMember` / `leaveOtherRooms` с `at`,
   вызывающие в хосте и MCP.
2. core: окна в `createUsageLedger` и в функциях индекса Claude и Codex.
3. core: восстановление старых комнат и `roomUsage`.
4. protocol + host: `rooms.usage`, кэш, замер на большом логе.
5. desktop: значок и поповер комнаты, Copy, значок Chat, тексты.
6. E2E и живая проверка на настоящей комнате с ведущим и агентами разных провайдеров.

## 10. Вне объёма

- Деньги и процент лимита подписки (лимиты — строка внизу окна).
- Итоги работы и проекта, итог по всем комнатам.
- CSV и другие выгрузки, графики во времени, автоматические сравнения.
- Деление расхода по ходам (какое письмо какой комнаты запустило ход).
- Вычитание времени в архиве у вернувшейся комнаты.
- Расход вне Parley (сессии CLI, запущенные мимо окна).
