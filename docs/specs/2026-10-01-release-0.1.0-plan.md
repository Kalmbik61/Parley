# Первый релиз Parley 0.1.0 — план

Цель: по тегу `v0.1.0` CI собирает macOS-сборки и выкладывает их в GitHub Releases
репозитория `Kalmbik61/Parley`. Человек скачивает `.dmg`, ставит и запускает без своего node.
Linux и Windows — следующие версии: им нужна схема клавиш Ctrl+Shift, заголовок окна без
hiddenInset и перенос хоста на Windows. Здесь их не делаем.

На чём основано:
- исследование 2026-09-30 — выжимка в основном checkout,
  `.superpowers/releases/research-2026-09-30.md`;
- копии файлов Orca (MIT) — рядом, в `orca-files/`;
- решения пользователя:
  - MIT, `Copyright (c) 2026 Evgeniy`;
  - appId `dev.parley.desktop`;
  - встроенный Node 22;
  - без подписи Apple, аккаунт будет позже;
  - иконку пользователь сделал — она уже в `packages/desktop/build/`.

Ветка `feat/release-0.1.0` стоит поверх `feat/parley-rename` (переименование, иконка,
английский README). Worktree — `.claude/worktrees/parley-release`.

## Решения

- **V1. Версия и метаданные.**
  - `0.1.0` во всех `package.json`: корень и четыре пакета.
  - В корневом `package.json` и `packages/desktop/package.json`:
    - `"license": "MIT"`;
    - `"author": "Evgeniy"`;
    - `"homepage": "https://github.com/Kalmbik61/Parley"`;
    - `"repository": {"type": "git", "url": "https://github.com/Kalmbik61/Parley.git"}`.
  - Файл `LICENSE` (MIT) в корне.
  - Строка статуса после этого показывает `Host 0.1.0`.
- **V2. Упаковка macOS** (`packages/desktop/electron-builder.yml`):
  - `appId: dev.parley.desktop`;
  - цели — `dmg` и `zip`, каждая для `arm64` и `x64`;
  - `identity: '-'` (ad-hoc) и `hardenedRuntime: false`;
  - `artifactName: parley-macos-${arch}.${ext}` у dmg и у zip;
  - `publish: github`, `owner: Kalmbik61`, `repo: Parley`, `releaseType: draft`;
  - иконка берётся из `build/` сама.

  Записи `extraResources` с NOTICE и OFL не трогать: их проверяет `src/notice.test.ts`.
  Локальная сборка `pnpm --filter @parley/desktop dist` должна работать как раньше.
- **V3. Встроенный Node 22.**
  - Скрипт `packages/desktop/scripts/fetch-node.mjs` скачивает
    `node-v<версия>-darwin-<arch>.tar.gz` с nodejs.org/dist.
    - Версия — последняя 22.x на момент работы, закреплена константой.
    - Сверяет `SHASUMS256.txt`.
    - Распаковывает только `bin/node` в `packages/desktop/build/node/darwin-<arch>/bin/node`.
      Каталог скрыт от git.
  - `extraResources` кладёт его в `Contents/Resources/node/bin/node` своей архитектуры.
  - Хост, его MCP, statusLine и notify Codex запускаются этим node, если окно собрано и файл
    есть. Иначе — как сейчас, node из PATH login-shell (режим разработки).
  - Пути в командах хуков и statusLine — в кавычках: приложение могут положить в каталог с
    пробелом.
  - `node-pty` 1.1.0 — N-API, prebuilds darwin-arm64 и darwin-x64 есть, пересборка не нужна.
- **V4. CI** (`.github/workflows/ci.yml`).
  - Запуск — на pull_request и push в master, `macos-15`.
  - Шаги:
    1. `pnpm install --frozen-lockfile`;
    2. `pnpm build`, `pnpm typecheck`, `pnpm lint`;
    3. юнит-тесты всех пакетов с `--retry=1`: известные флейки хоста не блокируют.
  - E2E в CI пока не гонять — пункт в TODOS.
- **V5. Релиз** (`.github/workflows/release.yml`). Запуск — на `push: tags: ['v*']` и
  `workflow_dispatch`; у ручного запуска вход `dry_run`, по умолчанию true: только собрать
  и выложить артефакты в Actions.
  - Права — `permissions: contents: write`.
  - Задача **`create-release`**:
    - тег равен версии `packages/desktop/package.json`, иначе — ошибка;
    - `gh release create <тег> --draft --title "Parley <версия>"`, заметки — из
      `CHANGELOG.md` для этой версии;
    - `--prerelease`, если в теге есть «-».
  - Задача **`build-mac`** на `macos-15`:
    - pnpm, Node 22, кэш electron и electron-builder по `pnpm-lock`;
    - установка с повтором;
    - `pnpm build`, затем `fetch-node` для arm64 и x64;
    - `pnpm --filter @parley/desktop exec electron-builder --mac --arm64 --x64 --publish always`;
    - `SHA256SUMS.txt` по всем dmg и zip, выложить его в релиз.
  - Задача **`publish-release`**:
    - проверить, что релиз — черновик и в нём все файлы: 2 dmg, 2 zip, `latest-mac.yml`,
      `SHA256SUMS.txt`;
    - `gh release edit --draft=false`.
  - Гейты можно взять у Orca (`assert-github-release-is-draft.mjs`,
    `verify-release-required-assets.mjs`, MIT): упростить, с шапкой-атрибуцией и абзацем в
    NOTICE.
  - Имя тега никогда не подставлять в shell напрямую: только через `env`.
- **V6. Уведомление о новой версии.** Без подписи Apple автообновления на macOS нет.
  - Главный процесс при старте и раз в 24 часа зовёт
    `GET https://api.github.com/repos/Kalmbik61/Parley/releases/latest`.
    - Без токенов, таймаут 10 с, черновики и prerelease не берёт.
    - Сравнивает semver с `app.getVersion()`.
    - Ошибка сети молчит.
  - Новее — окно показывает тост «Parley X.Y.Z is available» с кнопками «Download» и «Later».
    - «Download» открывает `html_url` релиза в браузере через `shell.openExternal`.
    - Закрытую версию окно помнит в `ui.json`.
  - Настройки: переключатель «Check for updates», по умолчанию включён, в разделе «General»
    или близком.
  - `PARLEY_UPDATE_CHECK=off` выключает проверку в тестах и E2E. E2E-конфиг задаёт его всегда.
  - Тексты — в `shared/strings.ts`, по-английски.
  - Юнит-тесты: сравнение версий, разбор ответа, ошибки сети, запомненная версия,
    переключатель.
- **V7. Документы.**
  - README по-английски: раздел «Install».
    - Скачать `.dmg` из Releases, перетащить в Applications.
    - Первый запуск неподписанного приложения: System Settings → Privacy & Security →
      «Open Anyway» или `xattr -dr com.apple.quarantine /Applications/Parley.app`.
    - Требования: macOS на Apple Silicon или Intel; установленные и залогиненные `claude`
      и/или `codex`; git. Node не нужен.
    - Обновления: окно сообщает о новой версии.
    - «Build from source» — как сейчас.
  - `CHANGELOG.md` по-английски, раздел `0.1.0` с главным: окно, сессии, комнаты и решения,
    Claude Code и Codex, строка статуса.
  - TODOS (по-русски):
    - Linux — Ctrl+Shift и заголовок окна;
    - Windows — спайки;
    - подпись и нотаризация Apple, потом автообновления electron-updater и Homebrew cask;
    - E2E в CI.

## Шаги

Каждый шаг — отдельный агент, по очереди. Каждый заканчивается зелёными проверками и одним
коммитом.

- **P1. Версия, лицензия, упаковка, встроенный Node** — V1, V2, V3.
  - Проверки:
    - сборка, typecheck, lint, юнит-тесты затронутых пакетов;
    - `fetch-node` для arm64 и x64;
    - локальная сборка `electron-builder --mac --arm64 --x64` в `dist/`, без публикации:
      `--publish never`.
  - Что проверить у собранного:
    - есть 2 dmg и 2 zip;
    - в `Info.plist` — `CFBundleIdentifier dev.parley.desktop` и `CFBundleShortVersionString
      0.1.0`;
    - `codesign --verify --deep --strict` проходит;
    - `Contents/Resources/node/bin/node --version` — v22, `lipo -archs` нужной архитектуры;
    - упакованный хост встроенным node стартует с временным `PARLEY_HOME`, создаёт сокет и
      гасится;
    - `require('node-pty')` из `Resources/host` встроенным node работает.
- **P2. CI и релиз** — V4 и V5.
  - Проверки: YAML разбирается (node + пакет `yaml`, если есть в дереве); логика задач
    вычитана; шаги CI повторены локально.
- **P3. Уведомление о новой версии** — V6.
  - Проверки: сборка, typecheck, lint, юнит-тесты окна, затронутые E2E.
- **P4. Документы** — V7. Идёт после того, как английский README из `feat/parley-rename`
  влит в эту ветку.
- **V. Проверка целиком.**
  - Все юнит-тесты, сборки, все E2E (`--workers=1`) через замок.
  - Повторить локальную сборку из P1 на итоговом дереве.
- **R. Ревью.** Одна состязательная линза:
  - безопасность workflow: инъекция тега, права токена, `pull_request_target` не использовать;
  - пропавший файл в релизе;
  - запуск без встроенного node;
  - пути с пробелами;
  - приватность проверки обновлений;
  - смена appId.
- **F. Правки по ревью.**

## Рамка

- Настоящие `claude` и `codex` не запускать.
- Не писать в настоящие `~/.harnas`, `~/.parley`, `~/harnas/worktrees`, `~/.claude`,
  `~/.codex`, `~/.agents`, `~/Library/Application Support/*`. Собранное приложение не
  запускать на настоящем профиле: только `PARLEY_HOME` во временном каталоге.
- Сеть: nodejs.org (Node), npm, GitHub raw (файлы Orca). Никаких push и тегов — их делает
  контролёр с согласия человека.
- Без `git stash`. В индекс — явные пути или `git add -u` плюс новые файлы по списку.
- Каждый шаг — один коммит на русском, в стиле репозитория, последняя строка
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- README и CHANGELOG — только по-английски, без упоминаний harnas. Спеки и TODOS — по-русски.

## Отступления после ревью (шаг F)

Ревью и проверка дали правки, которые меняют решения выше. Действует то, что здесь, а не прежний текст
разделов V3, V5, V6 и V7.

- **V3.** `fetch-node` достаёт из архива не один `bin/node`, а ещё и `LICENSE`: он ложится в
  `build/node/darwin-<arch>/LICENSE` и едет в `Contents/Resources/node/LICENSE`. Бинарь Node в dmg и
  zip раздаётся вместе с текстом лицензии (MIT Node.js, V8, OpenSSL, ICU); `verify-packaged-apps.sh`
  его требует, раздел Node.js в `NOTICE` на него ссылается. Кэш без суммы лицензии считается
  устаревшим.
- **V5.**
  - electron-builder идёт всегда с `--publish never` и токена не получает. Файлы в черновик
    (dmg, zip, blockmap, `latest-mac.yml`, `SHA256SUMS.txt`) кладёт отдельный шаг
    `gh release upload` — после сборки, `verify-packaged-apps.sh` и `SHA256SUMS.txt`, и только он
    берёт `GH_TOKEN`. Вместо `--publish always` из V5;
  - права по умолчанию — `contents: read`, запись просят задачи `create-release`, `build-mac` и
    `publish-release`. В пробном прогоне у `build-mac` право записи остаётся: GitHub не даёт задать
    права задачи по условию;
  - `create-release` забирает всю историю (`fetch-depth: 0`) и проверяет, что коммит тега лежит в
    истории master (`git merge-base --is-ancestor HEAD origin/master`);
  - чужие действия закреплены полным SHA коммита, версия — в комментарии; список — в
    `release-workflows.test.ts`;
  - `verify-packaged-apps.sh` проверяет архитектуру `pty.node` и `spawn-helper` по `lipo`, отсутствие
    `build/Release` и `build/Debug` у node-pty и, если на раннере есть Rosetta, запускает встроенный
    node x64 через `arch -x86_64`.
- **V6.**
  - проверка идёт только у собранного окна (`app.isPackaged`); `pnpm dev:desktop` в сеть не ходит;
  - «Later» только закрывает тост и в `ui.json` ничего не пишет; версию закрывают «Download» и
    смахивание тоста;
  - включённый переключатель проверяет сразу (`settingsChanged` после `app:save-ui`), выключенный
    снимает стоящий тост.
- **V7.** README: GitHub видит IP-адрес; `PARLEY_UPDATE_CHECK=off` не виден, если оболочка не
  ответила за срок; после замены приложения — «Restart host…» и без баннера; шаги первого запуска
  повторяются при каждом обновлении; Intel-сборка не проверена на Intel-маке. То же — в CHANGELOG,
  «Known limitations».
