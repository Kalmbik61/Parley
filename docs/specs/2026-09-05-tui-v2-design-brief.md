# Промпт для агента-дизайнера: макеты TUI v2 (сайдбар + одна панель)

Скопировать целиком в сессию дизайнера. Дизайн только для терминала.

---

Ты проектируешь интерфейс терминального приложения. Никакого кода, никакого веба:
результат — текстовые макеты и правила, по которым потом будет писаться Ink-приложение.

## Что за продукт

`my-harnas` — терминальный харнесс поверх Claude Code. В нём живут «работы»
(единица координации в проекте) и их сессии: настоящий `claude` в панели, сессии
знают друг о друге через общую карту и MCP. Прочитай перед началом, целиком и в
этом порядке:

1. `docs/specs/2026-09-05-tui-v2-design.md` — **спецификация того, что ты рисуешь**.
   Она прошла инженерное ревью, решения в ней окончательные: одна панель, сайдбар без
   рамок, префиксный ввод `ctrl+q`, четыре рантайм-состояния сессии с цветами.
2. `docs/specs/2026-09-02-coordination-tui-design.md` — прежний дизайн. Из него
   действуют разделы 4.3–4.5 (диалоги запуска, возобновления, дозаказа), 5 (строка
   статуса), 6.1–6.6 (глифы, цвета, усечение, сортировка, виртуализация). Раскладку и
   клавиши оттуда не брать.
3. `docs/specs/2026-09-02-coordination-design.md` — что такое работа, сессия, карта,
   сообщения, артефакты.
4. `README.md` — что есть сейчас, чтобы понимать, от чего уходим.
5. `TODOS.md` — что отложено; этого в макетах быть не должно.

Образец стиля — herdr (https://github.com/herdrdev/herdr, скриншот в README):
узкий сайдбар без рамок, номера у рабочих пространств, `new` строкой, секция
агентов с глифом и словом состояния справа, главная область целиком под агента,
тонкие разделители, ничего лишнего. Копировать не нужно, нужно то же ощущение:
тихий интерфейс, где внимание привлекает только цветная точка.

## Что нужно спроектировать

1. **Сайдбар** (спецификация 2.1) в трёх состояниях ширины: 26 колонок, 18 колонок
   (терминал 80), скрыт (терминал уже 60, доступен как оверлей по `prefix b`).
   Верх: работы с номерами, проектом и веткой, точкой состояния; строка `new`.
   Низ: дерево сессий выбранной работы, слово состояния справа, компактная строка
   под выбранной сессией (токены, длительность, `▤N`, `⋮N`). Подсветка выбранной
   строки фоном. Работы `done` свёрнуты в одну строку.
2. **Точка состояния** (спецификация 4.1): `working` серый мигающий (показать обе
   фазы), `blocked` жёлтый, `unseen` синий, `idle` тусклый, плюс `pending` `◌`,
   `exited` `○`, `done` `✓`, `failed` красный `✗`. Точка работы как максимум по её
   сессиям. Монохромный вариант: чем различаются состояния без цвета.
3. **Панель** (2.2): пустая панель без сессии; карточка незапущенной сессии
   (`pending` с брифом, `exited` с кодом выхода, `done` с резюме) и карточка
   «запущена вне харнесса». Сама панель Claude — просто область, ничего поверх.
4. **Строка статуса** (2.3): обычное состояние, событие `⚑`, ожидание второй
   клавиши префикса со списком действий, предупреждение о битом конфиге.
5. **Оверлеи** (2.4), каждый на 120×40 и на 80×24: детали сессии со всеми секциями,
   пикер работ с фильтром, пикер истории с фильтром, справка по привязкам с первой
   строкой «как сменить префикс», подтверждение закрытия сессии, диалог запуска
   `pending` (поверх прежнего 4.3, но как оверлей), диалог возобновления,
   подтверждение выхода при живых сессиях.
6. **Режим навигации по сайдбару** (`prefix s`): как видно, что фокус в сайдбаре,
   а не в панели.
7. **Состояния**: нет работ вообще; работа без сессий; работа с 20+ сессиями и
   дочерними в 2 уровня; сессия без метрик; очень длинные заголовки и ярлыки;
   сессия, запущенная вне харнесса; `⋮N` субагентов у работающей сессии.

## Ограничения

- Stock Ink 5 + React 18, без кастомного рендерера. Перерисовка по событиям; единственный
  таймер — мигание точки `working`.
- Обязательные размеры: **80×24** и **120×40**. На 80×24 сайдбар 18 колонок.
- Цвета: 16 ANSI плюс dim/bold. Всё должно читаться без цвета и без Unicode
  (ASCII-запасной для каждого глифа, таблицу 6.1 прежнего дизайна дополнить новыми).
- Панель принадлежит агенту: никаких оверлеев и подписей поверх живого Claude, кроме
  оверлеев из раздела 2.4, которые пользователь открыл сам.
- Один провайдер, Claude: никаких бейджей `Cl/Cx/GL` и фильтров по провайдеру.
- Русский язык интерфейса, короткие подписи. Слова состояний (`working`, `blocked`,
  `unseen`, `idle`) остаются английскими, как в спецификации, но предложи русские
  варианты отдельно, если считаешь, что они читаются лучше.
- Не изобретай механики сверх спецификации. Чего нет — отметь вопросом, а не дорисуй.
  Сплиты, мышь в макетах и detach не рисовать.
