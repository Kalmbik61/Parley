# TUI v2: макеты (сайдбар и одна панель)

Дата: 2026-09-05. Основание: `2026-09-05-tui-v2-design.md` (спецификация),
`2026-09-02-coordination-tui-design.md` (действуют 4.3–4.5, 5, 6.1–6.6),
`2026-09-02-coordination-design.md`, README, TODOS. Кода нет — только макеты
и правила. Провайдер один (Claude): бейджей и строки «провайдер модель» нет.

## 0. Легенда макетов

- Рамок у раскладки нет. Правый край экрана не рисуется; между сайдбаром и
  панелью — тонкий `│` (dim). Рамки есть только у оверлеев.
- `▌` в первой колонке — условное обозначение фона выбранной строки
  (bright black на всю ширину строки; в монохроме reverse video).
  Реального глифа в интерфейсе нет.
- Подписи в скобках внутри панели — аннотации макета, не текст интерфейса.
- Точка working мигает; в макетах показана фаза A (`●`). Обе фазы — §1.4.
- Пустые строки экранов включены: высота макетов честная (24 и 40 строк).

Легенда:

- `1 Авторизация ●` — работа: номер (1..9, дальше без номера), заголовок,

- `new` — одна строка на сайдбар; Enter/клик — новая сессия Claude (5.1).
- `сессии · Авторизация` — заголовок нижней части: дерево сессий выбранной
  работы, порядок стабильный (по `createdAt`), строки не скачут.
- `● план  working` — строка сессии: глиф состояния, ярлык, справа слово
  состояния. Под **выбранной** — компактная строка: `↑вход ↓выход · длительность
  · ▤N непрочитанных · ⋮N живых субагентов` (пустые части опущены).
- `└ ● ревью` — дочерняя сессия (порождена «бэкенд»), отступ + `└`.
- Строка статуса — §3. Событие гаснет при подключении к сессии-источнику.

### 1.3 Сайдбар скрыт

Терминал уже 60 колонок — сайдбар прячется сам; на любой ширине его прячет
`prefix b`. Панель занимает всё, строка статуса остаётся:

```text

        (панель Claude Code)
```

```text
│▌  ~/dev/shop · main      │    она не перерисовывается)
```

### 1.4 Точки состояния

Обе фазы мигания working (чередование раз в секунду, единственный таймер UI;
цвет обеих фаз bright black):

```text
фаза A (0–500 мс)                фаза B (500–1000 мс)
 ● план           working         ○ план           working
```

Все состояния в строке сессии (Unicode / ASCII):

```text
 ● план           working        * план           working   ← bright black, мигает
 ● бэкенд         blocked        * бэкенд         blocked   ← yellow
 ● ревью           unseen        * ревью           unseen   ← blue
 ● доки              idle        * доки              idle   ← dim
 ◌ тесты          pending        . тесты          pending   ← dim
 ○ сборка          exited        ! сборка          exited   ← dim
 ✓ план              done        + план              done   ← без цвета
 ✗ миграции        failed        x миграции        failed   ← red
```

Монохром (`NO_COLOR` / 16-цветный терминал без ярких):

- жизненный цикл различим формой глифа: `◌ ○ ✓ ✗`;
- четыре activity-состояния — все `●` — различаются **словом справа**
  (на ширине 18 — буквой w/b/u/i);
- working дополнительно различим **миганием** `●↔○`; статичный `○` exited
  от мигающего отличается и словом, и неподвижностью;
- выбранная строка — reverse video вместо серого фона.

Вариант А для ширины 18 (рассмотрен): совсем убрать правую колонку — состояние
несёт только точка. Отклоняю: в монохроме blocked/unseen/idle становятся
неразличимы. **Рекомендую вариант Б (буквы)** — они же работают как ASCII-запас.
Спецификация (раздел 7) говорит «слово заменяется одним глифом», не называя
глиф, — вопрос №2.

### 1.5 Режим навигации по сайдбару (prefix s)

Пока фокус в сайдбаре, ввод не идёт гостю. Два признака одновременно:

1. разделитель `│` становится cyan (в монохроме bold);
2. строка статуса показывает режим (левая часть вместо события).

```text
▌1 Авторизация          ● ┃
▌  ~/dev/shop · main      ┃   (панель живёт, но ввод ей не идёт;
 2 Платежи              ● ┃    жирный/цветной разделитель — фокус в сайдбаре)
 …                        ┃
 сайдбар · ↑↓/jk — по строкам · Enter — подключить · Esc — в панель
```

`┃` в макете — тот же `│`, показанный жирным. Поверх панели ничего не
рисуется. Рассматривал вариант «мигающий курсорный маркер у выбранной строки» —
отклонил: второй мигающий элемент нарушает правило одного таймера.

## 2. Панель без живого агента (карточки)

Единственный случай, когда панель рисует харнесс. Карточка — блок с отступом
слева 3, вертикально в верхней трети панели. Ширина строк ≤ панель−6.
Макеты — панель 61 (80×24); на 93 то же, строки длиннее не становятся.

Нет сессии (пустая панель):

```text

   сессий нет
   ctrl+q c — новая сессия · ctrl+q g — возобновить из истории

```

`◌` pending (создана агентом, ждёт запуска):

```text

   ◌ тесты · pending
   создана сессией «бэкенд»
   бриф: .harnas/works/w-0042/briefs/s-04.md

   Enter — запустить (покажет бриф)

```

`○` exited:

```text

   ○ бэкенд · exited 14:02 · код 0
   отчёта не было · резюме: нет
   ctrl+q R — дозаказать авто-резюме

   Enter — возобновить

```

`✓` done (для `✗` failed — то же с глифом и словом failed):

```text

   ✓ план · done 12:40
   «План готов: 5 шагов, миграции отдельно.»
   арт: plan: …works/w-0042/artifacts/plan.md

   Enter — возобновить (резюме перезапишет новый report)

```

`●` запущена вне харнесса (launchedBy: cli, pid жив):

```text

   ● бэкенд · working · запущена вне харнесса
   pid 48213 · подключение невозможно: PTY не у харнесса

   ctrl+q i — детали

```

## 3. Строка статуса

Одна строка, вся ширина, вне сетки сайдбара. Справа всегда `ctrl+q ?`
(кроме ожидания префикса). Четыре состояния, ширина 120 и 80:

Обычное (событий нет):

```text
                                                                                                              ctrl+q ?
                                                                       ctrl+q ?
```

Событие `⚑` (yellow bold; гаснет при подключении к сессии-источнику, события
без строки-источника — при следующем нажатии клавиши):

```text
 ⚑ ревью ждёт ответа — не подключена                                                                          ctrl+q ?
 ⚑ ○ бэкенд вышла без отчёта · ctrl+q r — возобновить                  ctrl+q ?
```

Ожидание второй клавиши префикса:

```text
 ctrl+q … c новая · w работы · g история · i детали · s сайдбар · j/k сессии · x закрыть · r возобновить · ? все
 ctrl+q … c новая · w работы · g история · i детали · ? все
```

На 80 список действий усечён справа; `? все` не отбрасывается. Неизвестная
клавиша молча отменяет префикс.

Битый конфиг (разовое предупреждение при старте):

```text
 ⚑ ~/.harnas/config.json не читается — работаю с дефолтами                                                    ctrl+q ?
 ⚑ config.json не читается — дефолты                                   ctrl+q ?
```

## 4. Оверлеи

### 4.0 Раскладка оверлеев

- Рисуются поверх панели; сайдбар остаётся видимым, строка статуса тоже.
  Центр — по области **панели**, пока ширина оверлея + 2 влезает в панель;
  иначе центр по всему терминалу (оверлей ложится и на сайдбар).
- Рамка `┌─┐│└┘` cyan (монохром: bold заголовок в рамке), фон строк оверлея —
  фон терминала. Заголовок — в верхней рамке.
- Ширины: подтверждения 48; пикеры и справка 56; детали 64.
  Максимум всегда `min(своя, терминал − 4)`.
- Высота: `min(контент + 2, строки − 3)` — строка статуса и одна строка панели
  сверху остаются видны. Не влезло — прокрутка `↑↓/jk`, у нижней рамки `… N ниже`.
- На 80×24: детали 59×20 (центр по терминалу — в панель 61 влезают впритык,
  но 59 > 61−2 → по терминалу), пикеры 56×16, подтверждения без изменений.
- Пока оверлей открыт, весь ввод — ему. `Esc` закрывает без изменений.
  Одновременно открыт максимум один оверлей.

### 4.1 Детали сессии — `prefix i`

120×40 (бокс 64, в центре панели):

```text
┌ детали · бэкенд ─────────────────────────────────────────────┐
│ ЗАДАЧА   Реализовать шаги 1–3 плана                          │
│ СОСТ.    ● working · 32м · последнее событие 14с назад       │
│ ТОКЕНЫ   ↑1.2к ↓845 · кэш чт 50к зп 3.0к                     │
│ СВОДКА   progress: «миграции готовы, пишу хендлеры»          │
│ ВХОДЯЩИЕ ▤ план 09:41 «жду миграции, потом гоняй»            │
│          план 09:12 «начинай со схемы»                       │
│ АРТЕФ.   plan: …works/w-0042/artifacts/plan.md               │
│ СУБАГ.   ⋮ explore repo · 4м                                 │
│ ИСТОРИЯ  ◌ 09:12 → ● 09:14                                   │
│ ЦЕЛЬ     Логин по e-mail, сессии, миграции                   │
│                                                              │
│ ↑↓ — прокрутка · Esc — закрыть                               │
└──────────────────────────────────────────────────────────────┘
```

- СОСТ.: activity/статус + длительность + время с последнего события любой оси;
  для exited — `○ exited 14:02 · 52м · код 0` (код текстом, глиф один);
  для «вне харнесса» — пометка после слова состояния.
- СВОДКА: `progress:` — промежуточный отчёт агента; без пометки — report
  done/failed; `авто:` — summarySource=auto; `(отчёта нет)` + для exited
  подсказка `R — дозаказать`; пока считается — `авто-резюме: считается…`.
- ВХОДЯЩИЕ: непрочитанные с `▤` первыми, затем последние 5 прочитанных (dim).
  Исходящие не показываются. Просмотр здесь не гасит `unseen`.
- ЦЕЛЬ: цель работы; если пуста — редактируется здесь же (механика ввода —
  вопрос №8).

### 4.2 Пикер работ — `prefix w`

Все работы глобального индекса, включая другие проекты. Фильтр — простой
набор текста (первая строка, `▌` — курсор ввода). 120×40 (56 шир.):

```text
┌ работы ──────────────────────────────────────────────┐
│ > авт▌                                               │
│──────────────────────────────────────────────────────│
│▌Авторизация        ~/dev/shop · main               ● │
│ Автоплатежи        ~/dev/billing · master          ✓ │
│                                                      │
│ Enter — выбрать · Esc                                │
└──────────────────────────────────────────────────────┘
```

80×24 — та же ширина 56, высота 16, список короче. `Enter` выбирает работу
в сайдбаре (низ сайдбара переключается на её сессии). Работа чужого проекта:
её сессии запускаются с cwd того проекта.

### 4.3 Пикер истории — `prefix g`

Сессии `~/.claude` текущего проекта по свежести: заголовок, возраст,
длительность, токены. 120×40:

```text
┌ история · ~/dev/shop ────────────────────────────────┐
│ > ▌                                                  │
│──────────────────────────────────────────────────────│
│▌исправить flaky-тест auth       2ч · 41м · 12к/3.1к  │
│ рефакторинг session store      1д · 1ч 12м · 45к/8к  │
│ настроить CI кэш               3д · 18м · 6.2к/900   │
│ … 41 ниже                                            │
│ Enter — возобновить в «Авторизация» · Esc            │
└──────────────────────────────────────────────────────┘
```

`Enter` регистрирует сессию в текущей работе и запускает `--resume` (5.3).
На 80×24 — 56×16, колонка токенов отбрасывается первой, возраст последним.

### 4.4 Справка — `prefix ?`

Первая строка — как сменить префикс. Ниже фильтр и все привязки:

```text
┌ привязки · префикс ctrl+q ───────────────────────────┐
│ префикс перехватывает терминал? смените его:         │
│ HARNAS_PREFIX=w или "prefix" в ~/.harnas/config.json │
│──────────────────────────────────────────────────────│
│ > ▌                                                  │
│ c        новая сессия Claude в выбранной работе      │
│ C        дочерняя сессия выбранной, ждёт ваш запрос  │
│ w        пикер работ                                 │
│ g        пикер истории (возобновление)               │
│ i        детали выбранной сессии                     │
│ j / k    следующая / предыдущая сессия               │
│ 1..9     подключиться к сессии по номеру             │
│ s        фокус в сайдбар                             │
│ b        спрятать / показать сайдбар                 │
│ x        закрыть выбранную сессию                    │
│ d        удалить выбранную сессию (с подтверждением) │
│ D        удалить выбранную работу целиком            │
│ r        возобновить выбранную сессию                │
│ R        дозаказать резюме (exited)                  │
│ ?        эта справка                                 │
│ q        выйти из харнесса                           │
│ ctrl+q   отправить ctrl+q агенту                     │
└──────────────────────────────────────────────────────┘
```

На 80×24 — 56×16 с прокруткой (`… 6 ниже` у нижней рамки).

```text
│                                              │
│ Enter — запустить · Esc — позже              │
└──────────────────────────────────────────────┘
```

Тело — первые строки брифа (`▏` — цитата, `↑↓` — прокрутка). Правка — внешним
редактором; при `Enter` файл перечитывается с диска.

Вторая строка — каким будет старт (дизайн 5.2). У сессии без задачи там
`старт: ждёт ваш запрос`: бриф уйдёт в `--append-system-prompt` контекстом, а
первым сообщением агент дождётся запроса пользователя. Ту же строку показывает
карточка `pending` в панели (§2).

### 4.6 Возобновление — Enter на `○`/`✓`/`✗`, prefix r

```text
┌ возобновить ○ бэкенд ────────────────────────┐
│ claude --resume 7fa0e1ee-cc7b…               │
│ вышла 14:02, код 0 · отчёта не было          │
│ резюме: нет — R закажет авто-резюме          │
│                                              │
│ Enter — возобновить · Esc                    │
└──────────────────────────────────────────────┘
```

Для `✓`/`✗`: строка резюме — `резюме: «…» (будет перезаписано)`, переход
`done/failed → active` пишется в историю. Код выхода — текстом, глиф один.

### 4.7 Дозаказ резюме — `prefix R` на exited

```text
┌ резюме для ○ бэкенд ─────────────────────────┐
│ один вызов claude -p по транскрипту          │
│ результат — сводка с пометкой «авто»         │
│                                              │
│ Enter — заказать · Esc                       │
└──────────────────────────────────────────────┘
```

### 4.8 Закрытие сессии — `prefix x`

```text
┌ закрыть ● бэкенд ────────────────────────────┐
│ процессу будет послан SIGHUP · pid 48213     │
│ транскрипт останется в ~/.claude             │
│                                              │
│ Enter — закрыть · Esc                        │
└──────────────────────────────────────────────┘
```

### 4.9 Выход при живых сессиях — `prefix q`

```text
┌ выход ───────────────────────────────────────┐
│ живые сессии: план, бэкенд                   │
│ их процессы будут завершены                  │
│                                              │
│ Enter — выйти · Esc — остаться               │
└──────────────────────────────────────────────┘
```

Формулировка второй строки зависит от судьбы PTY-детей при выходе — вопрос №5.

### 4.10 Удаление сессии — `prefix d`

```text
┌ удалить ○ бэкенд ────────────────────────────┐
│ запись, бриф и журнал событий будут удалены  │
│ транскрипт в ~/.claude останется             │
│ дочерние: ревью, тесты → поднимутся на уровень│
│ Enter — удалить · Esc                        │
└──────────────────────────────────────────────┘
```

Третья строка есть только у сессии с детьми и режется по ширине рамки: они
поднимутся к родителю удалённой (дизайн 5.5). Живой процесс, чей PTY держит
харнесс, закрывается перед удалением: SIGHUP, ожидание до 3 с, затем SIGKILL.

### 4.11 Отказ удалить живую сессию вне харнесса — `prefix d`

```text
┌ удалить ● ревью ─────────────────────────────┐
│ сессия жива, но её процесс не у харнесса     │
│ закройте её там, где она запущена, и повторите│
│ Esc — понятно                                │
└──────────────────────────────────────────────┘
```

Подтверждать нечего: у оверлея только выход. С pid строка о процессе называет
его номером — `сессия жива, но её процесс не у харнесса · pid 48213`.

### 4.12 Удаление работы — `prefix D`

```text
┌ удалить работу w-0002 · Авторизация ─────────┐
│ 3 сессии, карта, брифы, журналы и артефакты  │
│ будут удалены; транскрипты ~/.claude останутся│
│ запись уйдёт из глобального индекса          │
│ Enter — удалить · Esc                        │
└──────────────────────────────────────────────┘
```

Длинный заголовок режется по ширине рамки. Процессы сессий, чьи PTY у
харнесса, закрываются до удаления, как в 4.10.

### 4.13 Отказ удалить работу с живой сессией вне харнесса — `prefix D`

```text
┌ удалить работу w-0002 ───────────────────────┐
│ «ревью» жива, но её процесс не у харнесса    │
│ закройте её там, где она запущена, и повторите│
│ Esc — понятно                                │
└──────────────────────────────────────────────┘
```

## 5. Состояния и границы

Фрагменты сайдбара 26; на 18 действуют правила §7.

Нет работ вообще (верх сайдбара — только `new`, низ пуст):

```text
 работ нет                │
 new — первая сессия      │      панель: карточка «сессий нет» (§2)
──────────────────────────│
                          │
```

Работа есть, сессий нет:

```text
▌1 Платежи                │
▌  ~/dev/shop · feat/pay  │
 new                      │
──────────────────────────│
 сессии · Платежи         │
 сессий нет               │
 ctrl+q c — новая         │
```

(точка состояния у работы без сессий не рисуется — вопрос №6)

20+ сессий, дерево в 2 уровня — окно `visibleWindow`, ряды не рвутся,
заголовок `сессии · <работа>` всегда виден (липкий):

```text
 сессии · Миграция БД     │
 … 9 выше                 │
 ✓ шаг 7             done │
▌● шаг 8          working │
▌  ↑8.1к ↓2.3к · 41м · ⋮2 │
   └ ● проверка    unseen │
     └ ● линт     working │      ← второй уровень: +2 отступа
 ◌ шаг 9          pending │
 … 12 ниже                │
```

Сессия без метрик (лог ещё не привязан) — `—` на месте чисел:

```text
▌● разведка       working │
▌  — · 2м                 │
```

Очень длинные заголовки и ярлыки (минимум ярлыка — 4 знака, слово состояния
не отбрасывается):

```text
 1 Перенос платёжного п…● │
   …рабочие/very-long-mo… │
▌● исследовать вар…   idle│
▌  ↑340 ↓88 · 5м          │
```

Сессия, запущенная вне харнесса, — в дереве как обычная (activity из хуков
и лога работает), панель показывает карточку §2:

```text
 ● бэкенд         blocked │      ← точка и слово живут, attach невозможен
```

`⋮N` субагентов — только в компактной строке выбранной сессии и в деталях
(СУБАГ.); в невыбранных строках счётчик не показывается:

```text
▌● бэкенд         working │
▌  ↑1.2к ↓845 · 32м · ⋮2  │
```

## 6. Глифы и цвета: дополнение к 6.1–6.2 прежнего дизайна

Новые и изменённые строки (остальное — таблица 6.1 без изменений):

| Смысл | Unicode | ASCII | Цвет (16 ANSI) |
|---|---|---|---|
| working, фаза A (0–500 мс) | `●` | `*` | bright black |
| working, фаза B (500–1000 мс) | `○` | `o` | bright black |
| blocked | `●` | `*` | yellow |
| unseen | `●` | `*` | blue |
| idle | `●` | `*` | dim |
| pending | `◌` | `.` | dim (как было) |
| exited | `○` | `!` | dim (**было yellow**) |
| done | `✓` | `+` | без цвета (**было green**) |
| failed | `✗` | `x` | red (как было) |
| точка работы | как у сессии-максимума | — | blocked > working > unseen > остальное |
| буква состояния (ширина 18) | `w b u i` | те же | цвет своего состояния |
| живые субагенты `⋮N` | `⋮` | `:` | dim, счётчик обычный |
| разделитель сайдбар/панель | `│` | `\|` | dim; cyan/bold в режиме навигации |
| горизонтальный разделитель сайдбара | `─` | `-` | dim |
| рамка оверлея | `┌ ─ ┐ │ └ ┘` | `+ - \|` | cyan (монохром: bold заголовок) |
| курсор фильтра в пикере | `▌` | `_` | default |
| строка `>` фильтра | `>` | `>` | cyan |

Удалены из употребления: `◐ idle` (жёлтый полукруг), бейджи `Cl/Cx/GL`,
magenta для провайдеров, рамки панелей и заголовки `SESSIONS/TERMINAL`,
`❯`-стрелка выбора. `▤ ▾ ▸ └ ⚑ ‹› ▏ … ↑↓ ⇄` — без изменений.

Мигание в ASCII-режиме: `*` ↔ `o`. Монохром — §1.4. Цвет никогда не
единственный носитель смысла: activity дублируется словом/буквой, жизненный
цикл — формой глифа.

### Русские слова состояний (предложение, отдельно)

| Английское | Русское | Длина |
|---|---|---|
| working | работает | 8 |
| blocked | ждёт | 4 |
| unseen | новое | 5 |
| idle | тихо | 4 |
| exited | вышла | 5 |
| pending | ждёт запуска | 12 |

Читаются мягче, но: «ждёт» теряет разницу «ждёт разрешения» / «ждёт запуска»,
слова перестают совпадать с терминами спецификации, журналов и тестов, а
`pending` по-русски не влезает в 26. **Рекомендую оставить английские** —
это статусные термины, как в git. Если менять, то все сразу и в деталях тоже.

## 7. Усечение: сайдбар 26 и 18

Минимальная длина ярлыка и заголовка — **4 знака + `…`** (спецификация,
раздел 7). Слово состояния на ширине 26 не отбрасывается никогда.

Строка работы (26): `[N ]заголовок … точка`.
Порядок: усекается только заголовок; номер и точка — никогда.
Вторая строка `проект · ветка`: первой усекается ветка (до 4 + `…`), затем
путь проекта **слева** (важен хвост). На 18 вторая строка отбрасывается целиком.

Строка сессии (26): `[отступ] глиф ярлык … слово`.
Порядок: ярлык до 4 знаков; отступ дерева и глиф не отбрасываются.
На 18: слово → буква (w/b/u/i у живых, ничего у остальных), ярлык до 4.

Компактная строка (26): `↑вход ↓выход · длительность · ▤N · ⋮N`.
Порядок отбрасывания: **токены → длительность**; `▤N` и `⋮N` не отбрасываются
никогда. Кэш-счётчики в сайдбар не выводятся вообще (только детали).
На 18: токены отброшены всегда → `длительность · ▤N · ⋮N`; не влезло —
отбрасывается длительность.
`metrics: null` → `—` на месте токенов и длительности.

Заголовок `сессии · <работа>`: слово «сессии» не усекается, имя работы —
до 4 + `…`.

Заголовок оверлея в рамке: усекается с `…`, рамка не ломается.
Пути артефактов — слева (`…42/artifacts/plan.md`). Числа и время —
существующие `formatDuration` / `formatRelative` и правила 6.3.

## 9. Вопросы к спецификации и принятые решения

Решения приняты 2026-09-05 и внесены в `2026-09-05-tui-v2-design.md`.

| № | Решение |
|---|---|
| 1 | Номера у работ: `prefix 1..9` выбирает работу. Сессии переключаются `j`/`k`, кликом и из режима навигации |
| 2 | Буквы `w/b/u/i` на ширине 18 приняты, они же ASCII-запас |
| 3 | Верх сайдбара — работы текущего проекта; работа чужого проекта, выбранная через пикер, закрепляется в сайдбаре до выхода со второй строкой пути её проекта |
| 4 | Одна строка на каждую `done`-работу |
| 5 | PTY-дети получают SIGHUP при выходе, текст «их процессы будут завершены» верный; транскрипты остаются |
| 6 | У работы без сессий справа пусто |
| 7 | Компактная строка под `pending` не показывается |
| 8 | Цель работы правится в оверлее деталей по `e` однострочным полем, пустая или нет; `Enter` сохраняет, `Esc` отменяет |
| 9 | Оверлей сайдбара закрывается всеми тремя способами: `Enter` с подключением, `Esc`, повторный `prefix b` |
| 10 | Синхронно: один общий тикер в модуле, точки подписываются; тикер живёт только пока есть хотя бы одна `working` |
| 11 | Побеждает последнее по времени; предупреждение о конфиге — обычное событие `⚑` |
| 12 | Карточка `pending` показывает только путь к брифу; сам бриф — в оверлее запуска по `Enter` |

Исходные формулировки вопросов:

1. **`prefix 1..9`**: раздел 2.1 нумерует работы, раздел 3.2 говорит
   «подключиться к *сессии* с этим номером». Кто пронумерован — работы,
   сессии или обе группы (и как тогда выглядят номера сессий в сайдбаре)?
2. **Ширина 18**: каким именно «одним глифом» заменяется слово состояния
   (раздел 7)? В макетах предложены буквы `w/b/u/i` — требует подтверждения.
3. **Верх сайдбара**: работы только текущего проекта или весь глобальный
   индекс? Как показывается работа чужого проекта, выбранная через пикер
   (второй строкой путь её проекта?).
4. **Done-работы**: «свёрнуты в одну строку» — одна строка на каждую работу
   (как в макетах) или одна суммарная строка на все done?
5. **Выход с живыми сессиями**: PTY-дети завершаются вместе с харнессом или
   переживают его? От этого зависит текст подтверждения 4.9.
6. **Работа без сессий**: что справа вместо точки — пусто (как в макетах),
   `—` или `◌`?
7. **Компактная строка под выбранной pending-сессией**: показывать
   (`— · —`) или прятать до запуска?
8. **Цель работы в деталях**: механика редактирования (инлайн-поле в
   оверлее? отдельный промпт?) и можно ли править непустую цель.
9. **Оверлей сайдбара по `prefix b` (<60 колонок)**: закрывается ли после
   Enter-подключения, повторным `prefix b`, Esc — или всеми тремя?
10. **Фаза мигания**: все working-точки мигают синхронно (общий таймер) или
    каждая своим? Синхронность тише; спецификация говорит «таймер живёт в
    activity-dot», что читается как «каждая своим».
11. **Строка статуса**: что побеждает при одновременном событии `⚑` и
    предупреждении о битом конфиге — последнее по времени?
12. **Карточка pending в панели**: показывать ли первые строки брифа прямо
    в карточке, или только путь (2.2 упоминает лишь «последнее резюме»)?
