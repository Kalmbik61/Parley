# Подключение провайдеров в строке статуса и GLM на подписке Z.ai

**Дата:** 2026-10-02. **Статус:** ждёт ревью пользователя.
**Ветка:** `feat/providers-connect` от `master` 661fbeb (Parley 0.3.0).
**Исследование:** отчёт «GLM CLI и вход через Parley» (`.superpowers/reports/`, вне репозитория). В нём ZCode, herdr, GLM через Claude Code и Codex и устройство провайдеров Parley.

## 1. Задача

Пользователь, 2026-10-02:
- «Как в итоге мы будем логиниться в GLM?»
- «Оно должно работать для всех пользователей»; «нужно подключение по подписке».
- «Внизу слева у нас отображается Claude, Codex, GLM. Подключённый — светлым, opacity 1; не подключён — тёмным. При клике открывается механизм подключения этого провайдера или инструкция».

Сейчас:
- Встроенный провайдер `glm` запускает команду `glm`, которой нет ни у кого (`packages/core/src/providers.ts`, README, «Providers»).
- Строка статуса всегда показывает Claude и Codex; если CLI нет, у них стоит «not found». Прочие провайдеры видны, только когда их CLI найден (`StatusBar.tsx`, `CORE_PROVIDERS`).
- Подключить провайдера из окна нельзя. Вход в аккаунты бывает только в терминале агента.

## 2. Решения

1. **GLM — это официальный Claude Code на адресе подписки Z.ai.**
   - GLM-сессия запускает тот же `claude`, что и сессия Claude, но с адресом `https://api.z.ai/api/anthropic`, моделями GLM и ключом Z.ai.
   - Комнаты, MCP-сервер Parley, хуки, гид и навык работают как у Claude.
   - ZCode не берём: официальной сборки его CLI нет, и флагов настроек на запуск у него тоже нет. Без хуков и MCP не было бы комнат.
   - Codex на Z.ai — вне рамок.
2. **Подписка, а не оплата API.**
   - У Z.ai нет входа аккаунтом для сторонних программ: подписка GLM Coding Plan работает по API-ключу. Чем платится запрос, решает адрес.
   - `/api/anthropic` и `/api/coding/paas/v4` расходуют квоту подписки (окна 5 часов и неделя). Общий `/api/paas/v4` — оплата за токены.
   - Parley ходит только на `/api/anthropic`. По FAQ Z.ai, когда квота исчерпана, с баланса ничего не списывается.
   - Есть непроверенное сообщение: без купленной подписки `/api/anthropic` может списывать с баланса. Поэтому карточка прямо пишет «Requires an active GLM Coding Plan».
3. **Ключ вставляет пользователь в карточке GLM.** Parley хранит его в файле `secrets.json` в доме Parley с правами `0600`, а не в связке ключей.
4. **Строка статуса слева всегда показывает Claude, Codex и GLM.**
   - Подключённый провайдер — opacity 1, неподключённый — приглушён.
   - Клик открывает карточку провайдера: подключение (GLM) или инструкцию (Claude, Codex).
   - Свои провайдеры из `providers.json` — как сейчас: только найденные.
5. **Папка `~/.claude` общая** с обычными сессиями Claude, как в официальной инструкции Z.ai. Плагины, навыки и общий CLAUDE.md пользователя работают и в GLM-сессиях.
6. **Правило README сужается** (раздел 7).

## 3. Что видит человек

### 3.1 Строка статуса

- **Состав.** Слева всегда сегменты Claude, Codex и GLM, в этом порядке; за ними найденные свои провайдеры.
- **Подключённый сегмент** выглядит как сейчас: значок, имя, версия CLI, полоска лимитов.
- **Неподключённый сегмент** — только значок и имя, приглушённые (`opacity` около 0,4; значение подбирается по контрасту в обеих темах). Текста «not found» больше нет.
- **Сегмент — кнопка.** Подсказка `title` и имя кнопки для экранных чтецов: «Claude Code — connected», «GLM — not connected. Click to connect».
- **Клик** открывает карточку провайдера — поповер над сегментом (`renderer/ui/popover.tsx`), и у подключённого, и у неподключённого.
- **У GLM** версия — версия `claude` (это он и есть). Лимитов нет (4.5).

«Подключён» значит, что Parley может запустить провайдера прямо сейчас:
- **Claude Code и Codex** — CLI найден в `PATH` хоста или через `PARLEY_<CMD>_BIN`. Вошёл ли человек в аккаунт, Parley не знает и не узнаёт: их учётные данные не читаются.
- **GLM** — найден `claude` **и** сохранён ключ Z.ai.

### 3.2 Карточка провайдера

Заголовок: значок, имя, состояние («Connected» или «Not connected») и версия.

**Claude Code или Codex, не подключён** — инструкция:
- команда установки из официальной документации с кнопкой «Copy» и ссылкой на страницу установки; команды сверяются с документацией в момент реализации;
- «Sign-in happens in the agent's terminal on the first session — Parley does not sign you in.»;
- «Installed it into a new folder? Quit Parley (⌘Q) and open it again: the app reads PATH once at launch.»;
- кнопка «Check again» — новый `providers.list`.

Parley ничего не ставит и не скачивает.

**Claude Code или Codex, подключён:**
- версия;
- лимиты, если есть;
- строка о том, что аккаунт меняет сам CLI: `/login` в сессии Claude Code, `codex login` в терминале для Codex.

**GLM:**
- **Описание.** «GLM models in Claude Code, on your GLM Coding Plan (Z.ai).» и «Requires an active GLM Coding Plan.»
- **Нет `claude`.** Сначала показывается блок установки Claude Code (как выше), поле ключа недоступно.
- **Ключа нет.** Поле пароля «Z.ai API key», кнопка «Save» и ссылка «Get a key» на `https://z.ai/manage-apikey/apikey-list`. Ссылка открывается в системном браузере через `openExternal`.
- **Ключ есть.** «Key ••••a1b2», кнопки «Replace» и «Remove».
- **Предупреждение.** «Don't run /logout in a GLM session: it signs Claude Code out of your claude.ai account everywhere.»
- **Ошибки сохранения** выводятся текстом под полем: пустой или слишком длинный ключ, хост без нужного метода.

Окно не проверяет ключ, потому что не ходит в сеть. Ошибка Z.ai появится в терминале GLM-сессии: 401 «Authentication Failed», 1113 или 1309 «subscription expired».

### 3.3 Диалог новой сессии

- **Пилюля неподключённого провайдера** выглядит недоступной, но клик по ней открывает карточку провайдера, а не выбирает его. Так GLM подключается прямо из диалога.
- **У GLM** можно выбрать модель и усилие:
  - «GLM-5.3» (`glm-5.3[1m]`);
  - «GLM-5.3 Flash» (`glm-5.3-flash[1m]`, понимает картинки);
  - усилие — как у Claude.

## 4. GLM-сессия

### 4.1 Запись реестра

Встроенная запись `glm` в `providers.ts` меняется:
- `command: 'claude'`. `args` и `resumeArgs` — как у Claude, но без пары `--dangerously-load-development-channels {channel}`: каналу нужен вход Anthropic.
- `linkBy: 'session-id'`, `mcpConfig: 'json-file'`, `models: GLM_MODELS` (`provider-models.ts`).
- Новые поля `RunnerConfig`. Они есть только у встроенных записей и из `providers.json` не читаются:
  - `settingsEnv` — несекретные переменные и модель для файла `--settings` (4.2);
  - `secret: 'zai'` — какой ключ хост кладёт в окружение процесса (4.3).
- Новое поле `ProviderEntry.transcript: 'claude'` у `claude` и `glm`. По нему, а не по литералу `'claude'`, работают:
  - проверка транскрипта перед `--resume` (`launch.ts`);
  - метрики (`metrics.ts`);
  - резюме (`summary.ts`).

### 4.2 Файл настроек GLM

`--settings` получает не общий `settings.json` работы, а `settings-glm.json` рядом с ним. В нём те же `hooks` и `statusLine` и вдобавок:

```json
{
  "model": "glm-5.3[1m]",
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.z.ai/api/anthropic",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.3[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.3[1m]",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-5.3-flash[1m]",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
    "API_TIMEOUT_MS": "3000000",
    "CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT": "0"
  }
}
```

- **Откуда значения.** Со страницы Z.ai для Claude Code (`docs.z.ai/devpack/tool/claude`, сверено 2026-10-02). Исключение — последняя переменная: с Claude Code 2.1.154 не-Claude модели получают урезанный системный промпт, а `0` возвращает полный, как у обычных сессий (anthropics/claude-code#63291).
- **Приоритет.** `--settings` стоит выше пользовательских настроек. Поэтому `model` и `env` пользователя, например `model: "opus"` или чужой `ANTHROPIC_BASE_URL`, GLM-сессию не уводят.
- **Ключа в файле нет:** файл лежит в проекте открытым текстом.

### 4.3 Ключ в окружении

- **Когда ключ попадает в процесс.** При каждом запуске GLM-сессии (новой и через `resume`) хост читает ключ и кладёт `ANTHROPIC_AUTH_TOKEN` в окружение процесса поверх `agentEnv` и `plan.env` (`sessions-service.ts`).
- **Куда ключ не попадает.** В `LaunchPlan` и `LaunchPlan.env`, карту, бриф, конфиг MCP, `settings-glm.json`, журналы хоста и уведомления.
- **Нет ключа — GLM-сессия не запускается.**
  - `sessions.create` и подъём спящей сессии отвечают ошибкой «GLM is not connected: add a Z.ai key (status bar → GLM)». Записи в карте не появляется, как при ненайденном CLI.
  - Почему так строго: адрес Z.ai без ключа оставил бы активным вход claude.ai, и его токен ушёл бы на Z.ai.
- **Только официальному `claude`.** Ключ получает только процесс, чья команда — `claude` (с учётом `PARLEY_CLAUDE_BIN`). Запись `glm` в `providers.json` с другой командой ключа не получает.
- **CLI отказывает.** `parley-core work session new --provider glm` не работает: план, напечатанный без ключа и запущенный руками, ушёл бы на Z.ai со входом claude.ai.
- **Агенты.** `spawn_session` с `provider: 'glm'` проходит ту же проверку.

### 4.4 Что общего с Claude

- **Транскрипт** лежит в `~/.claude/projects/…/<uuid>.jsonl`, как у Claude. Возобновление проверяет его так же (4.1), метрики и резюме читают его тем же адаптером.
- **Состояние** берётся из хуков (`activity-service`, ветка не-Codex). Ввод и будильник работают как у Claude.
- **Страховка активности.** Индекс логов хоста (`log-index.ts`) ищет лог по `providerSessionId`, не глядя на провайдера. Поэтому страховка активности по логу работает для GLM без правок.
- **История.** Окно не показывает список сессий из истории Claude (`providersWithHistory` в окне не используется), поэтому GLM и Claude в истории не смешиваются.

### 4.5 Чего у GLM-сессий нет

- **Лимитов в строке статуса.** `rate_limits` в строке состояния бывают только у подписок claude.ai. Квоту Z.ai Parley не запрашивает: окно и хост в сеть не ходят.
- **Канала** (`--dangerously-load-development-channels`).
- **Картинок у GLM-5.3:** модель только текстовая. Для скриншотов из окна нужна GLM-5.3 Flash.
- **Параллельности сверх тарифа.** Z.ai советует Lite на один проект, поэтому несколько GLM-агентов в комнате могут получать 429.

## 5. Хранение ключа

- **Формат.** Файл `secrets.json` в доме Parley (`parleyHome()`, учитывает `PARLEY_HOME`): `{ "zai": { "key": "…" } }`.
- **Права и запись.**
  - Права файла — `0600`. Права каталога не трогаем: хватает прав самого файла.
  - Запись атомарная: временный файл с `0600`, затем `rename`.
  - Удаление ключа убирает поле; если файл остался пустым, он удаляется.
- **Кто читает.** Читает и пишет только модуль хранилища в core (`packages/core/src/secrets.ts`); хост работает через его API.
- **Что видит окно.** Хост отдаёт окну только `keyHint`: «••••» и четыре последних знака.
- **Проверка ключа.** Пробелы по краям обрезаются. Пустой ключ, ключ длиннее 512 знаков или с пробелами и управляющими символами внутри получает отказ `bad_request`.
- **Шифрование — позже**, вместе с подписью Apple. Без неё `safeStorage` Electron просил бы доступ к связке после каждого обновления (ad-hoc подпись меняется), а хост без окна не смог бы расшифровать ключ.

## 6. Протокол и хост

Изменения — только добавления, версия протокола остаётся 1.
- **`providers.list`.** У элемента появляются необязательные поля:
  - `needs?: 'cli' | 'key' | null` — чего не хватает для запуска (`null` — подключён);
  - `keyHint?: string | null` — у провайдеров с ключом.

  `available` для GLM истинно, когда `claude` найден и ключ есть.
- **Новые методы.** `providers.setKey { provider: string, key: string } → { keyHint: string }` и `providers.clearKey { provider: string } → { ok: true }`.
- **Событие `providers.changed`** (`events.ts`) приходит после `setKey` и `clearKey`. По нему окна перечитывают `providers.list` — окон может быть несколько.
- **Журнал хоста.** Параметры запросов хост не журналирует (проверено поиском по `packages/host/src`). Тест закрепляет, что ключ не попадает в журнал.
- **Старый хост.** Окно знает новые методы. Если у хоста их нет (сборка старее), карточка GLM показывает «Restart host» вместо поля (`capabilities.ts`).

## 7. Правила проекта

README, раздел «Legal boundary» — новая формулировка (по-английски):

> Parley never reads, stores or injects the credentials of Claude Code or Codex. The one secret it keeps is a Z.ai API key that you paste in yourself to use GLM: it is stored only on this Mac (`~/.parley/secrets.json`, readable only by you) and is passed only to GLM sessions, which run the official `claude` against Z.ai's GLM Coding Plan endpoint.

Остальное в «Legal boundary» не меняется:
- Parley не входит за вас;
- не пишет в `~/.claude`, `~/.claude.json`, `~/.codex` и `~/.agents`;
- передаёт хуки только через `--settings`;
- не делает скрытых запусков и автоответов и не использует YOLO-флаги.

Что ещё меняется в README:
- таблица «Providers» — строка GLM;
- абзац о строке статуса — вместо «not found»;
- новый раздел «GLM (Z.ai)»: подписка, ключ, модели, что не работает, `/logout`.

Страж `packages/core/test/frame-scan.ts`:
- `api.z.ai` встречается только в записи `glm` реестра и в тестах;
- `secrets.json` — только в модуле хранилища;
- `ANTHROPIC_AUTH_TOKEN` — только там, где хост собирает окружение процесса.

## 8. Тесты

- **core:**
  - запись `glm`: команда, шаблоны без канала, модели, `transcript`;
  - `settings-glm.json`: `env`, `model`, те же хуки, ключа нет;
  - хранилище: права `0600`, атомарность, подсказка, отказы на плохой ключ, удаление;
  - план запуска GLM — без ключа внутри;
  - отказ CLI `work session new --provider glm`;
  - проверка транскрипта и метрики для `glm`.
- **host:**
  - `providers.list`: `available`, `needs` и `keyHint` во всех сочетаниях — нет `claude`, нет ключа, всё есть;
  - `setKey`, `clearKey` и событие;
  - `sessions.create` для GLM без ключа — ошибка, записи в карте нет;
  - окружение процесса GLM содержит `ANTHROPIC_AUTH_TOKEN`, у Claude и Codex его нет;
  - ключ не попадает в журнал.
- **desktop:**
  - строка статуса: три сегмента всегда, неподключённые приглушены, клик открывает карточку;
  - варианты карточки;
  - поле ключа: маска, очистка после сохранения, ошибки;
  - пилюля диалога открывает карточку.
- **E2E.** Временный дом и заглушка `claude` через `PARLEY_CLAUDE_BIN`; заглушка печатает только имена переменных и аргументы. Сценарий:
  - GLM приглушён;
  - пользователь вводит ключ в карточке, GLM становится ярким;
  - GLM-сессия запускается с `settings-glm.json` и с `ANTHROPIC_AUTH_TOKEN` в окружении; значение ключа в вывод не попадает.
- **Без настоящих сервисов.** Настоящие `claude` и Z.ai в тестах не участвуют.

## 9. Живая проверка

Делает человек, на собранной ветке. Перед ней нужно убрать стенд автора: запись `glm` в `~/.parley/providers.json` (она перекрыла бы встроенную) и `~/.local/bin/claude-glm`.

Что проверить:
1. GLM-сессия стартует без вопросов, которые держат её до ответа человека. Предупреждение о двух способах входа — только текстом.
2. `/status` показывает `Anthropic base URL: https://api.z.ai/api/anthropic` и `Auth token`; модель — GLM-5.3.
3. Инструменты Parley работают через Z.ai: `get_map`, сообщение в комнату, `read_room`. Схемы без `pattern` и без свойств `$ref` — проверено чтением `mcp/tools.ts`.
4. Хуки доходят: состояние «работает» или «ждёт» в окне меняется.
5. Обычная сессия Claude рядом остаётся на подписке claude.ai, её `/status` без адреса Z.ai.
6. С моделью GLM-5.3 Flash, выбранной в диалоге, картинка из окна доходит до агента.
7. Пользователь, ни разу не запускавший Claude Code: применяется ли `env` из `--settings` до мастера первого запуска. Если нет, `ANTHROPIC_BASE_URL` переезжает в окружение процесса рядом с ключом.

## 10. Вне рамок

- ZCode.
- Codex на Z.ai.
- Китайский адрес `open.bigmodel.cn`.
- Linux и Windows.
- Шифрование ключа.
- Квота Z.ai в строке статуса.
- Проверка ключа запросом к Z.ai.
- Вход в Claude Code и Codex из окна.

## 11. Риски

- **Условия Z.ai.** Квоту подписки можно расходовать только в официально поддерживаемых инструментах. Claude Code в их списке, и Parley запускает его без изменений. Как Z.ai отличает инструмент от «интеграции», неизвестно.
- **Позиция Anthropic.** Anthropic не поддерживает Claude Code на не-Claude моделях, хотя и не запрещает. Поведение может меняться от версии к версии Claude Code, поэтому живую проверку стоит повторять при заметных обновлениях.
- **Ключ видят команды агента.** Ключ из окружения процесса доступен командам, которые агент запускает в Bash. Нужно проверить, есть ли в Claude Code настройка, вычищающая учётные переменные из окружения дочерних процессов. Если есть — включить её в `settings-glm.json`.
- **`/logout`.** Из-за общего `~/.claude` `/logout` в GLM-сессии выходит из claude.ai во всех сессиях. Предупреждение есть в карточке и будет в README.
