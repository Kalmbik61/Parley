## Границы и ручная приёмка

E2E использует изолированные временные HOME/PARLEY_HOME, фиктивный ключ и локальную CLI-заглушку. Это проверяет поведение Parley и интерфейса. Реальные Z.ai API, подписка и авторизация не проверялись; настоящие credentials не читались и не изменялись.

Контракт host-managed авторизации подтверждён статическим анализом официального Claude Code **2.1.287** и диагностикой с фиктивными значениями. GLM требует эту версию или новее; произвольный исполняемый файл через `PARLEY_CLAUDE_BIN` остаётся существующей доверенной настройкой пользователя. Host-managed режим сохраняет политики администратора и пользовательскую широкую очистку окружения; GLM использует совместимое имя `PARLEY_HOOK_CAPABILITY`. Это не заменяет живую проверку работы официального CLI с сервисом.

Для ручной приёмки остаются:

- Активная GLM Coding Plan: endpoint/auth/model в `/status`, первый запуск с видимыми вопросами доверия/onboarding в Terminal.
- Реальное выполнение MCP, HTTP- и командных хуков, Bash и permissions; отсутствие Z.ai key в окружении дочерних процессов официального CLI.
- Flash с изображением, соседняя обычная Claude-сессия, поведение при исчерпании подписочной квоты.
- Проверка существующих пользовательских записей `glm`/`claude-glm`, которые могут перекрывать встроенную конфигурацию; пользовательские файлы автоматически не удалялись.

Сохранён принятый контракт resume: используется модель запуска (по умолчанию GLM-5.3 либо существующая `WorkSession.model`). Выбор через Chat `/model` отдельно не сохраняется и может сброситься после resume. Ограничения модели, хуков и permissions из managed policy сохраняют силу. Живая приёмка требует отдельного явного разрешения пользователя на работу с настоящим ключом.
