# План реализации: окно как у Orca

Дата: 2026-09-27. Статус: план готов, реализация не начата. Основание —
`2026-09-26-desktop-orca-ui-design.md`, дальше «спека». При расхождении плана со спекой
права спека.

> **Для исполнителя-агента.** План в формате проекта. Кусок — одна-две задачи с
> файлами, интерфейсами, поведением, тестами и приёмкой. Внутри задачи порядок всегда
> один: красный тест → минимальный код → зелёный прогон → коммит.
> REQUIRED SUB-SKILL: superpowers:executing-plans или
> superpowers:subagent-driven-development.

**Цель.** Наше окно выглядит и работает как «агентская IDE» Orca:
- свой каркас раскладки вместо dockview;
- карточки работ со вниманием;
- уведомления с переходом;
- терминал с отправкой «с защитой»;
- палитра ⌘J;
- редактор с превью;
- ревью с заметками агенту;
- встроенный браузер с Design Mode.

Юридическая рамка проекта при этом не нарушается.

**Архитектура.**
- Хост остаётся единственным владельцем сессий, PTY и git-жизни worktree. Протокол
  только растёт, версия прежняя.
- Main-процесс Electron получает файловые операции редактора, хранилища окна,
  уведомления и защиту `<webview>`.
- Рендерер переписывается на собственный каркас: дерево сплитов из групп вкладок,
  слой поверхностей, zustand-хранилища.

**Стек.** Electron 44, React 18, TypeScript strict ESM, zustand 5, Tailwind 4,
shadcn/ui на Radix, lucide-react, cmdk, sonner, `@dnd-kit`, `@tanstack/react-virtual`,
xterm.js 5.5, Monaco (`monaco-editor` + `@monaco-editor/react`), pdf.js, vitest,
Testing Library, Playwright `_electron`.

## Как гонять

- **Один кусок — один прогон.** Кусок — 1–2 задачи, агентам `model: 'sonnet'`
  (память «Мелкие воркфлоу на Sonnet»).
- **Между кусками — стоп.** Итог показывается человеку, человек читает диф, потом
  коммит. Каждый коммит зелёный сам по себе.
- **Перед стартом этапа** его файл сверяется с кодом прошлых этапов. Имена и типы из
  блоков «Интерфейсы» могли сдвинуться. План правится до кода, а не после.
- **Этапы строго по порядку**, раздел 16 спеки. Внутри этапа — по порядку кусков, если
  карта ниже не говорит иначе.
- **Живая приёмка** каждого этапа — за человеком, на собранном `harnas.app`.

## Как отмечать сделанное

- Кусок сделан, когда:
  - отмечены `[x]` все пункты его «Приёмки»;
  - прогоны зелёные;
  - есть коммит.
- Тогда же отмечается его строка в «Прогрессе» ниже, с хешем коммита:
  `- [x] 2.1 Модель раскладки — 3c742de`.
- Пункт приёмки, который сознательно не выполнен, не отмечается. Он получает
  приписку `— отложено: <почему>` и строку в `TODOS.md`.

## Правила проверки

Из опыта прошлых прогонов:

- **Фаза проверки** — две линзы с разными углами. Каждой сказано исходить из того,
  что дефект есть.
- **У линз разные имена временных файлов.** В одном рабочем дереве они видят файлы
  друг друга и принимают их за постороннее вмешательство.
- **Проверяющий сверяет код с планом** и ошибку самого плана структурно не видит.
  Диф всё равно читает человек.
- **Границы — инвариантом по диапазону,** а не одним числом.
- **`tsc -p tsconfig.json` в пакете не видит тестов** (`exclude` в tsconfig): «tsc
  чисто» не значит, что типы в тестах целы. Тесты гоняются vitest.
- **Типы окна проверяет только `pnpm typecheck`** (с 0.1). `build` окна — это
  `electron-vite build` на esbuild, eslint работает без типов, vitest их срезает:
  несходство моста, `fake-bridge.ts`, `TabMeta` или `ActionId` между кусками прошло бы
  все прочие прогоны зелёным.
- **«Все тесты зелёные» сверяется с базовым прогоном** на `72aac89`. Под нагрузкой
  `pnpm -r test` падают по таймауту два теста хоста: `activity-service` «6: автозаголовок…»
  и autoLaunch в `sessions-service` «…дочернюю pending…». По отдельности они зелёные.
  Новое падение сверх них — дефект куска. `pnpm -r test` на падении хоста дальше не идёт,
  поэтому окно гоняется отдельно.
- **Настоящий `claude` в автотестах не запускается никогда** — только stub через
  `HARNAS_CLAUDE_BIN`.
- **E2E гасят свой хост** (`e2e/stop-host.ts`) и работают с проектами в `/tmp`, которые
  чистят перед стартом. Иначе копятся хосты и работы (история `160bca8`).
- **`.omc/` не коммитится никогда**, стейджинг — только явными путями. Перед коммитом
  проверять `git diff --cached --stat`.

## Команды

- На каждом куске: `pnpm build`, `pnpm test`, `pnpm lint`, `pnpm typecheck` (с 0.1:
  типы окна по `tsconfig.node.json` и `tsconfig.web.json`, без вывода файлов).
- Один файл: `pnpm --filter @harnas/<пакет> test -- <файл>`.
- Окно: `pnpm --filter @harnas/desktop test`, E2E — `pnpm --filter @harnas/desktop e2e`.
  E2E нужны собранные хост и окно: `pnpm --filter @harnas/host build && pnpm --filter
  @harnas/desktop build`.
- Запуск окна: `pnpm dev:desktop`.
- Собрать `.app`: `pnpm --filter @harnas/desktop dist`. Приложение:
  `packages/desktop/dist/mac-arm64/harnas.app`.

## Сквозные ограничения

Каждый кусок молча включает эти требования. Значения — из спеки; строки с пометкой
«план» — константы, которые ввёл план, у спеки их нет.

- **Язык интерфейса — только английский** (решение пользователя 2026-09-27, кусок E.1).
  - Все видимые тексты окна — подписи, кнопки, меню macOS, тосты, уведомления,
    `aria-label`, `title`, заглушки, тексты ошибок — по-английски, как у Orca, в sentence
    case. Переключателя языка нет.
  - Тексты живут в `packages/desktop/src/shared/strings.ts` (одна таблица, main и
    рендерер берут её), параметризованные — функциями там же. В компонентах литералов
    интерфейса нет.
  - Русские строки интерфейса в этом плане и в спеке — это смысл, а не текст: кусок
    переводит их по глоссарию ниже, остальное — кратко и в духе Orca (сверять с клоном).
  - Ошибки хоста окно показывает своим английским текстом по `HostError.code`
    (`errorText(code)`); русское сообщение хоста — только в консоль. Хост, core и TUI
    не переводятся.
  - Даты и время — `en-US`. Комментарии в коде, коммиты и документы остаются
    по-русски.
  - Тест `english-ui` валит прогон, если в строковом литерале или JSX-тексте
    `packages/desktop/src` (кроме тестов и `e2e/`) есть кириллица. Исключение — строка с
    пометкой `// cyrillic-ok: <почему>` (например, нормализация `ё`/`е` в палитре).
  - Глоссарий: работа → **workspace** (мн. workspaces; «Новая работа» → «New
    workspace»); проект → project; сессия → session; агент → agent; комната → room;
    почта → mail; письмо → message; решения → decisions; будильник → auto-wake;
    вкладка → tab; группа → group; «Изменения» → Changes; «Файлы» → Files;
    палитра → command palette. Состояния сессии: работает → working; ждёт тебя →
    needs you; закончил · не просмотрено → done · unseen; простаивает → idle;
    ожидает запуска → not started; спит → asleep; закрыта → closed; готово → done;
    сбой → failed.

- **Стек.**
  - Node ≥ 20, pnpm 9, ESM, строгий TypeScript из `tsconfig.base.json`
    (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`).
  - React остаётся 18. Компоненты shadcn — в варианте с `forwardRef`, а не пропом `ref`
    из React 19.
- **Юридическая рамка**, спека 15.1:
  - учётные данные агентов не читаются;
  - в `~/.claude`, `~/.claude.json`, `~/.codex`, `~/.cursor` ничего не пишется;
  - хуки — только `--settings`;
  - к API провайдеров не ходим;
  - скрытых запусков агентов нет, в том числе для генерации текстов;
  - автоответов в диалоги агента нет;
  - YOLO по умолчанию нет;
  - закрытие сессии — только с согласия;
  - на GitHub от имени человека ничего не пишется;
  - агент браузером не управляет.
  Рамочный тест из куска 1.1 обязан оставаться зелёным.
- **Окно.**
  - `contextIsolation`, `sandbox`, без `nodeIntegration`.
  - Рендерер без Node, рантайм core в него не собирается — только типы.
  - Новые каналы IPC — только по белому списку с проверкой аргументов: `main/ipc.ts`, а
    группу `files:*` регистрирует `main/files/ipc.ts` (с 5.2).
  - Ошибка канала доходит до рендерера с кодом. Main бросает `encodeIpcError({ code,
    message })`, рендерер читает `decodeIpcError(err)` (`shared/ipc-error.ts`, E.1).
    Каналы оборачивает `withIpcError` (`main/ipc.ts`, E.1); с 5.2 она экспортируется для
    `files:*` и отдаёт `FilesDeniedError` как `files:denied`. Причина: `ipcMain.handle`
    отдаёт рендереру только `message`, а `contextBridge` теряет собственные поля `Error`.
  - Ключи `workKey` и `rootKey` — одни на main и рендерер: `shared/work-keys.ts` (5.2).
  - `file://` в рендерере не используется: байты файлов идут через `files.readBytes`.
- **Подставной мост.** Кусок, который расширяет `HarnasBridge` (`src/shared/bridge.ts`),
  тем же коммитом дополняет `renderer/test-utils/fake-bridge.ts`:
  - заглушку каждого нового метода, по умолчанию безвредную;
  - `emit…` на каждое новое событие `on…`;
  - журнал вызовов, если тесты его читают.
  Файл входит в «Изменить» такого куска, даже если там не назван. Иначе компонентные
  тесты падают на `bridge.app.<метод> is not a function`.
- **Хост.** Протокол только растёт, `PROTOCOL_VERSION` остаётся `1`. Новые методы —
  в `packages/host/src/methods/index.ts` одной строкой на группу.

## На что смотреть на ревью

Входы и условия, которые спека подразумевает, но легко пропустить. Тест на каждый
лежит в куске, который владеет кодом.

1. **Пути с пробелами, кавычками и кириллицей, macOS-синонимы `/tmp` и
   `/private/tmp`.**
   - Проверка корней сравнивает `realpath` обеих сторон (5.2).
   - У работ одного проекта общий корень `project`: `files.locate` ищет корень только
     среди корней своей работы, и ссылка есть в терминале каждой (5.2, 5.3).
   - Перетаскивание и путь скриншота экранируют `'` (5.4).
   - Ссылки терминала находят путь с кириллицей (5.3).
2. **Тридцать работ и сто сессий.**
   - Сайдбар виртуализирован после 50 карточек (3.3).
   - WebGL не упирается в лимит контекстов: политика сама отбирает контекст у давно
     скрытых терминалов, а не ждёт смены их видимости (5.3).
   - Слои поверхностей освобождаются по LRU (2.5).
3. **Работа, сессия или файл пропали, пока открыты.** Вкладка, уведомление, заметки и
   корень файлов не роняют окно:
   - `pruneLayout` (2.1);
   - тело «Сессия удалена» (2.4) видно: поверхности у удалённой сессии нет (2.5);
   - клик по уведомлению удалённой работы (4.3);
   - корень исчез (7.2).
4. **Кириллица, эмодзи и длинные ярлыки.**
   - `ё` = `е` в палитре (6.2).
   - Обрезка во вкладках, карточках и уведомлениях без разрыва суррогатных пар (2.4,
     3.3, 4.3).
   - Заметки с переводами строк уходят агенту целиком (8.4).
5. **Хост перезапустили или он старее окна.**
   - Терминалы переподключаются со снимком (2.5).
   - `pty.send` отвечает `not_found`, окно предлагает «Возобновить» (5.4).
   - Без нужного метода — мягкая подсказка, а не падение (3.1).
   - Повтор активности после подключения не даёт пачки уведомлений (4.3).
   - Реестр корней main перечитывает `works.list` на каждое подключение: снимок работ
     новому клиенту хост не шлёт, а первый `connect()` может упасть (5.2).
6. **Окно на 800 px и на 4K.** Ресайз сайдбаров держит пределы, сплит отказывает при
   нехватке места, строка вкладок прокручивается (2.3, 2.4).
7. **Симлинки, исполняемое и чужие схемы.** Агент может положить в worktree что угодно:
   - запись и обход без git не выходят за корень по симлинкам, временный файл не
     подложить (5.2, 7.1);
   - «Открыть в приложении» открывает только белый список документов, картинок и
     медиа: `.py` (Python Launcher исполняет и без бита x), `.html`, скрипты, бандлы и
     файлы с битом x — только показываются в Finder (5.2);
   - `rev`, `sessionId` и пути из рендерера проверяются в main (7.1, 8.4);
   - встроенный браузер не открывает `file:`, вложенный `<webview>` не прикрепляется
     (9.1).
8. **Терминал не отпускает события сам.**
   - ⌘-сочетание на macOS сначала получает страница, пункт меню — только
     необработанное. ⌘K и ⌘F терминала зовут `preventDefault`, иначе ⌘K заодно откроет
     палитру; `registerAccelerator: false` на macOS не действует (5.3).
   - `paste` xterm вставляет и при `preventDefault`: картинку гасит слушатель в capture
     со `stopPropagation` (5.4).
   - Подсветка и счётчик поиска — только с `allowProposedApi: true`; моки `SearchAddon`
     в jsdom этого не видят (5.3).
   - Неперехваченное исключение Playwright отдаёт событием `pageerror`, а не
     `console`: E2E наведения собирает оба (5.3).
9. **Отправка агенту рядом с человеком и будильником.**
   - Второй `pty.send` в окне Enter первого — `busy`; между проверками и вставкой нет
     `await` (5.1).
