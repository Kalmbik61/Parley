## 1. Цель
Живой разговор звук-звук:
1. Человек спрашивает.
2. Голос коротко подтверждает.
3. Разговор продолжается.
4. В паузе голос сообщает: «кстати, пришёл ответ: …».

Перебивание работает всегда. Память и «сон» — вне объёма. Факты о состоянии Parley — спека Nina `docs/specs/2026-11-04-human-overview-spec.md`.

## 3. Сессия GPT-Live
`voice.session.prepare` создаёт сессию:

```
{ model: 'gpt-live-1', instructions: VOICE_PROMPT, delegation: { type: 'client' } }
```

Сейчас `live-client.ts:106` передаёт только `{model}`. Instructions после старта не меняются, дополнения идут через `session.instructions.append`.

VOICE_PROMPT по руководству live-prompting:
- о Parley говорит только через делегацию; триггер делегации сверяется в T0;
- даёт короткое слышимое подтверждение;
- пересказывает итог с привязкой к вопросу и времени снимка;
- не произносит id;
- о действиях: «подготовил карточку, подтвердите на экране».

Ключ остаётся на хосте, клиент получает только SDP-ответ.

## 4. Request и мост делегаций
**Request на хосте.** Поля:
- `requestId`;
- `originKey` — уникальный, из исходных `voiceSessionId` + `delegation.id`; после восстановления не меняется;
- `conversationId` — разговор острова, а не голосовая сессия;
- `seq`, `version`, `text`, `context`, `jobId`, `supersededBy`, `transcriptPartial`;
- `delivery` — отметки доставки по потребителю.

Повтор события или потерянного submit с тем же `originKey` возвращает тот же Request.

**Привязка текста:**
1. Буфер хранит фрагменты input-транскрипта с таймкодами, перекрывающиеся тоже.
2. Вывод модели не считается границей реплики человека: в дуплексе «угу» может прозвучать посреди фразы.
3. Текст поручения — фрагменты человека, связанные по времени с `offset_ms` делегации.
4. Если к сроку фрагментов нет, мост ждёт до 1,5 с. После этого Request получает `transcriptPartial: true`. Такому Request разрешены только уточнение и статус: без `supersedes` и без подготовки действий.
5. В контекст job входят последние реплики и открытые Request разговора.

**Submit:**
- остров вызывает локальный метод с доверенным `origin: 'island'`;
- remote-метод `jobs.submit` по-прежнему ставит `mobile` (`methods/voice.ts:22`).

**Подтверждения.** Любой `thinking.append` или `commentary.append` может подавить ещё ожидающее автоподтверждение, в том числе чужой делегации (live-delegation, раздел «Suppress automatic acknowledgments»). Правила:
- Мост откладывает append, пока ждёт подтверждений открытых делегаций, но не дольше конечного срока. Срок выбирается в T0.
- После срока фиксируется `ack_audible = false | unknown`, и прогресс и итог идут по обычным правилам очереди. Отсутствие звука не блокирует append навсегда.
- Этот срок отдельный от ворот §5 и не разрешает озвучивать потенциально вытесненный итог.
- Старт job не блокируется ожиданием подтверждения.

## 5. Связь поручений
1. Первым шагом голосовая job вызывает:
   ```
   link_request({ supersedes: [{ requestId, expectedVersion }] | [], reason })
   ```
2. Хост проверяет одной транзакцией:
   - тот же разговор;
   - ожидаемую версию;
   - отсутствие исполненных действий;
   - что ни одна карточка не подтверждена.

   Затем отменяет старый job, если он ещё идёт, и отзывает его карточки. Схема «проверить, потом отозвать» запрещена.
3. Отмена допустима, только если у старого job явный allowlist: чтение плюс `propose_*`. `schedule_check` и похожие инструменты не считаются read-only. Независимые job и чужой разговор не отменяются. Уже исполненное не «отменяется».
4. Если связь неоднозначна или Request частичный, ничего не отменяется. Новый итог просит человека уточнить.
5. **Ворота очереди.** Как только хост принял новый Request этого разговора (даже в состоянии `queued`), все ещё не переданные в Live итоги прежних Request не озвучиваются до разрешения связи. Это касается и итогов уже `completed`, ждущих озвучки.
   - Вытеснение такого Request помечает его итог неактуальным. Завершённый job при этом не выдаётся за отменённый.
   - Через 15 с голос говорит «уточняю поручение», но вытесняемый итог не выпускает.
   - Если связь не определилась, голос спрашивает человека.
   - Уже переданное в Live отозвать нельзя.

## 6. Статус («ну что там?»)
- **Основной путь.** На каждое `assistant.job.changed` мост отправляет `thinking.append` с компактным статусом и временем, соблюдая правило подтверждений из §4. Live отвечает из этого статуса и называет время.
- **Запасной путь.** `request_status()` — только чтение, работа не повторяется, хост сверяет version.

## 7. Очередь речи
- **Состояния:** `queued`, `submitted`, `played` (есть доказательство локального воспроизведения), `unknown`, `dropped`.
- **Экран — отдельное измерение:** `card: hidden | shown`. `deliveredInline` ставится по `shown`.
- **Отправка в Live разрешена, когда одновременно:**
  - нет локальной речи человека;
  - пауза не меньше 700 мс (пилот);
  - модель ничего не воспроизводит (сигнал из T0);
  - ворота из §5 открыты.
- **Политика мягкая.** Во время речи человека не начинаем, перебивание человеком сохраняется. Через 30 с итог показывается карточкой, голос по-прежнему ждёт паузу.
- **Длина.** Итог до 300 токенов, лимит append — 500. Длиннее — коротко плюс «подробности на экране».
- **Нормализация** — общий нормализатор из спеки Nina:
  - словарь refs, границы токенов, длинные номера;
  - известные ссылки заменяются именем, неизвестные — на «участник», «комната», «работа»;
  - удаляются только известные mood-теги;
  - второго фильтра нет;
  - гарантия касается только текста приложения.
- Если человек перебил озвучку итога, состояние становится `unknown`, итог остаётся карточкой.

## 8. Assistant Core
1. **Job-scoped MCP.** Сейчас `job-executor.ts:43` запускает CLI без MCP. Нужен токен на каждый `jobId`; токен разговора (`assistant-service.ts:542–548`) не копируется. Allowlist инструментов явный.
2. **`JobResult { answer, capturedAt, cards, toolRefs }`.** `cards` и `toolRefs` хост записывает сам. `completed` означает «ответ готов». `confirm = Boolean(текст)` запрещено.
3. **`needs_confirmation`** ставится, когда действие заявлено без карточки или исход неизвестен после рестарта. Повтор действия запрещён.
4. **Связка `assistantJobs` и `assistantService`** (`host.ts:829–847`): общий провайдер и источник обзора.
5. **JOB_PROMPT:** 1–3 предложения, имена, «не знаю» вместо догадки, первым шагом `link_request`.
6. **Кап** — 2 job на провайдера.

## 9. Восстановление и бюджет
- Закрытие голоса не отменяет job.
- `requests.list({ conversationId, consumer })` возвращает открытые Request и недоставленные терминальные итоги. Отметка доставки устойчивая.
- Новая Live-сессия получает контекст с `delegation_id: null` или новой привязкой.
- Бюджет: уже есть 30 мин на сессию, дневной лимит и 15 с инициализации. Добавляется автозакрытие после 3 мин тишины без открытых Request.

## 10. Безопасность
- Live — недоверенный источник намерений.
- Ключ и CLI остаются на хосте.
- В append нет логов, argv и refs.
- Запись — только через карточки.
- Отзыв карточек атомарен.

## 12. Приёмка (реальный OpenAI и Mac)
| ID | Сценарий |
|---|---|
| VA-01 | Запрос → слышимое подтверждение ≤2 с → другая тема → итог в паузе |
| VA-02 | Перебивание останавливает речь, job продолжается |
| VA-03 | Уточнение зарегистрировано до передачи старого итога в Live → старый не озвучен, карточки отозваны, новый озвучен. Вариант: старый job уже completed, итог ждёт в очереди речи → помечен неактуальным, не озвучен, как отменённый не показан |
| VA-04 | Два независимых Request → оба подтверждения слышны, оба итога доставлены |
| VA-05 | Неоднозначное или частичное уточнение → ничего не отменено, голос спрашивает |
| VA-06 | «Ну что там?» → статус со временем, без повторного выполнения |
| VA-07 | Job завершился во время отключения, ответ submit потерян, событие пришло повторно → один Request, одна каноническая запись и карточка, итог доставлен после reconnect |
| VA-08 | Голос закрыт до итога → одна каноническая запись и карточка, повторы отсечены по event id |
| VA-09 | Read-only job → `completed` с `toolRefs` от хоста |
| VA-10 | «Создай комнату» → карточка, до подтверждения ничего не создано |
| VA-11 | Текст приложения без id и mood-тегов, в том числе при инъекциях и длинных номерах; речь Live проверяется вручную |
| VA-12 | 3 мин тишины без Request → сессия закрыта, usage записан |
| VA-13 | Нет ключа или исчерпан лимит → понятная ошибка, текстовый режим работает |
| VA-14 | Делегация посреди реплики, задержанные или переставленные фрагменты → текст собран верно или помечен частичным |
