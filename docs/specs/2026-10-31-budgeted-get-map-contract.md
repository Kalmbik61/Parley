# Бюджет get_map (b-008)

Источник: принятый план pl-02, ревизия 0, пункт 2. Продолжение P35
(a1fb045c) и схемы SQLite/LetterReader от 2026-10-23; хранилище и окно не меняются.

Без аргументов возвращается обзор schemaVersion 3. Его строки — короткие сводки,
а не полные сессии, комнаты или планы. Поля collections содержат точные total,
returned, complete и next для sessions, rooms, plans, deletedSessions и unreadRooms.
Все коллекции ограничены; планы представлены всеми статусами, включая завершённые.
Вызывающая сессия и комнаты её членства идут первыми. Остальные строки упорядочены
по id. Приоритет не даёт дополнительных прав чтения.

Потолок — 49152 байта UTF-8 сериализованного результата MCP:
`{content:[{type:'text',text:JSON.stringify(result,null,2)+'\n'}]}`.
Учитывается повторное экранирование строки text. JSON собирается целиком до
сериализации; строка готового JSON никогда не обрезается. Коллекции получают
отдельные ограниченные доли бюджета, поэтому большое число сессий не вытесняет комнаты.

Продолжение обзора: `get_map {field:'sessions',cursor:collections.sessions.next}`.
Для других коллекций — соответствующее имя поля. Ответ списка содержит items и
page с total/returned/complete/next. maxBytes ограничивает весь результат списка:
от 2048 до 49152 байт (большие запросы нормализуются к 49152). Без next обход закончен.
Курсор связан с работой, вызывающим, полем, нормализованным maxBytes и хешем
содержимого карты/счётчиков. Смена данных даже при прежнем updatedAt даёт
stale-cursor; чужой запрос или повреждённый курсор — invalid-cursor. После stale
нужно начать список заново. Старые before/after писем и offset текста не меняются.

`get_map {session}` возвращает прежнюю адресную проекцию, независимо от наличия
сессии в обзоре. Полные task/summary/history/artifacts/contextFrom доступны прежними
полями. `get_map {room}` сохраняет проверку членства/владения и скрытие плейбука.
`get_map {field:'plan',id:'pl-01',rev:0}` возвращает текущую точную ревизию плана,
status и text/next: полный JSON плана читается через textPage, куски text склеиваются
и разбираются после завершения. Неверная ревизия требует обновить список plans;
полный план доступен тем, кто вправе читать комнату. Исторические ревизии не создаются.
Потолки старых текстовых и почтовых страниц остаются 64/256 КиБ. Провайдеры читаются
только по field:providers. Private proof и снимок окна не расширяются.
