# Обновление лимитов и закрытие фоновых вкладок

**Дата:** 2026-10-04. Дополнение к подключению провайдеров, разрешённое пользователем после ручной проверки GLM.

## Поведение

В начале строки провайдеров слева появляется кнопка Refresh limits. Она вызывает один общий сбор лимитов, показывает состояние выполнения и не допускает повторного параллельного запроса. Старый хост без нового метода оставляет кнопку недоступной. Обновление не запускает сессии и не перезапускает хост.

Claude и Codex немедленно перечитывают данные, уже записанные их официальными CLI. Время наблюдения сохраняется: кнопка не заставляет простаивающий CLI обратиться к своему сервису.

По нажатию Refresh limits GLM получает отдельные метаданные через `GET https://api.z.ai/api/monitor/usage/quota/limit`, с сохранённым ключом Z.ai только в заголовке запроса хоста. Автоматический опрос локальных CLI не отправляет запросы к Z.ai. Адрес фиксирован; перенаправления запрещены, ожидание и размер ответа ограничены. Окно получает проверенные проценты с `source: 'zai'`, а не ключ или исходный ответ. GLM-файлы строки статуса Claude Code по-прежнему исключены, чтобы не показывать чужую подписочную квоту.

При отказе Z.ai общая кнопка сообщает безопасную ошибку, а доступные локальные данные других провайдеров всё равно обновляются. Последняя корректная квота сохраняется с прежним временем наблюдения; замена или удаление ключа очищает её и не позволяет позднему ответу старого запроса вернуть данные другого аккаунта.

Крестик активной вкладки виден постоянно; у фоновой вкладки появляется при наведении или фокусе. Нажатие закрывает её без переключения. Несохранённый файл по-прежнему требует решения Save/Discard/Cancel.

## Подтверждённые границы Z.ai

[Официальный плагин](https://github.com/zai-org/zai-coding-plugins/blob/main/plugins/glm-plan-usage/skills/usage-query-skill/scripts/query-usage.mjs) передаёт ключ в `Authorization` без добавления Bearer и трактует `TOKENS_LIMIT.percentage` как пятичасовое использование. Он не документирует различие недельных окон. [Описание плана](https://docs.z.ai/devpack/overview) подтверждает пятичасовые и недельные квоты в кредитах, но не задаёт JSON-схему monitor API.

Поэтому поддерживается только один однозначный `TOKENS_LIMIT` без неизвестных тегов периода. Неизвестные `unit`/`number`, несколько таких окон, `CREDIT_LIMIT`, месячный MCP и `accountcredit` не преобразуются в пятичасовую или недельную квоту. Неизвестный момент сброса остаётся неизвестным; обратный отсчёт не выдумывается.

В диагностике с разрешённым сохранённым ключом оба варианта заголовка — официальный raw и проверочный Bearer — вернули HTTP 200 с `success: false`, `code: 401`. Данные квоты и соответствие новых окон проверить не удалось. Это отказ именно monitor API: пользователь отдельно подтвердил, что GLM-сессия работает. Ключ и полный ответ в журналы не выводились.

## Исправления после пользовательской проверки

Повторный запуск после закрытия последнего окна на macOS вызывал `Object has been destroyed`: обработчик `second-instance` удерживал уничтоженный BrowserWindow. Теперь он проверяет живость окна, открывает закрытое через готовую фабрику с прежним подключением к хосту и восстанавливает свёрнутое. Ссылка очищается только при закрытии соответствующего окна; уведомления сохраняют отложенную навигацию.

Быстрое обновление CLI завершалось до заметного кадра вращения. Кнопка теперь сразу показывает обратную связь минимум 600 мс, а долгий запрос удерживает её до завершения. Данные и ошибки не задерживаются. При reduced motion вместо вращения видны песочные часы; таймер очищается при смене подключения и размонтировании.

Проверка: 95 выбранных unit-тестов, typecheck и lint прошли. Три видимых Electron E2E проверили настоящий повторный запуск вторым процессом, восстановление окна, сохранение PID хоста и движение индикатора после готовности данных. Данные загрузились за 6,4 мс, а видимое вращение продолжалось 601,9 мс; зафиксированы 63 разных кадра. Скриншоты открытого/восстановленного окна и вращения просмотрены агентом; независимое ревью не нашло замечаний.

Текущая исправленная сборка: `packages/desktop/dist/window-fix/mac-arm64/Parley.app`, подпись проверена. Для замены прежней запущенной копии нужен именно выход из приложения (`⌘Q`), а не закрытие окна красным крестиком. Новые версии обработчика безопасно поддерживают повторное открытие после закрытия окна.

401 остаётся отдельным вопросом доступа к Z.ai: сохранённый ключ отклонён также безопасным GET списка моделей. Новый предполагаемый адрес monitor API не решил отказ. ## Понятные ошибки обновления

Пользователь подтвердил личную подписку Lite и ключ из Z.ai API Keys. [Описание плана](https://docs.z.ai/devpack/overview) подтверждает поддержку Claude Code и пятичасовые/недельные лимиты Lite; повышение тарифа не является решением отказа авторизации. Текущий локальный хост уже объявляет `providers.refreshLimits`, поэтому тост `host error` не связан с отсутствием этого метода.

Причина отказа терялась дважды: общий сбор превращал её в новую ошибку без категории, затем RPC возвращал только `internal`. Теперь до окна доходит ровно `{ provider: 'glm', reason }`, где `reason` — одна из `authentication`, `unsupported_response`, `timeout`, `unavailable`. Ответ HTTP 401 и HTTP 200 с `code: 401` дают одинаковую категорию авторизации. Сырые сообщения, заголовки, тела и причины исключений не передаются.

Строка статуса выбирает фиксированный текст только для точной комбинации `internal`, `glm` и известной категории. Для 401 она предлагает открыть GLM и заменить полный ключ Z.ai. Неизвестные коды или данные по-прежнему дают безопасное общее сообщение. Чтение лимитов Claude/Codex, сохранение последней правильной квоты GLM, защита смены ключа и видимый отклик минимум 600 мс сохранены.

Проверка пути сохранения не обнаружила автоматической подстановки маски, placeholder или обрезки ключа: поле содержит только ввод пользователя, хост передаёт его в core, а core убирает лишь пробелы по краям. Синтетический полный ключ прошёл запись/чтение без изменения содержимого; реальные ключи в этой проверке не использовались. Валидация непрозрачных ключей не ограничивалась предположением об их формате.

Прошли 62 теста коллектора/сервиса/RPC и 82 теста строки статуса, полная сборка, typecheck и lint. Отдельный видимый Electron E2E прошёл за 4,1 с с синтетической ошибкой: агент проверил читаемый тост 401 при 800×500, движение и завершение индикатора, повторный клик и отсутствие сырого текста. Скриншот просмотрен; настоящие ключи и сервис Z.ai в этом сценарии не использовались. Эти изменения объясняют отказ, но не подтверждают успешный доступ к квоте: для этого нужен ответ Z.ai после пересохранения полного ключа пользователем.

Новая отдельная сборка с понятными ошибками: `packages/desktop/dist/quota-errors/mac-arm64/Parley.app`. Для её применения нужно выйти из прежнего приложения через `⌘Q`, открыть новую копию и подтвердить штатный Restart host. Проверка ad-hoc подписи прошла; работающий пользовательский хост и сессии автоматически не перезапускались.

## Добавление от 2026-10-05: формат квоты в кредитах

Диагностика с сохранённым ключом пользователя (по его просьбе) показала, что `401` больше не повторяется: monitor API отвечает HTTP 200, `success: true` на оба вида заголовка. Ключ имеет форму `id.secret`. Но формат другой: вместо одного `TOKENS_LIMIT` приходят два элемента `CREDIT_LIMIT` с `unit`, `number`, `usage`, `currentValue`, `remaining`, `percentage` и `nextResetTime` (мс), плюс `level: "lite"`. Прежний разбор отвергал такой ответ (`unsupported_response`), и Refresh limits у GLM показывал ошибку.

Решение пользователя — разбирать кредиты. Сочетания сверены по живому ответу: `unit: 3, number: 5` со сбросом через 29 минут — пятичасовое окно, `unit: 6, number: 1` со сбросом через 5,3 дня — недельное; описание тарифа называет именно эти два окна в кредитах. Официальный скрипт плагина кредитов по-прежнему не разбирает, документации на коды нет, поэтому:

- толкуются только эти два сочетания; месячный `TIME_LIMIT` и прочие пропускаются;
- окно со сбросом дальше своей длины (5 часов или 7 дней плюс минута) не толкуется: коды значат не то;
- повтор окна или процент не числом — отказ, а не догадка;
- распознанные кредитные окна главнее прежнего `TOKENS_LIMIT`, который по-прежнему понимается.
