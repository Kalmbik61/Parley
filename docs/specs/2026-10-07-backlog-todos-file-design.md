# Файл бэклога на выбор: `.parley/backlog.md` или `TODOS.md`

Дата: 2026-10-07. Статус: дизайн согласован в чате 2026-10-07, план — `docs/specs/2026-10-07-backlog-todos-file-plan.md`.

Связано:
- спека бэклога `docs/specs/2026-10-02-plans-backlog-design.md` (разделы 2–4: где бэклог, `.parley/`, формат);
- фикс `fix/backlog-stub-git-marker` (коммит `8afde94`): ложный `git-context-unverified` в проектах без git под `~/.git`-заглушкой. Эта спека от него не зависит.

## 1. Зачем

Человек держит отложенную работу в `TODOS.md` проекта и хочет, чтобы бэклог Parley жил там же, а не в отдельном `.parley/backlog.md`. Если файла нет, его нужно создать.

Писать в файл человека Parley по умолчанию не должен: правило «Parley пишет только в свои каталоги» остаётся. Поэтому `TODOS.md` — выбор человека на проект, а не умолчание.

## 2. Что сейчас (проверено 2026-10-07 на `origin/master` 8d97474)

| Что | Где |
|---|---|

| Через этот путь ходят: MCP `backlog_list`/`backlog_suggest`, `search_history`, эффекты плана, принятие предложений, хост, кнопка «Open file» | `core/src/work/backlog.ts`, `backlog-suggestions.ts`, `history-search.ts:164`, `host/src/methods/backlog.ts:83`, `desktop/src/main/ipc.ts:513` |

| Снимок бэклога отдаёт `file.relativePath` только как `.parley/backlog.md` или `.harnas/backlog.md` | `protocol/src/backlog.ts:38`, `host/src/methods/backlog.ts:90` |

## 3. Решения

| Вопрос | Решение |
|---|---|
| Где выбор хранится | `.parley/preferences.json`, поле `backlogFile: "state" \| "todos"`. Локально, не в git, рядом с `backlogRule` |
| Умолчание | Нет поля — выбора не было, бэклог в `.parley/backlog.md` |
| Испорченное значение или файл настроек | Для пути бэклога — `.parley/backlog.md`. Бэклог не ломается; запись выбора по-прежнему отказывает с `preferences-invalid` |
| Какой файл — «TODOS.md» | Существующий в папке проекта `TODOS.md` или `TODO.md`, регистр не важен, имя — как на диске. Если есть оба — `TODOS.md`. Нет ни одного — `TODOS.md`, создаётся при первой записи |
| Папка | `context.projectPath` из `resolveSharedProjectContext`: для git-проекта с worktree — та же папка основного checkout, где сейчас лежит общий `.parley/` |
| Где выбор предлагается | Вкладка Backlog: переключатель «Backlog file» и разовая плашка |
| Пункты при переходе `.parley` → `TODOS.md` | Переносятся в `TODOS.md`, `.parley/backlog.md` удаляется |
| Пункты при переходе `TODOS.md` → `.parley` | `TODOS.md` не трогаем; Parley снова пишет в `.parley/backlog.md` |
| Агенты | Ничего не меняется: инструменты ходят через `sharedProjectPaths` |

Подходы, которые отвергли: ссылка `.parley/backlog.md` → `TODOS.md` (core отказывается работать со ссылками, git видит ссылку, Windows) и синхронизация двух файлов (два источника правды).

## 4. Путь бэклога

`sharedProjectPaths()` после выбора каталога состояния читает `preferences.json` без исключений и решает:

- `backlogFile` не `"todos"` → `backlog = <dir>/backlog.md`, как сейчас;
- `"todos"` → `backlog = <projectPath>/<имя>`, где имя — найденный `TODOS.md`/`TODO.md` или `TODOS.md`.

К `SharedProjectPaths` добавляются:
- `backlogChoice: 'state' | 'todos' | null` — сохранённый выбор, `null` — выбора не было или значение испорчено;
- `todosFile: string | null` — имя найденного на диске `TODOS.md`/`TODO.md` (`null`, если нет).

Поиск — один `readdir` корня проекта, имена `/^todos?\.md$/i`. Порядок: точное `TODOS.md`, любое `todos.md` по алфавиту, точное `TODO.md`, любое `todo.md` по алфавиту. Тип записи здесь не проверяется: ссылка, каталог или нечитаемый файл дадут прежнюю ошибку чтения (`shared-file-unreadable`) — безопасная сторона.

Замок (`backlog.lock`), счётчики ID и предложения агентов остаются в `.parley/`: в режиме `todos` каталог состояния всё равно создаётся при первой записи.

**Гонка с переключением.** Писатель мог вычислить пути до того, как переключение заняло замок. Поэтому `withBacklogTransaction` после взятия замка вычисляет пути заново и работает с ними. Замок один и тот же в обоих режимах (`<dir>/backlog.lock`).

**Права файла.** Запись в бэклог сохраняет права существующего файла; новый файл — `0o644`. Иначе у `TODOS.md` с битом исполнения git увидел бы смену режима.

**Рукописные пункты.** Первая запись Parley проставит ID всем `- [ ]` в `TODOS.md` (`<!-- b-00N -->` в конце строки), как сейчас в `.parley/backlog.md`. Строки без `- [ ]`, абзацы, таблицы, код остаются байт в байт.

## 5. Переключение: `setBacklogFile(projectPath, file)`

Новая функция core, `file: 'state' | 'todos'`. Всё — в одной транзакции бэклога (`withBacklogTransaction`), то есть под замком проекта и после восстановления недописанных добавлений.

Сначала читается `preferences.json` так же строго, как при записи правила: испорченный файл — `preferences-invalid` до любых изменений.

**`state` → `todos`:**

1. Рукописным пунктам `.parley/backlog.md` проставляются ID (`ensureBacklogIdsInTransaction`), чтобы перенос опознавал пункты по ID.
2. Пункты `.parley/backlog.md`, чьих ID ещё нет в целевом файле, дописываются в него как есть: строка, подробности, пометки `taken`/`done`/`by`. Раздел пункта сохраняется: есть в целевом файле заголовок с тем же названием — пункт встаёт в конец этого раздела, нет — в конец файла добавляется `## <раздел>`. Пункты без раздела — в конец файла. Логика та же, что у `appendSource`.
3. Результат разбирается до записи: дубль ID, маркеры конфликта, незакрытый блок кода — ошибка, ничего не меняется.
4. Целевой файл пишется (сравнение версии, права сохраняются). Если переносить нечего, запись пропускается.
5. `.parley/backlog.md` удаляется, если его версия не изменилась с шага 1; иначе — `backlog-conflict`.
6. Счётчик ID поднимается до наибольшего ID в обоих файлах и сохраняется (см. ниже).
7. В `preferences.json` записывается `backlogFile: "todos"`.

Повтор после сбоя безопасен: уже перенесённые ID пропускаются (шаг 2), а сбой между удалением и записью выбора оставляет пункты в `TODOS.md` при выборе `state` — следующее переключение ничего не дублирует.

**`todos` → `state`** и любой выбор при `backlogChoice === null` с тем же файлом: записывается только `backlogFile`. Файлы не трогаются.

**Тот же выбор, что сохранён** — без изменений файлов, выбор переписывается тем же значением.

**Уникальность ID между файлами.** При любом переключении счётчик ID (`backlogSeq` в `.parley/backlog-suggestions.json`) поднимается до наибольшего ID в `.parley/backlog.md` и в `TODOS.md`. Счётчик сохраняется только при записи, а оставленный файл никто не пишет. Без этого после перехода обратно в `.parley` новый пункт мог бы получить ID из `TODOS.md`, и следующий перенос пропустил бы его как уже перенесённый, а `.parley/backlog.md` удалился бы вместе с ним. Нечитаемый или непонятный файл счётчик не поднимает и переключению не мешает.

## 6. Хост и протокол

- Новый метод `backlog.file.set` `{ projectPath, file: 'state' | 'todos' }` → снимок бэклога, как у остальных изменяющих методов. Ошибки — через тот же `safeError`.
- Снимок: у `file` появляются необязательные `choice: 'state' | 'todos' | null` и `todos: string | null`. Необязательные — чтобы новое окно разбирало снимок старого хоста. `relativePath` допускает ещё имя `TODOS.md`/`TODO.md` в любом регистре (`/^todos?\.md$/i`).
- `inspectSharedIgnore`: проверка «git скрывает бэклог» (`parley-dir-ignored`) смотрит на бэклог, только если он лежит в каталоге состояния. Память проверяется как раньше.
- Наблюдатель хоста уже следит за корнем проекта: правки `TODOS.md` в корне обновляют вкладку без нового кода. Повтор чтения по сигналу корня уже покрыт тестом `backlog-service.test.ts`; сам сигнал от `TODOS.md` проверяется живьём (приёмка, п. 2) — тест на настоящем `fs.watch` флейкает на macOS.

## 7. Окно: вкладка Backlog

- Рядом с «Agent suggestions» — переключатель «Backlog file» с двумя пунктами: `.parley/backlog.md` и `file.todos ?? 'TODOS.md'`. Значение — `choice ?? 'state'`. Смена вызывает `backlog.file.set`.
- Плашка, когда `choice === null` и `todos !== null`: «This project has TODOS.md. Keep the backlog there?» с кнопками «Use TODOS.md» и «Keep in .parley» (имя — из `file.todos`). Любая кнопка сохраняет выбор, и плашка больше не показывается.
- Старый хост (в снимке нет `choice`) — ни переключателя, ни плашки.
- «Open file» открывает выбранный файл: `app:open-backlog` уже берёт `paths.backlog`.
- Тексты — по-английски в `packages/desktop/src/shared/strings.ts`.

## 8. Ошибки

| Случай | Поведение |
|---|---|
| `TODOS.md` больше 1 МБ | `shared-file-too-large`, как у любого общего файла; выбор не меняется |
| Маркеры конфликта или незакрытый блок кода в `TODOS.md` | `backlog-merge-conflict` / `backlog-invalid`; при переключении ничего не меняется |
| `TODOS.md` — ссылка или каталог | `shared-file-unreadable` |
| Дубль ID в самом `TODOS.md` (человек скопировал строку с пометкой) | `backlog-invalid`, ничего не меняется. Пункты, чьи ID уже есть в `TODOS.md`, при переносе пропускаются, поэтому сам перенос дублей не создаёт |
| `.parley/backlog.md` изменили во время переноса | `backlog-conflict`; `TODOS.md` уже содержит пункты, повтор их не дублирует |
| Испорченный `preferences.json` | Бэклог читается из `.parley/backlog.md`; переключение — `preferences-invalid` |

## 9. Тесты и приёмка

Тесты:
- core: выбор пути (нет выбора, `todos` с `TODOS.md`, `TODO.md`, оба, регистр, нет файла, испорченные настройки); перенос с разделами, подробностями и ID; повтор после сбоя; дубль ID; права файла; обратное переключение не трогает `TODOS.md`; писатель, который ждал замок во время переключения, пишет в новый файл; `inspectSharedIgnore` в режиме `todos`;
- хост: поля снимка, `backlog.file.set`, `backlog.get` и `backlog.add` по `TODOS.md`;
- протокол: схемы метода и снимка, старый снимок без новых полей;
- окно: переключатель, плашка, старый хост.

Приёмка:
1. В dev-окне на 800×500 с длинным путём проекта: проект с `TODOS.md` → плашка → «Use TODOS.md» → пункты `.parley/backlog.md` в конце `TODOS.md`, `.parley/backlog.md` удалён.
2. Агент вызывает `backlog_suggest` — пункт появляется в `TODOS.md`, вкладка обновляется.
3. Переключение обратно — `TODOS.md` не меняется, новые пункты идут в `.parley/backlog.md`.
4. Проект без `TODOS.md`: плашки нет, выбор `TODOS.md` в переключателе создаёт файл при первой записи.
