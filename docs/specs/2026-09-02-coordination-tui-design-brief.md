# Промпт для агента-дизайнера: TUI слоя координации

Скопировать целиком в сессию дизайнера. Дизайн только для терминала.

---

Ты проектируешь интерфейс терминального приложения. Никакого кода, никакого веба:
результат — текстовые макеты и правила, по которым потом будет писаться Ink-приложение.

## Что за продукт

`my-harnas` — терминальный харнесс поверх агентских CLI (Claude Code, Codex, GLM).
Уже работает: слева сверху список сессий с историей, слева снизу подсессии выбранной
сессии, справа настоящий агент во встроенном псевдотерминале. Прочитай перед началом:

- `README.md` — текущий макет, клавиши, ограничения;
- `.ralph/specs/ui.md` — действующая спецификация UI;
- `packages/tui/src/components/*.tsx` — как сейчас выглядят строки списков и панели;
- `docs/specs/2026-09-02-coordination-design.md` — **что нужно спроектировать**:
  слой «работ», в которых несколько агентских сессий разных провайдеров знают друг о
  друге через общую карту, порождают друг друга и обмениваются сообщениями.

## Что нужно спроектировать

Новый режим левой колонки и всё, что вокруг него, не ломая существующий режим
«все сессии»:

1. **Список работ**: работы сгруппированы по проектам; внутри работы — сессии.
   У сессии видны: статус (`pending / active / idle / exited / done / failed`), бейдж
   провайдера (`Cl`, `Cx`, `GL`, у GLM нет истории), бейдж модели, токены
   (input / output / cache read / cache write — как их уместить в узкую строку, решаешь ты),
   длительность, признак непрочитанных сообщений, кто породил сессию (дерево или отступ).
2. **Панель деталей** для выбранной сессии: задача, резюме, артефакты (ссылки на файлы),
   входящие сообщения, существующие подсессии субагентов, история переходов статуса.
3. **Переключение режимов** колонки: «все сессии» ↔ «работы», согласованно с текущими
   клавишами (`Tab`, `p`, `n`, `r`, `R`, `Enter`, `Ctrl+Q` уже заняты, см. README).
4. **Диалоги**: новая работа (заголовок, цель), новая сессия в работе (провайдер из
   реестра, роль, задача), подтверждение запуска `pending` сессии с показом брифа,
   возобновление `exited`, дозаказ резюме. Помни, что правая панель может быть занята
   живым агентом, которому принадлежит весь ввод.
5. **Уведомления**: новая `pending` сессия, созданная агентом; новое сообщение; сессия
   завершилась без отчёта; предупреждение о второй параллельной сессии одного провайдера.
   Ненавязчиво: пользователь может в этот момент печатать в правой панели.
6. **Состояния**: пустая работа, работа без активных сессий, сессия без метрик (ещё не
   привязана к логам), очень длинные заголовки и задачи, много сессий (20+) в одной работе.

## Ограничения

- Stock Ink 5 + React 18, без кастомного рендерера. Перерисовка по событиям, не 60fps.
- Терминал может быть узким: обязательно макеты для **80×24** и **120×40**; на 80×24
  колонка слева очень узкая, и надо решить, что скрывать.
- Цвета: базовые 16 ANSI плюс dim/bold. Дизайн должен читаться и без цвета (монохром)
  и без Unicode-символов (дать ASCII-запасной вариант для каждого значка).
- Правая панель принадлежит агенту: ничего поверх неё не рисовать, оверлеи только в
  левой колонке или в строке статуса.
- Язык интерфейса русский, короткие подписи.
- Не изобретай новые механики поверх спецификации: если чего-то в ней нет, отметь
  вопросом, а не дорисуй.
