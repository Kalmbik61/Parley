# Заполненность контекста и сжатие по теме — дизайн

Дата: 2026-10-15. Статус: согласовано в диалоге (зачем: агенты в комнате работают, пока контекст не
переполнится, и сжимаются только автоматически; человек хочет видеть заполненность у каждого и сжимать
по клику с фокусом на теме комнаты или чата; занятый агент — сжать после хода; в комнате — и по одному,
и «Compact all»; фокус — подставленный текст, который можно править; подход A — родной источник
процента у каждого провайдера; в комнате — число на карточке участника и значок в шапке). Основание: код
`origin/master` 13b814c (после v0.12.1 и PR #51 «расход токенов комнаты»), строка статуса
`core/src/work/statusline.ts`, `pty.send` (`host/src/pty/send.ts`), смена effort
(`host/src/pty/effort-switch.ts`), будильник (`host/src/wake/wake-service.ts`).

---

## 1. Зачем

- Агент в комнате работает ход за ходом, пока контекст не заполнится, и тогда CLI сжимает его сам — в
  самый неудобный момент и без представления, что важно для комнаты. Большой контекст к тому же
  дорожает: каждый ход заново читает его весь (кэш смягчает, но не отменяет).
- Сколько контекста занято, в окне не видно нигде. Строка статуса Claude Code получает процент после
  каждого ответа модели (`context_window.used_percentage`), но Parley сохраняет из её входа только лимиты.
- Сжать агента можно только руками в его терминале (`/compact`), по одному, и фокус надо набирать самому.

## 2. Решения

1. **Видно у каждого агента**: процент заполнения контекста — на карточке участника комнаты и в тулбаре
   Chat; в шапке комнаты — значок с максимумом по живым участникам.
2. **Сжатие — только по клику человека.** Сам хост сжатие не начинает, автоматического порога нет.
3. **Фокус по теме**: поповер с готовой инструкцией из названия комнаты (у Chat — имени сессии); её можно
   поправить или стереть (пусто — обычный `/compact`).
4. **В комнате — и по одному, и все сразу** (`Compact all`).
5. **Занятый агент сжимается после хода**: просьба ждёт в хосте, значок показывает `⏳`, её можно
   отменить до начала.
6. **Подход A — родной источник процента**: Claude и GLM — строка статуса (то же число, что считает сам
   Claude Code); Codex — последняя запись `token_count` его rollout-лога (как «% context left» в Codex).
7. **Codex сжимается без фокуса**: его `/compact` описан как «summarize conversation to prevent hitting
   the context limit», признаков аргументов нет, а `compact_prompt` — глобальная настройка, не на вызов.
   Поле в поповере у Codex неактивно. Живая проба (7.3) может это поменять.

## 3. Что видит человек (окно)

Тексты окна — на английском, как всё окно.

### 3.1 Пороги

| Заполнено | Цвет чипа |
|---|---|
| < 60 % | нейтральный (как соседние чипы) |
| 60–84 % | янтарный (`accent`) |
| ≥ 85 % | красный (`destructive`) |

Настроек порогов нет.

### 3.2 Чип на карточке участника

`ParticipantStrip`: справа во второй строке — чип контекста. Текст «чем занят» (`doing`/задача) перед ним
сжимается многоточием, чип — нет (`shrink-0`). Кнопку в кнопку не вложить, поэтому кнопкой открытия
терминала остаётся первая строка, как уже сделано у карточки с бейджем субагентов (`AgentsBadge`); фон,
рамка наведения и тултип — у блока карточки, как сейчас.

| Состояние | Текст чипа | Тултип |
|---|---|---|
| процент известен | `82%` (цвет по 3.1) | `Context: 164k of 200k tokens` |
| данных нет | `—` | `No context data yet` |
| просьба ждёт конца хода | `⏳` | `Compaction queued — runs when the agent is free` |
| идёт сжатие | `…` | `Compacting…` |
| сжато, новой цифры ещё нет | `compacted` | `Compacted — waiting for the next update` |

Клик по чипу — поповер этого агента:

- строка `Context · S01 backend`, ниже `164k of 200k tokens · 82%` (или `—`, если неизвестно);
- поле инструкции (многострочное, до 1000 знаков) с текстом по умолчанию (3.5);
- кнопка `Compact`; пока просьба ждёт — вместо неё `Cancel`; пока идёт сжатие — неактивная `Compacting…`;
- у Codex поле неактивно, под ним `Codex compacts without focus`.

У спящего агента (нет процесса) чипа на карточке нет: его процент устарел, а сжимать нечего. В списке значка
комнаты (3.3) он помечен `asleep`.

### 3.3 Значок в шапке комнаты

`RoomHeader` получает слот `contextChip` рядом с `usageChip`. Текст — `Ctx 82%`: максимум по живым
участникам (тому, кому сжатие нужнее всех), цвет по 3.1. Ни у кого нет данных — `Ctx —`. Есть ждущие
просьбы — `Ctx 82% ⏳`.

Поповер:

- список участников комнаты (создатель, если он сессия, и `members`): имя, полоса заполнения, процент,
  состояние (3.2), `Compact` / `Cancel`; спящие — серые, с пометкой `asleep`, без кнопки;
- одно общее поле инструкции с текстом комнаты (3.5) — его берут и `Compact` в строке, и `Compact all`;
- `Compact all` — `sessions.compact` для каждого запущенного участника; итог — тост
  `Compacting 3 agents · 1 queued · 1 skipped` (skipped — спящие и те, кому хост отказал).

### 3.4 Chat

`ChatToolbar`: рядом с `SessionUsageChip` — `SessionContextChip`, чип `Ctx 62%` с теми же состояниями
(3.2) и поповером одной сессии (как 3.2), текст по умолчанию — Chat (3.5).

### 3.5 Инструкции по умолчанию

Это текст для агента, поэтому по-английски (как все тексты агентам), в `shared/strings.ts`:

- комната: `Focus on room "<title>": the human's task, decisions made, open questions, who owns what,
  and files touched. Drop details unrelated to this room.`
- Chat: `Focus on "<session name>": the current task, decisions made, open questions, and files touched.
  Drop unrelated details.`

Правка человека живёт, пока открыт поповер; по умолчанию каждый раз подставляется заново.

### 3.6 Старый хост

- Хост не знает `sessions.compact` (`useHostSupports`) — кнопок и поповера сжатия нет, чип только с
  процентом.
- В `LiveMetrics` нет `context` — чипа процента нет; нет `compaction` — состояние сжатия не показывается.
  Окно не падает.

### 3.7 Узкое окно

Поповеры — `w-[min(360px,calc(100vw-32px))]`. Чип на карточке не выталкивает имя: в тесной строке
сжимается текст «чем занят». Проверка — 800×500, длинное название комнаты (120 знаков), длинные имена
агентов и ролей.

## 4. Данные: откуда процент и как он попадает в окно

### 4.1 Claude и GLM — строка статуса

`runStatusline` (`core/src/work/statusline.ts`) рядом с `saveLimits` зовёт `saveContext`: если во входе есть
`context_window` с числовым `used_percentage`, атомарно (временный файл и `rename`, как файл лимитов) пишет
`context/<сессия>.json` в каталог работы:

```
{ "at": "<ISO>", "usedPercent": 82.4, "windowTokens": 200000, "usedTokens": 164800 }
```

- `usedPercent` ← `context_window.used_percentage`;
- `windowTokens` ← `context_window.context_window_size`, нет — `null`;
- `usedTokens` ← сумма входа, записи и чтения кэша из `context_window.current_usage`, нет — `null`.

Имена полей входа сверяются с живым входом в пробе (7.3). Как и с лимитами: сбой записи не трогает строку
терминала и код выхода, своя строка статуса человека работает как раньше, сети нет. Каталог —
`workPaths(...).context` рядом с `limits`; id сессии проверяется `isFileSafeId`.

### 4.2 Codex — rollout-лог

Разбор лога Codex (`core/src/codex/index-session.ts`) уже читает `token_count` ради накопительного
расхода. Он дополнительно запоминает из последней такой записи `info.last_token_usage` и
`info.model_context_window` и отдаёт `context` той же формы (`at` — время записи). Процент — по формуле
Codex TUI (там не считаются базовые 12 000 токенов окна: `percent_of_context_window_remaining`), занято =
100 − осталось. Формулу сверить в пробе с «% context left» на экране Codex.

### 4.3 В окно — `LiveMetrics.context`

```ts
interface ContextFill {
  usedPercent: number;       // 0–100
  windowTokens: number | null;
  usedTokens: number | null;
  at: string;                // время наблюдения
}
// LiveMetrics:
context?: ContextFill | null; // null — неизвестно; поля нет — хост старее
```

Хост собирает его вместе с остальными живыми метриками сессии (`activity-service`): у Codex — из индекса лога,
у Claude и GLM — из файла `context/<сессия>.json`. Файл пишет строка статуса, а не хук: пересчёт метрик по хукам и
логу мог бы прочитать его раньше записи последнего ответа, и процент завис бы до следующего события. Поэтому
файлы запущенных сессий Claude и GLM перечитывает отдельный лёгкий опрос раз в 5 секунд (`ContextService`); новое
значение — пересчёт метрик сессии. Нативные id и пути в окно не уходят.

### 4.4 После сжатия

Пока не пришло наблюдение новее конца сжатия (5.5), окно не показывает прежний процент — вместо него
`compacted` (3.2). Иначе после клика человек видел бы те же «92 %» и решил бы, что сжатие не сработало.
Для этого хост держит в памяти время конца последнего сжатия сессии и отдаёт `context: null` с
`compaction: 'compacted'`, пока `context.at` старше.

## 5. Хост: сжатие

### 5.1 Протокол

- `sessions.compact({ ref, instructions: string | null })` → `{ state: 'started' | 'pending' }` или
  `{ state: 'refused', reason: 'unknown-screen' | 'asleep' }`.
- `sessions.cancelCompact({ ref })` → `{ cancelled: boolean }` (`false` — просьбы не было или сжатие уже
  началось).
- Ошибки: нет сессии — `not_found`; инструкция длиннее 1000 знаков после очистки — `bad_request`.

Окно зовёт их только по клику человека; `Compact all` — вызов на каждого участника.

### 5.2 Когда печатать

Сразу (`started`), если одновременно:

- процесс сессии запущен;
- активность — `idle` (не `working`, не `blocked`);
- на экране нет диалога и ползунка (`choiceInProgress`), как у `pty.send`;
- поле ввода агента пусто (черновика человека нет), как у `pty.send`;
- замок `sessions.exclusive` свободен (не идёт смена модели или effort).

Иначе — `pending`: просьба запоминается (одна на сессию; новая заменяет текст прежней) и проверяется
заново на каждом событии активности, черновика и замка этой сессии — без опроса, тем же способом, каким
будильник ловит свободный момент. Ни одного хука с запуска процесса («экран неизвестен») — `refused`,
как `pty.send`: у свежей сессии на экране может быть вопрос доверия к папке. Процесса нет — `asleep`.

### 5.3 Что печатается

- Claude и GLM: `/compact <инструкция>` и Enter (`typeAndSubmit`). Инструкция — одна строка: переводы строк
  и табы — в пробелы, управляющие символы и escape-последовательности убираются (`sanitizeForSend`), пусто —
  голый `/compact`.
- Codex: голый `/compact` и его клавиша отправки. `sanitizeForCodex` сейчас нарочно экранирует `/compact`
  в тексте `pty.send` — сжатие идёт своим путём, мимо этой очистки; `pty.send` остаётся как есть.

### 5.4 Замок и будильник

С момента печати и до конца сжатия (5.5) хост держит `sessions.exclusive` этой сессии: будильник уже
уступает этому замку (`wake-service.ts`, `choiceInProgress` с `exclusive.held`), смена модели и effort —
тоже. Ждущая просьба (`pending`) замка не держит, но будильник проверяет и её: пока просьба ждёт, указатель
письма этой сессии не печатается — иначе свободный момент забрал бы указатель, а сжатие ждало бы ещё ход.

### 5.5 Конец сжатия

- Claude и GLM: хук `PostCompact` (его уже ловит лента — заметка `Conversation compacted`); `PreCompact`
  переводит состояние в `running`, если печать уже была.
- Codex: запись `compacted` в rollout-логе новее момента печати (хуков сжатия у Codex нет: `CODEX_HOOK_EVENTS`
  их не содержит).
- Нет сигнала 5 минут после печати — хост снимает замок, состояние сбрасывается, в `host.log` и окну —
  предупреждение `Compaction of S01 did not report back — check its terminal`.
- Процесс вышел — замок снимается, просьба забывается.

### 5.6 В окно — `LiveMetrics.compaction`

`compaction?: 'pending' | 'running' | 'compacted' | null` — ждёт, идёт, закончено и новой цифры ещё нет
(4.4), ничего. Поля нет — хост старее.

### 5.7 Чего нет

- Ждущие просьбы живут только в памяти хоста: перезапуск хоста их теряет, окно показывает процент без `⏳`.
- Повторов при сбое нет: исход видит человек.
- Хост не будит спящую сессию ради сжатия.

## 6. Крайние случаи

- **Агент вышел или уснул, пока просьба ждала** — просьба снимается, тост `S01 stopped — compaction
  cancelled`.
- **Два клика или `Compact all` поверх ждущей просьбы** — текст заменяется, просьба остаётся одна.
- **Человек печатает в терминале агента, пока просьба ждёт** — хост ждёт пустого поля ввода, поверх не
  печатает.
- **CLI сжался сам (автосжатие) раньше нашей просьбы** — просьба всё равно выполнится: её поставил человек и
  исход ему виден; угадывать «уже не нужно» хост не берётся.
- **Сессия в архивной комнате** — сжатие доступно, пока процесс жив (архив гасит агентов, обычно их уже нет).
- **Агент в нескольких комнатах** не бывает (`leaveOtherRooms`): тема комнаты однозначна.

## 7. Проверки

### 7.1 Модульные

- core: `runStatusline` пишет `context/<сессия>.json` при `context_window`; без него, с нечисловым
  процентом, с битым stdin — файла нет, строка терминала та же; id вне `isFileSafeId` — файла нет.
- core: разбор лога Codex отдаёт `context` из последнего `token_count`; формула процента; лог без
  `model_context_window` — `null`.
- host: сервис сжатия — свободен → печать и `started`; `working`/`blocked`/черновик/замок → `pending` и
  печать на первом подходящем событии; экран неизвестен → `refused`; нет процесса → `asleep`; `Cancel`;
  замена текста; будильник молчит при `pending` и под замком; `PostCompact` снимает замок; таймаут 5 минут;
  выход процесса; Codex — голый `/compact`; инструкция из нескольких строк — одна строка.
- host: `LiveMetrics.context` у Claude из файла, у Codex из индекса; `compacted`, пока наблюдение старше конца
  сжатия.
- окно: пороги цвета; состояния чипа; тексты по умолчанию с длинным названием; Codex — поле неактивно;
  старый хост — нет кнопок; `Compact all` — тост с итогом.

### 7.2 E2E

На стабе CLI, окно 800×500 и с `--force-device-scale-factor=2`: чип на карточке и значок в шапке видны,
поповеры не вылезают за край при длинном названии комнаты и длинных именах; клик `Compact` у свободного
агента печатает `/compact …` в его PTY; у занятого — `⏳`, затем печать после `idle`.

### 7.3 Живая проба (первый пункт плана)

На настоящих CLI, до кода сервиса:

1. Принимает ли Codex `/compact <текст>` и что делает с текстом.
2. Совпадает ли наш процент с «% context left» Codex и с `/context` Claude Code.
3. Какой `context_window_size` Claude Code сообщает для моделей GLM. Неверный — у GLM показываются токены
   без процента. Проверяется в приёмке через сессию GLM в Parley (ключ Z.ai у человека; исполнитель ключи не
   вводит), а не в пробе.
4. Зовёт ли Claude Code строку статуса сразу после `/compact` (иначе `compacted` висит до следующего ответа —
   это приемлемо, но надо знать).
5. Имена полей `context_window` во входе строки статуса (4.1).
6. `/compact` с инструкцией в ~1000 знаков, напечатанный одной записью в PTY (как печатает хост), выполняется
   как команда, а не уходит сообщением и не сворачивается во вставку.

Расхождения с этим дизайном — правка спеки до кода.

## 8. Вне объёма

- Автосжатие по порогу и напоминания «пора сжать».
- Процент в строке сессии сайдбара и в панели агентов.
- Будить спящую сессию ради сжатия.
- Сохранять ждущие просьбы между перезапусками хоста.
- Свой текст инструкции, запомненный для комнаты.
