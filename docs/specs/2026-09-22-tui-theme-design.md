# Тема TUI: палитра, роли и заливка фона — дизайн

Дата: 2026-09-22. Статус: согласовано в диалоге по разделам, дальше план
реализации. Основание: `2026-09-02-coordination-tui-design.md` (цветовая карта

Референс — herdr (herdr.dev): он везёт свои палитры и по умолчанию красит ими,

## 1. Зачем

Сегодня harnas красится шестнадцатью именами ANSI: `cyan` у активной зоны,
`magenta` у провайдера, `green`/`yellow`/`red` у статусов, `dimColor` у меты.
Как это выглядит, решает не харнесс, а схема терминала: один и тот же кадр у
одного человека сине-серый, у другого кислотный. Фон зон не рисуется вовсе —
сайдбар и панель агента стоят на общем фоне терминала, и раскладка держится
только рамками.

Итерация даёт три вещи:

1. свою палитру по умолчанию: harnas выглядит одинаково у всех, и это тот же
   приём, что в herdr — тема `terminal` возвращает сегодняшнее поведение;
2. фон зон: сайдбар на тон темнее панели, зона живого агента цвета темы;
3. один словарь цвета на весь UI — роли вместо имён ANSI, разбросанных по
   компонентам.

Правило из шапки `glyphs.ts` не отменяется: цвет не единственный носитель
смысла, каждый статус различим глифом. Тема обязана деградировать до монохрома
без потери смысла — и в этой итерации монохром впервые получает носитель для
выбранного ряда (4.3).

## 2. Решения диалога

| Вопрос | Решение |
|---|---|
| Что по умолчанию | Своя палитра, как у herdr. `terminal` — явный отказ от неё |
| Глубина в зоне агента | Подменяются только «пустые» стороны ячейки: нет цвета → `fg.default`, нет фона → `bg.agent`. Что гость окрасил сам — не трогаем, ремапа 16 ANSI нет |
| Набор тем | Пять палитр плюс `terminal`: `mocha` (дефолт), `latte`, `gruvbox`, `nord`, `tokyo-night` |
| Автопереключение свет/тьма | Нет. Только явный выбор: ключ конфига и оверлей настроек |
| Деградация | Фон заливается от 256 цветов. 16 цветов — ветка `terminal`. Ноль — монохром |
| Устройство темы | Палитра из 14 hex плюс `kind`; роли считаются из неё одной общей функцией |
| Доставка в компоненты | Модульный синглтон рядом с глифами: `applyThemeConfig()` / `theme()` |
| Фон под рамками | Рамки остаются штатными (`borderStyle`), тема даёт им только цвет. Фон под гранями — терминальный |
| Выбор ряда в монохроме | Жёлоб в один знак слева: `›` у выбранной строки (4.3) |

## 3. Модель

### 3.1 Палитра

Единственное, что своё у каждой темы, — четырнадцать именованных цветов и
пометка светлая/тёмная. Имена взяты у Catppuccin: на них ложатся и Nord, и
Gruvbox, и Tokyo Night.

```ts
export interface Palette {
  kind: 'dark' | 'light';
  base: string;    // фон панели и зоны агента
  mantle: string;  // фон сайдбара и строки статуса — на тон в сторону от base
  crust: string;   // фон оверлеев — дальше всех от текста
  surface: string; // выбранный ряд, плашка `new`
  overlay: string; // рамка неактивной зоны
  text: string;    // тело
  subtext: string; // второстепенное
  muted: string;   // мета: время, токены, заголовки проектов, pending
  red: string; green: string; yellow: string;
  blue: string; magenta: string; cyan: string;
}
```

Слот заполняется из исходной схемы, а если в ней такого слоя нет (у Nord нет
ничего темнее `nord0`), значение подбирается сдвигом яркости от соседнего. Это
наши слоты, а не чужая спецификация.

### 3.2 Роли

Компоненты видят только роли и никогда не hex. Роль отдаёт **пропсы Ink**, а не
строку — так она умеет сказать «цвета нет, но есть `dim`», и так уже устроен
`statusColor` (`{ color?, dimColor? }`).

| Роль | Из палитры | Где |
|---|---|---|
| `bg.panel` | base | заливка панели агента и карточки |
| `bg.sidebar` | mantle | заливка блоков сайдбара |
| `bg.status` | mantle | строка статуса |
| `bg.overlay` | crust | оверлеи и диалоги |
| `bg.agent` | base | ячейки PTY без своего фона |
| `bg.selection` | surface | выбранный ряд во всех списках |
| `bg.badge` | surface | плашка `new` (фон только под текстом) |
| `border.active` | cyan | рамка активной зоны |
| `border.idle` | overlay | рамка неактивной зоны |
| `fg.default` | text | тело, заголовки и label сессий |
| `fg.second` | subtext | цитата брифа, второй ряд строки |
| `fg.muted` | muted | время, токены, заголовки проектов, `pending`, прочитанные |
| `fg.accent` | magenta | провайдер, заголовки workflow, `▤` |
| `status.live` | green | `●` active, `✓` done |
| `status.warn` | yellow | `◐` idle, `○` exited, `⚑`, предупреждения |
| `status.fail` | red | `✗` failed, ошибки запуска |

Соответствие с таблицей 6.2 спеки координации — один в один: активная зона
голубая, провайдер и сообщения пурпурные, статусы зелёный/жёлтый/красный, мета
приглушённая. Меняется только источник: не имя ANSI, а роль темы.

Роли `blue` палитра держит про запас: сегодня он не занят ни одной ролью и
нужен, чтобы палитра оставалась полной при следующем цвете смысла.

### 3.3 Пять палитр

Источник правды о том, годятся ли значения, — тест на контраст (7.2): при
провале правится светлота слота, а не порог, и оттенок при этом сохраняется.
Отклонения от исходных схем ровно восемь, все в двух палитрах: nord (`subtext`,
`muted`, `red`) и latte (`subtext`, `muted`, `green`, `yellow`, `cyan`). У nord
причина в том, что схема не даёт слоя темнее `nord0` и её серый слишком близок
к фону; у latte — в том, что акценты светлой схемы рассчитаны на белый фон, а

### 3.4 Реестр и доступ

`packages/tui/src/theme/`: по файлу на палитру, `roles.ts` с общей функцией,
`index.ts` с `applyThemeConfig(name)` и `theme()`. Это зеркало `glyphs.ts`:
настройки применяются один раз при чтении конфига, компоненты зовут `theme()`
в теле рендера, перерисовку даёт смена состояния конфига — ровно как сегодня
работает `ascii`.

```ts
export function theme(): Theme;
export function applyThemeConfig(name: string, level?: number): void;
```

`level` — уровень цвета (4.1). По умолчанию берётся у chalk; параметр нужен
тестам и ничему больше.

Значение `terminal` — не палитра, а ветка в `roles()`: роли отдают имена ANSI и
`dimColor`, заливки нет. Она же работает на шестнадцати цветах, поэтому
отдельного кода на 16-цветную деградацию не появляется.

## 4. Уровни цвета

### 4.1 Три уровня, одна точка ветвления

Уровень спрашивается у chalk (`chalk.level`, 0–3) — того самого, которым Ink и
печатает. `chalk` становится прямой зависимостью `@harnas/tui`; сейчас он
приходит транзитивом через Ink, версия та же пятая, дубля в дереве не будет.
Считать уровень самим по `TERM`/`COLORTERM` не годится: разойдёмся с тем, что
реально делает вывод.

| Уровень | Когда | Что отдают роли |
|---|---|---|
| 3, 2 | truecolor, 256 цветов | hex палитры, заливка включена |
| 1 | 16 цветов | имена ANSI и `dimColor`, заливки нет — ветка `terminal` |
| 0 | `NO_COLOR`, не TTY, `TERM=dumb` | пусто: chalk всё равно снимет коды |

Ветвление живёт в `roles()` и больше нигде. Компонент не спрашивает про
уровень — он спрашивает роль и получает пропсы, которые на этом уровне имеют
смысл. Решение «добивать ли строку пробелами» принимается по одному флагу
`theme().fills`.

### 4.2 ASCII и тема не пересекаются

`ascii` — про глифы, тема — про цвет; терминал без Unicode вполне может быть
truecolor, и наоборот. Единственный стык — `selectionProps` (`glyphs.ts:152`):
сегодня ASCII даёт `inverse`, Unicode — фон `blackBright`. Новое правило:

- уровень ≥2: выбор ряда — `bg.selection`, в обоих наборах глифов. `inverse`
  поверх залитого фона читается как дыра, поэтому в ASCII он тоже уходит;
- уровень 1: как сегодня — `inverse` в ASCII, `blackBright` в Unicode;
- уровень 0: жёлоб (4.3).

### 4.3 Выбор ряда в монохроме

При уровне 0 chalk снимает и фон, и `inverse`: выбранный ряд не виден — это так
уже сегодня, тема лишь делает дыру заметной. Носитель для монохрома: колонка-
жёлоб слева шириной в один знак у списков сайдбара и оверлеев — `›` у выбранной
строки, пробел у остальных; у двустрочного ряда маркер стоит на первой строке.

Жёлоб существует только при уровне 0: выше выбор несёт фон, и колонку отбирать
не за что. Полезная ширина текста в этом режиме — `width - 1`, считается там же,
где уже считается ширина сайдбара. Знак едет в набор глифов (`cursor`: `›`,
в ASCII `>`), чтобы правило «смысл не только цветом» держалось в одном месте.

## 5. Как красится картинка

### 5.1 Строка — единица заливки

`backgroundColor` есть у `<Text>` и отсутствует у `<Box>` (проверено в
`ink@5.2.1/build/styles.d.ts`). Значит зону нельзя залить контейнером: каждая
строка блока — один `<Text backgroundColor>`, добитый пробелами до ширины блока,
и пустые строки тоже, иначе в «дырках» просвечивает терминал.

Хелпер `pad` из `sidebar.tsx:212` переезжает в `theme/fill.ts` и становится
общим для сайдбара, панели, оверлеев и строки статуса. Добивка делается только
при `theme().fills` — на уровнях ≤1 строки остаются такими же, как сегодня.

### 5.2 Зоны и рамки

Рамки остаются штатными: `borderStyle` у `<Box>`, тема меняет только цвет —
`borderColor={active ? border.active : border.idle}` в `panel.tsx:209`,
`sidebar.tsx:764`, `overlay.tsx:171`. Ни рисование граней, ни расчёт размеров
не трогаются.

Плата известна и принимается: у Ink нет фона ни у `<Box>`, ни у рамки, а
харнесс живёт без альтернативного экрана — значит символы граней стоят на фоне
терминала. Пока фон терминала близок к теме, шва не видно; на контрастном
(тёмная тема в светлом терминале) между блоками видны светлые линии в одну
клетку. Лечится это только переносом рисования рамок в тему, что переписывает
всю недавнюю работу по рамкам, — не в этой итерации.

Плашка `new` берёт `bg.badge` и до ширины **не** добивается: фон только под
текстом, иначе она столкнётся с полноширинной подсветкой выбранного ряда.

### 5.3 Зона агента

В `styleProps` (`terminal-view.tsx:12`) появляется подстановка: `color` не задан
→ `fg.default`, `backgroundColor` не задан → `bg.agent`. Всё, что гость окрасил
сам, остаётся его — ремапа шестнадцати ANSI-индексов нет.

Плюс две добивки, которых сейчас нет: хвост каждой строки до ширины панели и
пустые строки ниже `snapshot.rows`. `terminal-buffer.ts` не трогается — он
остаётся честным слепком экрана гостя, а срезанные им хвостовые пробелы
(`terminal-buffer.ts:213`) возвращает уже вид.

Инверсия гостя становится предсказуемее: ячейка с `inverse` теперь получает
явные `color` и `backgroundColor`, и `\e[7m` меняет местами именно их, а не
цвета терминала. Это главный пункт живой проверки (7.3).

### 5.4 Мета вместо `dimColor`

Сегодня «тусклое» — это `dimColor`, то есть SGR 2: терминал приглушает текущий
цвет сам, и на залитом фоне результат непредсказуем. Выше уровня 1 мета
получает свой цвет `fg.muted`, а `dimColor` остаётся только в ветке `terminal`
и на шестнадцати цветах.

## 6. Конфиг и оверлей

Один ключ рядом с остальными в `packages/core/src/config.ts`:

```
theme: 'mocha'         // 'latte' | 'gruvbox' | 'nord' | 'tokyo-night' | 'terminal'
HARNAS_THEME=nord
```

Проверяется тем же `take()`, что и остальные поля: неизвестное имя не валит
запуск, остаётся дефолт, а причина уезжает в `warning` и показывается строкой
статуса как `⚑` — «`theme: ожидается одно из mocha, latte, gruvbox, nord,
tokyo-night, terminal`».

Список имён (`THEME_NAMES`) живёт в core, палитры — в tui: core валидирует имя,
tui превращает имя в цвета. Про UI core по-прежнему не знает ничего.

Оверлей настроек (`prefix ,`) получает третий вид поля. Тема не булева и не
числовая — это выбор из списка: `←`/`→` листают значения, ввода текста нет.
Смена применяется сразу: `update({ theme })` пишет файл, зовёт
`applyThemeConfig`, меняет состояние — кадр перерисовывается целиком, как
сегодня с `ascii`.

## 7. Тесты

### 7.1 Уровень цвета в тестах

Тесты идут при `chalk.level = 0`. Если уровень темы равен уровню chalk, все
проверки `lastFrame()` увидят монохромный режим с жёлобом и поедут. Поэтому
уровень темы — отдельная величина: берётся у chalk, но переопределяется.

В общий `setupFiles` добавляется `pinTheme(1)` (по образцу `pinUnicodeGlyphs()`
из `test/glyphs-env.ts`): роли отдают имена ANSI, chalk их снимает, кадр
совпадает с сегодняшним знак в знак.

Уровень при этом **липкий**: `applyThemeConfig(name)` без уровня меняет имя
палитры и только его. Иначе пин сбрасывался бы сам — тему применяет
`useConfig` при чтении конфига, и первый же смонтированный компонент вернул бы
уровень к `chalk.level`, то есть к нулю, а кадр — к монохрому с жёлобом.
У `terminal` роли считаются по ветке уровня 1, но липким остаётся настоящий
уровень терминала: иначе выбор `terminal` навсегда опускал бы харнесс до
шестнадцати цветов и возврат к палитре ничего бы не дал. Тест, которому нужна заливка, ставит
`FORCE_COLOR=3` и `pinTheme(3)`; тест про монохром — `pinTheme(0)`.

Ожидаемая правка существующих тестов: `sidebar-selection.test.tsx` — там
`blackBright` и `cyan` становятся ролями. Остальные файлы не меняются.

### 7.2 Новые тесты

1. `roles.test.ts` — по каждой из пяти палитр: все роли определены; при уровне 1
   роли отдают только имена ANSI и `dimColor`; при 0 — пустые пропсы.
2. **Контраст автоматом.** Считаем относительную яркость и проверяем пары
   «текст на своём фоне». Порог зависит от того, полотно это или подсветка:
   `fg.default` и `fg.second` — не ниже 4.5:1 против `bg.panel`, `bg.sidebar` и
   `bg.overlay` и не ниже 3:1 против `bg.selection`; `fg.muted` — не ниже 3:1
   против всех четырёх, потому что это мета, а не тело текста; акценты и
   статусы — не ниже 3:1 против всех четырёх. Это ловит «жёлтый на белом» у
   светлой палитры машиной, а не глазами.

   Требовать 4.5:1 от меты против подсветки ряда нельзя: этот фон самый
   тёмный в тёмных палитрах и самый близкий к тексту в светлой, и такой порог
   выдавливает `muted` к цвету тела — в первом прогоне куска 1 он поднял мету
   во всех четырёх тёмных палитрах и слил `subtext` с `muted` в latte.
3. **Иерархия ступеней.** Тест на контраст доволен, когда три ступени текста
   слились в одну, поэтому рядом идёт отдельный инвариант: контраст между
   `text` и `subtext` и между `subtext` и `muted` — не ниже 1.2:1 в каждой
   палитре. Без него палитра проходит проверку, потеряв смысл ролей.
4. Заливка: у сайдбара при уровне 3 каждая строка блока добита до ширины и
   несёт фон — включая пустые; плашка `new` несёт фон только под текстом.
5. PTY: ячейка без фона получает `bg.agent`, ячейка с фоном гостя не тронута,
   хвост строки и строки ниже `snapshot.rows` добиты.
6. Монохром: жёлоб `›` у выбранной строки, полезная ширина на знак меньше, в
   кадре ни одного ANSI-кода.
7. Конфиг: тема из файла, из `HARNAS_THEME`, битое имя → дефолт плюс `⚑`;
   оверлей листает значения и пишет файл.

### 7.3 Живая проверка

Машиной не проверяется, делается руками:

- `claude` в панели: диффы, диалоги выбора, спиннеры, `inverse`-ячейки;
- тёмный и светлый терминал — видно ли шов под рамками (5.2);
- iTerm2 и Terminal.app: уровни 3 и 2, заливка должна выглядеть одинаково;
- `HARNAS_THEME=terminal` — картинка совпадает с сегодняшней;
- `NO_COLOR=1` — жёлоб на месте, смысл читается.

## 8. Порядок работ

1. Реестр и роли с тестами, включая контраст. Ничего не подключено — картинка
   не меняется.
2. Ключ конфига в core, чтение в `use-config.ts`, поле в оверлее настроек.
3. Замена имён ANSI на роли по всем компонентам, без заливки. Картинка не
   меняется: на уровне 1 роли отдают те же цвета.
4. Заливка зон при уровне ≥2: сайдбар, панель, оверлеи, строка статуса.
5. Зона агента: подстановка дефолтов и добивка.
6. Монохромный жёлоб и правка `selectionProps`.
7. Правка цветовой карты 6.2 в `2026-09-02-coordination-tui-design.md`, глиф
   `cursor` в таблице 6.1, список тем в README.

## 9. Вне объёма

- Автопереключение свет/тьма по фону терминала (`COLORFGBG`, запрос OSC 11).
- Пользовательские палитры из файла: сначала пять встроенных, потом видно.
- Ремап шестнадцати ANSI-индексов гостя на палитру темы.
- Перенос рисования рамок в тему ради фона под гранями (5.2).
- Фон за пределами зон: без альтернативного экрана он принадлежит терминалу.
