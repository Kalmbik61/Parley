# Обновление CLI агентов из Parley и стартовые вопросы CLI — дизайн

Статус: решения человека приняты 2026-11-02 (раздел 9), план — `2026-11-02-cli-update-and-startup-prompts-plan.md`. Лид s-209, владелец s-38, комната r-19.
Версии, на которых собраны факты: Codex 0.162.0 (standalone), Claude Code 2.1.316 (native), macOS arm64.

## 1. Задача

1. Codex при запуске из Parley останавливается на выборе «Update available · 0.162.0 → 0.166.0»
   (Update now / Skip / Skip until next version). Сессия, запущенная с телефона, на нём висит.
   Часть 1 (отдельный коммит) выключает проверку ключом `-c check_for_update_on_startup=false`.
2. Человек при этом должен иметь возможность обновить CLI из Parley, когда вышла новая версия.
3. Claude в проекте с `.mcp.json` останавливается на «5 new MCP servers found in this project. Select any
   you wish to enable». С телефона на него не ответить (`pty.input` телефону не разрешён). Раздел 7.

## 2. Что выяснено

### 2.1 Вопрос об обновлении в Codex

- TUI показывает выбор, если в кэше `~/.codex/version.json` версия новее установленной и не отложена
  (`dismissed_version`). Выбор пропускается, когда передан непустой стартовый промпт, и возможен при `resume`
  без промпта (`docs/research/2026-09-29-codex-research.md:212`).
- Ключ `check_for_update_on_startup` есть в `ConfigToml` бинаря 0.162.0; `codex doctor` печатает
  «startup update check true». Часть 1 передаёт `false` флагом `-c`, конфиг человека не трогается.
- Кэш Codex у человека: `{"latest_version":"0.166.0","last_checked_at":"2026-11-01T13:20:39Z","dismissed_version":"0.164.0"}`.
  Источник, который Codex опрашивает: `https://api.github.com/repos/openai/codex/releases/latest`; для brew —
  `https://formulae.brew.sh/api/cask/codex.json` (строки бинаря).
- Следствие: с выключенной проверкой Codex, судя по исходникам codex-rs, сам кэш не обновляет (на 0.162 вживую
  не проверено). Значит, полагаться на `~/.codex/version.json` как на источник последней версии нельзя.

### 2.2 Способ установки и `codex update`

- Есть команда `codex update` («Update Codex to the latest version»). Способ Codex выбирает сам (строки бинаря,
  `codex doctor`):
  - переменные `CODEX_MANAGED_BY_NPM` / `_BUN` / `_PNPM` / `_VITE_PLUS` (их ставит JS-обёртка пакета) →
    `npm install -g @openai/codex`, `bun install -g …`, `pnpm …`, `vp …`;
  - brew cask → `brew upgrade --cask codex`;
  - standalone → `curl -fsSL https://chatgpt.com/codex/install.sh | CODEX_NON_INTERACTIVE=1 sh`
    (Windows: `install.ps1`).
- У человека `codex doctor`: «install method standalone», «update action standalone installer»,
  «managed by npm: no · bun: no · pnpm: no».
- **У человека две установки, обе 0.162.0:** `~/.local/bin/codex` → `~/.codex/packages/standalone/current/…`
  (первая в PATH; именно её запускает Parley, видно в `ps`) и `~/.nvm/versions/node/v22.23.3/bin/codex`
  (обёртка npm). Вероятная причина того, что выбор предлагал npm, — запуск через обёртку npm; не проверено.
- Устройство standalone: `releases/<версия>-<target>/`, симлинк `current`, `install.lock`. Работающий процесс
  держит свой бинарь. Удаляет ли установщик старые каталоги `releases/`, не проверено.

### 2.3 Claude и другие провайдеры

- Вопроса об обновлении, который блокирует запуск, у Claude нет: native-установка обновляется в фоне
  (`~/.claude.json`: `installMethod: "native"`). Есть `claude update` («package-manager installs update
  through the package manager»). Для Claude Parley держит `minVersion: '2.1.287'`. Фоновое обновление посреди
  работы уже наблюдалось (`docs/research/2026-10-04-parley-token-benchmark.md`, §3).
- GLM и свои провайдеры запускают тот же бинарь `claude`, своего вопроса об обновлении у них нет.
- Другие стартовые вопросы Claude (из sg-23): доверие к папке (закрыто A29 / `trust.json`), новые серверы
  `.mcp.json` (раздел 7), предупреждение bypass-permissions, уведомление о своём API-ключе (спека своих
  провайдеров, 6.2). В этой спеке закрывается только вопрос о серверах MCP.

### 2.4 Что уже есть в Parley

- Установленная версия: `probeCliVersion` (`--version`, 3 с) в `packages/core/src/providers.ts`; её показывают
  `ProvidersSettings.tsx` и строка состояния (`StatusBar.tsx`, сегмент провайдера с версией).
- Карточки согласия: `host/src/consents/consents-service.ts` (виды `folder-trust`, `agent-switch`),
  отложенный запуск — `held-launches.ts`, ответ — `consents.decide`. Карточку видят окно, остров и телефон.

## 3. Как узнать последнюю версию

| Вариант | Как | Минус |
|---|---|---|
| **A (рекомендую)** | Хост сам раз в сутки опрашивает источник по способу установки: GitHub releases API (тег `rust-v<версия>`), для brew — cask API. Кэш в `<parleyHome>/cli-updates.json` | Ещё один сетевой запрос в сутки |
| B | Читать `~/.codex/version.json` | После Части 1 файл перестаёт обновляться |
| C | `codex doctor --json` раз в сутки | Читает тот же кэш, работает секунды, формат не обещан |

Правила для A:
- проверка идёт в фоне при старте хоста и потом раз в 24 ч (не чаще чем раз в 20 ч), только для включённых
  провайдеров; запуск сессий её не ждёт;
- таймаут 5 с; если нет сети, получен 403 или упёрлись в rate limit, Parley молчит, в кэш пишется только время
  попытки. GitHub без токена даёт 60 запросов в час, одного в сутки хватает;
- сравнение по semver, пре-релизы не учитываются;
- способ установки определяется по realpath запускаемого бинаря: `~/.codex/packages/standalone/` → standalone,
  `node_modules/@openai/codex` → npm-семейство, `Caskroom` → brew, иначе «неизвестно» (сравниваем с GitHub).

## 4. Как обновлять

| Вариант | Суть | Оценка |
|---|---|---|
| **1 (рекомендую)** | Хост запускает `<абсолютный путь бинаря, который запускает Parley> update` дочерним процессом без pty | Способ выбирает Codex, Parley его не дублирует |
| 2 | Parley сам собирает команду (`npm …`, `brew …`, `install.sh`) | Копирует логику Codex и сломается, когда она изменится |
| 3 | Только показать команду для копирования | Безопасно, но обновить из Parley и с телефона нельзя |

Детали варианта 1:
- окружение — `agentEnv` без унаследованных `CODEX_MANAGED_BY_*` и `CODEX_MANAGED_PACKAGE_ROOT`: устаревшая
  метка увела бы обновление не в ту установку; обёртка npm поставит их сама;
- одновременно идёт только одно обновление (блокировка в хосте); таймаут 5 мин; вывод пишется в журнал хоста;
- после обновления снова вызывается `probeCliVersion`. Успех — версия выросла; иначе показываются текст ошибки
  (например, нет прав на npm prefix) и команда для ручного запуска;
- если в PATH есть вторая копия с другой версией (как у человека), строка это показывает: «ещё одна копия:
  ~/.nvm/…/codex 0.162.0 (npm)». Parley её не трогает;
- интерактивна ли `codex update` для npm и brew, не проверено: для standalone Codex сам ставит
  `CODEX_NON_INTERACTIVE=1`. Первое настоящее обновление запускает человек кнопкой, тест работает на фейковом бинаре;
- Claude (по решению 4): та же строка с `claude update`.

## 5. Работающие сессии во время обновления

| Вариант | Суть |
|---|---|
| **a (рекомендую)** | Сессии не трогать: работающие продолжают на старом бинаре, новые запуски и подъём спящих идут на новой версии. Строка предупреждает: «2 сессии Codex работают — останутся на 0.162.0 до перезапуска» |
| b | Кнопка недоступна, пока работает хоть одна сессия Codex | В занятом пространстве кнопка может так и не стать доступной |
| c | Остановить всё, обновить, поднять | Прерывает ходы агентов |

Риск варианта a: флаги Parley проверены на 0.162 (`--no-daemon`, ключи `-c`). Если новая версия отвергнет флаг,
запуск провалится. Защита: после обновления хост делает пробный `codex -c check_for_update_on_startup=false --version`
и при отказе показывает ошибку в строке провайдера (сессии не перезапускаются).

## 6. Где окно показывает обновление (решение человека)

- **P1 (рекомендую).** Настройки → Провайдеры, строка провайдера: «Codex 0.162.0 → 0.166.0 · standalone ·
  [Обновить] · Пропустить эту версию». «Пропустить» хранится в `cli-updates.json` до следующей версии.
- **P2 (рекомендую вместе с P1).** Строка состояния: в сегменте провайдера уже есть версия, рядом добавляется
  тихая метка «↑», по щелчку открывается P1.
- P3. Тихая заметка в чате при старте сессии. Повторяется в каждой сессии, это шум. Не рекомендую.
- P4. Телефон: та же строка в мобильных настройках. Нужен новый изменяющий метод в allowlist моста
  (спека мобильного приложения, 4.3), поэтому это отдельный шаг после P1.

## 7. Claude: новые серверы MCP из `.mcp.json`

Факты и гипотеза:
- Claude спрашивает о серверах из `.mcp.json`, о которых нет решения в `enabledMcpjsonServers` /
  `disabledMcpjsonServers` и при `enableAllProjectMcpServers` ≠ `true`. Решение хранится по пути проекта
  (`~/.claude.json` → `projects[<cwd>]` или `.claude/settings.local.json`). Worktree Parley — это новый путь,
  поэтому, скорее всего, вопрос появляется в каждом новом worktree (так же ведёт себя доверие к папке); не проверено.
- Прошлое исследование: `disabledMcpjsonServers` в записи проекта исключает сервер, а одно
  `enabledMcpjsonServers` в той пробе не дало «connected» (`docs/research/2026-10-03-parley-cli/capabilities.md`,
  F4). Claude находит `.mcp.json` и выше по дереву, вплоть до домашней папки (бенчмарк 2026-10-04, §2).

Дизайн:
1. Перед запуском Claude хост читает `.mcp.json` в папке сессии и выше, вплоть до домашней папки. Для каждого
   сервера он берёт имя и отпечаток: хеш command/args/url без значений env.
2. Хост сравнивает их с решением, которое хранит сам Parley (`<parleyHome>/mcp-consent.json`, ключ — realpath
   корня основного репозитория, поэтому worktree одного проекта делят решение, плюс имя и отпечаток), и с
   собственными настройками Claude (три ключа выше из user/project/local и `projects[<cwd>]`).
3. Если о каком-то сервере решения нет, запуск откладывается (`held-launches`, как для `folder-trust`) и
   поднимается карточка нового вида `project-mcp`: список серверов, выбор для каждого, по умолчанию всё выключено.
   Её видят окно (`ConsentPrompt`), остров и телефон (`consents.decide`).
4. Запись перед запуском — предпочтительно флагом `--settings` с `enabledMcpjsonServers` / `disabledMcpjsonServers`
   (Parley уже передаёт `--settings`), тогда в проекте ничего не пишется. Запасной путь — `.claude/settings.local.json`
   worktree (он в gitignore). Какой из путей гасит вопрос, решает спайк (задача T4).
5. Молча ничего не включается: запуск сервера — это доверие к исполнению кода. Если отпечаток сервера изменился,
   человека спрашивают снова. «Отклонить все» равно Esc.
6. Пересечение с sg-23: этот раздел закрывает только вопрос о серверах MCP. Остальные стартовые вопросы sg-23
   (bypass-permissions, API-ключ) остаются в бэклоге.

## 8. Задачи после решения человека

Каждую задачу делает один исполнитель Sonnet, лид проверяет.

- T1 core: модуль проверки последней версии (запрос, кэш, semver, способ установки) с тестами на фейковом fetch.
- T2 host: метод `providers.update`: блокировка, очищенное окружение, повторная проба, пробный запуск;
  тесты на фейковом бинаре.
- T3 desktop: строка в `ProvidersSettings` и метка в `StatusBar` (по решению 1).
- T4 спайк на живом Claude во временной папке: гасит ли `--settings` с `enabledMcpjsonServers` /
  `disabledMcpjsonServers` вопрос о серверах, или нужен `settings.local.json`.
- T5 host: карточка `project-mcp`, отложенный запуск, хранение решений, запись. Затрагивает доверие к исполнению
  кода и границу записи: обязательно ревью старшей модели.
- T6 desktop/mobile: вид карточки `project-mcp`.

## 9. Решения человека (2026-11-02)

Человек принял рекомендации («обновите мастер и давайте приступать далее», передано s-38):

1. Где показывать: P1 — строка в Настройки → Провайдеры и P2 — метка «↑» в сегменте провайдера строки
   состояния. Заметки в чате нет. Телефон (P4) — позже, отдельным шагом.
2. Как обновлять: вариант 1 — хост запускает `<запускаемый бинарь> update`.
3. Работающие сессии: вариант a — остаются на старом бинаре, новые запуски идут на новой версии.
4. Claude: его версия в той же строке, «Обновить» запускает `claude update`. Подавлять при старте у Claude
   нечего. Последняя версия Claude — npm dist-tags `@anthropic-ai/claude-code`, тег из настройки
   `autoUpdatesChannel` (по умолчанию `latest`; 2026-11-02: `latest` 2.1.316, `stable` 2.1.309).
5. Серверы MCP: одно решение на все worktree репозитория, по умолчанию выключено, молча не включается никогда.

## 10. Не проверено

- Перестаёт ли Codex обновлять `~/.codex/version.json` при `check_for_update_on_startup=false` (вывод сделан по исходникам).
- Интерактивна ли `codex update` для npm и brew; удаляет ли установщик standalone старые каталоги `releases/`.
- Почему выбор предлагал npm (гипотеза — запуск через обёртку npm).
- Появляется ли вопрос о серверах MCP в каждом новом worktree и какой путь записи его гасит.
