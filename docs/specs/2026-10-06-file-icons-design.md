# Значки файлов и папок (Material Icon Theme)

**Дата:** 2026-10-06. **Статус:** ждёт ревью пользователя.
**Ветка:** `feat/file-icons` от `master` cec7dcb (Parley 0.5.2).
**Пункт TODOS.md:** раздел 5, «Значки Material для файлов и папок» (просьба пользователя 2026-09-28).

## 1. Задача

Пользователь, 2026-10-06:
- «Взять иконки из Material UI, как в VS Code, и добавить их к нам». Речь о расширении **Material Icon Theme** для VS Code, а не о библиотеке MUI: в MUI обычные значки интерфейса, по типу файла они не различаются.
- «Главное — положить эти иконки в отдельный пакет, чтобы они всегда были в одном месте. Чтобы потом мы либо удалили и заменили пакет и всё заменилось автоматически, либо сделали ещё какие-то действия».

Сейчас:
- Дерево файлов (`files/Tree.tsx`) рисует один lucide `File` на любой файл. У папок значка нет, есть только шеврон.
- Вкладки файлов (`layout/Tab.tsx`) выбирают один из шести lucide-значков по виду файла (`files/file-kind.ts`).
- Палитра ⌘P (`palette/Palette.tsx`) у файлов рисует lucide `File`.
- В «Изменениях» (`review/ChangesPanel.tsx`, `review/FileDiffSection.tsx`) и в поиске по файлам (`files/SearchPanel.tsx`) значков файлов нет.

## 2. Решения

1. **Набор — Material Icon Theme целиком.** Берём npm-пакет `material-icon-theme` 5.39.0 (MIT, © Material Extensions):
   - 1251 SVG в `icons/`, всего около 1 МБ;
   - таблица соответствий `dist/material-icons.json`, тот же манифест, что читает VS Code.

   Отобранную часть не делаем: 1 МБ на фоне приложения незаметен, а без полного набора редкие типы остались бы без значков. Решение пользователя 2026-10-06.
2. **Отдельный пакет `@parley/file-icons` — единственное место, которое знает о наборе.**
   - Внутри: зависимость от `material-icon-theme`, правила выбора значка, плагин сборки, лицензия.
   - Окно знает только API пакета (раздел 4.2) и не импортирует `material-icon-theme` напрямую.
   - Замена набора — правка одного этого пакета (раздел 4.5).
3. **SVG не лежат в git.** Пакет берёт их из `node_modules/material-icon-theme` при dev-сервере и при сборке. Версия закреплена точно (`5.39.0`, без `^`): набор меняется только явной сменой версии.
4. **Значок рисуется как `<img>`.** Встроенный `<svg>` и спрайт не годятся: внутри файлов набора повторяются `id` (`id="folder"` и другие), при встраивании они столкнутся. `<img>` изолирует каждый файл. Так же уже нарисованы значки провайдеров (`components/AgentIcon.tsx`). CSP окна (`img-src 'self'`) локальные SVG пропускает.
5. **В дереве у папки шеврон и значок, как в VS Code по умолчанию.** У файла на месте шеврона пусто, поэтому значки стоят ровным столбиком. Решение пользователя 2026-10-06.
6. **Места — пять из TODO:** дерево, вкладки файлов, палитра ⌘P, «Изменения», поиск по файлам. Вложения чата (`chat/AttachmentChip.tsx`) вне рамок (раздел 8).

## 3. Что видит человек

Размер значка в списках — 16 px: набор нарисован на сетке `viewBox 0 0 16 16`. Во вкладках — 14 px, рядом с остальными значками вкладок. Окончательный размер выбирается на живой проверке (раздел 7.4).

1. **Дерево файлов.**
   - Строка папки: шеврон (14 px, как сейчас), значок папки, имя. Значок у открытой папки свой, у закрытой — свой (`folder-src-open` / `folder-src`).
   - Строка файла: пустое место шириной шеврона, значок файла, имя.
   - Симлинк сохраняет lucide `Link2` на месте значка: значок по имени скрыл бы, что это ссылка.
   - Игнорируемые и «мёртвые» строки и сейчас приглушены прозрачностью 50 % на всю строку. Значок приглушается вместе с ними, отдельного правила не нужно.
   - Буква и цвет git-статуса остаются на имени и справа, значок их не меняет.
2. **Вкладки файлов.** Значок выбирается по имени файла. Таблица `FILE_ICONS` из lucide уходит. `fileKind` остаётся: по нему по-прежнему выбирается тело вкладки и превью.
3. **Палитра ⌘P.** У файловых пунктов значок по имени файла. Значок работы (lucide `Folder`) не меняется: это работа, а не папка на диске. Остальные значки палитры тоже без изменений.
4. **«Изменения».** Значок стоит между буквой статуса и путём: в строке списка (`ChangesPanel.tsx`) и в заголовке файла в диффе (`FileDiffSection.tsx`). У переименованного файла значок по новому пути, у удалённого — по пути, который показан в строке.
5. **Поиск по файлам.** В заголовке группы значок стоит после шеврона, перед путём.

Во всех местах значок декоративный: имя файла стоит рядом, поэтому `alt=""`, и экранный чтец его пропускает. `draggable={false}`: строки дерева перетаскиваются, картинка не должна утаскиваться отдельно.

Светлая тема берёт варианты `_light` там, где они есть в наборе (52 значка: `toml`, `jinja`, папка `.idea` и другие). Тема переключается на лету, как у значка Codex.

## 4. Пакет `@parley/file-icons`

### 4.1 Состав

`packages/file-icons/` устроен так же, как `@parley/protocol` и `@parley/core`:
- сборка `tsc` в `dist/`;
- тесты на `vitest`;
- в `exports` два входа.

| Вход | Где работает | Что даёт |
|---|---|---|
| `@parley/file-icons` | рендерер, тесты | правила выбора значка (4.2, 4.3) |
| `@parley/file-icons/vite` | конфиг electron-vite (Node) | плагин сборки (4.4) |

- **Зависимость:** `material-icon-theme` (`5.39.0`) — в `dependencies` пакета `@parley/file-icons`.
- **Окно** берёт `@parley/file-icons` в `devDependencies`: рендерер Vite собирает целиком, а `dependencies` окна electron-builder положил бы в `app.asar` вторым, мёртвым разом. Страж — `src/package-deps.test.ts`.

### 4.2 API

```ts
export type IconTheme = 'dark' | 'light';

/** Каталог значков относительно `index.html` рендерера; его же использует плагин. */
export const FILE_ICONS_DIR = 'file-icons';

/** Адрес SVG файла по имени или пути: `file-icons/nodejs.svg`. */
export function fileIconUrl(path: string, theme: IconTheme): string;

/** Адрес SVG папки по пути; у открытой папки — свой значок. */
export function folderIconUrl(path: string, open: boolean, theme: IconTheme): string;
```

- Адрес относительный. `<img src>` разрешает его от `index.html`: в dev — от адреса dev-сервера, в сборке — от `out/renderer/` (как `pdfjs/` в `PdfPreview.tsx`).
- Пакет не зависит от React и от хранилищ окна. Тема приходит параметром.

### 4.3 Правила выбора

Правила повторяют VS Code для манифеста иконок:
- **Регистр не важен.** При первом вызове пакет один раз строит таблицы с ключами в нижнем регистре. В манифесте есть ключи с заглавными буквами (`APKBUILD`, `META-INF`), их тоже приводим.
- **Файл:**
  1. последние два сегмента пути в `fileNames`: в манифесте есть такие составные ключи (`.devcontainer/devcontainer.json` → `container`);
  2. полное имя файла в `fileNames` (`package.json` → `nodejs`, `.gitignore` → `git`, `dockerfile` → `docker`);
  3. расширения по точкам, от длинного к короткому, в `fileExtensions`: `foo.test.ts` → `test.ts` (`test-ts`), затем `ts`. У файла с точкой в начале имени (`.eslintrc`) часть после неё тоже считается расширением;
  4. иначе общий `file`.
- **Папка:**
  1. последние два сегмента пути (`.github/ISSUE_TEMPLATE`) в `folderNames`, у открытой — в `folderNamesExpanded`; в манифесте есть такие составные ключи;
  2. затем одно имя папки;
  3. иначе `folder` / `folder-open`.
- **Светлая тема:** на каждом шаге сначала смотрим `light.<таблица>`, потом основную таблицу.
- **id → файл:** берём имя файла из `iconDefinitions[id].iconPath`, а не `${id}.svg`. У 72 значков файл называется иначе (`sty` → `sty.clone.svg`).
- `languageIds` не используем: языка файла окно не знает. Все частые расширения (js, ts, json, py, md, yml…) в `fileExtensions` и так есть — проверено на 5.39.0.
- `rootFolderNames` пусты, `highContrast` окну не нужен.

Неизвестное имя получает общий значок, исключений нет. Битых адресов быть не может: в сборку идёт весь каталог `icons/` (4.4).

### 4.4 Плагин сборки

`fileIcons()` из `@parley/file-icons/vite` устроен так же, как `pdfjsAssets()` в `packages/desktop/electron.vite.config.ts`:
- `configureServer` — dev-сервер отдаёт `/file-icons/<имя>.svg` из `material-icon-theme/icons/`. Имя проверяется по списку файлов каталога, чужие пути не отдаются;
- `generateBundle` — кладёт все SVG каталога в `file-icons/` сборки рендерера и туда же `LICENSE` пакета.

Окно подключает плагин одной строкой в `renderer.plugins`.

### 4.5 Замена набора

Всё, что связано с набором, живёт в `packages/file-icons/`. Окно не меняется, пока API 4.2 сохраняется.
- **Новая версия Material Icon Theme** — поднять версию в `package.json` пакета и прогнать его тесты.
- **Другой набор** — поменять зависимость, правила выбора (4.3) и источник SVG в плагине (4.4), переписать раздел NOTICE.
- **Убрать значки** — функции могут отдавать один общий значок. Окно продолжит работать без правок.

## 5. Окно

- **Компонент** `components/FileTypeIcon.tsx`: `<FileTypeIcon path kind="file|folder" open? size? />`. Тему берёт из `useUiStore((state) => state.dark)` и рисует `<img alt="" draggable={false}>` с адресом из пакета. Других знаний о наборе в окне нет.
- **Дерево** (`files/Tree.tsx`): разметка строки из 3.1. У симлинка остаётся `Link2`.
- **Вкладки** (`layout/Tab.tsx`): `FileTypeIcon` вместо `FILE_ICONS`. Атрибут `data-file-kind` остаётся на картинке: за него держатся тесты вкладок.
- **Палитра** (`palette/documents.ts`, `palette/Palette.tsx`): у документа палитры с `icon: 'file'` появляется поле `filePath`. Палитра рисует по нему `FileTypeIcon`.
- **«Изменения»** (`review/ChangesPanel.tsx`, `review/FileDiffSection.tsx`) и **поиск** (`files/SearchPanel.tsx`): `FileTypeIcon` в строке, как в 3.4 и 3.5.
- **Сборка** (`electron.vite.config.ts`): `fileIcons()` в плагинах рендерера.

Новых текстов интерфейса нет.

## 7. Проверка

### 7.1 Пакет (`packages/file-icons`, vitest)
- `package.json` → `nodejs`; `.devcontainer/devcontainer.json` → `container` (составной ключ); `README.MD` (регистр) → `readme`; `.gitignore` → `git`; `Dockerfile` → `docker`.
- `foo.test.ts` → `test-ts`, `index.d.ts` → `typescript-def`, `a/b/c.ts` → `typescript`.
- Неизвестное `x.unknownext` и имя без точки → `file`.
- Папки: `src` закрытая и открытая; `node_modules` → `folder-node`; `.github/ISSUE_TEMPLATE` по составному ключу; неизвестная папка → `folder` / `folder-open`.
- Светлая тема: `config.toml` → `toml_light.svg`, в тёмной — `toml.svg`. Полное имя важнее расширения: `pyproject.toml` → `python-misc` в обеих темах.

- Каждый адрес, который отдают функции, есть среди файлов `material-icon-theme/icons/`. Это проверка по всему манифесту, а не по выборке.

## 9. Приёмка

1. Во всех пяти местах `package.json` показывает значок Node, `tsconfig.json` — значок TypeScript-конфига, неизвестный файл — общий значок файла.
2. В дереве у `src/` закрытой и открытой разные значки; у неизвестной папки — общий значок папки; столбик значков ровный.
3. В светлой теме `.toml` показывает вариант `_light`, после переключения темы значок меняется без перезагрузки.
4. В собранном приложении значки грузятся, в консоли нет ошибок CSP и 404.
5. `import` из `material-icon-theme` есть только внутри `packages/file-icons/`.
6. NOTICE содержит раздел Material Icon Theme, `LICENSE` пакета лежит в `file-icons/` сборки.
7. Все тесты пакета и окна зелёные, E2E 7.3 проходит, живая проверка 7.4 пройдена.
8. Пункт «Значки Material для файлов и папок» удалён из TODOS.md.
