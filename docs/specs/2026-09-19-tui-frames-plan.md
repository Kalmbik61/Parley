# Рамки зон в TUI: план реализации

> **Для Claude:** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ: выполнять этот план задача за задачей
> через `superpowers:executing-plans`. Каждая задача — TDD: тест, падение, код,
> зелёный, коммит.

**Цель:** визуально разделить зоны интерфейса рамками, перенести строку `new`
в верх блока работ и дать ей вид кнопки.

**Подход:** рамки блоков сайдбара рисуются символами внутри того же плоского
списка строк, который отдаёт `layout()` — иначе ломается контракт «номер строки
сверху ↔ цель клика» (`use-actions.ts:229`) и точная высота сайдбара. Рамка
панели PTY, наоборот, делается штатным `<Box borderStyle>`, потому что там
такого контракта нет; её цена — минус 2 колонки и 2 строки у гостя, которые
вычитаются там же, где уже вычитает док треда.

**Стек:** TypeScript, React 18, Ink 5.2.1, vitest, ink-testing-library.

---

## Решения, принятые на этапе дизайна

1. Рамки у **обеих** зон: блоки сайдбара («работы», «сессии · <работа>») и
   панель PTY. Это разворачивает решение TUI v2
   (`2026-09-05-tui-v2-design.md:526` — «Рамки панелей и заголовки … удаляются»
   и легенду макетов `2026-09-05-tui-v2-mockups.md:10` — «Рамок у раскладки
   нет»). Спеки правятся в задаче 7.
2. Заголовок блока — в верхней грани. В Ink подписей в рамке нет, поэтому
   верхняя грань собирается строкой вручную.
3. Активная зона — **cyan + bold**, неактивная — dim. Это не новый приём:
   ровно так уже рисуется `Divider` (`sidebar.tsx:210`), и признак
   `navigating` уже приходит в `SidebarProps`.
4. Кнопка `new` — компактная плашка (фон только под текстом), первой строкой
   блока работ. Полноширинную плашку не берём: тем же приёмом рисуется
   подсветка выбранной строки, получился бы фон на фоне.
5. Внутри `SidebarOverlay` блоки рисуются **без своих рамок** — рамку даёт сам
   оверлей. Новый проп `framed={false}` по образцу существующего
   `divider={false}`.
6. Разделитель `│` в 27-й колонке исчезает: его место занимает правая грань
   блоков. `panelLeft` становится `width` вместо `width + 1`, панель отыгрывает
   колонку обратно.
7. Палитра и заливка фона — **вне этого плана**, отдельная работа по системе
   тем. Здесь используются только цвета существующего контракта
   (`2026-09-02-coordination-tui-design.md:459`): cyan у активного, dim у меты.

## Бюджет места

**Колонки.** Внешняя ширина сайдбара остаётся контрактной (26, узкая 18);
содержимое считается по `width - 2`. Пороги `NARROW = 18` ведут себя как
раньше: 26 → 24 остаётся широким, 18 → 16 остаётся узким.

**Строки.** Четыре строки уходят на грани двух блоков, две возвращаются:
нынешняя строка-линейка и строка `сессии · <работа>` уезжают в верхние грани.
Чистая цена — 2 строки.

**Панель.** `bodyCols - 2`, `panelRows - 2`. На 120×40 гостю было 93×39,
станет 92×37.

## Задача 3: layout() выдаёт блоки

**Файлы:**

- Изменить: `packages/tui/src/components/sidebar.tsx:398-490`
- Тест: `packages/tui/src/components/sidebar.test.tsx`

Самая содержательная задача. `layout()` продолжает возвращать **плоский массив
ровно из `height` строк** — это обязательное условие, на нём держится
`sidebarTargets` и клик мышью. Добавляются строки вида `kind: 'frame'` с
`target: null`, и бюджет окна сессий уменьшается на строки граней.

**Шаг 1. Написать падающие тесты**

```ts
it('строки граней не ломают соответствие строки и цели клика', () => {
  const targets = sidebarTargets(props);
  const rows = frameOf(render(<Sidebar {...props} />));
  // Грань — там, где цели нет.
  expect(targets[0]).toBeNull();
  expect(rows[0]).toContain('╭');
  // Цель строки работы совпадает с её номером сверху.
  const at = rows.findIndex((line) => line.includes('Авторизация'));
  expect(targets[at]).toEqual({ kind: 'work', key: '/dev/shop w-0001' });
});

it('высота сайдбара остаётся ровно height', () => {
  expect(sidebarTargets({ ...props, height: 24 })).toHaveLength(24);
});
```

**Шаг 2. Падение. Шаг 3. Реализация**

Блок работ: грань-верх с заголовком `работы` → кнопка → работы → грань-низ.
Блок сессий: грань-верх с заголовком `сессии · <работа>` → сессии → грань-низ.
Строки `──────` и `сессии · …` из нынешнего кода **удаляются** — они уехали
в заголовки. `capacity` уменьшается на 4 строки граней.

**Шаг 4. Зелёный. Шаг 5. Коммит**

```bash
git commit -am "feat(tui): layout собирает сайдбар двумя блоками с гранями"
```

it('кнопка стоит первой строкой блока работ, до самих работ', () => {

## Задача 5: боковые грани и ширина содержимого

**Файлы:**

- Изменить: `packages/tui/src/components/sidebar.tsx` — `Row`, `WorkRow`,

**Шаг 1. Переписать тест контракта раскладки**

Нынешний `for (const line of all) expect(dividerAt(line)).toBe(26)` проверяет
разделитель, которого больше нет. Заменить на проверку правой грани:

```ts
it('правая грань стоит в 26-й колонке у каждой строки', () => {
  for (const line of frameOf(render(<Sidebar {...props} />))) {
    expect(line[25]).toMatch(/[│╮╯]/);
  }
});

it('внутри оверлея своих граней у блоков нет', () => {
  const rows = frameOf(render(<SidebarOverlay {...props} />));
  expect(rows.some((line) => line.includes('╭─ работы'))).toBe(false);
  expect(rows.some((line) => line.includes('РАБОТЫ'))).toBe(true);
});
```

**Шаг 2. Падение. Шаг 3. Реализация**

Строки получают левую грань `│ ` и правую `│`, содержимое считается по
`width - 2`. `Divider` удаляется вместе с пропом `divider`. Новый проп
`framed?: boolean` (по умолчанию `true`); `SidebarOverlay` передаёт `false`,
и тогда грани не рисуются, а заголовки блоков становятся обычными строками.
Цвет граней: `navigating ? bold cyan : dimColor` — как было у `Divider`.
