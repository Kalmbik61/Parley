# TUI v2: сайдбар и одна панель (по образцу herdr) — дизайн

Дата: 2026-09-05. Статус: согласовано, ждёт инженерного ревью и макетов.
Провайдер в этой версии один: Claude Code. Codex и GLM остаются в реестре
`packages/core/src/providers.ts`, но в интерфейсе не показываются, пока провайдер
один.

Заменяет в части раскладки, ввода и панели ДЕТАЛИ документ
`docs/specs/2026-09-02-coordination-tui-design.md`. Карта работы, MCP-инструменты,
бриф, реестр провайдеров и жизненный цикл из
`docs/specs/2026-09-02-coordination-design.md` остаются в силе, за исключением
пунктов раздела 8 ниже.

---

## 1. Зачем

Текущий TUI зеркалит историю `~/.claude`: список сессий скачет при каждом событии,
режим «работы» спрятан за клавишей `w`, панель ДЕТАЛИ делает левую колонку тяжёлой,
а фокус между списками и терминалом переключается вручную через `Ctrl+Q`.

Образец — интерфейс herdr (https://github.com/herdrdev/herdr): узкий сайдбар без
рамок, одна главная область целиком под агента, все клавиши идут агенту, харнесс
слушает только префикс и мышь, а состояние агента видно цветной точкой.

Решения, принятые в обсуждении:

| Вопрос | Решение |
|---|---|
| Сплиты главной области | Нет. Одна панель, переключение через сайдбар. Раскладка хранится так, чтобы вторая панель не потребовала переделки |
| Источник состояния агента | Хуки Claude Code через `--settings` плюс jsonl-watcher как страховка |
| Быстрая сессия без работы | `new` сразу открывает Claude, работа создаётся автоматически с заголовком из первой реплики |
| Детали сессии | Компактно под выбранной сессией в сайдбаре, полностью в оверлее по запросу |
| Персистентность панелей между запусками харнесса | Не делаем: транскрипт хранит сам Claude, после перезапуска сессии возобновляются через `--resume` |
| Префикс | `ctrl+q`, настраивается. `ctrl+b` занят Claude Code («запустить в фоне») |

Юридическая рамка без изменений: запускается только немодифицированный `claude` из
PATH под логином пользователя, `~/.claude` только на чтение, `.credentials.json`
не трогать. Флаг `--settings` и хуки — документированные возможности Claude Code,
бинарь не модифицируется.

## 2. Раскладка

Три зоны: сайдбар слева, панель справа, строка статуса внизу. Рамок нет, между
сайдбаром и панелью тонкий вертикальный разделитель.

```
 1 Авторизация          ●     │
   ~/dev/shop · main          │
 2 Платежи               ●    │  (панель Claude Code — целиком его,
   ~/dev/shop · feat/pay      │   никаких заголовков и подписей харнесса)
                              │
 new                          │
──────────────────────────────│
 сессии · Авторизация         │
 ● план            working    │
   ↑1.2к ↓845 · 12м · ▤1      │
 ● бэкенд          blocked    │
   └ ● ревью        unseen    │
 ○ тесты           exited     │
                              │
 ⚑ бэкенд ждёт разрешения                                  ctrl+q ?
```

### 2.1 Сайдбар

Ширина по умолчанию 26 колонок, настраивается; на терминале уже 80 колонок
сайдбар сворачивается до 18 (только номера, глифы и усечённые заголовки), а по
`prefix b` прячется совсем.

**Верх — работы.** Пронумерованы 1..9 (дальше без номера), заголовок, второй строкой
проект (хвост пути) и ветка git. Справа точка состояния работы — максимум по её
сессиям (раздел 4). Выбранная работа подсвечена фоном. Сортировка: `active`
работы по времени последнего события, `done` ниже и свёрнуты в одну строку,
`archived` скрыты.

**Строка `new`.** Одна на сайдбар. `Enter` или клик — новая сессия Claude
(раздел 5.1). Если работ нет, это единственная строка верхней части.

**Низ — сессии выбранной работы.** Заголовок `сессии · <работа>`. Дерево по
`parent` с отступом и глифом `└` у дочерних. Строка сессии: глиф состояния, ярлык
(`label`), справа слово состояния. Под **выбранной** сессией одна компактная
строка: токены вход/выход, длительность, `▤N` непрочитанных, `⋮N` живых
субагентов, если есть. Сортировка — порядок дерева по `createdAt`, стабильный:
строки не переставляются при событиях, меняются только глифы и слова.

Ярлык сессии, порождённой агентом, — `label` из `spawn_session`. Ярлык сессии,
созданной через `new`, — заголовок Claude Code (`custom-title` / `ai-title` /
первая реплика, по существующей цепочке core), пока пользователь не переименовал.

### 2.2 Панель

Одна, на всю оставшуюся ширину и высоту между верхом терминала и строкой статуса.
Внутри — PTY с `claude`, рендер через `@xterm/headless` как сейчас, с курсором
гостя. Харнесс ничего не рисует поверх панели.

Когда выбранная сессия не запущена (`pending`, `exited`, `done`, `failed`), панель
показывает карточку сессии: ярлык, состояние, последнее резюме и подсказку
действия (`Enter — запустить` / `Enter — возобновить`). Это единственный случай,
когда панель рисует харнесс.

### 2.3 Строка статуса

Одна строка внизу на всю ширину. Слева последнее событие `⚑` (как в прежнем
дизайне: pending от агента, новое сообщение, сессия вышла без отчёта, агент ждёт
разрешения, готово авто-резюме). Справа подсказка `ctrl+q ?`. Во время ожидания
второй клавиши префикса строка показывает `ctrl+q …` и список основных действий.

### 2.4 Оверлеи

Рисуются поверх панели, центрированы, с рамкой, закрываются `Esc`. Пока оверлей
открыт, ввод идёт ему, а не гостю.

- **Детали сессии** (`prefix i`): задача, состояние с временем простоя и кодом
  выхода, токены по четырём счётчикам, сводка с пометкой источника, входящие
  (непрочитанные и последние 5 прочитанных), артефакты, субагенты, история
  переходов, цель работы (редактируется здесь же, если пуста).
- **Пикер работ** (`prefix w`): все работы из глобального индекса, включая другие
  проекты, с фильтром по набору текста. `Enter` выбирает работу в сайдбаре.
- **Пикер истории** (`prefix g`): сессии `~/.claude` текущего проекта по свежести,
  с заголовком, возрастом, длительностью и токенами; фильтр по тексту. `Enter`
  возобновляет сессию в текущей работе (раздел 5.3).
- **Справка** (`prefix ?`): все действующие привязки с фильтром.
- **Подтверждения**: закрытие сессии, запуск `pending` с показом брифа (как в
  прежнем дизайне 4.3), возобновление (4.4), дозаказ резюме (4.5).

## 3. Ввод

### 3.1 Модель

Все клавиши идут в панель, включая стрелки, `Tab`, `Esc`, `Ctrl+C`. Харнесс
перехватывает только:

- **префикс** `ctrl+q` (байт 0x11, настраивается `HARNAS_PREFIX=<буква>` и в
  конфиге): после него одна клавиша действия; неизвестная клавиша отменяет
  префикс, второй `ctrl+q` отправляет `ctrl+q` гостю;
- **мышь** (раздел 3.3);
- ввод, пока открыт оверлей или сайдбар в режиме навигации.

### 3.2 Действия по префиксу

| Клавиша | Действие |
|---|---|
| `c` | новая сессия Claude в выбранной работе (или новая работа, если работ нет) |
| `w` | пикер работ |
| `g` | пикер истории для возобновления |
| `i` | оверлей деталей выбранной сессии |
| `j` / `k` | следующая / предыдущая сессия в сайдбаре с подключением к панели |
| `1`..`9` | подключиться к сессии с этим номером в сайдбаре |
| `s` | фокус в сайдбар: стрелки и `j`/`k` ходят по строкам, `Enter` подключает, `Esc` возвращает в панель |
| `b` | спрятать / показать сайдбар |
| `x` | закрыть выбранную сессию (SIGHUP процессу) с подтверждением |
| `r` | возобновить выбранную `exited`/`done`/`failed` сессию (диалог возобновления) |
| `R` | дозаказать резюме для `exited` сессии |
| `?` | справка по привязкам |
| `q` | выйти из харнесса с подтверждением, если есть живые сессии |
| `ctrl+q` | отправить `ctrl+q` гостю |

Ключи, занятые Claude Code (`ctrl+b`, `ctrl+c`, `ctrl+d`, `ctrl+l`, `ctrl+o`,
`ctrl+r`, `ctrl+t`, `Esc`), харнесс не использует без префикса.

### 3.3 Мышь

Харнесс держит SGR-отслеживание мыши включённым всегда, как Claude Code. Клик по
строке работы выбирает её, клик по строке сессии выбирает и подключает, клик по
`new` создаёт сессию. Клик и колесо в области панели транслируются гостю с
пересчётом координат, если гость запросил отслеживание мыши; иначе колесо листает
скроллбэк нашего буфера. Выделение текста — родное через `option`/`shift`-клик,
как у Claude Code, это фиксируется в README.

## 4. Состояния сессии

### 4.1 Две оси

Жизненный цикл из карты остаётся: `pending`, `active`, `idle`, `exited`, `done`,
`failed` (спецификация координации, раздел 6). Для `active` сессии добавляется
рантайм-состояние `activity`, которое живёт в карте рядом со статусом:

| `activity` | Индикатор | Слово | Смысл |
|---|---|---|---|
| `working` | серый, мигает 1 Гц | working | агент думает или выполняет инструменты |
| `blocked` | жёлтый | blocked | ждёт разрешения или ответа на вопрос |
| `unseen` | синий | unseen | ход закончен, пользователь ещё не подключался к панели |
| `idle` | тусклый | idle | ждёт ввода, пользователь это видел |

Остальные статусы карты показываются как раньше: `pending` тусклый `◌`,
`exited` тусклый `○`, `done` `✓` (без цвета, работа завершена отчётом),
`failed` красный `✗`. Мигание — единственный таймер в UI, только пока есть хотя бы
одна `working` сессия.

Состояние работы — максимум по её сессиям в порядке `blocked` > `working` >
`unseen` > остальное; цвет точки тот же.

### 4.2 Источник: хуки Claude Code

При запуске сессии харнесс пишет `settings/<session-id>.json` в папку работы и
передаёт его через `--settings`. В нём объявлены хуки, каждый вызывает
`harnas-core hook <событие> --work-dir … --session …`:

| Хук Claude Code | Событие харнеса | Переход |
|---|---|---|
| `UserPromptSubmit` | `prompt` | → `working` |
| `Notification` с `permission_prompt` | `blocked` | → `blocked` |
| `Notification` с `idle_prompt` | `waiting` | → `unseen` (или `idle`, если панель на экране) |
| `Stop` | `stop` | → `unseen` (или `idle`) |
| `SessionEnd` | `end` | → `exited`, если не было `report` |

Команда хука пишет переход в карту через существующее хранилище (атомарно, под
блокировкой) и завершается за миллисекунды. Точный набор имён событий
`Notification` уточняется по документации Claude Code на момент реализации; если
какого-то события нет, соответствующий переход берёт страховка.

`--settings` добавляет наши хуки к пользовательским, не заменяя их. Файл настроек
лежит в папке работы, в `~/.claude` ничего не пишется.

### 4.3 Страховка: jsonl-watcher

Существующий watcher core по файлу сессии: новая запись ассистента → `working`;
тишина дольше порога (по умолчанию 30 секунд после последней записи ассистента
без `Stop`) → `unseen`/`idle`. Страховка не понижает `blocked`: снять его может
только хук или новая запись пользователя.

### 4.4 «Видел / не видел»

`unseen` переходит в `idle`, когда сессия подключена к панели и панель на экране.
Подключение — через сайдбар, `prefix j/k/1..9` или клик. Чтение через оверлей
деталей не считается просмотром.

## 5. Создание и возобновление

### 5.1 `new`

Без диалога. Харнесс создаёт запись сессии `pending` с ярлыком «новая сессия»,
запускает `claude --session-id <uuid> --mcp-config <…> --settings <…>` в панели
и сразу подключает. Работа: если выбрана — сессия ложится в неё; если работ нет
или выбрана строка `new` верхнего уровня — создаётся новая работа с заголовком
«без названия» и пустой целью. Как только у сессии появляется заголовок Claude
Code, ярлык сессии и, для новой работы, её заголовок обновляются из него один
раз; дальнейшие переименования — только руками.

Бриф для такой сессии не пишется: она стартует без промпта, а карту и правила
агент получает через MCP. `contextFrom` пуст.

### 5.2 Порождённые агентом

`spawn_session` создаёт `pending` с брифом, как в спецификации координации.
В сайдбаре строка появляется с синей точкой внимания и событием `⚑`. `Enter` в
сайдбаре или клик открывает диалог запуска с брифом, `Enter` запускает.

### 5.3 Возобновление из истории

Пикер `prefix g` показывает сессии `~/.claude` текущего проекта. `Enter`
регистрирует выбранную сессию в текущей работе (`providerSessionId` = её uuid,
ярлык из её заголовка, `history` начинается с `active`) и запускает
`claude --resume <uuid> --mcp-config <…> --settings <…>`. Метрики считаются по
всему транскрипту, включая часть до регистрации.

### 5.4 Перезапуск харнеса

Живых процессов после выхода нет. При старте сессии со статусом `active` в
картах помечаются `exited` (без отчёта), и `prefix r` возобновляет их через
`--resume`. Сессии, запущенные вне харнесса (`harnas-core work session new`),
к панели не подключаются, как и раньше.

## 6. Уведомления

Строка статуса — единственный канал, правила из прежнего дизайна (раздел 5)
сохраняются. Новое событие: «<сессия> ждёт разрешения» при переходе в `blocked`
у неподключённой сессии. Событие гаснет при подключении к сессии-источнику.

## 7. Глифы и цвета

Индикатор состояния — один глиф `●` с цветом (раздел 4.1); ASCII-запасной `*`.
Остальные глифы и правила усечения — из прежнего дизайна (6.1–6.4), с двумя
уточнениями: слово состояния справа не отбрасывается никогда, ярлык усекается
до 4 знаков минимум; при ширине сайдбара 18 слово состояния заменяется одним
глифом.

Мигание `working`: чередование глифа `●` и `○` того же цвета раз в секунду.
`NO_COLOR` или монохром: состояния различаются словом справа, мигание остаётся.

## 8. Что меняется относительно прежних документов

- Режим «все сессии» и клавиша `w` как переключатель режимов **удаляются**.
  История доступна через пикер `prefix g`.
- Панель ДЕТАЛИ **заменяется** компактной строкой в сайдбаре и оверлеем.
- `Ctrl+Q` как «вернуть фокус» **заменяется** префиксом. Опция
  `HARNAS_ESCAPE_KEY` становится `HARNAS_PREFIX`.
- Рамки панелей и заголовки `SESSIONS` / `SUBSESSIONS` / `TERMINAL`
  **удаляются**.
- В спецификацию координации **добавляется** поле `activity` у сессии и команда
  `harnas-core hook`.
- Раздел 7 спецификации координации (изменения в TUI) **заменяется** этим
  документом.
- Provider-фильтр `p`, маркеры `Cl/Cx/GL` и бейдж провайдера **не показываются**,
  пока провайдер один; реестр и адаптеры Codex остаются в core.
- Сплит (раздел 2.5 прежнего дизайна) остаётся отложенным.

## 9. Ошибки и граничные случаи

- `--settings` не принят бинарём (старая версия Claude Code): сессия запускается
  без хуков, состояния идут только от страховки, в строке статуса разовое
  предупреждение.
- Хук не смог записать карту (блокировка занята): хук завершается с нулевым кодом,
  чтобы не мешать Claude, и пишет предупреждение в лог харнесса; страховка
  выправит состояние.
- Два харнеса на одном проекте — не поддерживается, как и раньше.
- Терминал уже 60 колонок: сайдбар прячется автоматически, доступен по `prefix b`
  как оверлей.
- Префикс перехвачен внешним терминалом: пользователь меняет его через
  `HARNAS_PREFIX`; в справке первой строкой написано, как это сделать.

## 10. Тесты

- **Сайдбар, оверлеи, пикеры, строка статуса** — ink-testing-library, фикстуры
  карт во временной директории, `HARNAS_HOME` во временной папке.
- **Префикс и мышь** — тесты маршрутизации ввода: байты до и после префикса,
  двойной префикс, клики по координатам сайдбара и панели.
- **Состояния** — `harnas-core hook` на временной карте для каждого события;
  страховка по jsonl на фикстурах; переход `unseen → idle` при подключении.
- **Запуск** — stub-бинарь получает `--session-id`, `--mcp-config`, `--settings`;
  содержимое файла настроек проверяется на наличие всех хуков.
- Настоящий `claude` в тестах не запускается никогда.

## 11. Вне объёма

- Сплиты и несколько панелей.
- Фоновый сервер и detach/reattach.
- Codex и GLM в интерфейсе (реестр остаётся).
- Свой агентский цикл для API-провайдеров.
