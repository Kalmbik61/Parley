# TUI v2: сайдбар и одна панель (по образцу herdr) — дизайн

Дата: 2026-09-05. Статус: согласовано, прошло инженерное ревью (`/plan-eng-review`,
восемь решений внесены), ждёт макетов и реализации через Workflow.
Провайдер в этой версии один: Claude Code. Codex и GLM остаются в реестре
`packages/core/src/providers.ts`, но в интерфейсе не показываются, пока провайдер
один.

Заменяет в части раскладки, ввода и панели ДЕТАЛИ документ
`docs/specs/2026-09-02-coordination-tui-design.md`. Карта работы, MCP-инструменты,
бриф, реестр провайдеров из `docs/specs/2026-09-02-coordination-design.md`
остаются в силе с поправками раздела 9 ниже.

---

## 1. Зачем

Текущий TUI зеркалит историю `~/.claude`: список сессий скачет при каждом событии,
режим «работы» спрятан за клавишей `w`, панель ДЕТАЛИ делает левую колонку тяжёлой,
а фокус между списками и терминалом переключается вручную через `Ctrl+Q`.

Образец — интерфейс herdr (https://github.com/herdrdev/herdr): узкий сайдбар без
рамок, одна главная область целиком под агента, все клавиши идут агенту, харнесс
слушает только префикс и мышь, а состояние агента видно цветной точкой.

Решения, принятые в обсуждении и на ревью:

| Вопрос | Решение |
|---|---|
| Сплиты главной области | Нет. Одна панель, переключение через сайдбар. Раскладка хранится так, чтобы вторая панель не потребовала переделки |
| Источник состояния агента | Хуки Claude Code через `--settings` плюс jsonl-watcher как страховка |
| Доставка событий хука | Хук только дописывает stdin-JSON в `events/<session>.jsonl`; состояние выводят читатели (ревью, иссу 1) |
| Набор хуков | Полный: promptы, разрешения, вопросы агента, elicitation, Stop, субагенты, SessionStart/End (ревью, иссу 3) |
| Живость после перезапуска | По `pid` и времени старта процесса, записанным в карту (ревью, иссу 2) |
| Ось простоя | Одна: статус `idle` из жизненного цикла карты удаляется, `activity` выводится одной функцией core (ревью, иссу 6) |
| Настройки | `~/.harnas/config.json`, переменные `HARNAS_*` перекрывают; мышь выключаема (ревью, иссу 4) |
| Быстрая сессия без работы | `new` сразу открывает Claude, работа создаётся автоматически с заголовком из первой реплики |
| Детали сессии | Компактно под выбранной сессией в сайдбаре, полностью в оверлее по запросу |
| Персистентность панелей между запусками харнесса | Не делаем: транскрипт хранит сам Claude, после перезапуска сессии возобновляются через `--resume` |
| Префикс | `ctrl+q`, настраивается. `ctrl+b` занят Claude Code («запустить в фоне») |
| Объём | Один заход, без разбиения на фазы (ревью, Step 0) |

Юридическая рамка без изменений: запускается только немодифицированный `claude` из
PATH под логином пользователя, `~/.claude` только на чтение, `.credentials.json`
не трогать. Флаг `--settings` и хуки — документированные возможности Claude Code
(проверено по `code.claude.com/docs/en/hooks` и `cli-reference` 2026-09-05),
бинарь не модифицируется.

## 2. Раскладка

Три зоны: сайдбар слева, панель справа, строка статуса внизу. Рамок нет, между
сайдбаром и панелью тонкий вертикальный разделитель.

```
 1 Авторизация          ●     │
   ~/dev/shop · main          │
 2 Платежи               ●    │  (панель Claude Code — целиком его,
   ~/dev/shop · feat/pay      │   никаких заголовков и подписей харнесса)
                              │
 new                          │
──────────────────────────────│
 сессии · Авторизация         │
 ● план            working    │
   ↑1.2к ↓845 · 12м · ▤1      │
 ● бэкенд          blocked    │
   └ ● ревью        unseen    │
 ○ тесты           exited     │
                              │
 ⚑ бэкенд ждёт разрешения                                  ctrl+q ?
```

### 2.1 Сайдбар

Ширина по умолчанию 26 колонок (`sidebarWidth` в конфиге); на терминале уже 80
колонок сайдбар сворачивается до 18 (только номера, глифы и усечённые заголовки),
а по `prefix b` прячется совсем.

**Верх — работы.** Пронумерованы 1..9 (дальше без номера), заголовок, второй строкой
проект (хвост пути) и ветка git. Справа точка состояния работы — максимум по её
сессиям (раздел 4). Выбранная работа подсвечена фоном. Сортировка: `active`
работы по времени последнего события, `done` ниже и свёрнуты в одну строку,
`archived` скрыты.

**Строка `new`.** Одна на сайдбар. `Enter` или клик — новая сессия Claude
(раздел 5.1). Если работ нет, это единственная строка верхней части.

**Низ — сессии выбранной работы.** Заголовок `сессии · <работа>`. Дерево по
`parent` с отступом и глифом `└` у дочерних. Строка сессии: глиф состояния, ярлык
(`label`), справа слово состояния. Под **выбранной** сессией одна компактная
строка: токены вход/выход, длительность, `▤N` непрочитанных, `⋮N` живых
субагентов, если есть. Сортировка — порядок дерева по `createdAt`, стабильный:
строки не переставляются при событиях, меняются только глифы и слова.

Ярлык сессии, порождённой агентом, — `label` из `spawn_session`. Ярлык сессии,
созданной через `new`, — заголовок Claude Code (`custom-title` / `ai-title` /
первая реплика, по существующей цепочке core), пока пользователь не переименовал.

### 2.2 Панель

Одна, на всю оставшуюся ширину и высоту между верхом терминала и строкой статуса.
Внутри — PTY с `claude`, рендер через `@xterm/headless` как сейчас, с курсором
гостя. Харнесс ничего не рисует поверх панели.

Когда выбранная сессия не запущена (`pending`, `exited`, `done`, `failed`) или
запущена вне харнесса (раздел 5.4), панель показывает карточку сессии: ярлык,
состояние, последнее резюме и подсказку действия (`Enter — запустить` /
`Enter — возобновить` / `запущена вне харнесса, подключение невозможно`). Это
единственный случай, когда панель рисует харнесс.

### 2.3 Строка статуса

Одна строка внизу на всю ширину. Слева последнее событие `⚑` (как в прежнем
дизайне: pending от агента, новое сообщение, сессия вышла без отчёта, агент ждёт
разрешения или ответа, готово авто-резюме, ошибка конфига). Справа подсказка
`ctrl+q ?`. Во время ожидания второй клавиши префикса строка показывает `ctrl+q …`
и список основных действий.

### 2.4 Оверлеи

Рисуются поверх панели, центрированы, с рамкой, закрываются `Esc`. Пока оверлей
открыт, ввод идёт ему, а не гостю. Все оверлеи строятся на одном компоненте
`overlay.tsx` поверх существующего `dialog.tsx`.

- **Детали сессии** (`prefix i`): задача, состояние с временем с последнего события
  и кодом выхода, токены по четырём счётчикам, сводка с пометкой источника, входящие
  (непрочитанные и последние 5 прочитанных), артефакты, субагенты, история
  переходов, цель работы (редактируется здесь же, если пуста).
- **Пикер работ** (`prefix w`): все работы из глобального индекса, включая другие
  проекты, с фильтром по набору текста. `Enter` выбирает работу в сайдбаре.
- **Пикер истории** (`prefix g`): сессии `~/.claude` текущего проекта по свежести,
  с заголовком, возрастом, длительностью и токенами; фильтр по тексту. `Enter`
  возобновляет сессию в текущей работе (раздел 5.3).
- **Справка** (`prefix ?`): все действующие привязки с фильтром; первой строкой —
  как сменить префикс, если его перехватывает терминал.
- **Подтверждения**: закрытие сессии, запуск `pending` с показом брифа (прежний
  дизайн 4.3), возобновление (4.4), дозаказ резюме (4.5).

## 3. Ввод

### 3.1 Модель

Все клавиши идут в панель, включая стрелки, `Tab`, `Esc`, `Ctrl+C`. Харнесс
перехватывает только:

- **префикс** (`prefix` в конфиге, по умолчанию `ctrl+q`, байт 0x11): после него
  одна клавиша действия; неизвестная клавиша отменяет префикс и никуда не уходит,
  второй `ctrl+q` отправляет `ctrl+q` гостю. Префикс распознаётся в любом месте
  входящего чанка: байты до него уходят гостю, байты после — действию;
- **мышь** (раздел 3.3), если `mouseCapture` включён;
- ввод, пока открыт оверлей или сайдбар в режиме навигации.

### 3.2 Действия по префиксу

| Клавиша | Действие |
|---|---|
| `c` | новая сессия Claude в выбранной работе (или новая работа, если работ нет) |
| `w` | пикер работ |
| `g` | пикер истории для возобновления |
| `i` | оверлей деталей выбранной сессии |
| `j` / `k` | следующая / предыдущая сессия в сайдбаре с подключением к панели |
| `1`..`9` | подключиться к сессии с этим номером в сайдбаре |
| `s` | фокус в сайдбар: стрелки и `j`/`k` ходят по строкам, `Enter` подключает, `Esc` возвращает в панель |
| `b` | спрятать / показать сайдбар |
| `x` | закрыть выбранную сессию (SIGHUP процессу) с подтверждением |
| `r` | возобновить выбранную `exited`/`done`/`failed` сессию (диалог возобновления) |
| `R` | дозаказать резюме для `exited` сессии |
| `?` | справка по привязкам |
| `q` | выйти из харнесса с подтверждением, если есть живые сессии |
| `ctrl+q` | отправить `ctrl+q` гостю |

Ключи, занятые Claude Code (`ctrl+b`, `ctrl+c`, `ctrl+d`, `ctrl+l`, `ctrl+o`,
`ctrl+r`, `ctrl+t`, `Esc`), харнесс не использует без префикса.

### 3.3 Мышь

При `mouseCapture: true` (по умолчанию) харнесс держит SGR-отслеживание мыши
включённым всегда, как Claude Code. Клик по строке работы выбирает её, клик по
строке сессии выбирает и подключает, клик по `new` создаёт сессию. Клик и колесо
в области панели транслируются гостю с пересчётом координат, если гость запросил
отслеживание мыши; иначе колесо листает скроллбэк нашего буфера. Выделение текста —
родное через `option`/`shift`-клик, как у Claude Code, это фиксируется в README.

При `mouseCapture: false` харнесс мышь не включает и кликов не ловит; если гость
сам запросил отслеживание, оно пробрасывается как сейчас.

### 3.4 Конфигурация

`~/.harnas/config.json` (в `HARNAS_HOME`), необязательный:

```json
{
  "prefix": "q",
  "sidebarWidth": 26,
  "mouseCapture": true,
  "ascii": false,
  "silenceThresholdMs": 30000
}
```

Переменные окружения `HARNAS_PREFIX`, `HARNAS_SIDEBAR_WIDTH`, `HARNAS_MOUSE`,
`HARNAS_ASCII`, `HARNAS_SILENCE_MS` перекрывают файл. Загрузчик один, в core
(`config.ts`), с дефолтами и валидацией; битый файл → дефолты и событие `⚑` в
строке статуса. `HARNAS_ESCAPE_KEY` больше не читается.

## 4. Состояния сессии

### 4.1 Две оси

**Жизненный цикл** в карте: `pending`, `active`, `exited`, `done`, `failed`.
Статус `idle` из спецификации координации удаляется (раздел 9): о том, что делает
живой агент, говорит вторая ось.

**Activity** — рантайм-состояние `active` сессии. В карту не пишется, выводится
читателями одной функцией core `activityOf(events, log, seen, now)` из журнала
событий (раздел 4.2) и, как страховка, из jsonl-лога (раздел 4.3):

| `activity` | Индикатор | Слово | Смысл |
|---|---|---|---|
| `working` | серый, мигает 1 Гц | working | агент думает или выполняет инструменты |
| `blocked` | жёлтый | blocked | ждёт разрешения, ответа на вопрос или ввода для MCP |
| `unseen` | синий | unseen | ход закончен, пользователь ещё не подключался к панели |
| `idle` | тусклый | idle | ждёт ввода, пользователь это видел |

Остальные статусы карты показываются как раньше: `pending` тусклый `◌`,
`exited` тусклый `○`, `done` `✓` (без цвета, работа завершена отчётом),
`failed` красный `✗`. Мигание — единственный таймер в UI (раздел 8).

Состояние работы — максимум по её сессиям в порядке `blocked` > `working` >
`unseen` > остальное; цвет точки тот же.

«Видел / не видел» (`seen`) — состояние клиента TUI в памяти, не карты: `unseen`
переходит в `idle`, когда сессия подключена к панели и панель на экране.
Подключение — через сайдбар, `prefix j/k/1..9` или клик. Чтение через оверлей
деталей не считается просмотром. После перезапуска харнесса все завершившие ход
сессии считаются `idle`.

### 4.2 Источник: хуки Claude Code

Харнесс задаёт процессу `claude` переменные `HARNAS_WORK_DIR` и
`HARNAS_SESSION_ID` (те же, что MCP-серверу) и передаёт `--settings
<work>/settings.json`. Файл настроек **один на работу**, потому что команда хука
не зависит от сессии:

```json
{
  "hooks": {
    "UserPromptSubmit":  [{ "hooks": [{ "type": "command", "command": "cat >> \"$HARNAS_WORK_DIR/events/$HARNAS_SESSION_ID.jsonl\"" }] }],
    "Notification":      [{ "hooks": [{ "type": "command", "command": "…та же команда…" }] }],
    "PermissionRequest": [{ "hooks": [{ "type": "command", "command": "…" }] }],
    "Stop":              [{ "hooks": [{ "type": "command", "command": "…" }] }],
    "SubagentStart":     [{ "hooks": [{ "type": "command", "command": "…" }] }],
    "SubagentStop":      [{ "hooks": [{ "type": "command", "command": "…" }] }],
    "SessionStart":      [{ "hooks": [{ "type": "command", "command": "…" }] }],
    "SessionEnd":        [{ "hooks": [{ "type": "command", "command": "…", "timeout": 5 }] }]
  }
}
```

Хук не содержит логики: stdin-JSON от Claude Code дописывается в журнал сессии
как есть. Код выхода всегда 0 (у `UserPromptSubmit` код 2 стёр бы промпт
пользователя). `--settings` мержится с настройками пользователя, чужие хуки не
удаляются. Ничего в `~/.claude` не пишется.

Свёртка событий в `activity` (`core/work/activity.ts`, чистая функция, табличные
тесты):

| Событие (`hook_event_name`, `notification_type`) | Переход |
|---|---|
| `UserPromptSubmit` | → `working` |
| `SessionStart` (любой `startup_type`) | → `working` |
| `Notification` / `permission_prompt`, `agent_needs_input`, `elicitation_dialog`, `elicitation_url_dialog` | → `blocked` |
| `PermissionRequest` | → `blocked` |
| `Notification` / `elicitation_complete`, `elicitation_response` | → `working` |
| `Stop` | → ход закончен (`unseen` или `idle` по `seen`) |
| `Notification` / `idle_prompt` | → ход закончен, если не `blocked` |
| `SubagentStart` / `SubagentStop` | счётчик живых субагентов ±1, не ниже 0 |
| `SessionEnd` | → жизненный цикл `exited`, если не было `report` |
| прочие события, битая строка | игнорируются, не падение |

Порядок — порядок строк в файле. `events.ts` читает файл инкрементально с
запомненного смещения, а не целиком на каждое изменение; watcher core
расширяется на каталог `events/` работы.

### 4.3 Страховка: jsonl-watcher

Та же функция `activityOf` принимает индекс лога: новая запись ассистента →
`working`; тишина дольше `silenceThresholdMs` (по умолчанию 30 секунд) после
последней записи ассистента без `Stop` → ход закончен. Страховка не понижает
`blocked`: снять его может только событие хука или новая запись пользователя.
Если каталога `events/` нет (старый Claude Code без `--settings`), работает
только страховка, а в строке статуса разовое предупреждение.

Существующие `deriveStatus` и `IDLE_THRESHOLD_MS` в `core/work/metrics.ts`
удаляются вместе со статусом `idle`; «молчит Nм» в деталях становится временем с
последнего события любой оси.

## 5. Создание и возобновление

### 5.1 `new`

Без диалога. Харнесс создаёт запись сессии `pending` с ярлыком «новая сессия»,
запускает `claude --session-id <uuid> --mcp-config <…> --settings <…>` в панели
с переменными `HARNAS_*` в окружении и сразу подключает. В карту при старте
записываются `pid`, `startedAtProcess` (время старта процесса из ОС) и
`launchedBy: "tui"`. Работа: если выбрана — сессия ложится в неё; если работ нет
или выбрана строка `new` верхнего уровня — создаётся новая работа с заголовком
«без названия» и пустой целью. Как только у сессии появляется заголовок Claude
Code, ярлык сессии и, для новой работы, её заголовок обновляются из него один
раз; дальнейшие переименования — только руками.

Бриф для такой сессии не пишется: она стартует без промпта, а карту и правила
агент получает через MCP. `contextFrom` пуст.

### 5.2 Порождённые агентом

`spawn_session` создаёт `pending` с брифом, как в спецификации координации.
В сайдбаре строка появляется с синей точкой внимания и событием `⚑`. `Enter` в
сайдбаре или клик открывает диалог запуска с брифом, `Enter` запускает.

### 5.3 Возобновление из истории

Пикер `prefix g` показывает сессии `~/.claude` текущего проекта. `Enter`
регистрирует выбранную сессию в текущей работе (`providerSessionId` = её uuid,
ярлык из её заголовка, `history` начинается с `active`) и запускает
`claude --resume <uuid> --mcp-config <…> --settings <…>`. Метрики считаются по
всему транскрипту, включая часть до регистрации.

### 5.4 Перезапуск харнесса и сессии вне него

`harnas-core work session new` пишет `launchedBy: "cli"` и, если запуск идёт через
напечатанную команду, pid неизвестен (`null`).

При старте харнесс проверяет каждую `active` сессию: если `pid` записан, процесс
жив (`process.kill(pid, 0)`) и его время старта совпадает с `startedAtProcess`,
сессия остаётся `active` с пометкой «вне харнесса» (панель показывает карточку,
подключение невозможно, детали доступны); иначе → `exited` с записью в history
(`exitCode: null`). Сессии с `pid: null` считаются живыми, пока лог обновляется, и
`exited` после `silenceThresholdMs` × 10. Та же проверка выполняется по событию
watcher, не по таймеру, и ловит процессы, убитые снаружи во время работы.

`prefix r` возобновляет `exited` через `--resume`.

## 7. Глифы и цвета

Индикатор состояния — один глиф `●` с цветом (раздел 4.1); ASCII-запасной `*`.
Остальные глифы и правила усечения — из прежнего дизайна (6.1–6.4), с двумя

`NO_COLOR` или монохром: состояния различаются словом справа, мигание остаётся.

## 9. Что меняется относительно прежних документов

- Режим «все сессии» и клавиша `w` как переключатель режимов **удаляются**.
  История доступна через пикер `prefix g`.
- Панель ДЕТАЛИ **заменяется** компактной строкой в сайдбаре и оверлеем.
- `Ctrl+Q` как «вернуть фокус» **заменяется** префиксом. `HARNAS_ESCAPE_KEY`
  **заменяется** конфигом и `HARNAS_PREFIX`.
- Рамки панелей и заголовки `SESSIONS` / `SUBSESSIONS` / `TERMINAL`
  **удаляются**.
- В спецификации координации: статус `idle` **удаляется** из жизненного цикла
  (старые карты с `idle` читаются как `active`); у сессии **добавляются** поля
  `pid`, `startedAtProcess`, `launchedBy`; в раскладке работы **добавляются**
  `events/` и `settings.json`; раздел 7 (изменения в TUI) **заменяется** этим
  документом; команда `harnas-core hook` **не вводится**.
- Provider-фильтр `p`, маркеры `Cl/Cx/GL` и бейдж провайдера **не показываются**,
  пока провайдер один; реестр и адаптеры Codex остаются в core.
- Сплит (раздел 2.5 прежнего дизайна) остаётся отложенным, см. `TODOS.md`.

## 10. Ошибки и граничные случаи

- `--settings` не принят бинарём (старая версия Claude Code): сессия запускается
  без хуков, состояния идут только от страховки, в строке статуса разовое
  предупреждение.
- Каталог `events/` недоступен для записи: хук завершается нулём (ошибка `cat`
  подавляется `|| true`), страховка ведёт состояние.
- Битая строка в журнале событий пропускается.
- pid переиспользован ОС: расхождение `startedAtProcess` → `exited`.
- Два харнеса на одном проекте — не поддерживается, как и раньше.
- Терминал уже 60 колонок: сайдбар прячется автоматически, доступен по `prefix b`
  как оверлей.
- Префикс перехвачен внешним терминалом: пользователь меняет его в конфиге; в
  справке первой строкой написано, как это сделать.
- Битый `config.json`: дефолты и событие `⚑`.
