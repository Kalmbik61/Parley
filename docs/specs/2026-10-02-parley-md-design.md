## 1. Зачем

Агенты разных провайдеров в одном проекте знают разное.

1. **Каждый CLI читает свой файл.** Claude Code читает CLAUDE.md, а AGENTS.md —
   только когда CLAUDE.md нет. Codex читает AGENTS.md, а CLAUDE.md по умолчанию не
   читает никогда. В проекте только с CLAUDE.md (AI_APP, DentalBot, course-platform)
   сессия Codex правил проекта не видит.
2. **Свои правила Parley доходят только до Claude.** Системная вставка
   (`systemGuidance`) уезжает через `--append-system-prompt`. У шаблона Codex
   подстановки `{systemPrompt}` нет, и встроенных правил Codex не получает вовсе —
   только бриф первым сообщением, MCP `parley` и навык. Встроенная запись GLM
   запускает команду `glm` без аргументов; человек может подменить её в
   `~/.parley/providers.json` — на машине разработки это обёртка `claude-glm` с
   шаблонами Claude.
3. **Тихая сессия Codex остаётся без брифа.** Бриф сессии без задачи едет системной
   вставкой (`launch.ts`, `quiet`), а у Codex её нет — бриф не доходит никаким путём.
4. **Правилам совместной работы негде жить.** Кто ведёт комнаты, кто ревьюит, какой
   провайдер на что — это не правила проекта для одного агента, а правила команды
   агентов в Parley. CLAUDE.md и AGENTS.md для них не место: их читают и вне Parley,
   а часто ещё и пишут другие инструменты (GSD собирает CLAUDE.md по меткам, OMC и
   gstack дописывают свои блоки).

## 2. Решения

| Вопрос | Решение |
|---|---|
| Сводка CLAUDE.md и AGENTS.md | Не делаем. Агенты читают свои файлы как раньше, Parley их не выключает и не пересказывает. Сжатие ради токенов отложено |
| Что такое PARLEY.md | Правила совместной работы агентов в Parley. Пишет человек. Лежит в корне проекта обычным файлом; коммитить его или нет, решает человек |
| Что получает сессия | Слой Parley: встроенные правила, строка моста (только Codex), бриф тихой сессии, PARLEY.md |
| Доставка | Claude — `--append-system-prompt`, как сейчас; Codex — новый `-c developer_instructions`; GLM — встроенная запись без изменений, подмена на шаблонах Claude получает слой через `{systemPrompt}` |
| Мост между файлами | Codex — `-c project_doc_fallback_filenames=["CLAUDE.md"]`; Claude — ничего (без CLAUDE.md он читает AGENTS.md сам); в проекте оба файла — каждый агент читает свой |
| Откуда читается PARLEY.md | Из корня проекта — и для сессий в worktree |
| Как появляется | Хост кладёт шаблон перед первой сессией окна в проекте, один раз; удалённый человеком файл сам не возвращается; в меню «⋯» заголовка проекта — Open/Create PARLEY.md |
| Нетронутый шаблон | Не стоит токенов: HTML-комментарии и пустые разделы агентам не уходят |
| Предел | 32 КБ после обработки; длиннее — обрезка по строке и уведомление |

## 3. Слой Parley

### 3.1 Состав и порядок

Для каждой сессии — при запуске, возобновлении и быстром старте — Parley собирает
текст из частей в таком порядке; пустые части выпадают:

1. **Встроенные правила** — `systemGuidance(map, sessionId)` как сейчас; потолок в
   14 строк не меняется.
2. **Строка моста** — только у Codex и только когда мост действует (раздел 4.2).
3. **Блок роли** — если роль задана; нативная роль Claude доставляется через `--agent`
   и не дублируется в слое (спека ролей).
4. **Плейбук рецепта** — только ведущему, снимок комнаты (спека рецептов).
5. **Бриф тихой сессии** — `writtenBrief`, если у сессии нет задачи, как сейчас.
6. **PARLEY.md** — после обработки (раздел 5.2) под строкой-заголовком
   `Team rules of this project (PARLEY.md):`.
7. **Память проекта** — только факты-фразы, до 12 КБ (спека памяти).

Навигатор добавляет условную подсказку в существующую строку `read_guide`, а не
тела скиллов и не отдельный блок. Она появляется только при доступном `find_skill`.
Все расширения `systemGuidance` проверяются вместе: потолок остаётся 14 строк.

Части разделяются пустой строкой. Нетихая сессия по-прежнему получает бриф первым
сообщением, а не в слое.

### 3.2 Доставка по провайдерам

| | Claude | Codex | GLM |
|---|---|---|---|
| Слой | `--append-system-prompt {systemPrompt}` — как сейчас, при запуске и `resume` | `-c {developerInstructions}` — новая подстановка: готовая пара `developer_instructions=<строка TOML>`, при запуске и `resume` (в `CODEX_CONFIG_FLAGS`) | встроенная запись не меняется; подмена в `providers.json` с `{systemPrompt}` (обёртка `claude-glm`) получает слой так же, как Claude |
| Мост | — | `-c project_doc_fallback_filenames=["CLAUDE.md"]` — постоянная пара в `CODEX_CONFIG_FLAGS` | — |

- Значение `developer_instructions` — вывод `JSON.stringify(текст)`: это валидная
  базовая строка TOML, а `-c` разбирает значение как TOML. Кавычки, `'''`, `"""`,
  обратные слэши и переводы строк флаг не ломают. Аргументы уходят отдельными
  элементами argv, без оболочки.
- Пустая подстановка выбрасывает пару целиком, как у `{mcpConfig}`. На деле слой не
  пуст никогда: встроенные правила есть всегда.
- Кто подменил аргументы Codex через `providers.json` без `{developerInstructions}`,
  слоя и моста не получит — это его подмена; подстановка описывается в README, а хост
  предупреждает о такой подмене (раздел 7). На машине разработки так и есть: запись
  `codex` от 2026-09-25 целиком заменяет `args` и `resumeArgs`; убрать или обновить её
  решает человек.

### 3.3 Общий предел аргументов

Сборщик проверяет каждый окончательный аргумент после TOML/JSON-экранирования в
байтах UTF-8: предел Parley — 96 КиБ (98 304 байта), включая ключ
`developer_instructions=`. Отдельные пределы блоков сохраняются. Если итог не
помещается, запуск возвращает `session-layer-too-large` с размерами блоков до
создания процесса: человек сокращает правила, роль, плейбук или бриф. Удалять
инструкции молча нельзя. Это overflow **итогового** аргумента после documented marked preprocessing отдельных блоков (§5.2, роли §5.2, рецепты §6.3), не отказ от их обрезки с marker/warning. 96 КиБ — product ceiling, не обещание ОС.

Host непосредственно перед `pty.start`, после merge `agentEnv(process.env)`,
`plan.env` и `PARLEY_HOOK_TOKEN`, проверяет final executable/argv/env:

```text
stringBytes = sum(utf8Bytes(s) + 1 NUL for s in [executable, ...argv])
            + sum(utf8Bytes(key + "=" + finalValue) + 1 NUL)
estimatedBytes = stringBytes + pointerSize * (argc + envc + 2) + 32768 reserve
require estimatedBytes <= runtime ARG_MAX
```

NUL запрещён; runtime limits bounded/injectable. На Linux каждую строку argv/env
с NUL проверять против `32 * pageSize`; ARG_MAX зависит от stack limit. Нет limits
→ безопасная pre-spawn ошибка; E2BIG очищается без raw argv/env. Aggregate env/other
args overflow — отдельная spawn-budget ошибка; hook token unregister при guard
failure. Core-only tests не доказывают окончательный env guard. macOS synthetic
probe принят, Linux/long paths/custom env/providers остаются gates P32 по
[контракту §6](../research/2026-10-03-parley-cli/contracts.md#6-p09-utf-8-argv-и-окончательное-окружение).

Непустой generated suppression Codex candidate (production off) проверяется отдельно: overflow убирает **весь** generated список, сохраняя human User/SessionFlags и native list; final args/env пересобираются и проверяются вновь. Если overflow остаётся, отказ до spawn. Проверка общая для launch/quick/auto/resume. Host log получает безопасные warnings каждой попытки; user notices PARLEY.md — once host/project, `provider-override-gap` — once host global. Обычная custom подмена без placeholder сохраняет warning+launch; только обязательная недоставимая роль/permissions даёт отказ.

### 3.4 Когда агент видит изменения

- **Новая сессия** получает текущий PARLEY.md с первого хода.
- **Возобновлённая** получает правку только после сжатия контекста. Claude Code
  записывает системный промпт на первом запросе разговора и до сжатия использует
  записанный, в том числе после `--resume` (cli-reference, «System prompt flags in
  resumed conversations»). Codex при `resume` не сравнивает `developer_instructions`
  с сохранённым и новый текст до сжатия не шлёт (исходники 0.156.1).
- **Идущая** сессия правку не видит до перезапуска: текст передан флагом при старте
  процесса.

## 4. Мост

### 4.1 Что читает каждый

Папка сессии — её рабочая папка: корень проекта или путь worktree.

| В папке сессии | Claude | Codex |
|---|---|---|
| только AGENTS.md | AGENTS.md — читает сам (Claude Code ≥ 2.1.277) | AGENTS.md |
| только CLAUDE.md | CLAUDE.md | CLAUDE.md — через мост |
| оба | CLAUDE.md | AGENTS.md |
| ни одного | — | — |

Когда в проекте оба файла, их авторы уже решили, что писать какому агенту
(VoiceStudio: AGENTS.md — рабочий договор для всех агентов, CLAUDE.md — полная
«конституция», и при расхождении главнее она). Parley это не перебивает: ключ
`claude-md-and-agents-md` в `--settings` не ставится.

Fallback Codex читает CLAUDE.md только в тех папках от корня репозитория до папки
запуска, где нет ни `AGENTS.override.md`, ни `AGENTS.md`, и делит с ними общий бюджет
`project_doc_max_bytes` (32 КиБ по умолчанию).

### 4.2 Строка моста

Если в папке сессии Codex есть файл `CLAUDE.md` и нет ни `AGENTS.md`, ни
`AGENTS.override.md`, слой Codex получает строку:

> Project instructions here were written for Claude Code (CLAUDE.md): they may name
> skills, slash commands or tools you don't have — skip those parts.

Пример, ради которого она нужна: CLAUDE.md в AI_APP целиком состоит из маршрутов к
навыкам Claude (`/office-hours`, `/review`, `/ship`).

## 5. Файл PARLEY.md

### 5.1 Шаблон

По-английски, как все тексты для агентов и окна:

```markdown
# PARLEY.md

<!--
Team rules for agents working together in Parley. Every agent Parley launches in this
project gets this file on top of its own instructions (CLAUDE.md, AGENTS.md).
Comments like this one and empty sections are not sent to agents.
-->

## Roles
<!-- Who leads rooms by default; which provider or model takes which kind of work. -->

## Review
<!-- Who checks whose work before it reaches the human. -->

## Git and worktrees
<!-- Branches, commits and merges; what agents must never do (for example, push). -->

## Communication
<!-- Language of messages, report format, when to stop and ask the human. -->

## Definition of done
<!-- Checks that must pass before an agent reports done. -->
```

### 5.2 Обработка перед доставкой

1. Вырезаются HTML-комментарии `<!-- … -->` вне блоков кода (```` ``` ```` и `~~~`) —
   так же Claude Code обходится с CLAUDE.md.
2. Выпадают разделы с пустым телом: заголовок ATX (`#`…`######`), под которым до
   следующего заголовка нет ничего, кроме пробельных символов. Проход идёт снизу вверх,
   поэтому заголовок, все подразделы которого выпали, выпадает тоже. Строки внутри
   блоков кода заголовками не считаются.
3. Подряд идущие пустые строки схлопываются в одну; края обрезаются.
4. Ничего не осталось — части PARLEY.md в слое нет. Нетронутый шаблон даёт пустоту.
5. Больше 32 КБ — текст обрезается по последнему переводу строки с учётом места для конечной строки `[PARLEY.md is cut at 32 KB by Parley]`; весь обработанный блок **вместе с marker** ≤32 768 байт UTF-8. Безопасный warning `parley-md-truncated` обязателен; итоговую сборку слоя повторно не обрезать.

Импорты `@path` не раскрываются, frontmatter особо не обрабатывается: это обычный
текст.

### 5.3 Откуда читается

`<корень проекта>/PARLEY.md` — для всех сессий работы, включая сессии в worktree
(`projectPath`, а не рабочая папка сессии). Незакоммиченная правка сразу действует во
всех сессиях; свой PARLEY.md в ветке worktree не учитывается. Чтение через симлинк
разрешено — это только чтение.

## 6. Создание и кнопка

### 6.1 Само при первой сессии

Хост проверяет файл перед каждым запуском сессии окна — сразу после установки навыка
(`sessions-service.ts`, `installSkill`), во всех режимах: запуск, `resume`, быстрый
старт, autoLaunch. Проверка быстрая и идемпотентная; её сбой запуск не останавливает,
а пишется в `host.log`. Настройка `agentSkills` на неё не влияет.

Учёт — `parley-md-receipt.json` в каталоге состояния проекта (`stateDir`: `.parley/`,
у проекта со старым `.harnas/` — он):
`{ "version": 1, "recordedAt": "<ISO>", "created": true | false }`.

| Состояние | Что делает хост |
|---|---|
| Учёта нет, файла нет | Кладёт шаблон эксклюзивным созданием (`wx`), пишет учёт с `created: true`, шлёт окну уведомление `parley-md-created` |
| Учёта нет, путь занят (файл человека, из git, что угодно) | Не трогает путь, пишет учёт с `created: false` — чтобы позднее удаление файла не откатилось |
| Учёт есть | Ничего — есть файл или нет: если его нет, его удалил человек |
| Создание упало (права, диск) | Учёт не пишется, попытка повторится при следующем запуске; в `host.log` — один раз за жизнь хоста на проект |

Чтобы сбой записи учёта после создания не возвращал удалённый файл, реализация
сначала эксклюзивно резервирует receipt с `created: false`, затем создаёт PARLEY.md
через `wx` и атомарно обновляет receipt на `created: true`. Если начальная запись
receipt не удалась, файл не создаётся. При ошибке создания удаляется только
собственная ещё действующая reservation; запись concurrent явного Create не
удаляется. Если файл создан, а финальное обновление receipt не удалось, начальная
receipt сохраняется и ошибка журналируется: повторного auto-create не будет.
Занятая или повреждённая receipt также запрещает auto-create и даёт безопасную
диагностику. Явный Create сохраняет прежнее поведение. Удаление человеком и файла,
и receipt между перезапусками хоста неотличимо от нового проекта.

- `wx` не пишет поверх существующего пути, в том числе поверх битой ссылки. Две
  одновременные сессии создадут файл один раз: вторая получит `EEXIST` и запишет
  `created: false`.
- Только корень проекта, в worktree — никогда. Само создание — только у хоста:
  сессии CLI `parley-core` PARLEY.md читают, но не создают — как и навык.
- Окно показывает уведомление `Parley added PARLEY.md — team rules for your agents` с
  кнопкой Open: в `git status` появился новый файл, и человек должен знать, откуда он.
- Существующие проекты после обновления получат шаблон с первой же сессии окна — это
  пишется в CHANGELOG.

### 6.2 Кнопка в окне

- Меню «⋯» заголовка проекта в сайдбаре (`SectionMenu`, секция с ключом
  `projectPath`; у секции `pinned` пункта нет): `Open PARLEY.md`, а если файла нет —
  `Create PARLEY.md`. Есть ли файл, меню узнаёт при открытии.
- Create кладёт шаблон эксклюзивным созданием и пишет учёт с `created: true`, не
  глядя на прежний учёт: это явное действие человека. Если файл успел появиться,
  пункт просто открывает его.
- Файл открывается во вкладке редактора, как любой файл проекта.
- Создание идёт из главного процесса окна через ту же функцию core, что у хоста
  (главный процесс уже зовёт `@parley/core`).

## 7. Граничные случаи

| Случай | Поведение |
|---|---|
| PARLEY.md не читается: нет прав, на его месте папка, битая ссылка | Сессия идёт без части PARLEY.md. Хост — `host.log` и уведомление `parley-md-unreadable` один раз за жизнь хоста на проект; CLI — строка в `warnings` плана запуска |
| PARLEY.md длиннее 32 КБ | Обрезка (5.2); хост — уведомление `parley-md-truncated` один раз за жизнь хоста на проект; CLI — строка в `warnings` |
| Подмена `codex` в `providers.json` без `{developerInstructions}` | Обычная custom сессия запускается без слоя/моста с warning в host.log каждой попытки и `provider-override-gap` notice once host global; подмена не меняется. Недоставимая обязательная роль/permissions — отказ по спеке ролей §5.7 |
| Свой `project_doc_fallback_filenames` в `~/.codex/config.toml` | В сессиях Parley его заменяет флаг моста. Модуль моста не читает личный конфиг; общий каталог может читать настройки ролей и скиллов только для чтения. Пишется в README |
| Claude Code старше 2.1.277 | AGENTS.md сам не читает: в проекте только с AGENTS.md такой Claude правил проекта не увидит. Пишется в README |
| `CLAUDE.local.md` рядом с AGENTS.md без CLAUDE.md | Claude по умолчанию считает его своим файлом и AGENTS.md не читает — так устроен Claude Code. Пишется в README |
| Только `.claude/CLAUDE.md`, без `CLAUDE.md` в папке | Codex его не видит: fallback принимает только голое имя файла. Пишется в README |
| Проект — не git-репозиторий | Всё так же: PARLEY.md — просто файл |
| Длина аргумента | Ограничения отдельных блоков недостаточны: роль, рецепт, память и экранирование увеличивают итог. Общая проверка сериализованного argv — раздел 3.3 |

## 8. Тесты

**core (vitest):**
- обработка: комментарии вне и внутри блоков кода, вложенные пустые разделы,
  нетронутый шаблон даёт пустоту, обрезка по 32 КБ со строкой-меткой;
- сборка слоя: порядок всех частей, включая роль/рецепт/память; общий размер
  окончательного argv после экранирования, ошибка до spawn; строка моста — только у Codex и только при `CLAUDE.md`
  без `AGENTS.md` и `AGENTS.override.md` в папке сессии (корень и worktree);
- аргументы: Claude — слой в `--append-system-prompt` при запуске и `resume`;
  Codex — пара `developer_instructions` и мост при запуске и `resume`; GLM — без
  изменений; тихая сессия Codex получает бриф в `developer_instructions`;
- создание: один раз; занятый путь не трогается; удалённый файл не возвращается;
  Create не смотрит на учёт; worktree не трогается; ошибка наружу не бросается;
- уже существующие проверки остаются зелёными: потолок в 14 строк у `systemGuidance`,
  английские тексты (`english-text.test.ts`).

**host:** создание перед запуском во всех режимах; сбой не останавливает запуск;
warnings — в host.log каждой попытки; PARLEY.md notices — один раз host/project, `provider-override-gap` — один раз host global без повторов по проекту/provider. Plain custom Codex без placeholder запускается с предупреждением; обязательная недоставимая роль/permissions даёт отказ. Final env/hook token guard и token cleanup проверяются host-тестом; Linux runtime отдельно gate.

**окно:** пункт Open/Create в `SectionMenu` по наличию файла; e2e по образцу
`agent-skills.spec.ts`: Create → файл на диске → вкладка редактора.

## Приложение. Что читают CLI (проверено 2026-10-02)

**Claude Code 2.1.287** (code.claude.com/docs/en/memory, …/cli-reference):
- CLAUDE.md, `.claude/CLAUDE.md` и `CLAUDE.local.md` от папки запуска вверх,
  `~/.claude/CLAUDE.md`, правила `.claude/rules/*.md`; вложенные CLAUDE.md — по мере
  чтения файлов в их папках.
- AGENTS.md (с 2.1.277): по умолчанию (`claude-md-or-agents-md`) — только когда нет
  CLAUDE.md и `CLAUDE.local.md`. Читать оба —
  `pluginConfigs."agents-md@builtin".options.instructionFiles = "claude-md-and-agents-md"`
  в `~/.claude/settings.json`, файле `--settings` или managed; в проектных настройках
  ключ игнорируется.
- HTML-комментарии в CLAUDE.md вырезаются перед подачей модели; CLAUDE.md подаётся
  пользовательским сообщением после системного промпта.
- `--append-system-prompt` работает и интерактивно. Системный промпт записывается на
  первом запросе разговора и до сжатия используется записанный, в том числе после
  `--resume`; `--system-prompt-snapshot off` (≥ 2.1.257) пересобирает его на каждом
  запросе.
- CLAUDE.md корня переживает `/compact`: перечитывается с диска.
- `claudeMdExcludes` исключает файлы по шаблону абсолютного пути (в этом дизайне не
  используется).

**Codex 0.156.1** (исходники `rust-v0.156.1`, `codex debug prompt-input`):
- AGENTS.md: глобальный (`$CODEX_HOME`: `AGENTS.override.md`, иначе `AGENTS.md`) и
  проектные — в каждой папке от корня (маркер `.git`) до папки запуска первый из
  `AGENTS.override.md`, `AGENTS.md`, имён fallback. Общий бюджет проектных файлов
  `project_doc_max_bytes` = 32 768: файл на границе обрезается, следующие выпадают.
- CLAUDE.md по умолчанию не читается. `project_doc_fallback_filenames` (по умолчанию
  `[]`) читается вместо AGENTS.md и только там, где его нет; принимаются только голые
  имена файлов.
- `-c developer_instructions=…` дописывается первой частью начального
  developer-сообщения; своего предела длины у Codex нет.
- `codex resume`: история воспроизводится как записана; AGENTS.md перечитывается, и
  изменения дописываются; изменённый `developer_instructions` до сжатия не шлётся
  (вывод по `core/src/session/mod.rs`).
- Ключи `-c` делятся по точкам; значение разбирается как TOML.
