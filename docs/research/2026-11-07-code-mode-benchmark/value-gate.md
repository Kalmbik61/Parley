## Почему данных недостаточно

1. **Прирост промпта — не размер результата.** Разность `P(j+1) − P(j) − o(j)` содержит не только результат инструмента. Туда же попадают системные напоминания и уведомления, загрузка схем, хуки, изменения мышления и контекста, обрамление инструмента. Сжатие контекста может спрятать даже большой результат. Нативный размер результата дают только подсчёт токенов провайдером на точном содержимом или контролируемые парные прогоны.
2. **Граница не доказана, нулевые издержки не обоснованы.** Модель «один `code_execute` с промптом и выходом первого шага» не является нижней границей стоимости замены. Скрипт может стоить меньше `o1`. Сохранённый контекст, схемы и нужный итог могут стоить больше. Нулевые издержки обёрток, discovery, остаточных схем и ошибок противоречат принятому учёту переходной поверхности.
3. **Нет горизонта переноса и семантических границ задачи.** В классике удалённый результат остаётся в контексте и читается из кеша на каждом следующем запросе до сжатия или конца сессии. Это главный эффект Code Mode, а окно до первого потребителя его не видит. Соседние запросы когорты — не задачи с целью и принятием результата. У Codex классика уже работает как code mode внутри `exec`, а принадлежность вызовов запросам выводилась бы из накопительных счётчиков.
4. **Правило агрегации не утверждено.** Правило «GO, если GO хотя бы у одного провайдера» противоречит требованию T10 проверять и Claude, и Codex. Codex с 19 окнами не набирает минимума в 20 даже по отклонённому черновику.

## Варианты для решения человека

Ни один вариант сейчас не разрешён.

1. **Исследование нативной атрибуции токенов.** Сначала фиксируются граница личных данных и бюджет: какие результаты из замороженных транскриптов можно отправить на подсчёт токенов провайдером, кто разрешает отправку, сколько это стоит и где хранятся итоги. Затем нативный размер каждого промежуточного результата и горизонт переноса по каждому окну. Даже после этого остаются недоказанными издержки замены и семантические границы задач.
2. **Явный пересмотр гейта: изолированное контролируемое сравнение.** Человек разрешает заменить офлайн-гейт T1b парными прогонами классики и замены. Условия: изолированные копии воркспейса, заранее написанные чек-листы задач, нативный usage, оба провайдера. Это платные ходы и отдельное решение о бюджете. Сама замена для таких прогонов ещё не реализована.
