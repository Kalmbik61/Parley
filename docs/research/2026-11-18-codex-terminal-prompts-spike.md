# Спайк: вопросы Codex 0.166.0 на экране терминала

**Дата:** 2026-11-18. **Стенд:** собственный скрипт Node (`node-pty` + `@xterm/headless`, экран снимается строками так же, как `Screen.text`), настоящий `codex` 0.166.0, флаги как у сессии Parley (`--no-daemon`, заголовок окна `spinner/status/session-id`, уведомления OSC 9, без проверки обновлений), `-a on-request -s read-only`, отдельный временный `CODEX_HOME` (в нём только копия файла входа), рабочая папка — пустой временный репозиторий. Parley не запускался. Размеры: 80×24 и 120×40.

Образцы экранов — `packages/core/src/feed/codex/__fixtures__/prompts/<имя>-<cols>x<rows>.txt` (только строки экрана; путь заменён на `/work/project`).

## Ответы на вопросы плана

### 1. Одобрение команды (`-a on-request`, `read-only`)
Замер: просьба `touch created.txt` → экран `command-approval-80x24`, `command-approval-120x40`.

- Вопрос — блок из 15 строк (80×24, команда в одну строку): `Would you like to run the following command?`, `Environment: local`, `Reason: …`, `$ <команда>`, три варианта, `Press enter to confirm or esc to cancel`. Над блоком — история хода.
- Варианты: `1. Yes, proceed (y)`, `2. Yes, and don't ask again for commands that start with … (p)`, `3. No, and tell Codex what to do differently (esc)`. Выбранный вариант помечен `›` в начале строки (по умолчанию первый).
- Клавиши (измерено): `y` — одобряет сразу, без Enter (`command-approved…`); цифра `1` — одобряет сразу, без Enter (120×40); стрелка вниз сдвигает `›` (`command-approval-second-selected-80x24`). Enter подтверждает выбранное — по подписи на экране, отдельно не мерялось. `p`, `2`, Esc на этом экране не мерялись.
- Вывод: цифры и буквы в скобках срабатывают одним нажатием; «слепой» Enter после стрелок меняет решение — нужна сверка экрана.

### 2. Одобрение правки файла (`apply_patch`)
Экран `patch-approval-80x24`: `Would you like to make the following edits?`, `Description: Apply proposed file edits`, `Destination:` и путь файла (переносится по строкам), три варианта: `1. Yes, proceed (y)`, `2. Yes, and don't ask again for these files (a)`, `3. No, and tell Codex what to do differently (esc)`. Блок — 14 строк; над ним краткий дифф (`Added hello.txt (+1 -0)`).
Esc на этом экране (измерено): ход прерван — `■ Conversation interrupted` (`patch-after-esc-80x24`), а не «скажи Codex иначе». Остальные клавиши — как в п. 1 (не мерялись отдельно).

### 3. Вопрос агента с вариантами (`request_user_input`)
- **Условие:** инструмент работает только в режиме Plan. В обычном режиме Codex отвечает `request_user_input is only available in Plan mode` (`plan-mode-only-note-80x24`), вопроса нет. Plan включается командой `/plan` (в Parley её надо слать в терминал; панель на ней не строится).
- Экран `question-options-80x24` / `-120x40`: `Question 1/1 (1 unanswered)`, текст вопроса, варианты `1. Red (Recommended)  <описание>` … `4. None of the above  Optionally, add details in notes (tab)`, подсказка `tab to add notes | enter to submit answer | esc to interrupt`. Блок — 9 строк.
- Клавиши (измерено): стрелки двигают `›`; цифра `3` — выбирает и отправляет ответ сразу (`question-answered-by-digit-120x40`: `answer: Blue`); Enter отправляет выбранное; Tab открывает заметки.

### 4. Вопрос со свободным вводом
Отдельного вида «свободный ответ» у Codex нет: свободный текст — это пункт `None of the above` + заметки. Измерено: стрелкой выбрать пункт 4 (`question-other-selected-80x24`), `Tab` открывает поле `Add notes` (`question-notes-open-80x24`), текст печатается как есть (`question-notes-typed-80x24`), Enter отправляет — ответ `answer: None of the above`, `note: purple please` (`question-answered-80x24`). Печать без предварительного Tab не мерялась. Это совпадает с планом панели: текст из поля идёт как печать, отдельным сообщением `\r` позже.

### 5. Auto-review (`-c approvals_reviewer="auto_review"`)
Замер: три сценария по одному ходу — `touch created.txt`, `apply_patch` для нового файла, `curl -sI https://example.com` (сеть в песочнице закрыта). Во всех трёх вопрос до человека **не дошёл**: рецензент одобрил сам, ход закончился (`auto-review-no-prompt-80x24`; заголовок `Working` → `Ready`, без `Action Required`, без OSC 9 об одобрении). Почему у автора вопросы всё же приходят — на этом стенде не воспроизвелось; наиболее вероятный источник по замерам — вопросы Plan-режима (п. 3) и стартовые экраны (п. 6), которые от рецензента не зависят. Опасные команды, которые рецензент мог бы отправить человеку, не пробовались (риск для личной системы).

### 6. Доверие хукам
Запуск с двумя `-c hooks.<Event>=[…]` (как собирает `codex-hooks.ts`): сразу при старте экран `hooks-trust-80x24`/`-120x40`: `Hooks need review`, `2 hooks are new or changed.`, варианты `1. Review hooks`, `2. Trust all and continue`, `3. Continue without trusting (hooks won't run)`, `enter confirm · esc skip`. Экран блокирует вход в TUI до ответа; цифра `3` принимается одним нажатием, дальше `Ready` и приглашение. Заголовок окна на этом экране не выставлен вовсе (см. п. 7).
Отдельно: при первом запуске в новой папке — экран `trust-folder-80x24` (`Folder access … Trust this folder?`, `1. Trust and continue` / `2. Quit`, `enter continue · esc quit`); в Parley его гасит флаг доверия, но в сессиях без него он возможен. Заголовка нет и на нём.

### 7. Что видит Parley (OSC 0/2 и OSC 9)
| Экран | Заголовок окна | OSC 9 |
|---|---|---|
| Старт до первого кадра | `<спиннер> Starting \| <id>` (после старта — `Ready \| <id>`) | нет |
| Доверие папке, доверие хукам | **нет заголовка вообще** | нет |
| Ход идёт | `<спиннер> Working \| <id>` | нет |
| Одобрение команды | `[ ! ] Action Required \| <id>`, затем мигает `[ . ] Action Required` | `Approval requested: <команда, обрезана до ~40 знаков>` |
| Одобрение правки | `[ ! ] Action Required` | `Codex wants to edit <файл>` |
| Вопрос `request_user_input` (Plan) | `[ ! ] Action Required` | **нет** |
| Ход закончен | `Ready \| <id>` | `Agent turn complete` или текст ответа |

Вывод для Parley: `Action Required` честно ставит «ждёт человека» для одобрений и вопросов Plan; экраны доверия (папка, хуки) для Parley «тихие» — их ловит только сторож старта (20 с). Сырые потоки в репозиторий не кладутся.

### 8. Где вопрос и сколько строк
Вопрос — внизу экрана, над подвалом приглашения (сам подвал на экране вопроса скрыт). Высота блока: одобрение команды 15 (80×24) / 14 (120×40), одобрение правки 14, вопрос с вариантами 9, хуки ≈ 9, доверие папке ≈ 12. Блок одобрения растёт с длиной команды (многострочная команда, длинный путь — переносы) и с `Reason:`.

## Годятся ли 24 запрошенные и 16 показанных строк
- **24 запрошенные** — достаточно: это весь экран 80×24; на 120×40 блок вопроса также виден целиком в нижних 24 строках.
- **16 показанных** — на грани: блок одобрения занимает 14–15 строк при команде в одну строку; длинная команда или путь обрежут верх блока (потеряется `Would you like…`/`Reason`). Рекомендация: показывать до 20 последних непустых строк (запрашивать по-прежнему 24). Решение за ведущим.

## Не воспроизведено
Запрос MCP, предложение сменить модель, сообщение о лимите, экран входа: за разумное время не воспроизводятся без вмешательства в личные настройки или траты лимита; замеров нет, догадок не записано. Esc и буквы `p`/`a` на экранах одобрения не мерялись; печать в поле заметок без Tab не мерялась; Auto-review на опасных командах не пробовался.

## Уборка
Временный `CODEX_HOME` (с копией файла входа), рабочий репозиторий, скрипты и сырые потоки стёрты; личный каталог Codex не изменялся; файл входа и сырые потоки в репозиторий не входят.
