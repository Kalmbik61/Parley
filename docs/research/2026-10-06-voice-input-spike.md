## 1. Сводка

1. **Claude Code умеет ровно то, что просит пункт 17, но только внутри своего поля ввода.** Команда `/voice`: человек держит клавишу или нажимает её дважды, речь живьём встаёт в поле ввода CLI. Распознаёт сервер Anthropic под логином claude.ai; лимиты из `/usage` это не тратит. Русский есть. **[док]**
2. **У Codex CLI диктовки в поле ввода нет.** `/voice` в TUI — голосовой разговор: модель realtime слушает, отвечает голосом и передаёт задачи агенту. Диктовка есть только у настольного приложения Codex и идёт через `app-server`, а машинный режим мы не берём (TODOS, пункт 18). **[исходник]**
3. **Путь «через CLI» закрывает одну клетку из многих:** ввод в саму сессию Claude на логине claude.ai. Сессии GLM, Codex, поле комнаты и диалог «New session or room» он не закрывает. Для них нужен свой распознаватель — это часть 2 разведки. **[вывод]**
4. **Рамка соблюдена.** Распознаёт сам официальный CLI под логином человека, Parley только жмёт клавиши в PTY — тот же принцип, что у вида Chat. **[вывод]**
5. **У пользователя диктовка уже включена глобально:** в `~/.claude/settings.json` стоят `voiceEnabled: true` и `language: "Russian"`. Значит, в виде Terminal окна Parley зажатый пробел в сессии Claude, скорее всего, уже запускает диктовку. Это первая живая проба (раздел 5). **[вывод]**

## 2. Claude Code

### 2.1 Что есть **[док]**

Страница `code.claude.com/docs/en/voice-dictation`.

- **Включение.** `/voice` переключает, `/voice hold` / `tap` / `off` задают режим. Команда пишет в пользовательские настройки (`voice.enabled`, `voice.mode`), так что выбор живёт между сессиями.
- **Режим hold (по умолчанию).** Человек держит клавишу (по умолчанию пробел) и говорит. CLI узнаёт удержание по автоповтору клавиши в терминале, поэтому есть короткий разгон: подвал пишет «keep holding…», потом «listening…». Пробелы, напечатанные за разгон, CLI сам стирает. Человек отпускает клавишу — текст встаёт на место курсора и ждёт Enter. С `voice.autoSubmit: true` сообщение уходит само, если в нём не меньше трёх слов.
- **Режим tap.** Первое нажатие при пустом поле включает запись, второе останавливает и отправляет, если слов не меньше трёх. Запись сама кончается после 15 с тишины или 2 мин всего.
- **Отмена.** `Esc` или `Ctrl+C` отменяют запись и возвращают поле к прежнему виду.
- **Что видно.** Промежуточный текст стоит в поле тусклым, курсор-столбик ходит вместе с громкостью.
- **Язык** берётся из настройки `language` — той же, что задаёт язык ответов Claude. Языков 20, русский (`ru`) среди них. Если настройка пустая, диктовка идёт по-английски, с неподдерживаемым языком — тоже по-английски, с предупреждением.
- **Подсказки распознаванию:** CLI сам добавляет имя проекта и ветку git.
- **Клавиша** — действие `voice:pushToTalk` в контексте `Chat`, переназначается в `~/.claude/keybindings.json`. Сочетание с модификатором (`meta+k`) включает запись сразу, без разгона.
- **Требования.** Нужен логин claude.ai. С `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `apiKeyHelper`, Bedrock, Vertex или Foundry команды `/voice` нет. Микрофон должен быть локальным.
- **Разрешение macOS** спрашивается у терминала, в котором запущен CLI.

### 2.2 Как устроено **[бинарь]**

- Запись — нативный модуль `audio-capture-napi`: 16 кГц, моно, `linear16`.
- Звук уходит потоком по WebSocket на `/api/ws/speech_to_text/voice_stream` основного API Anthropic с OAuth-токеном claude.ai. Без токена CLI пишет «Voice mode requires a Claude.ai account».
- В бинарник вшит `Info.plist` с `NSMicrophoneUsageDescription` («Claude Code uses the microphone for voice dictation»). По документации разрешение всё равно получает приложение, из которого CLI запущен.
- Предохранитель: после трёх сбоев за 10 с CLI ставит диктовку на паузу.

### 2.3 Что это значит для Parley **[Parley] [вывод]**

- **Включать на сессию, а не глобально.** Хост уже передаёт `claude` флаг `--settings {settingsFile}` (`packages/core/src/providers.ts`). Туда можно положить `voice: { enabled: true, mode: "hold", autoSubmit: false }`, и в `~/.claude` ничего не запишется. Команда `/voice` из меню, наоборот, записала бы в глобальные настройки — тот же капкан, что с `/model` у нормалайзера.
- **Микрофон спросят у Parley.** Хост запускает окно (`spawnHost`, `packages/desktop/src/main/host-launcher.ts`), а PTY с CLI — потомки хоста. Значит, macOS покажет запрос от имени Parley.app. Сейчас в `Info.plist` сборки стоит заглушка Electron «This app needs access to the microphone» — её надо заменить своим текстом. Подпись ad-hoc: после обновления разрешение может слететь, как было с доступом к папкам.
- **Вид Terminal, скорее всего, работает уже сейчас.** Если зажать пробел в xterm.js окна, браузер шлёт автоповтор, а CLI видит то же, что в обычном терминале. Кнопка микрофона в этом виде нужна только для удобства. Она бы слала в PTY пробелы с шагом автоповтора, пока её держат. Подходит только hold с `autoSubmit: false`: tap отправляет сам, а пункт 17 требует, чтобы отправлял человек.
- **Вид Chat — главная сложность.** Расшифровка попадает в поле ввода CLI, а у окна поле своё. Хост уже читает экран чистым текстом (`screen.text()` в `packages/host/src/pty/screen.ts`, по нему читается подвал). Поэтому можно забирать продиктованный текст с экрана в поле окна и очищать поле CLI. Слабые места — перенос строк и многострочный ввод. Нужна проба.
- **GLM — нет.** Сессии GLM запускаются с `ANTHROPIC_AUTH_TOKEN` (`packages/host/src/sessions/provider-env.ts`), а с ним CLI команды `/voice` не даёт.
- **Язык диктовки нельзя развести с языком ответов:** настройка одна. Пользователю это не мешает — у него русский.
- **Комната и диалог «New session or room»:** за ними нет CLI, этот путь их не закрывает.

## 3. Codex CLI **[исходник]**

- **`/voice` — голосовой разговор, а не диктовка.** Описание команды: «start or stop voice; use /voice settings to choose a voice» (`codex-rs/tui/src/slash_command.rs`). Есть клавиши `chat.toggle_voice` и `chat.toggle_voice_mute`. Модель realtime (в строках есть `gpt-realtime-1.5` и `gpt-live-1-codex`) слушает, отвечает голосом и передаёт задачи фоновому агенту Codex (`codex-rs/core/src/realtime_conversation.rs`).
- **Звук.** Отдельный процесс `codex-resources/voice/bin/codex-voice-host` на GStreamer и Opus. Соединение — WebRTC или WebSocket. **[бинарь]**
- **Вход.** С логином ChatGPT — `chatgpt.com/backend-api/codex/realtime/calls`, с API-ключом — `api.openai.com/v1/realtime` (`codex-rs/codex-api/src/endpoint/realtime_call.rs`).
- **Сеанс «только расшифровка» есть, но не для поля ввода.** Это `[realtime] type = "transcription"` с моделью `gpt-4o-mini-transcribe` (`codex-rs/codex-api/src/endpoint/realtime_websocket/methods_v2.rs`). Кода, который вставлял бы расшифровку в поле ввода TUI, нет. Что TUI делает с расшифровкой в этом режиме, вживую не проверял.
- **Флаг `in_app_dictation`** (stable, включён) — по комментарию в `codex-rs/features/src/lib.rs`, это разрешение диктовки в настольных приложениях. Задаётся требованиями, а не настройкой человека, и в TUI не используется. Настольный Codex диктует через `app-server`.
- **Вывод.** Для сессий Codex пути «через CLI» под пункт 17 нет. Голосовой разговор — другая функция. В виде Terminal он доступен как есть, ведь это возможность самого CLI, но диктовкой он не является.

## 4. Что из этого следует **[вывод]**

| Где вводят | Claude (claude.ai) | Claude на GLM | Codex |
|---|---|---|---|
| Терминал сессии | `/voice` CLI, скорее всего, уже работает | нет | нет (только разговор `/voice`) |

| Поле комнаты | нет | нет | нет |
| Диалог «New session or room» | нет | нет | нет |

Для пустых клеток нужен свой распознаватель в Parley. Варианты — локальный (macOS Speech framework, whisper.cpp) или API по ключу, который человек вводит сам. Это часть 2: GLM, OpenAI по ключу, локальное распознавание.

Есть ещё один путь, но решать его не мне: **скрытая сессия `claude` как диктофон** для комнаты и диалогов. Хост держит скрытый PTY с `claude`, пока кнопка зажата, шлёт пробелы, потом забирает текст с экрана и очищает поле. В модель ничего не уходит. Технически это выполнимо, но это уже функция CLI, использованная вне самого CLI, а рамку проекта задаёт пользователь. Без его решения этот путь не предлагаю.

## 5. Живые пробы — не сделаны, нужен человек

- **П1. Терминал.** Parley → сессия Claude → вид Terminal → зажать пробел и сказать фразу по-русски. Смотрим три вещи: появился ли запрос macOS на микрофон от имени Parley; есть ли в подвале переход «keep holding…» → «listening…»; встал ли текст в поле. Улики — снимок экрана и `/usr/bin/log show --predicate 'subsystem == "com.apple.TCC"'`.
- **П2. Искусственный автоповтор.** Скрипт пробы шлёт пробелы в PTY с шагом 30–50 мс. Смотрим, считает ли CLI это удержанием. Это основа для кнопки микрофона и для вида Chat. Проба покажет системный запрос на микрофон от имени того приложения, из которого она запущена.
- **П3. Забор текста в Chat.** После П1 прочитать поле ввода через `screen.text()`. Проверить длинную фразу с переносом и очистку поля (`Ctrl+U` или `Esc`).
