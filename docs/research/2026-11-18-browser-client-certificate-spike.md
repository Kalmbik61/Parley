# Браузер Parley: клиентский сертификат (SSO с mTLS), спайк на локальном стенде

**Дата:** 2026-11-18. **Electron:** 44.4.5 (Chrome 152.0.7977.130). **Машина:** macOS 27.2, Node 22.23.3, OpenSSL 4.1.0.
**Спека и план:** `docs/specs/2026-11-18-browser-client-certificate-design.md` (разделы 3 и 5), `docs/plans/2026-11-18-browser-client-certificate-plan.md`, задача 0.
**Скрипты и сертификаты:** scratchpad сессии, в репозиторий не входят; после спайка стёрты вместе с временной связкой.

## Как устроена проба

- **Стенд.** Свой Electron из `packages/desktop/node_modules/electron`, не Parley. Окно с `<webview>` в разделе `spike-cert`: `will-attach-webview` снимает preload, разрешения раздела — отказ, сертификат сервера принимает только `setCertificateVerifyProc` этого раздела (только для `127.0.0.1`). Обработчик `app.on('select-client-certificate')` пишет аргументы в журнал и отвечает по сценарию (`first` — первый сертификат списка, `none` — `callback()`, `delay` — первый через 1,5 с). Управление — HTTP на `127.0.0.1:18999`.
- **Серверы Node `https`, `127.0.0.1`.** A (18443) — страница без запроса сертификата; B (18444) — `requestCert: true, rejectUnauthorized: false` (сертификат запрошен, не обязателен); C (18445) — `requestCert: true, rejectUnauthorized: true` (без сертификата рукопожатие рвётся). B и C отвечают заголовками CORS (`Allow-Origin` = `Origin`, `Allow-Credentials`, `Allow-Headers`) и пишут в журнал, пришёл ли сертификат клиента.
- **Связка.** Свой тестовый центр, клиентская пара `CN=Spike Test Client` с `extendedKeyUsage=clientAuth`, `.p12` импортирован только во временную связку в scratchpad; она добавлена в начало списка поиска пользователя, прежние две оставлены.
- **Страница с `fetch`** — гость на `https://127.0.0.1:18443/`; запрос к B и C — на другой порт, то есть другой источник, как в находке.
- **Каждый сценарий — в свежем процессе Electron** (кроме первого сквозного прогона), чтобы кэш сессии не портил следующий замер. Все цифры ниже — по журналу события и журналу серверов.

## Что подтверждено и что требует правки в разделе 3 спеки и задачах 1–4

**Подтверждено:**

- «Гость раздела» определяется как в плане: `contents.getType() === 'webview' && contents.session === session.fromPartition(BROWSER_PARTITION)`, и `contents.hostWebContents` есть — окно-хозяин находится.
- `pageHost` из `contents.getURL()` даёт хост верхней страницы и при запросе скрипта, и при подфрейме (но не хост фрейма).
- Поля `ClientCertInfo` (`fingerprint`, `subjectName`, `issuerName`, `serialNumber`, `validExpiry`) есть и имеют ожидаемый вид; `validExpiry` — секунды.
- Очередь 3.2: одновременные запросы приходят отдельными событиями, нужен общий ответ на один `хост:порт`.
- Выбор «с галочкой» и «без» — разница только у нас (в Хромиуме выбор живёт, пока жив раздел).
- Предзапрос CORS (при TLS-требовании сертификата на рукопожатии) идёт с сертификатом.

**Требует правки (для ведущего):**

1. **`url` события — `хост:порт` без схемы.** Задача 1 в `select(contents, url, …)` кормит его в `hostPortOf(url)`, который по интерфейсу «только `https`, иначе `null`» вернёт `null` для `127.0.0.1:18444`. Нужно либо брать `url` как есть (проверив форму `хост:порт`), либо принимать оба вида.
2. **Отмена необратима до перезапуска.** Спека 3.1 «ничего не запоминается» верна для нашей памяти, но Хромиум запоминает отказ в разделе. Человек, нажавший `Cancel`, до выхода из Parley на этот `хост:порт` сертификата не отправит. Решение за ведущим и человеком: оставить и сказать в тексте слоя; или не звать `callback()` до ухода вкладки (запрос висит, `Cancel` его не закрывает); или завести раздел под перезапуск.
3. **«Clear browsing data» (Р6, задача 5)** сотрёт наш файл выборов, но уже принятый в этом запуске выбор (и отказ) Хромиум оставит. Вопрос зададут заново только после выхода из Parley. Строку в CHANGELOG и текст приёмки нужно привести к этому.
4. **«Запомненный отпечаток пропал из списка»** достижим только для первого события на `хост:порт` в запуске; повторно событие не придёт, так что случай после ответа не встречается.
5. **Запрос macOS к ключу не виден Parley** (вопрос 5): задача 4 (`CLIENT_CERT_HINT`) покрывает только наш слой выбора, но не окно системы.

## Не проверено

- Вид окна SecurityAgent на экране (снимок недоступен; описание — со слов ведущего).
- Сертификаты на аппаратном ключе или у стороннего поставщика («токен»), собранное подписанное приложение, другая версия macOS.
- Сервер, отвечающий на `OPTIONS` без CORS-заголовков; находка с `:6443` этим стендом не воспроизведена.
- Сброс кэша сертификатов через другой раздел (`session.fromPartition` с новым именем) и через `app.relaunch()` не мерился.

Выбор ветки по вопросу 7: событие снова приходит и после ухода со страницы, и после удаления `<webview>`, оставленный запрос не держит вкладку и не плодит соединения. **Следует ветка «не сейчас»** поправки 1: `Not now`, `Escape`, уход со страницы и закрытие вкладки забывают запрос без `callback`. Оговорка: все три замера идут с отпущенной ссылкой на `callback`; в Parley ссылка живёт в очереди запросов, пока запрос не забыт, а при забвении отпускается. Что `callback` не будет вызван вообще, Chromium перенёс в замере 7в (запрос оборвался сам через ~28 с), а в 7а/7б — по уходу вкладки; **отдельно «забыть запрос при живой вкладке без `callback`» не мерилось**, кроме того, что в 7в она жила 28 с.

### Окно macOS в этом раунде

В первом прогоне 7а после ухода со страницы я по ошибке ответил на **повторное** событие `callback(cert)` (хотел проверить, что запрос идёт дальше). Это подпись ключом новой временной связки, и **macOS показала окно `SecurityAgent`** (455×184, по списку окон), рукопожатие встало, `fetch` через 30 с оборвался `net::ERR_TIMED_OUT`, стенд я остановил. Ведущий велел не закрывать системные процессы и продолжать без подписи; человека просили нажать Deny. Остальные прогоны 7а, 7б, 7в сделаны с `callback()` без сертификата — окно больше не появлялось; событие 7а при этом то же (приходит снова). Это ещё раз подтверждает вопрос 5: любая подпись нового ключа даёт окно, `callback(cert)` без «Always Allow» подписью кончается ожиданием человека.
