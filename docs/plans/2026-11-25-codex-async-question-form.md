A native `response_item` function/custom call and an `item_completed` AgentMessage with delivery=async and questions describe the same cards. Keep the original indices and deduplicate in either order across batches and replay. A queued acknowledgement is not an answer. Consume native user replies in the send_user_message_question_reply envelope by exact questionItemId, handle terminal answers and suppress duplicate raw envelopes. Preserve ordinary user messages and child rollouts. A completed/aborted turn expires its remaining asynchronous questions. Test both historical and current formats, options, free text, replay, actual reply and expiration.

Account for line wraps, the native title limit, multiple questions, disappearance, concurrent answers, teardown and retries. Verify transitions and only report success when Codex has taken the answer. Retain existing approval handling. Cover the decision path with captured screens and the normal feed service.

Validate in the question form and with the isolated Codex 0.166.0 TUI, exercising option selection and free text and checking the native reply. Run relevant core, host and desktop tests and package type checks.

Cover the reported queue and the form's choice and text submission in the existing desktop tests.
