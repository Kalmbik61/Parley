# Qwen Code questions and approvals in Chat

Qwen 0.27.2 sends a PermissionRequest for write_file, edit and ask_user_question. Observed permission hooks had no tool_use_id and could lack prompt_id. A question carried questions with headers, options and descriptions. Qwen collects answers from its confirmation UI. Its scheduler can ignore a hook allow when human interaction is required. Returning an allow or adding answers to tool_input does not answer such a dialog.

Use the running native Qwen dialog as the authority. Show recognised questions and permission choices through the existing Chat cards. Do not generate an approval from a notification or model output. Reuse the desktop terminal prompt panel for unrecognised, truncated or localized layouts. Preserve independent use of the terminal and Qwen's existing approval mode. Keep transcript ownership in the Qwen parser.

1. Host Qwen terminal adapter, packages/host/src/feed/qwen-prompt.ts and its tests. Recognise real 0.27.2 question, review and permission layouts from the active viewport while the current process is genuinely waiting. Build a standard card for the visible step and accept explicit choices only. Check the current screen, process and pending identity at decision time and before any further write. Use native numeric choices, guarded free-text/multi-select where supported, and a terminal-panel fallback otherwise. Avoid leaking terminal history or credentials. Distinguish the explicit one-time approval from persistent choices and denial. Plain transcript-like text must never arm decisions. Validation includes question choice, multiple questions, permission allow once and deny, stale process/screen, unknown dialog fallback.
2. Host lifecycle, packages/host/src/feed/feed-service.ts and relevant Qwen activity/feed tests. Subscribe to actual Qwen program-status blocked permission/question, handle redraw, stale/answered cards, completion, provider switch, exit, detach, cold seed and normal terminal fallback. Integrate the adapter with feed snapshot/delta and feed.decide. Avoid waiting on hooks when the CLI must draw its prompt first. Drive existing question and permission card types and route fallback through the desktop Chat terminal prompt panel. Scope any desktop change to Qwen.
3. Verify through host tests and an isolated real Qwen 0.27.2 PTY with a local model. Demonstrate both accepting and refusing a permission and answering an agent question. Preserve Claude/Codex and keep the installed host running.
