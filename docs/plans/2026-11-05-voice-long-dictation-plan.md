# План: длинное поручение голосом приходит обрезанным (b-027)

- **Дата:** 2026-11-05.
- **Основание:** карточка беклога b-027; разбор s-283 (этот документ, §1).
- **Спецификация:** `docs/specs/2026-11-04-voice-assistant-modules-design.md` (далее — «Голос↔Ассистент», §4 п.3–4).
- **База:** origin/master@404596d4 (релиз 0.30.0). Ветка `fix/voice-long-dictation`.
- **Push и PR — только по команде человека.** Сообщения коммитов — на английском (AGENTS.md).

## 1. Причина (разбор с доказательствами)

Источник — живая сессия острова на 0.30.0 (`live_u2_Egpmop…`, 316 с голоса, 7 Request). Данные взяты только на чтение из
`~/.parley/parley.db`: `assistant_requests` (текст, `context_json`, `transcript_partial`) и `voice_telemetry`
(`transcript_wait_ms`). Сырых дельт и `offset_ms` в базе нет: остров тексты не логирует.

### Дефект 1. Начало поручения режется паузой человека

`TranscriptBuffer.collect` (`packages/core/src/voice-live/transcript.ts:81–95`) начинает текст после последней паузы
≥ `TURN_GAP_MS` (1,2 с) в речи человека. Спека требует того же: «Начало — пауза в речи или `offset_ms` предыдущей
делегации» (§4 п.3). При живой диктовке паузы «на подумать» длиннее 1,2 с обычны, и в Request уходит только кусок после
последней из них.

4 из 7 Request начинаются с середины фразы. `context_json` того же Request хранит отрезанные куски как отдельные
«реплики человека». Между ними нет ни одной реплики модели:

| Ушло в Request | Отрезано (из `recentTurns`) |
|---|---|
| `, что он дал конкретные шаги для того, чтобы... ассистент заработал на телеф оне` | `Всё, хорошо понял` · `. Тогда напиши` · `в улучшайзинг сессии S38` |
| `знать, что он скажет` | `Да-да-да, я уже отправил. Как только он даст ответ, дай мне` |
| `, обязательно скажи, что исполнители должны быть Sonnet` | `Да, давай, напиши тогда` · `ему, начинаем разработку` |
| `... Не совсем понял, что это за заглушка. … чтобы я смог проверить` | `Напиши ему, что` · `... проверен API-ключ, … значит всё работает` · `. Пусть готовят экраны для телефонов` |

GPT-Live в этой сессии на таких паузах ход не забирал: делегация пришла один раз, в конце фразы. Это расходится с
синтетическим T0, где делегация пришла посреди реплики.

### Дефект 2. Ложный `transcriptPartial`, из-за которого повтор не помогает

`flush` в `packages/core/src/voice-live/bridge.ts:149–163` считает транскрипт дошедшим, только если
`highWaterMs ≥ offsetMs − COVERAGE_GAP_MS` (1,2 с). Если между концом речи и `offset_ms` прошло больше 1,2 с тишины, мост
ждёт полный срок `TRANSCRIPT_WAIT_MS` (1,5 с) и отправляет Request с `transcriptPartial: true`. Фрагментов в тишине нет,
поэтому это условие не отличает тишину от отставания транскрипта.

- Телеметрия: две длинные делегации ждали 1501 и 1502 мс, обе ушли с `transcript_partial = 1`. Пять коротких ждали 0–11 мс,
  у всех 0.
- Запоздавших фрагментов не было. У «Sonnet» следующая реплика человека в контексте совпадает с текстом Request символ в
  символ, а пришедший позже фрагмент приклеился бы к ней.
- Частичному Request хост запрещает готовить действия (`packages/host/src/assistant/request-link.ts:201`: «do not prepare
  actions. Ask the person to say it again»). Ответы ассистента в сессии: «Похоже, фраза не записалась целиком, поэтому
  карточку … я не сделал. Повтори…». Повтор снова длинный и с паузой перед `offset_ms` → снова partial → снова отказ.
- По T0 (§2d, §2e) запоздавший фрагмент приходит максимум через 1,2 с после своего `end_ms`, а `delegation.created` — через
  0,85–1,3 с после конца фразы. К сроку 1,5 с отставание уже покрыто, и недостающий `highWater` в этот момент означает
  тишину.

### Воспроизведение

Скретч-скрипт (вне репозитория) прогнал `createDelegationBridge` 0.30.0 на форме реальной сессии: ответ модели, фраза
человека с паузами 1,5 и 1,4 с, `offset_ms` через 1,5 с после конца речи. Итог: текст
`", обязательно скажи, что исполнители должны быть Sonnet"`, `transcriptPartial: true`, ожидание 1500 мс. Это совпадает с
базой (1502 мс). Короткая фраза без пауз с той же тишиной перед `offset_ms` тоже уходит partial.

### Проверено и не причастно

- Хост принимает до 4000 знаков (`packages/protocol/src/assistant.ts:217`); job получает текст целиком
  (`job-context.ts:26–27`).
- `MAX_FRAGMENTS` 800 × ~200 мс ≈ 160 с речи человека: на фразу в 30–60 с хватает.
- Путь Whisper (Speak answers выключено) в этой сессии не использовался. У него свой предел: запись останавливается после
  1,2 с тишины (`packages/desktop/src/renderer/island/assistant/listen.ts:15`, `SILENCE_MS`) и через 60 с
  (`MAX_LISTEN_MS`). Это тот же класс ошибки, но в этот план он не входит: см. §5.
- Телефон: ни одна ветка пока не использует `createDelegationBridge`. Модуль общий («его берут остров и телефон»), поэтому
  контроллер r-24 получит исправление вместе с ядром.

## 2. Новое правило (заменяет §4 п.3–4 «Голос↔Ассистент»)

**Границы текста.** Текст поручения — это реплика человека, которая заканчивается у `offset_ms`. В неё входят фрагменты
человека с `startMs ≤ offsetMs` и `startMs > afterMs` (`offset_ms` прежней делегации). Сборка идёт назад от последнего
фрагмента и останавливается, когда между двумя соседними фрагментами человека есть **ответ модели**. Пауза человека
реплику больше не делит.

- **Ответ модели между фрагментами `a` и `b`** — фрагменты модели с `a.endMs ≤ startMs < b.startMs`. Их склеенный текст
  после `normalizeHumanText` (режет `[hum]`) содержит не меньше `REPLY_MIN_WORDS = 3` слов. Слово — токен между
  пробелами, в котором есть буква (`\p{L}`). Короче — это поддакивание («Угу.», «Ага.»), оно реплику не делит.
- Если ответа модели и прежней делегации нет, текст начинается с первого фрагмента человека в буфере. `MAX_REQUEST_TEXT`
  по-прежнему оставляет хвост.
- **Пробел на паузе.** Если промежуток между соседними фрагментами в собранном тексте не меньше `TURN_GAP_MS`, между ними
  ставится пробел. После паузы фрагмент приходит без ведущего пробела (в живых данных `". Тогда напиши"` и
  `"в улучшайзинг сессии S38"`), и без пробела слова склеились бы. Пробел ставится, только если следующий фрагмент
  начинается с буквы или цифры (`^[\p{L}\p{N}]`). Перед знаком препинания пробела нет: `", обязательно…"`,
  `". Тогда…"`, `"... проверен…"` приклеиваются как есть. Внутри непрерывной речи фрагменты по-прежнему склеиваются как
  есть («Par» + «ley»). Двойные пробелы схлопывает `glue`.
- `turns()` и `TURN_GAP_MS` для контекста (`recentTurns`) не меняются.

**Когда транскрипт дошёл.**

- Транскрипт дошёл, если текст не пуст и `highWaterMs ≥ offsetMs − COVERAGE_GAP_MS`. Это правило не меняется; ожидание до
  `TRANSCRIPT_WAIT_MS` тоже.
- **Новое — на сроке:** Request частичный, только если текст пуст или последний фрагмент человека пришёл (по `deps.now()`)
  меньше чем `TRANSCRIPT_QUIET_MS = 500` мс назад: поток ещё идёт, хвост может быть в пути. Иначе Request полный
  (`transcriptPartial: false`). Тишина перед `offset_ms` больше не делает его частичным.

## 3. Задачи

    `splits(fromMs, toMs) => boolean` говорит, делит ли промежуток `[fromMs, toMs)` между фрагментами реплику. Без него
    не делит ничто. Деление по `turnGapMs` из `collect` убрать. Добавить в `TranscriptBuffer` метод
    `textBetween(fromMs, toMs): string` (склейка фрагментов с `fromMs ≤ startMs < toMs`, как `glue`).

    + `REPLY_MIN_WORDS`); экспортировать `REPLY_MIN_WORDS` и `TRANSCRIPT_QUIET_MS`.
  - `bridge.ts`. Запоминать `deps.now()` последнего фрагмента человека и применять правило срока из §2. Шапку модуля

- **Тесты (приёмка).**

  - `bridge.test.ts`: на сроке фрагменты человека ещё приходят (последний < 500 мс назад), `highWater` не дотянул →

## 5. Вне плана

- Путь Whisper острова: обрыв записи после 1,2 с тишины и на 60 с (`listen.ts`). Тот же класс ошибки; нужна отдельная
  карточка беклога.

  третьего Request. По спеке это так задумано, правило не меняется.
