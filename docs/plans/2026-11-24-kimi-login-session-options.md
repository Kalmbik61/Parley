# Kimi sign-in and session creation

1. **Sign-in terminal** (host auth service, auth methods and events, desktop provider card/store/terminal). Offer a Sign in button for native Kimi when installed and signed out. Reuse the existing provider login PTY, its input/resize/cancel/cleanup and UI, and run the resolved Kimi executable with the fixed login command in the user's real Kimi environment. Reflect in-progress login across views, allow device authorization links using existing safe handling, and refresh actual Kimi auth on exit. Account failures or cancellation must allow retry. Scope any new capability narrowly. Cover host and renderer paths with fixtures.
2. **Model catalog** (core provider registry and capabilities, catalog reading and cache, host provider-list integration if necessary). Read the installed CLI's bounded `kimi provider list --json`, retaining only model aliases, displayName and supportEfforts. Never expose or persist raw output or any credentials. All launch validation and provider listing must see the same model options. Avoid a subprocess per registry lookup, stale post-login results, or blocking unrelated providers on a missing or hanging CLI. Preserve missing/older CLI fallback, existing templates and other providers. Add fixture tests including unsupported effort, errors and cache. CLI 2.7.3 on this Mac returns six aliases, five with low/high/max.
3. **Creation and first turn** (desktop agent row and launch builders, host launch validation, core launch configuration and host Kimi ACP session startup). Render and submit ordinary model/effort selectors using the catalog in task 2. Accept validated Kimi choices and preserve default/omitted values. Use the live ACP config to apply explicit choices in model-then-thinking order before any first prompt. Validate the selected values after a model switch, fail visibly for a stale or unsupported choice, respect chat changes on resume, and keep catalog/model UI working for other providers. Cover UI to create request and launch to first prompt with tests. Do not open a real Kimi session or consume user quota during tests.

Use the previous local fix branch. Verify a signed-out user can open and interact with the embedded terminal, complete a fixture login, select an available model and supported effort, and start a session with both choices in effect. Check the actual installed CLI catalog without printing configuration or signing the user in.
