# Лимит Claude после сброса вендором посреди окна

## Проблема
12.11.2026 Anthropic сбросил лимиты человека посреди недельного окна. Parley показывал 96 % (карточка провайдера,
строка состояния, `get_map` → `providers`), реально было около 10 %. Те же числа читают сессии.

## Причина
`laterWindow` (`packages/core/src/limits.ts`) при равном `resetsAt` брал большее `usedPercent`: расход в окне не убывает.
Сброс вендором оставляет `resets_at` (1794844800) и роняет расход, поэтому устаревшие 92–96 % из 46 файлов побеждали
свежие 2–10 % до конца окна. «Самое свежее по `at`» брать нельзя: простаивающую сессию Claude Code зовёт скрипт строки
статуса (смена режима, `/compact`) со старыми числами и новым `at`.

## Правило
- Скрипт строки статуса пишет `{ at, changedAt, rateLimits }`. `changedAt` — когда числа этой сессии действительно менялись:
  прежний файл сессии с теми же `rateLimits` (глубокое сравнение) — его `changedAt` (нет поля — его `at`); иначе, или файла нет
  / он не читается — `at`. Запись остаётся атомарной, импорты — только листовые модули.
- `ProviderLimits.changedAt?` разбирается из файла; невалидное значение — как отсутствующее.
- `mergeLimits` сводит каждое окно отдельно, с `changedAt ?? at` той записи, откуда окно. Равный `resetsAt`: побеждает окно с
  более поздним `changedAt ?? at`, при равенстве — большее `usedPercent`. Разный `resetsAt`: позднее окончание (как раньше).
  Неизвестный `resetsAt`: последнее наблюдение по `at` (как раньше). `at` свода — позднейший, `changedAt` свода — позднейший.

## Запасной вариант
Источники без `changedAt` (старые файлы на диске, лог Codex, квота Z.ai) сравниваются по `at`. Ничего не удаляется и не
переписывается хостом: после выхода версии старые файлы работают сразу, а сессии со старым скриптом — пока не перезапущены.
Для файлов без `changedAt` простаивающая сессия снова может перебить работавшую (как при «самом свежем по `at`»), пока
скрипт не запишет `changedAt`; это временно и ограничено сессиями со старым скриптом.

## Почему повтор простаивающей сессии по-прежнему проигрывает
Её числа не меняются, значит `changedAt` остаётся старым, пока `at` свежеет. Сессия, числа которой менялись позже, выигрывает.

## Тесты
`limits.test.ts`: стародавние 96 % (без `changedAt`) против свежих 10 % при равном `resets_at`; повтор простаивающей сессии;
смешанный порядок `at`; неизвестный `resets_at`; пятичасовое окно; свод по окну, а не по общему `changedAt`; разбор `changedAt`.
`statusline.test.ts`: числа те же — `changedAt` прежний; изменились — `at`; прежний файл без `changedAt` — его `at`; битый файл.
Прежний тест «равный resetsAt — большее usedPercent» заменён равным по смыслу (простаивающая сессия с `changedAt`) плюс тест на ничью.

## Вне задачи
`stuck.ts`, `limit-return.ts`, `sessions-service.ts` не менялись. Удаление/перезапись файлов, перезапуск живых сессий, правка
Codex и Z.ai.
