# План: карточки для узнанных вопросов терминала Codex (слой 2)

> **Исполнителю:** прочитай «Global Constraints» и «Решения, принятые при планировании», затем только свою задачу. Шаги — флажки `- [ ]`, иди по порядку. Чужих файлов не трогай; если задача без них не делается, остановись и напиши ведущему.

**Goal:** Одобрение команды, одобрение правки и вопрос с вариантами, которые Codex показывает в терминале, становятся обычными карточками Parley: с кнопками в Chat, на острове, в Telegram и на телефоне. Решение человека хост вводит в терминал клавишами.

**Architecture:** Чистая функция в core узнаёт вопрос по строкам экрана и даёт клавиши для каждого решения. Служба ленты хоста (`feed-service.ts`), увидев, что сессия Codex ждёт человека, читает экран, и если вопрос узнан и карточки хука нет, заводит карточку существующего вида и «держит» её не хуком, а записью о вопросе терминала. `feed.decide` для такой карточки сверяет экран, пишет клавишу в терминал и закрывает карточку. Что не узнано или не применилось — остаётся слою 1 (панель в Chat).

**Tech Stack:** TypeScript (`exactOptionalPropertyTypes: true`), vitest 2; хост — `@xterm/headless`.

**Spec:** `docs/specs/2026-11-18-chat-terminal-prompts-design.md`, раздел 4. Замеры: `docs/research/2026-11-18-codex-terminal-prompts-spike.md`. Образцы экранов: `packages/core/src/feed/codex/__fixtures__/prompts/`.

**База:** та же ветка, что у слоя 1 (рабочая копия исполнителя), поверх его коммитов. Короткие пути: `core/…` — от `packages/core/src/`, `host/…` — от `packages/host/src/`, `renderer/…` — от `packages/desktop/src/renderer/`.

## Решения, принятые при планировании

| Вопрос | Решение |
|---|---|
| Какие вопросы узнаём | Три: одобрение команды, одобрение правки, вопрос с вариантами (`Question N/M`). Доверие хукам и папке, смена модели, лимит — слой 1 |
| Образец | Вся форма: строка-заголовок дословно, варианты с номерами подряд от 1, строка-подсказка дословно. Нет любой из трёх частей — не узнано |
| Отпечаток вопроса | Вид + текст команды, пути или вопроса + подписи вариантов. Положение метки `›` и спиннеры в него не входят |
| Какой клавишей отвечать | Цифрой варианта: одно нажатие без Enter (замерено для `1` и `3`). Буквы в скобках не используем |
| Когда хост пишет клавишу | Только если прямо перед записью экран даёт тот же отпечаток. Между проверкой и записью нет `await` |
| Решение применено? | `feed.decide` отвечает сразу после записи клавиши (`applied: true`) и закрывает карточку. Если через 1,5 с тот же вопрос всё ещё на экране — карточка уже закрыта, а человеку остаётся панель слоя 1: сессия по-прежнему ждёт и ждущей карточки нет. Отката карточки нет |
| Чем «держится» карточка | Своя таблица вопросов терминала в `feed-service.ts`; хранилище хуков `hooks/pending.ts` не трогаем: его записи завязаны на ответ хука |
| Когда заводить карточку | `activity.onChange`: сессия Codex стала `blocked` с нуждой `approval` или `question`, в ленте нет ждущей карточки, записи о вопросе терминала нет. Экран читается каждые 100 мс до 2 с, пока вопрос не узнан |
| Ответили в терминале | Пока карточка ждёт, экран читается раз в секунду. Отпечаток другой или вопроса нет — карточка `elsewhere`. Сессия перестала ждать — то же |
| Режим «Ask in Parley» | Ждущая карточка хука есть — карточка по экрану не заводится (общее правило «в ленте нет ждущей карточки») |
| Флаг `decisions` ленты | На время жизни карточки терминала ставится `'window'` (иначе остров, Telegram и помощник не дают кнопок); после закрытия возвращается прежнее значение |
| Карточка одобрения команды | `permission`, `toolName: 'Bash'`, `toolInput: { command, description? }` — как у карточек хука Codex |
| Карточка одобрения правки | `permission`, `toolName: 'apply_patch'`, `toolInput: { path }` |
| «Allow and don't ask again» | Вариант 2 Codex. Кнопка появляется, когда у карточки непустые `suggestions`; исполнитель задачи 2 строит одну запись в том виде, который принимает `renderer/chat/always-rules.ts`, с текстом варианта 2 |
| Карточка вопроса | `question` с одним вопросом (тем, что на экране) и вариантами без последнего «None of the above». Несколько вопросов подряд — карточка на каждый экран |
| Свой ответ («Other») | Многошаговая печать: стрелками до «None of the above», Tab, текст, Enter — со сверкой экрана между шагами (задача 4) |
| Отказ с текстом | Что делает вариант 3 и куда печатать текст — по замеру задачи 0; правило записано там |
| Пометка карточки | Необязательное поле `via?: 'terminal'` у карточек: по нему хост находит свои записи после перезапуска ленты и снимает их |

## Поправка после дозамера (2026-11-18)

Отчёт: раздел «Дозамер для слоя 2» в `docs/research/2026-11-18-codex-terminal-prompts-spike.md` (коммит 1bf61c2a). Где текст задач ниже расходится с этим разделом, верен этот раздел.

- **Клавиши подтверждены замером:** `1` — разрешить, `2` — разрешить и не спрашивать, `3` — отказать. Все три — одним нажатием, на одобрении команды и на одобрении правки.
- **Отказ у Codex прерывает ход** (`■ Conversation interrupted`, заголовок `Ready`, поле ввода свободно). Пояснения Codex не просит.
- **Отказ с текстом (задача 4):** после `3` хост ждёт, пока сессия перестанет быть `blocked` (до 5 с), и отправляет текст обычным сообщением человека — тем же отправителем, что у метода `pty.send` (вставка Codex и отдельный Enter). Если у `feed-service` нет доступа к отправителю, он добавляется необязательной зависимостью и подключается в `host/host.ts`. Не дождались — текст не печатается, в журнал хоста идёт запись с исходом, без текста.
- **Строка-подсказка вопроса бывает разной** (один вопрос, несколько, узкое окно). Образец вопроса требует не дословную строку, а строку, содержащую `tab to add notes | enter to submit`. У одобрений строка `Press enter to confirm or esc to cancel` — дословно.
- **Неполная форма — не узнана.** Одобрение узнаётся только с вариантами ровно `1.`, `2.`, `3.`. Если в блоке вопроса или одобрения есть стрелка прокрутки `↓` или `↑` (часть списка скрыта, узкое окно) — `null`: карточки нет, работает панель слоя 1.
- **Переносы:** `Reason:` и команда могут занимать несколько строк — склеивать до следующей части формы.
- **Несколько вопросов (`Question N/M`):** цифра на не последнем вопросе записывает ответ и показывает следующий вопрос; на последнем — отправляет все ответы. Карточка — на каждый экран вопроса. Цифра несуществующего варианта игнорируется Codex.
- **Повторный поиск (задача 3):** после решения по карточке терминала, если через `TERMINAL_PROMPT_CONFIRM_MS` сессия всё ещё `blocked`, ждущей карточки нет и записи о вопросе нет, поиск запускается снова. Так появляется карточка следующего вопроса из нескольких — и карточка того же вопроса, если клавиша не сработала. Тест: два экрана вопроса подряд дают две карточки, по одной на экран.
- **Свой ответ (задача 4), шаг 5:** после Enter ждать, что отпечаток вопроса сменился или вопроса нет (на не последнем вопросе экран переходит к следующему).
- **«None of the above»** цифрой отправляет ответ без текста — поэтому в варианты карточки он не входит, а свой текст идёт через Tab.

## Global Constraints

- Правила исполнителей — `docs/plans/2026-11-10-review-fixes/executor-rules.md`. В `Co-Authored-By` — модель, писавшая коммит; правка после возврата — новым коммитом.
- Parley ничего не отвечает сам: клавиша уходит только по `feed.decide` человека.
- Строки экрана не пишутся в журнал. В ленту попадают только разобранные поля узнанного вопроса.
- Новые поля типов — необязательные; карточки хука и ленты других агентов ведут себя как раньше, их тесты не меняются.
- Таймеры хоста: `unref()`, сняты в `stop()` и при закрытии карточки.
- Тесты хоста — на `packages/host/test/feed-fakes.ts` (`fakeFeedDeps`: `setScreen`, `writes`, `emitActivity`, `emitExit`); ожидания — по коду, не по тексту плана. Тесты ждут условие, а не фиксированное время.
- Один коммит на задачу, заголовок — из последнего шага. Push и pull request — по слову человека.

## Review Focus

1. **Клавиша не уходит в чужой вопрос.** Экран сменился между показом карточки и решением — записи в терминал нет, карточка `elsewhere`. Тесты — задача 3.
2. **Одна карточка на вопрос.** Повторные события активности, мигание заголовка и перерисовка экрана не плодят карточки; карточка хука и карточка экрана одновременно не появляются. Тесты — задача 3.
3. **Ничего не узнано — ничего не сломано.** Незнакомый экран, другая версия формы, пустой экран: карточки нет, слой 1 работает. Тесты — задачи 1 и 3.
4. **Свой ответ не печатается вслепую.** На любом шаге экран не тот — печать останавливается, дальше клавиш нет. Тесты — задача 4.
5. **Флаг `decisions` возвращается.** После закрытия карточки терминала значение прежнее. Тест — задача 3.

### Task 3: Хост заводит карточку и отвечает клавишей

**Files:**
- Modify: `host/feed/feed-service.ts`, `packages/host/test/feed-fakes.ts` (если фальшивому экрану не хватает метода), `host/feed/feed-service.test.ts`

**Interfaces — Consumes:** `recogniseCodexPrompt`, `codexPromptKey` (задача 1), `applyCodexTerminalPrompt` (задача 2); `deps.pty.screenText`, `deps.pty.write`, `deps.activity.onChange`.

Константы в `feed-service.ts`: `TERMINAL_PROMPT_FIND_MS = 2_000`, `TERMINAL_PROMPT_FIND_STEP_MS = 100`, `TERMINAL_PROMPT_WATCH_MS = 1_000`, `TERMINAL_PROMPT_CONFIRM_MS = 1_500`.

Поведение:
- **Поиск.** По `activity.onChange` для сессии Codex с `activity === 'blocked'` и нуждой `approval` или `question`: если в ленте нет ждущей карточки и нет записи о вопросе терминала, начинается поиск — экран читается каждые `FIND_STEP_MS` до `FIND_MS`. Узнан — `applyCodexTerminalPrompt`, запись `{ cardId, prompt, прежнее decisions }`, `setDecisions(feed, 'window')`. Не узнан за срок — ничего. Повторное событие во время поиска второй поиск не запускает.
- **Слежение.** Пока запись есть, экран читается каждые `WATCH_MS`: отпечаток другой или вопроса нет — `settle(ref, 'elsewhere', [cardId])`, запись снята, `decisions` возвращён. То же, когда сессия перестала быть `blocked`.
- **Решение** (`decide`): удержанного хука нет, но есть запись о вопросе терминала → путь терминала. `codexPromptKey` дал `null` → `{ applied: false, state: 'pending' }` (свой ответ и отказ с текстом — задача 4). Иначе: прочитать экран; отпечаток не тот → карточка `elsewhere`, ответ `{ applied: false, state: 'elsewhere' }`, записи в терминал нет. Тот — `pty.write(ref, клавиша)`, `applyDecision`, `commit`, запись снята, `decisions` возвращён, ответ `{ applied: true, state }`. Через `CONFIRM_MS` экран читается ещё раз: тот же вопрос на месте — запись в журнал хоста без текста экрана (`op: 'feed.terminalPrompt'`, `outcome: 'not-applied'`).
- **Конец сессии, перезапуск ленты, `stop()`** — запись снята, таймеры сняты; карточка уходит в `stale` существующим путём выхода процесса.
- Сессии других агентов и Codex без нужды `approval`/`question` — без изменений.
