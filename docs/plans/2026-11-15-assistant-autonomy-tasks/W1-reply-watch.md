# W1 — слежение за сессией и снимок ответа

- **Исполнитель:** junior; senior-ревью (таймеры и подписка на активность).
- **Зависимости:** A6.
- **Сначала прочитать:** `00-common.md`; Спека §6.1, §6.2 целиком, §6.3 («Снимок»), §6.5 (RW-02, RW-04…RW-09,
  RW-16, RW-20); План §3, W1; отчёт A3 (точка исполнения, итог шага).

## Цель

После действия, исполненного без подтверждения, хост следит за сессией, которой дали работу, и выдаёт события «конец
хода» и «ждёт человека» с закреплённым текстом. Куда события идут дальше — W2; здесь они доходят до обратного вызова.

## Сначала сверить

1. Есть ли в ленте сессии записи `prompt` со временем (`deps.feed.snapshot(ref)`, типы ленты в
   `packages/protocol/src/feed.ts`). На них стоит привязка к своему ходу. Если времени у записи нет — остановись и
   сдай `failed` с тем, что нашёл: правило привязки надо менять в спеке.
2. Что нужно `silentTurnEnd` (`packages/core/src/work/silent-endings.ts:109-116`) и откуда хост берёт время старта pty
   (`packages/host/src/endings/silent-endings.ts:108-131`).

## Шаги

1. **`reply-watch.ts`** — чистый модуль: `createReplyWatch({ now, setTimer, onEvent, onNote })` с методами
   - `arm({ ref, name, kind: 'prompt' | 'resume', since })` — постановка; возвращает `watchId`;
   - `onActivity(ref, activity, turnEnd)` — вход от подписки на активность; `turnEnd` — результат `silentTurnEnd`;
   - `onPrompt(ref, at)` — в ленте появилась запись `prompt`;
   - `onClosing(ref)` — сессию закрывают или усыпляют;
   - `clear()` — режим выключили;
   - `recent()` — последние три сессии, которым давали работу (для W5).
   Правила — Спека §6.2: привязка к своему ходу, два вида событий и их ключи, выдержка 3 с только для «конца хода»,
   слежение живёт до «конца хода», пределы 20 и 2 часа с заметкой через `onNote`.
2. **`reply-snapshot.ts`** — чистые функции сборки снимка (Спека §6.3, «Снимок»): текст ответа хода из записей ленты
   после границы; правило длины 6000 → первые 1500 и последние 4500 с отметкой пропуска; для «ждёт человека» — вид
   ожидания и содержимое ждущей карточки; отметка «ответ прочитать не удалось»; последнее письмо помощника этой
   сессии.
3. **`run-plan.ts`.** Перед эффектом шага, который даёт сессии работу (`create_session` с задачей, `wake` с текстом,
   `message` сессии), снять время `since`; после успешного эффекта сообщить наружу `{ ref, name, kind, since }` —
   новым необязательным обратным вызовом в `PlanExecutors` или параметром `runPlan`.
4. **`assistant-service.ts`.** Слежение ставится только для действий, исполненных автоматически (`via: 'auto'`):
   шаги плана (п. 3), одиночное письмо сессии, автоматический ответ на запрос сессии (`kind: 'resume'`). Заметка
   `onNote` публикуется в состоянии как `AssistantState.watchNote` (новое необязательное поле в
   `protocol/src/assistant.ts`).
5. **`host.ts`.** Подписка на `activity.onChange` → `onActivity`; чтение ленты при событии — для снимка; событие с
   готовым снимком уходит в новую необязательную зависимость `onWatchEvent(event)`. Реализацию даёт W2.

## Тесты

`reply-watch.test.ts` на подставных часах:

- RW-04: одно событие активности дважды — один вызов `onEvent`; сессии `s-01` двух работ — разные события; два
  разрешения в одном ходе — два события «ждёт человека»;
- RW-05: конец хода и новая работа через секунду — события нет, слежение стоит;
- RW-06: слежения ставятся по шагам; остановка плана на третьем шаге не снимает первые два; ответ, пришедший до
  конца плана, выдан;
- RW-07: `onClosing` через секунду после конца хода — событие выдано сразу, слежение снято;
- RW-20: сессия работала над прежним ходом — его конец события не даёт; конец хода после `onPrompt` даёт;
- RW-02 (часть): «ждёт человека» → `arm` с `kind: 'resume'` → «конец хода» на той же сессии;
- пределы: 21-е слежение снимает старейшее с заметкой; 2 часа — снятие с заметкой; `clear()` снимает все без
  заметок.

`reply-snapshot.test.ts`: RW-08 (снимок закреплён за своим ходом, а не за последним), RW-09 (20 000 знаков — вывод в
конце сохранён; лента недоступна — отметка).

`run-plan.test.ts`: `since` снят до эффекта; сообщение уходит только после успешного шага.

`assistant-service.test.ts`: действие по клику слежение не ставит (RW-16); автоматическое — ставит.

- Не трогать остров.
