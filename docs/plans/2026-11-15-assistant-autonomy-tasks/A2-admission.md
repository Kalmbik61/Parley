# A2 — допуск запуска

- **Исполнитель:** senior-only. Причина: граница безопасности — кому хост поверит, что вызов пришёл с острова.
- **Зависимости:** A1.
- **Сначала прочитать:** `00-common.md`; Спека §3 («Учётные данные»), §5.2 целиком, §10 AU-07; План §2, A2.

## Цель

Каждый запуск модели помощника — попытка хода разговора или job — получает собственный токен и неизменяемую запись
допуска. Вызов инструмента на границе HTTP превращается в эту запись. Поведение карточек не меняется: `autoAtStart`
вычисляется и доезжает до обработчика, но ничего ещё не исполняет.

```
{ runId, kind: 'turn' | 'job', origin, autoAtStart }
```

`autoAtStart = (assistantAutonomy включён на старте запуска) && origin === 'island'`.

## Что есть сейчас

- Токен разговора создаётся один раз в `ensure()` (`packages/host/src/assistant/assistant-service.ts:535-542`) и живёт
  весь разговор, каким бы ни было происхождение хода (`Ask.origin`).
- `assistant-endpoint.ts:78-83`: `authenticate` возвращает `{ kind: 'conversation' }` или `{ kind: 'job', jobId }`.
- Токен job выпускает `job-tokens.ts` (`issue(jobId)`), зовёт его `job-executor.ts:89`.
- Идентичность разговора для заметок исхода — тот же токен: он лежит в `payload.token` карточки
  (`assistant-service.ts:458`) и сравнивается в `:1041` и `:1222`.

## Шаги

1. **Идентичность разговора отдельно от токена.** У `Conversation` появляется постоянный `id`. Всё, что сейчас
   сравнивает или хранит `conversation.token` ради «чей это разговор» (`payload.token`, `outcomeNote`), переходит на
   `id`. Имя поля в payload карточки можно оставить прежним, если так меньше правок, — значение должно быть `id`.
2. **Токен на попытку хода.** Перед каждым запуском CLI хода (включая повтор после сбоя продолжения) выпускается новый
   случайный токен; он пишется в конфиг MCP этого запуска. Токен прежней попытки перестаёт действовать сразу: при
   новой попытке, при конце хода, при отмене (`cancel`), при `reset` и вытеснении хода новым вопросом.
3. **Запись допуска хода.** Вместе с токеном хост хранит `{ runId, kind: 'turn', origin: ask.origin, autoAtStart }`.
   Флаг читается один раз, в момент выпуска токена, через новую зависимость сервиса `autonomy(): Promise<boolean>`
   (в `host.ts` — `async () => (await loadConfig()).config.assistantAutonomy`, по образцу `leanAgents`, `:966`).
4. **Запись допуска job.** `job-tokens.ts`: `issue` принимает запись допуска и хранит её с токеном; поиск по токену
   возвращает запись. `job-executor.ts` передаёт `job.origin` и значение флага на старте прогона.
5. **Граница HTTP.** `authenticate` возвращает запись допуска вызывающего. Токен законченного, отменённого или
   вытесненного запуска — 401, как сейчас у отозванного токена job. Обработчик (`tool(name, args, caller)`) получает
   запись целиком.
6. **`Owner`.** В `assistant-service.ts` `Owner` несёт запись допуска. Ничто пока не ветвится по `autoAtStart`.

## Тесты

В `assistant-service.test.ts`, `assistant-endpoint.test.ts`, `job-tokens.test.ts`:

- ход `reminder` сменился ходом `island`: вызов инструмента с токеном хода `reminder` — 401; запись допуска нового
  хода — `origin: 'island'`;
- то же для `telegram` → `island`;
- отмена хода между аутентификацией и обработкой: обработчик не создаёт карточку;
- запуск с происхождением `system` при включённом флаге: `autoAtStart === false`; `island` при включённом —
  `true`; `island` при выключенном — `false`;
- флаг включили посреди хода: запись допуска этого хода не меняется;
- заметка исхода (`[system: proposal … was sent]`) после смены токена по-прежнему попадает в разговор, создавший
  карточку, и не попадает в новый разговор после `reset`.

## Разрешено менять в существующих тестах

Только ожидания о токене хода: один токен на разговор → токен на попытку. Каждое изменённое ожидание перечисли в
отчёте.

## Не делать

- Никакого исполнения без подтверждения, новых значений `CardVia`, изменений в хранилище карточек — это A3.
- Промпты и описания инструментов — A4.
