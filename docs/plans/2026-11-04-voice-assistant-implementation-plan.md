## 1. Основа и правила

- Одна интеграционная ветка от origin/master. Фактический SHA фиксируется при старте каждого пункта.
- У параллельных исполнителей отдельные worktree. Общие файлы передаются последовательно (см. «Общие границы»).
- Push и PR — только по команде человека.
- Телефон — вне этого плана, отдельный этап после приёмки острова (T7), на тех же T2, T4 и T5.
- Код пишут junior-исполнители (Sonnet или Sol), по одной задаче, с файлами и критериями из этого плана. Цикл каждой задачи: тесты → ревью → коммит → следующая.
- Тесты пишутся внутри пунктов реализации, а не откладываются в приёмку.
- Сборка, lint и тесты на интеграции запускаются один раз; повтор — только после значимого изменения или сбоя.
- Проверки по пакетам:
  - core: `pnpm --filter @parley/core exec vitest run src/assistant/text.test.ts src/mcp/assistant.test.ts`;
  - host: `vitest run` через тот же `--filter` по human-overview / overview / assistant-service.test.ts.
- Сообщения коммитов, PR и CHANGELOG — на английском (AGENTS.md).

## 3. Трек O — срез состояния (без OpenAI)

### O1 — общий нормализатор
- **Файлы:** `packages/core/src/assistant/text.ts`, `packages/core/src/assistant/text.test.ts`. Публичный вход `@parley/core/assistant` уже существует.
- **Зависимости:** P0.
- **Что делает:** чистая функция «текст + словарь refs → человеческий текст», без Node/DOM.
  - Известные refs заменяются именами, неизвестные — по виду сущности («участник», «комната», «работа»).
  - Границы токенов, длинные номера, удаляются только известные mood-теги.
  - «S24» в обычном тексте не портится; DTO и refs не мутируются.
  - `speakable` не переиспользуется вслепую: `text.ts:138–146` удаляет любые `[[…]]` и refs вместо замены.
- **Приёмка:** H7 и H11 на самой функции (Срез §4); прежний контракт старых речевых функций сохранён.
- **Проверка:** `pnpm --filter @parley/core exec vitest run src/assistant/text.test.ts`.
- **Verifier / ревью:** s-258 (senior-ревью O1–O3).

### O2 — HumanOverviewV1 и проекция
- **Файлы:**
  - новые `packages/host/src/assistant/human-overview.ts` и `human-overview.test.ts` рядом с `packages/host/src/assistant/overview.ts`;
  - тип `HumanOverviewV1` и вложенные типы — новый файл `packages/protocol/src/human-overview.ts`; публичный экспорт — `packages/protocol/src/index.ts`; оба файла принадлежат O2. Core/MCP не импортирует protocol: он передаёт структурный payload через свой транспортный контракт; типизированные потребители host используют protocol.
- **Зависимости:** P0, O1.
- **Что делает:** три группы с приоритетом needsHuman; источники — существующие `OverviewSource`, `sessionDotStateWithNeed`, `liveLead`.
- **Приёмка:** H1–H7 и H9 (Срез §4):
  - архив исключён, неизвестность не превращается в idle, шаг плана не доказывает работающий процесс;
  - краткий и подробный текст имеют одни факты, неперечисленное обозначено;
  - старый `overviewText` и его проверки полноты id сохранены;
  - фикстура каталога 19/17 содержит только разрешённые данные, live-изменения помечены синтетическими.
- **Проверка:** `vitest run` через `--filter` по human-overview / overview.
- **Verifier / ревью:** s-258.

### O3 — контракт через Assistant Core и MCP
- **Файлы:**
  - `packages/host/src/assistant/assistant-service.ts` и его тесты;
  - `packages/core/src/mcp/assistant.ts`, `packages/core/src/mcp/assistant.test.ts`;
  - `packages/core/src/assistant/launch.ts` и соответствующие тесты.
- **Зависимости:** O2, T1. O3 и T1 не редактируют одновременно `assistant-service.ts` и MCP: передача последовательная.
- **Что делает:**

  - MCP сохраняет структуру (сейчас `core/src/mcp/assistant.ts:331–332` оставляет только `body.text`): CLI видит refs, человек — человеческий текст;
  - промпт `launch.ts:109` больше не обещает перечислить всех.
- **Приёмка:** H8, H10, H11:
  - после обзора выбирается правильный detail/propose target при одинаковых именах;
  - прежние подтверждения сохранены;
  - job берёт тот же источник обзора; итог job очищается O1;
  - подключение окончательного текста к Live — в T4, не второй фильтр в O3.
- **Проверка:** core — `src/mcp/assistant.test.ts`; host — `assistant-service.test.ts` через `--filter`.
- **Verifier / ревью:** s-258; senior-ревью границы MCP обязательно.
