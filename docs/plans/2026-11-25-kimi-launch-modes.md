# T2 — Kimi launch permission modes

Base: accepted island approval change `0f5d22da` on top of `c5592604`.
Native Terminal handoff is out of scope.

- Add the optional, Kimi-only creation preference `kimiPermissionMode` to the shared launch dialog and the create, map, launch and persistence contracts. Reject other providers and invalid values. Offer **Use Kimi settings** by default (omit the preference), **Always Ask** (`manual`), **Automatic / Ask When Needed** (`yolo`), and **Full access / Never Ask** (`auto`). Use matching labels and descriptions in Chat, retain provider options and the separate Plan choice, and localize the new strings. Explain that explicitly choosing a permission mode starts a new conversation in execution mode, and that full access concerns Kimi approvals, not sandbox or Parley authority. Gate the selector and the desktop transport on the live host's hello capability and require the advertised CLI option at launch.
- An incoming `launch.kimiAcp.sessionId` of `undefined` means ACP creates a conversation via `session/new`, including when Parley resumes without a provider ID. If the preference is explicit, require the advertised ACP `mode` option to support the selected value, then call `session/set_config_option` with `configId: "mode"` and `manual → default`, `yolo → yolo`, or `auto → auto`. Require the successful RPC to acknowledge the selected mode (even when reported current already matches) before activation or the first prompt. Surface unsupported, failed or mismatched acknowledgments and do not send a prompt.
- Without a preference, send no mode write and preserve inherited Kimi settings including Plan. On all provider-ID load/resume paths, send no creation preference writes, even with an old stored choice. Preserve model/effort restoration and provider-owned current mode and Plan. Chat changes never rewrite the historical creation preference.
- Add tests before implementation for the three mappings, persistence, default and Plan inheritance, missing and existing provider IDs on Parley resume, acknowledgement ordering and failure, Chat labels, and unchanged other providers. Run focused tests, builds and typechecks. Do not run paid provider turns, change live user config or approvals, or restart the app. Commit locally only.

Evidence: the task's verified Kimi Code CLI 2.7.3 ACP behavior, where setting the permission mode cancels Plan, and the [official interaction guide](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/interaction.html).

Chat must not claim the initial ACP mode snapshot is authoritative: Kimi 2.7.3 can report `default` despite active Plan or an inherited permission mode. Present mode choices as actions unless confirmed on this connection. In particular, choosing **Always Ask** must still send a request when the unverified snapshot reports `default`.
