# Что перенять из Herdr App в Parley

**План внедрения от 27 ноября 2026 года.** Цель — дать человеку возможность выйти из Parley во время долгой задачи и при возвращении видеть тот же процесс, его историю и достоверное состояние CLI.

**Основание.** Проверка на macOS проводилась с Herdr App 0.1.18, herdr-core 0.1.22, модом Agent Chat 0.1.5 и установленным Parley 0.39.7. Пути и контракты ниже сверены с `master` Parley на коммите `b74b93c42f6c9c38465ebd70b0d18f58f63a64f5`, включая уже влитую проверку разрешений Codex. Реализацию начинать от основной ветки. Соседний план отправки сообщений уже описывает подтверждение локальной строки по журналу. [План отправки](2026-11-25-chat-send-continuity-plan.md) · [Устройство Herdr App](https://github.com/herdrdev/herdr-app/blob/v0.1.18/defaults/AGENTS.md)

| Приоритет | Что увидит человек | Почему это стоит перенять | Условие выпуска |
|---|---|---|---|
| 1. Выход с работающими агентами | Дополнительный выбор при выходе. При следующем открытии продолжается тот же сеанс | В Herdr после полного выхода из App сохранился PID, терминал продолжал выполнять команды | Процесс действительно работает без Electron и узнаётся после повторного запуска |
| 2. Единая индикация CLI | Строка агента и переключаемые представления Chat/Terminal одинаково показывают, когда CLI работает или ждёт человека | Настоящие Qwen и OpenCode сообщили `idle`, Kimi сообщил `blocked` на вопросе о доверии к папке | Каждый подключённый CLI выдаёт проверенные сигналы. Отдельно проверяются история, ввод и разрешения |

Это два независимо выпускаемых изменения. Зависимости задач — 1 → 2 → 3 и 4 → 5 → 6. Матрицу CLI можно собирать одновременно с работой над выходом. Первый кандидат на поставку — режим выхода на macOS, первый новый клиент для индикации — OpenCode. Сроки пока не измерены. Для их оценки нужны сквозной тест выхода и записи сигналов реальных версий CLI.

## 1. Выход с работающими агентами

В Parley уже есть отдельный host. `packages/desktop/src/main/host-launcher.ts` запускает его с `detached: true` и `unref()`. Повторное окно проходит `hello` по действующему сокету с токеном. PTY отмечает host как занятый на время жизни процесса. Сегодня обычный выход намеренно зовёт `connection.stopHost()`, а закрытие последнего окна на macOS оставляет агентов работать. Механизм реализации — новый выбор в существующем диалоге. [Запуск host](https://github.com/Kalmbik61/Parley/blob/b74b93c42f6c9c38465ebd70b0d18f58f63a64f5/packages/desktop/src/main/host-launcher.ts#L111-L119) · [Действующий обработчик выхода](https://github.com/Kalmbik61/Parley/blob/b74b93c42f6c9c38465ebd70b0d18f58f63a64f5/packages/desktop/src/main/quit-guard.ts)

В пояснении сказать, что фоновые задачи продолжают работать и могут расходовать лимит провайдера. Выбор действует на этот выход. Сохранить текущие действия Enter и Escape.
- [ ] Расширить ответ `ask` до `'stop' | 'keep' | 'cancel'`. При положительном числе сеансов доступны все три выбора. При неизвестном числе показать текст «Не удалось определить число работающих сеансов» и те же варианты. При нуле оставить текущий выход без вопроса. Закрытие окна на macOS продолжает работать как сейчас.

Только `stop` вызывает `connection.stopHost()`. При `cancel` вернуть главное окно и сохранить загрузку обновления. Обычная очистка на `app.quit` закрывает клиентское соединение.

Критерий тот же — один host, тот же PTY, ни одного задания после завершения тестового host. На другой целевой ОС включать выбор после её проверки полного выхода и штатного завершения системы. ## 2. Статусы из нативного терминала

OSC 7501 — короткое сообщение, которое CLI пишет в поток своего терминала. В Parley уже есть ограниченный по памяти потоковый считыватель OSC и обработчик Qwen. Для Qwen готовность определяется сочетанием сигнала терминала с подключением MCP или другими существующими доказательствами. У Codex есть отдельные сигналы заголовка и уведомлений, у OpenCode — события локального сервера, у Kimi — события собственного сеанса. Новый статус служит для отображения в окне. [Текущий обработчик Qwen](https://github.com/Kalmbik61/Parley/blob/b74b93c42f6c9c38465ebd70b0d18f58f63a64f5/packages/host/src/pty/qwen-terminal.ts) · [Как Herdr показывает состояние](https://github.com/herdrdev/herdr-app/blob/v0.1.18/src/model.rs#L597-L607)

### Задача 5. Доставить статус в оба представления без изменения прав на ввод

**Контракт.** Предлагаемое опциональное поле `terminalStatus` в `activity.changed` несёт `state` и, для `blocked`, необязательный `kind` из `auth | permission | question`. Отсутствующее поле или `null` означает «показания CLI нет». Произвольные `msg`, `title`, вывод терминала и промпты в новый контракт не входят. Так старое окно продолжает читать знакомые поля, а новое окно подключается и к старому host.

- [ ] В `packages/protocol/src/events.ts` определить тип поля. В `packages/host/src/activity/terminal-link.ts` и `activity-service.ts` хранить его на время жизни процесса. Собирать один и тот же объект события для живого обновления и `current()`, который host повторяет после `hello`. Одинаковые кадры не вызывают повторную доставку. Смена только `terminalStatus` должна дойти до окна, не запуская подписчиков `onChange` для почты, сна, автоматической отправки и иных действий.
- [ ] Использовать кэш `packages/desktop/src/main/host-connection.ts` и `packages/desktop/src/renderer/store/activity.ts`. При отключении скрыть устаревший статус. В новом соединении актуальное событие имеет приоритет над запоздавшим стартовым снимком. Отсутствие записи в новом полном снимке сбрасывает прежнюю подсказку для этой сессии. Проверить также `clear` и совместимость старого и нового окна с обеими версиями host.
- [ ] В `packages/desktop/src/renderer/sidebar/SessionRow.tsx` и общей для Chat/Terminal панели `packages/desktop/src/renderer/chat/ChatToolbar.tsx` использовать одно правило показа. При закрытой или спящей сессии, явном результате, очереди или авторитетном ожидании Parley приоритет остаётся у этого состояния. Для доступной живой сессии сигнал дополняет строку, когда сообщает новое, например «CLI ждёт ввода». Одинаковую информацию показывать один раз. Для `blocked` без подтверждённого меню доступен штатный переход к терминалу. `done` означает завершение работы, о которой сообщил CLI, и не завершает задачу комнаты.
- [ ] Сохранить источник истины по действиям. Допуск к отправке остаётся у `pty.send`, история — у журнала или API провайдера, разрешение — у текущего запроса или проверенного меню. Пара `blocked → idle` сама не вызывает Enter, не снимает удерживаемый запрос, не открывает кнопки Approve и не подтверждает доставку. Направлять в существующий `qwenStatus` только события Qwen. В тесте `idle` другого CLI не делает Qwen готовым и не засчитывается как подключение MCP. Для Codex сохранить проверку свидетельства запроса из исправления `9033314d0`.
- [ ] В `activity/terminal-link.test.ts` и тестах `activity-service` проверить «изменилось только показание», повтор после `hello` и ноль управляющих вызовов. | CLI молчит, прислал только `idle` или перестал выдавать статус | Работают текущие события провайдера. Очередь, восстановление и возможность отправки подчиняются тем же правилам, что до изменения |

Для Qwen провести три контролируемых хода с локальным ответчиком и сверить обе поверхности с JSONL. Для каждого нового семейства провести один реальный ход и один доступный ему сценарий ожидания. Зафиксировать пару «CLI + версия», режим запуска и результат. Критерий приёмки — все строки таблицы проходят, журнал подтверждает фактически отправленный текст, каждая реплика показана один раз.

```sh
pnpm --filter @parley/host exec vitest run src/pty/send.test.ts src/feed/qwen-prompt.test.ts src/feed/feed-service-opencode.test.ts src/kimi/native-session-steer.test.ts
pnpm --filter @parley/core exec vitest run src/feed/qwen/apply-qwen.test.ts

```
