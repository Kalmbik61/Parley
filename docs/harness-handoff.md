# Свой terminal-харнесс поверх Claude Code — хендофф

Документ для переноса контекста в Cowork. Состояние на 30 августа 2026.

---

## 1. Цель

Терминальное приложение-обёртка над агентскими CLI. Макет:

- **слева сверху** — список сессий: имя и summary как в Claude Code, время работы;
- **слева снизу** — подсессии выбранной сессии: что сделано, subtitle с моделью (Opus / Codex / GLM);
- **справа** — полноценный терминал с работающим агентом и всеми фичами Claude Code.

Дальняя цель — оркестрация нескольких провайдеров (Claude, Codex, GLM) в одном цикле, с общим знанием о том, кто что делает.

Запуск строго локальный, в собственном терминале. Не сервер, не веб.

**Нельзя:** извлекать OAuth-токен из `~/.claude` и подставлять его в сторонний харнесс; писать свой клиент к API с этим токеном; давать другим людям работать через свою подписку.

**Можно:** запускать **немодифицированный официальный бинарь `claude`** на своей машине под своей подпиской. Документация прямо оговаривает допустимость входа конечного пользователя в неизменённый бинарь. Это и есть архитектурная основа проекта.

**Отдельно:** для непрерывной автономии подписка не подходит (5-часовое окно + недельный потолок). Always-on — только API-ключ с pay-as-you-go. У Codex и GLM свои ToS с похожими ограничениями.

⚠️ Политика по этому вопросу менялась четырежды за год. Перед закладкой архитектуры перечитать `code.claude.com/docs/en/legal-and-compliance`.

## 3. Принятые решения

1. **Правую панель не писать, а встраивать.** «Все фичи Claude Code» = сам Claude Code. Справа — PTY-процесс с настоящим бинарём. Это заодно ровно та граница, которая легальна.
2. **Ядро отдельно от UI.** Парсер + watcher + модель сессий — отдельный пакет, отдающий JSON в stdout. Тогда смена фронта стоит дни, а не переписывание.
3. **Стек: TypeScript, UI на Ink.** Причина: вся тяжёлая инженерия рендеринга в Claude Code существует ради стриминга на 60fps, которого в v1 нет — перерисовки идут по событию файла, раз в секунды. Стоковый Ink справляется.
4. **Tauri вычеркнут** — требование запускать в своём терминале. Rust + ratatui оставлен запасным вариантом на случай, если понадобится SSH-режим.
5. **v1 = только просмотр реальных сессий.** Никакого запуска агентов. Риск нулевой, и на нём валидируется парсер.

### Как устроен Claude Code (для ориентира, не для копирования)

React-рендерер на `react-reconciler`, коммитящий не в DOM, а в терминальные host-узлы (`ink-box`, `ink-text`, `ink-raw-ansi`); Yoga считает layout, кадр красится в буфер, диффится с предыдущим и уходит одной буферизованной записью в stdout. Начиналось с Ink, форкнуто до неузнаваемости из-за перфа: стоковый Ink создаёт по JS-объекту на ячейку на кадр. Yoga там — полный TS-порт, не биндинг к C++.

🚫 **В марте 2026 исходники Claude Code утекли через sourcemaps в npm, на них выросли community-тулкиты. Не строить на этом ничего** — это чужой проприетарный код, весь проект окажется на юридически битом фундаменте.

Легальные референсы: сам Ink, Gemini CLI (React + Ink, открыт), Codex CLI (Rust/ratatui), opencode (Go).

## 4. Слой данных

Всё для левой колонки уже лежит на диске:

- `~/.claude/projects/<slug>/<session-id>.jsonl` — по файлу на сессию.
- Мета: `cwd`, `gitBranch`, `version`, `sessionId`.
- Имя сессии — записи `type: "summary"`; иногда лежат в соседнем файле и ссылаются на `leafUuid`, тогда нужно сшивать глобально.
- Время работы — из таймстемпов первой и последней записи.
- Подсессии — сайдчейны субагентов внутри того же файла (`isSidechain: true`, `parentUuid`).
- Бейдж модели — `message.model` у записей подсессии.
- Codex пишет rollout-логи в `~/.codex/sessions`, GLM — в зависимости от харнесса.

**Формат недокументирован и ломается между релизами.** Парсер изолировать за адаптером с версией схемы и тестами на реальных файлах.

🚫 Не читать и не трогать `~/.claude/.credentials.json` ни при каких обстоятельствах.

## 5. Фазы

- **v0** — просмотрщик сессий, только чтение. Валидирует парсер.
- **v1** — PTY справа + `claude --resume <id>` по клику на сессию.
- **v2** — раннеры Codex и GLM, унифицированные бейджи моделей.
- **v3** — оркестрация: общий журнал задач, роутер по капабилити и стоимости.

### Оркестратор (v3, форма решена)

Каждый агент — процесс-адаптер с одинаковым контрактом (task in / structured JSON out): `claude -p --output-format stream-json` + `--resume`, `codex exec`, GLM через OpenAI-совместимый эндпоинт. Сверху роутер с реестром капабилити, общая шина задач (файлы в git или очередь), общий слой инструментов через MCP-сервер.

**Важно:** «знание друг о друге» делать не через прямой чат агентов, а через общий журнал задач — иначе цикл разъезжается и деньги горят.

### Встроенный терминал (v2, путь найден)

`node-pty` крутит настоящий `claude`, `@xterm/headless` работает vt-парсером (движок VS Code без DOM), каждый кадр буфер забирается и рисуется в Ink. Tmux/zellij как подложка — запасной вариант, если перф не вытянет.

Подводные камни: ресайз PTY, мышь и alt-screen в embedded-терминале, лимиты подписки при параллельных сессиях.

## 6. Где остановились

Написан экспортёр `claude-export.mjs` — без зависимостей, потоковое чтение, только чтение из `~/.claude/projects`.

```
node claude-export.mjs --limit 20 --full
```

Выход в `./claude-export`:

- `index.json` — по строке на сессию: id, cwd, ветка, summary, длительность, счётчики моделей и инструментов, `primaryModel`, число подсессий. Готовые данные для левой колонки.
- `sessions/<id>.json` (при `--full`) — дерево: главная цепочка + сайдчейны, у каждого модели и первая реплика как название задачи.
- `schema-report.json` — какие поля и каких типов реально встретились, с примерами.

Проверено на синтетической сессии с сайдчейном и оборванной последней строкой — считает корректно. На реальных данных не запускалось.

### Следующий шаг

Запустить экспортёр на своих сессиях и сверить `schema-report.json` с предположениями из раздела 4 — `isSidechain`, `leafUuid`, `message.model`. Где формат разошёлся, там правим модель данных, и только после этого проектируем UI.
