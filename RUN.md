# Инструкция для Claude Code — проект my-harnas

Работай в этой папке. Это my-harnas — терминальный харнесс поверх агентских CLI.
Вся документация уже подготовлена, ничего не переизобретай:

- `.ralph/PROMPT.md` — принципы проекта. Прочитай ПЕРВЫМ и соблюдай неукоснительно,
  особенно Key Principles: юридическая граница (только немодифицированный бинарь
  `claude`), `~/.claude` строго read-only, `.credentials.json` не трогать никогда,
  стоковый Ink без кастомного рендерера, ядро отдельно от UI.
- `.ralph/fix_plan.md` — полный план: High (v0) → Medium (v1) → Low (v2). Low — не
  опционально, это просто «позже».
- `.ralph/specs/` — спецификации: data-layer, ui, pty, runners.
- `.ralph/AGENT.md` — команды сборки и тестов.
- `docs/harness-handoff.md` — исходный контекст проекта.
- `tools/claude-export.mjs` — рабочий прототип парсера (портировать, не переписывать).

## Порядок работы

0. Подготовка: если git-репо ещё нет — `git init` и первый коммит
   `chore: ralph scaffolding`. Проверь node >= 20 и pnpm >= 9.
1. Прочитай `.ralph/PROMPT.md`, `.ralph/fix_plan.md` и specs.
2. Выполняй задачи fix_plan.md строго по порядку, ПО ОДНОЙ: реализовал → прогнал
   тесты → conventional commit → отметил чекбокс `[x]` в fix_plan.md → следующая.
3. Первые две задачи High Priority (прогон `tools/claude-export.mjs` на реальных
   `~/.claude/projects` без `--limit` и сверка schema-report со specs/data-layer.md)
   обязательны ДО любого кода парсера. Если реальная схема разошлась с описанной —
   сначала поправь specs/data-layer.md, находки зафиксируй в fix_plan.md → Notes.
4. Обнаруженные по ходу задачи добавляй в fix_plan.md → Discovered, не бросайся
   делать их сразу.
5. Заблокирован — остановись и опиши блокер. Никаких обходов через запрещённое
   (Protected Files, Key Principles).

## Контрольные точки

- Закончил весь блок High Priority (v0) — остановись, покажи сводку: что сделано,
  результат сверки схемы, что попало в Discovered. Дождись «продолжай».
- То же после Medium (v1) и после Low (v2).

## Возобновление

Эта инструкция реюзабельна: в новой сессии просто скажи «прочитай RUN.md и продолжай» —
состояние живёт в чекбоксах fix_plan.md, продолжай с первого неотмеченного.
