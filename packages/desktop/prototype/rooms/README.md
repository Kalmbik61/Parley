# Harnas · Organic rooms

Интерактивный прототип следующего интерфейса **my_harnas**. Основан на текущем Electron-проекте и переданном архиве «Прототип дизайна харнаса», а не на проекте scanum.

Визуальная основа — Organic: Figtree / Caprasimo, тёплая светлая и тёмная темы, скруглённая рабочая область, плотная оболочка IDE. Шрифты и предоставленные логотипы сохранены локально; после сборки внешние запросы для интерфейса не нужны.

## Запуск

Из корня `my_harnas`, с уже установленными зависимостями проекта:

```sh
pnpm --dir packages/desktop exec vite --config prototype/rooms/vite.config.mjs
```

Открыть `http://127.0.0.1:8891/`.

Собрать:

```sh
pnpm --dir packages/desktop exec vite build --config prototype/rooms/vite.config.mjs
```

Либо показать готовую сборку без Node:

```sh
python3 -m http.server 8891 --bind 127.0.0.1 --directory packages/desktop/prototype/rooms/dist
```

Не запускайте оба сервера на одном порту одновременно. HTML из `dist` нужно открывать через локальный сервер, а не через `file://`.

## Что попробовать

1. **Refunds**: посмотреть позиции команды, затем `Return for rework`. Замечание попадёт в следующую ревизию, историю решения и критерии плана.
2. `Approve plan` сохраняет согласованную редакцию. `Start implementation` отдельно переводит комнату к выполнению.
3. `Backend needs your input` открывает демонстрационный CLI-терминал. Его разрешение отделено от решения комнаты.
4. `Plan & ownership` показывает назначенные области, владельцев, зависимости и состояния. Нажатие на задание открывает сессию.
5. `Materials` / `Context` показывают анализ, контракт и план проверки. Документы открываются во вкладках; `Files` и `Changes` дают разные исходники и diff.
6. Напечатать `@` в сообщении и выбрать агента мышью или клавишами ↑/↓, Enter. **Упоминание становится цветным чипом прямо внутри редактора.** Backspace удаляет чип целиком. В отправленном сообщении mention остаётся внутри текста; отдельной строки адресатов над редактором нет. Сообщение видно всей комнате.
7. **New task**: имя, задача, агенты, роли, провайдер, модель/effort, worktree и источник контекста. Один агент отображается как Session; добавление второго через **Add agents** превращает ту же беседу в Room без потери истории. Переключателя типа нет. Model/effort помечены Proposed; реальный backend их пока не принимает.
8. Переключить workspace: комнаты, вкладки и черновики не смешиваются. Сессию можно перетащить в другую комнату того же workspace.
9. Свернуть карточку или закрыть вкладку комнаты: в sidebar останутся маленькие иконки Claude/Codex с числом участников и отдельным числом работающих. Закрытие вкладки не останавливает агентов.
10. **Settings**: Appearance, Agents & delivery, Terminal, Product map. Параметры отражают текущий config и backlog. Загрузка сценария через Product map требует подтверждения и заменяет локальные демоданные.
11. При создании выключить Start new agents: задача подготовлена, **Launch prepared** запускает только pending-участников в образце.

Клавиши: `⌘J` — поиск и команды; `⌘T` — новая задача; `⌘N` — workspace; `⌘B` / `⌘L` — боковые панели. В веб-браузере часть системных сочетаний может быть перехвачена браузером; у действий есть кнопки. Ширину боковых панелей можно менять перетаскиванием границы.

## Граница прототипа

Это React/Vite preview с локальными образцами данных, **без подключения к harnas-host**. Он не запускает агентов, команды, тесты проекта, commit или merge. Сообщения агентов, терминалы, изменения и результаты внутри интерфейса демонстрационные. Состояние примеров и тема сохраняются в localStorage текущего origin; черновики сохраняются между комнатами в пределах открытой страницы.

Production-код Electron, host, core и protocol не менялся. Новые зависимости не добавлены: используются React, Lucide, react-markdown и Vite из desktop-пакета.

Точное соответствие реализации и предложения: [INTEGRATION.md](./INTEGRATION.md). Проверки: [CHECKS.md](./CHECKS.md).
