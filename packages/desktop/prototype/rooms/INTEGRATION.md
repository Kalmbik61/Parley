## Главный сценарий

1. Создать workspace: проект, название, цель.
2. Нажать **New task**: назвать задачу и описать нужный результат.
3. Добавить одного или нескольких новых агентов либо подключить существующих в этом workspace. Для новых видны провайдер, модель, effort, роль, индивидуальные инструкции, рабочая папка и источник контекста.
4. **Launch task** запускает демонстрационный сценарий. Выключенный Start new agents позволяет сначала подготовить состав; **Launch prepared** запускает только ещё не начавших участников.
5. При одном участнике показывается **Session**, при нескольких — **Room**. Переключателя типа нет. **Add agents** сохраняет идентичность беседы, сообщения, решения и материалы. Терминал каждого участника остаётся отдельной вкладкой.
6. При сворачивании карточки или закрытии вкладки видны маленькие иконки провайдеров с числом участников каждого, общий состав и отдельный счётчик работающих сейчас. Закрытие вкладки не останавливает агентов. Неизвестный провайдер получает нейтральный значок.

Комната не требует выбора режима. Запрос определяет, нужно ли обсуждение, реализация, ревью или сравнение вариантов. Лид координирует команду и передаёт вопросы человеку. Предложение плана — доступный сценарий, а не обязательный этап любого сообщения. Итог и разрешения CLI остаются за человеком. Стандартизированная оценка вариантов 1–10 из будущего сценария команд требует отдельной спецификации критериев; сам рейтинг не утверждает решение.

## Упоминания

`@` открывает поиск участника. Выбор вставляет `@S03 Reviewer` **в место курсора в тексте**. Текст после курсора сохраняется, Backspace удаляет цельный mention. В отправленном сообщении тот же адресат остаётся inline. Отдельной плашки получателей над редактором больше нет.

Сериализация сохраняет стабильный код; общая функция разбора используется и для отображения, и для `to[]`. Только точные известные коды маршрутизируют сообщение; email и неизвестные коды остаются текстом. Упоминание адресует доставку/пробуждение, но сообщение видно всем в комнате. Приватность из mention не выводится.

## Настройки и ограничения

Базовые значения взяты из `packages/core/src/config.ts`: autoLaunch=true, messageRate=20/час, resumeRate=6/час, silenceThresholdMs=30000, fontSize=14, worktreeRoot=`~/harnas/worktrees`. Auto-wake — отдельная пауза, не синоним autoLaunch. Изменение silence threshold сейчас требует перезапуска host (TODO §4).

В preview значения хранятся только в localStorage. Переключение темы и образец шрифта меняют сам preview; лимиты и параметры запуска не меняют настоящий host или CLI. Model/effort сейчас отсутствуют в `sessions.create`; свободный ввод модели здесь демонстрирует будущую настройку без выдуманного каталога. При интеграции значения, допустимые effort и наличие CLI нужно валидировать у конкретного провайдера. Подписочные токены, Keychain и credentials не читаются; лимиты подписки не симулируются.

## Контракт переноса

- Одна долговечная conversation/task identity связывает состав, сообщения и вкладки; визуальное Session/Room определяется количеством участников. Существующие session IDs, `contextFrom`, права и терминалы сохраняются.
- Создание команды не является одной существующей атомарной операцией. При частичном сбое показать результат каждого запуска; Retry повторяет только неудавшихся, не создаёт дублей. Созданная работа сохраняется. Подключение существующего агента не перезапускает CLI.
- Добавление в другую комнату само по себе не удаляет старое членство. Исключительное членство потребует отдельного решения и миграции.
- Обновление lead/member выполняется host с проверкой workspace и актуального состава. Model/effort сохраняются как выбранная конфигурация запуска, не как гарантированное состояние CLI.
- `resolveProposal` должен включать proposalId, expectedRevision, действие и заметку. Утверждённая версия неизменяема; повторное нажатие идемпотентно. Изменение плана не расширяет ранее разрешённый запуск незаметно.
- Notes/diff/commit/merge привязываются к реальному выбранному root и сессии, не к общему названию комнаты. Владение областью — координация, не техническая блокировка файлов.
