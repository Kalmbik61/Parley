# Test vectors

All vectors use the cacophony JSON layout (`protocol_name`, `init_*`, `resp_*`, `handshake_hash`, `messages`;
even message indices are written by the initiator). Tests check every file's sha256 before using it.

## `ikpsk0-vectors.json` — `Noise_IKpsk0`

- Copied verbatim from the mobile spike (`remote-spike/noise-vectors/ikpsk0-vectors.json`, step S7a);
  sha256 `5511d881fbb1a9bb550ef1cfde138bfd4bfbea1b2d38c6fe98c6201831f8bf79`, checked on copy and in the tests.
- No published `IKpsk0` vectors exist. These six were generated by two implementations that share no Noise
  code — `github.com/flynn/noise` v1.1.0 (Go, x/crypto) and `noiseprotocol` 0.3.1 (Python, `cryptography` /
  OpenSSL). Each vector was generated by one and checked byte for byte by the other: both handshake messages,
  `handshake_hash` and six transport messages. Both implementations also matched published psk vectors
  (cacophony `KKpsk0`, `IKpsk1`, `IKpsk2`; snow `IKpsk0+psk2` for `noiseprotocol`).
  See `docs/research/2026-10-31-mobile-spike-results.md` §7.2.
- Vectors 0–2: `Noise_IKpsk0_25519_ChaChaPoly_SHA256`, the frozen suite (short payloads, empty payloads and
  prologue, payloads ≥ 1 KiB).
- Vectors 3–5: `Noise_IKpsk0_25519_ChaChaPoly_BLAKE2b`. The package does not ship BLAKE2b; the test builds a
  BLAKE2b primitives object from `@noble/hashes` and runs them through the same state machine, and also checks
  that the SHA-256 primitives do **not** reproduce them — a guard against mixing up the suite hash.
