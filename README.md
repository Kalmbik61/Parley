# my-harnas

Терминальный харнесс поверх агентских CLI. Слева — история сессий Claude Code и
Codex с подсессиями субагентов, справа — настоящий агент, запущенный во встроенном
псевдотерминале.

```
┌───────────────────────────┬──────────────────────────────────────────┐
│ SESSIONS (146)            │                                          │
│▌Cl my-harnas    12м ⚡Opus │  claude --resume <id> живёт здесь        │
│ Cx рефакторинг   1ч Codex │  весь ввод уходит агенту,                │
├───────────────────────────┤  Ctrl+Q возвращает фокус спискам         │
│ SUBSESSIONS               │                                          │
│ ▸ explore codebase   Opus │                                          │
└───────────────────────────┴──────────────────────────────────────────┘
 ⚑ строка статуса — единственный канал уведомлений      w · Ctrl+Q
```

Клавиша `w` переключает левую колонку во второй режим — **работы**: проекты →
работы → сессии внутри работы, с их статусом, провайдером, моделью, токенами и
непрочитанными сообщениями.

```
┌────────────────────────────┬────────────────────────┐
│ РАБОТЫ (2)                 │                        │
│ ~/dev/shop ─────────────── │                        │
│ ▾ Авторизация       ●2 ▤1  │  здесь тот же агент    │
│   ✓ план               12м │                        │
│     Claude Opus            │                        │
│▌  ● бэкенд          32м ▤1 │                        │
│▌    Codex GPT-5.2          │                        │
│ ▸ Платежи (4)           ●1 │                        │
├────────────────────────────┤                        │
│ ДЕТАЛИ — бэкенд            │                        │
│ Codex GPT-5.2              │                        │
│ Реализовать шаги 1–3 пла…  │                        │
│ ● active · 32м             │                        │
│ ↑1.2к ↓845 ⇄50к/3.0к       │                        │
│ ▤ план 09:41 «жду мигр…»   │                        │
│ арт: — · суб: 2            │                        │
│ ист: ◌ 09:12 → ● 09:14     │                        │
└────────────────────────────┴────────────────────────┘
```

Выбранный ряд подсвечен фоном (в макетах он обозначен `▌`), у сессии он
двухэтажный: статус и роль сверху, провайдер и модель — строкой ниже. Работы
сворачиваются и разворачиваются, `done` свёрнуты сразу, `archived` не
показываются. Карты работ (`<проект>/.harnas/works/<id>/map.json` и глобальный
индекс в `~/.harnas`) читаются по событиям watcher — как и история сессий.

Нижняя панель в этом режиме — **ДЕТАЛИ** выбранной строки: задача, статус
(у `◐ idle` — сколько молчит лог, у вышедших — время выхода и код), четыре
счётчика токенов, сводка (`progress:` — промежуточный отчёт агента, `авто:` —
дозаказанное резюме, `(отчёта нет)` — отчёта не было), входящие сообщения,
артефакты, субагенты и история переходов. На узкой колонке всё то же в
компактной форме; панель фокусируется по `Tab` и листается `↑↓` / `j k`.
Если выбрана работа — в панели её цель и счётчики сессий.

Работает строго локально, в вашем собственном терминале. Это не сервер и не веб-приложение.

> Интерфейс выше — текущий. Следующая версия (TUI v2, спроектирована и прошла
> инженерное ревью 2026-09-05) меняет его на узкий сайдбар без рамок и одну панель
> в стиле herdr, с префиксным вводом и цветными точками состояния агента.
> См. раздел «Куда идём» и `docs/specs/2026-09-05-tui-v2-design.md`.

## Архитектура

Три слоя, каждый отдельно тестируется и общается с соседями только данными:

```
   ~/.claude/projects/*.jsonl      <проект>/.harnas/works/<id>/       ~/.harnas/
   ~/.codex/sessions/*.jsonl         map.json  briefs/  artifacts/     providers.json
            │  только чтение                 │  пишет только харнесс   works-index.json
            ▼                                ▼                             │
   ┌──────────────────────── packages/core ───────────────────────────────┐
   │ адаптеры схем → индекс сессий → watcher     хранилище карты (lock,   │
   │ метрики: токены, длительность, инструменты   .bak, переходы статусов) │
   │ реестр провайдеров + бриф + MCP-конфиг      harnas-core CLI (JSON)    │
   │ harnas-mcp: get_map · report · spawn_session · wait_for · send/inbox  │
   └──────────────┬───────────────────────────────────────┬───────────────┘
                  │ типы и JSON                            │ stdio MCP
                  ▼                                        ▼
   ┌──────── packages/tui ────────┐            ┌── claude (стоковый бинарь) ──┐
   │ Ink: списки, детали, диалоги │  node-pty  │ --session-id --mcp-config    │
   │ PTY-менеджер + @xterm/headless│◀─────────▶│ агент видит карту через MCP  │
   │ строка статуса, события ⚑    │            └──────────────────────────────┘
   └──────────────────────────────┘
```

- **core** ничего не знает про UI: читает логи провайдеров, ведёт карту работы,
  считает метрики, поднимает MCP-сервер для агентов и печатает JSON в stdout.
  Всё, что читает `~/.claude` и `~/.codex`, делает это только на чтение.
- **tui** — тонкий потребитель core: рисует списки и панель, спавнит агента в
  псевдотерминале, маршрутизирует ввод. Перерисовка по событиям watcher, не по таймеру.
- **агент** — немодифицированный `claude` (или `codex`), запущенный под вашим
  логином. Про харнесс он узнаёт только из брифа и MCP-инструментов; ни один
  токен и ни один файл учётных данных через харнесс не проходит.

Карта работы — единственное общее состояние: кто что делает, что сделано, где
результат. Агенты её не редактируют, а отчитываются через `report`; читатели
(TUI, `get_map`) выводят из неё всё остальное.

## Куда идём: TUI v2

Спроектировано, ждёт макетов и реализации. Что меняется:

- **Сайдбар и одна панель.** Слева работы с номерами и точкой состояния, строка
  `new`, дерево сессий выбранной работы; справа панель целиком под агента, без
  наших заголовков. Список истории `~/.claude` уходит с главного экрана в пикер.
- **Префикс вместо escape-клавиши.** Все клавиши идут агенту, харнесс слушает
  только `ctrl+q` + действие (`c` новая сессия, `w` работы, `g` история, `i` детали,
  `j`/`k` соседняя сессия, `?` справка) и мышь. `ctrl+b` не используется: он занят
  самим Claude Code.
- **Состояние агента из его же хуков.** Сессия запускается с `--settings`, где наши
  хуки одной командой дописывают события в `events/<session>.jsonl`. Из них
  выводится `working` (серый, мигает), `blocked` (жёлтый: ждёт разрешения или
  ответа), `unseen` (синий: закончил, вы не смотрели), `idle`. Страховка —
  jsonl-watcher, как сейчас.
- **Быстрая сессия.** `new` открывает Claude без диалога, работа заводится сама и
  получает заголовок из первой реплики.
- **Живость по pid.** После перезапуска харнесса сессии, запущенные вне него и всё
  ещё живые, не объявляются вышедшими.
- **`~/.harnas/config.json`** для префикса, ширины сайдбара, порога тишины и
  выключателя мыши.

Один провайдер, Claude Code; Codex и GLM остаются в реестре и вернутся в интерфейс
позже. Отложенное с причинами — в `TODOS.md`.

## Юридическая рамка

Проект держится на одной границе, и она не обсуждается:

- запускается **только немодифицированный официальный бинарь** (`claude`, `codex`)
  из вашего `PATH`, под вашим же логином;
- харнесс **никогда не читает, не хранит и не подставляет учётные данные**:
  `~/.claude/.credentials.json` и `~/.codex/auth.json` не открываются ни при
  каких условиях;
- каталоги истории (`~/.claude/projects`, `~/.codex/sessions`) открываются
  **только на чтение**;
- никакого своего клиента к API и никаких обёрток над токенами подписки.

Это соответствует политике Anthropic (перечитано 2026-09-02): бинарь не должен
модифицироваться, а вход конечного пользователя в неизменённый Claude Code под
своей подпиской прямо допускается. Подробности — в
`code.claude.com/docs/en/legal-and-compliance`.

## Требования

- Node.js >= 20 (проверено на 22)
- pnpm >= 9
- `claude` и/или `codex` в `PATH` — те, что вы уже используете

## Установка и запуск

```bash
pnpm install
pnpm build
pnpm --filter @harnas/tui dev
```

`pnpm install` доустанавливает бит исполнения вспомогательному бинарю node-pty:
pnpm распаковывает его без прав, и без этого PTY не стартует.

Ядро можно использовать и отдельно от UI — оно печатает в stdout только JSON:

```bash
node packages/core/dist/cli.js index
node packages/core/dist/cli.js session <id>
```

## Клавиши

| Клавиша             | Действие                                                        |
| ------------------- | --------------------------------------------------------------- |
| `↑` `↓` или `j` `k` | навигация по активному списку                                   |
| `Tab`               | переключение панелей: сессии → подсессии → терминал             |
| `Enter`             | открыть выбранную сессию в правой панели                        |
| `Enter` на работе   | свернуть / развернуть её (режим работ)                          |
| `Enter` на сессии   | диалог запуска `◌`, возобновления `○` `✓` `✗`, attach к `●` `◐` |
| `w`                 | режим левой колонки: все сессии ↔ работы                        |
| `←` `→` или `h` `l` | свернуть / развернуть работу (режим работ)                      |
| `n`                 | новая сессия выбранного провайдера (режим «все сессии»)         |
| `n` в режиме работ  | диалог новой сессии в выбранной работе                          |
| `N`                 | диалог новой работы (режим работ)                               |
| `s` на `○`          | дозаказать резюме для сессии, вышедшей без отчёта               |
| `p`                 | фильтр по провайдеру: все → Claude → Codex → GLM → все          |
| `r`                 | принудительный ре-скан истории                                  |
| `R`                 | перезапустить завершившегося агента                             |
| `q` / `Ctrl+C`      | выход                                                           |
| `Ctrl+Q`            | вернуть фокус спискам из терминала                              |

Диалоги (новая работа, новая сессия, запуск, возобновление и дозаказ резюме) занимают место
нижней левой панели и модальны для левой колонки: `↑↓` / `Tab` — по полям,
`←→` — по вариантам селектора, `Enter` — далее и подтвердить, `Esc` — закрыть
без изменений. Правая панель при этом не трогается. Открываются они только из
фокуса списков: пока ввод идёт агенту, ничто не выпрыгивает.

Запуск идёт через тот же PTY-менеджер: команда и аргументы берутся из реестра
провайдеров, стартовым промптом становится бриф (`.harnas/works/<id>/briefs/`),
который перечитывается с диска при запуске — правьте его своим редактором.
Сессия, запущенная вне харнесса (`harnas-core work session new`), к панели не
подключается: у харнесса нет её PTY, и правая панель это прямо говорит.

Сессия, вышедшая без отчёта (`○`), резюме не оставляет. `s` на такой строке
дозаказывает его: харнесс достаёт транскрипт из логов провайдера (для Codex —
своим адаптером) и один раз зовёт стоковый `claude -p` командой из реестра.
Пока считается, в СВОДКЕ стоит «авто-резюме: считается…»; готовый текст
попадает в карту как `summary` с пометкой `авто` (`summarySource: "auto"`) и
всплывает в строке статуса. У GLM истории нет — дозаказ ему недоступен.

Нижняя строка терминала — строка статуса: единственное место уведомлений в обоих
режимах (включая предупреждение о параллельных агентах). `⚑N` — сколько событий
ещё не просмотрено; событие гаснет, когда фокус побывал на его строке в списках.

`HARNAS_ASCII=1` заменяет Unicode-глифы списка работ (`● ◌ ✓ ▤ ▾ …`) на
ASCII-запасные — для терминалов и шрифтов, которые их не рисуют. То же
происходит само, когда локаль терминала (`LC_ALL`, `LC_CTYPE`, `LANG`) задана и
не UTF-8.

Пока в правой панели работает живой агент, **весь ввод принадлежит ему** — включая
`q`, `Tab` и `Ctrl+C`. Забрать фокус обратно можно только escape-клавишей; она
настраивается: `HARNAS_ESCAPE_KEY=w` сделает ею `Ctrl+W`.

## Координация агентов

Работа — единица координации внутри проекта: заголовок, цель и сессии разных
провайдеров, которые знают друг о друге через одну общую карту. Пишет карту
только харнесс; агенты читают её и отчитываются через MCP-сервер.

```
<проект>/.harnas/works/<work-id>/
  map.json            карта работы: сессии, статусы, метрики, резюме, сообщения
  map.json.bak        предыдущая версия — обновляется при каждой записи
  briefs/<id>.md      стартовый промпт сессии; правится своим редактором
  mcp/<id>.json       конфиг MCP-сервера для этой сессии
  artifacts/          планы, отчёты и прочее, что кладут агенты

~/.harnas/
  providers.json      необязательные переопределения реестра провайдеров
  works-index.json    глобальный индекс работ: проект, id, заголовок, статус
```

`HARNAS_HOME` переносит `~/.harnas` в другое место — этим же тесты держатся
подальше от вашего настоящего каталога. Коммитить `.harnas/` проекта или
добавить его в `.gitignore` — ваш выбор, харнесс это не решает.

### Что видит агент

Каждой запускаемой сессии харнесс генерирует свой конфиг stdio-сервера
`harnas-mcp` и передаёт через окружение `HARNAS_WORK_DIR` и `HARNAS_SESSION_ID` —
представляться агенту не нужно, сервер знает, кто звонит. Инструменты:

| Инструмент                                          | Что делает                                                     |
| --------------------------------------------------- | -------------------------------------------------------------- |
| `get_map()`                                         | вся карта плюс провайдеры реестра с пометкой доступности       |
| `report(status, summary, artifacts)`                | `done` / `failed` — итог, `progress` — промежуточное резюме    |
| `spawn_session(provider, label, task, contextFrom)` | новая `pending` сессия с брифом; её откроет пользователь       |
| `wait_for(target, timeoutSec)`                      | ждать завершения сессии или сообщения; по таймауту — `running` |
| `send_message(to, text)`                            | сообщение другой сессии работы                                 |
| `check_inbox()`                                     | непрочитанные входящие; помечает их прочитанными               |

Пути артефактов — всегда относительно корня проекта. Сессия, запущенная с нашим
конфигом, но без `HARNAS_SESSION_ID`, получает только `get_map`.

### Без TUI

Слой работает и из обычного терминала — ядро печатает в stdout только JSON
(в установленном виде это бинарь `harnas-core`):

```bash
node packages/core/dist/cli.js work new --title "Авторизация" --goal "логин по e-mail"
node packages/core/dist/cli.js work list
node packages/core/dist/cli.js work map --work w-0001
node packages/core/dist/cli.js work session new \
  --work w-0001 --provider claude --label тесты --task "прогнать e2e"
```

Последняя команда создаёт `pending`-запись, пишет бриф и MCP-конфиг и печатает
готовую команду запуска (`command`, `args`, `cwd`, `env`). Запущенный ею стоковый
`claude` видит карту, отчитывается и может породить свои сессии; к панели
харнесса такая сессия не подключается — её PTY не у него.

## Что где лежит

- `packages/core` — чтение истории: потоковый разбор `.jsonl`, версионированные
  адаптеры схем, индекс сессий, watcher и CLI. Наружу отдаёт JSON и типы,
  про UI ничего не знает.
  - `src/work/` — карта работы: типы, хранилище с блокировкой, бриф, метрики,
    MCP-конфиг, дозаказ резюме.
  - `src/mcp/` — сервер `harnas-mcp` и его инструменты.
  - `src/providers.ts` — реестр провайдеров: чем запускать, как передать id,
    MCP-конфиг и промпт.
- `packages/tui` — Ink-приложение: списки, режим работ, диалоги, PTY-менеджер,
  VT-парсер (`@xterm/headless`), маршрутизация ввода, строка статуса.
- `docs/specs/` — спецификации слоя координации (`2026-09-02-coordination-design.md`),
  текущего режима работ и TUI v2 (`2026-09-05-tui-v2-design.md`, с отчётом
  инженерного ревью в конце) и брифы для дизайнера.
- `.ralph/specs/` — спецификации v0–v2: слой данных, старый UI, PTY, раннеры.
- `docs/schema/` — снимки реальных схем обоих провайдеров, по которым сверяется парсер.
- `TODOS.md` — отложенная работа с причинами и точками входа.

## Провайдеры

|             | История сессий           | Запуск в панели        |
| ----------- | ------------------------ | ---------------------- |
| Claude Code | да, `~/.claude/projects` | `claude --resume <id>` |
| Codex       | да, `~/.codex/sessions`  | `codex resume <id>`    |
| GLM         | нет                      | `glm`                  |

У GLM нет своего формата истории: он ходит через OpenAI-совместимый эндпоинт
внутри чужих харнессов. Поэтому в списке сессий его нет — но выбрать его в
переключателе провайдеров можно, и `n` запустит новую сессию.

## Известные ограничения

- **Мышь** пробрасывается только в SGR-кодировании (`?1006`). Древние форматы
  X10 (`?1005`) и urxvt (`?1015`) не поддерживаются.
- **Поведение живого `claude` внутри панели** проверяется вручную: настоящий
  бинарь в автотестах не запускается никогда — лимиты подписки и недетерминизм,
  тесты идут против stub-бинаря. Проверено 2026-09-02: полноэкранный интерфейс,
  навигация по его меню и возврат фокуса по Ctrl+Q работают. Прокрутка scrollback
  и мышь на живом агенте пока не проверялись.
- **Формат `.jsonl` недокументирован** и меняется между релизами. Расхождение
  ловится сверкой со снимком схемы, см. ниже.
- Запуск нескольких агентов сразу расходует лимиты подписки — харнесс предупреждает,
  но не блокирует.

## Разработка

```bash
pnpm -r test                          # все тесты
pnpm --filter @harnas/core test:coverage
pnpm lint
pnpm format
```

После обновления Claude Code или Codex стоит пересверить схему:

```bash
node tools/claude-export.mjs --full
node tools/scrub-export.mjs claude-export docs/schema
node tools/observe-schema.mjs --root ~/.codex/sessions --out docs/schema/codex-schema-report.json
git diff docs/schema/
```

Непустой diff означает, что формат поехал и нужен новый адаптер схемы.

Фикстуры для тестов делаются из реальных сессий с полной анонимизацией:
`node tools/make-fixtures.mjs <session-id> ...`.
