# my-harnas

Терминальный харнесс поверх агентских CLI. Слева — история сессий Claude Code и
Codex с подсессиями субагентов, справа — настоящий агент, запущенный во встроенном
псевдотерминале.

```
┌───────────────────────────┬──────────────────────────────────────────┐
│ SESSIONS (146)            │                                          │
│▌Cl my-harnas    12м ⚡Opus │  claude --resume <id> живёт здесь        │
│ Cx рефакторинг   1ч Codex │  весь ввод уходит агенту,                │
├───────────────────────────┤  Ctrl+Q возвращает фокус спискам         │
│ SUBSESSIONS               │                                          │
│ ▸ explore codebase   Opus │                                          │
└───────────────────────────┴──────────────────────────────────────────┘
 ⚑ строка статуса — единственный канал уведомлений      w · Ctrl+Q
```

Клавиша `w` переключает левую колонку во второй режим — **работы**: проекты →
работы → сессии внутри работы, с их статусом, провайдером, моделью, токенами и
непрочитанными сообщениями.

```
┌────────────────────────────┬────────────────────────┐
│ РАБОТЫ (2)                 │                        │
│ ~/dev/shop ─────────────── │                        │
│ ▾ Авторизация       ●2 ✉1  │  здесь тот же агент    │
│   ✓ план               12м │                        │
│     Claude Opus            │                        │
│▌  ● бэкенд          32м ✉1 │                        │
│▌    Codex GPT-5.2          │                        │
│ ▸ Платежи (4)           ●1 │                        │
├────────────────────────────┤                        │
│ ДЕТАЛИ — бэкенд            │                        │
│ Codex GPT-5.2              │                        │
│ Реализовать шаги 1–3 пла…  │                        │
│ ● active · 32м             │                        │
│ ↑1.2к ↓845 ⇄50к/3.0к       │                        │
│ ✉ план 09:41 «жду мигр…»   │                        │
│ арт: — · суб: 2            │                        │
│ ист: ◌ 09:12 → ● 09:14     │                        │
└────────────────────────────┴────────────────────────┘
```

Выбранный ряд подсвечен фоном (в макетах он обозначен `▌`), у сессии он
двухэтажный: статус и роль сверху, провайдер и модель — строкой ниже. Работы
сворачиваются и разворачиваются, `done` свёрнуты сразу, `archived` не
показываются. Карты работ (`<проект>/.harnas/works/<id>/map.json` и глобальный
индекс в `~/.harnas`) читаются по событиям watcher — как и история сессий.

Нижняя панель в этом режиме — **ДЕТАЛИ** выбранной строки: задача, статус
(у `◐ idle` — сколько молчит лог, у вышедших — время выхода и код), четыре
счётчика токенов, сводка (`progress:` — промежуточный отчёт агента, `авто:` —
дозаказанное резюме, `(отчёта нет)` — отчёта не было), входящие сообщения,
артефакты, субагенты и история переходов. На узкой колонке всё то же в
компактной форме; панель фокусируется по `Tab` и листается `↑↓` / `j k`.
Если выбрана работа — в панели её цель и счётчики сессий.

Работает строго локально, в вашем собственном терминале. Это не сервер и не веб-приложение.

## Юридическая рамка

Проект держится на одной границе, и она не обсуждается:

- запускается **только немодифицированный официальный бинарь** (`claude`, `codex`)
  из вашего `PATH`, под вашим же логином;
- харнесс **никогда не читает, не хранит и не подставляет учётные данные**:
  `~/.claude/.credentials.json` и `~/.codex/auth.json` не открываются ни при
  каких условиях;
- каталоги истории (`~/.claude/projects`, `~/.codex/sessions`) открываются
  **только на чтение**;
- никакого своего клиента к API и никаких обёрток над токенами подписки.

Это соответствует политике Anthropic (перечитано 2026-09-02): бинарь не должен
модифицироваться, а вход конечного пользователя в неизменённый Claude Code под
своей подпиской прямо допускается. Подробности — в
`code.claude.com/docs/en/legal-and-compliance`.

## Требования

- Node.js >= 20 (проверено на 22)
- pnpm >= 9
- `claude` и/или `codex` в `PATH` — те, что вы уже используете

## Установка и запуск

```bash
pnpm install
pnpm build
pnpm --filter @harnas/tui dev
```

`pnpm install` доустанавливает бит исполнения вспомогательному бинарю node-pty:
pnpm распаковывает его без прав, и без этого PTY не стартует.

Ядро можно использовать и отдельно от UI — оно печатает в stdout только JSON:

```bash
node packages/core/dist/cli.js index
node packages/core/dist/cli.js session <id>
```

## Клавиши

| Клавиша             | Действие                                                        |
| ------------------- | --------------------------------------------------------------- |
| `↑` `↓` или `j` `k` | навигация по активному списку                                   |
| `Tab`               | переключение панелей: сессии → подсессии → терминал             |
| `Enter`             | открыть выбранную сессию в правой панели                        |
| `Enter` на работе   | свернуть / развернуть её (режим работ)                          |
| `Enter` на сессии   | диалог запуска `◌`, возобновления `○` `✓` `✗`, attach к `●` `◐` |
| `w`                 | режим левой колонки: все сессии ↔ работы                        |
| `←` `→` или `h` `l` | свернуть / развернуть работу (режим работ)                      |
| `n`                 | новая сессия выбранного провайдера (режим «все сессии»)         |
| `n` в режиме работ  | диалог новой сессии в выбранной работе                          |
| `N`                 | диалог новой работы (режим работ)                               |
| `p`                 | фильтр по провайдеру: все → Claude → Codex → GLM → все          |
| `r`                 | принудительный ре-скан истории                                  |
| `R`                 | перезапустить завершившегося агента                             |
| `q` / `Ctrl+C`      | выход                                                           |
| `Ctrl+Q`            | вернуть фокус спискам из терминала                              |

Диалоги (новая работа, новая сессия, запуск и возобновление) занимают место
нижней левой панели и модальны для левой колонки: `↑↓` / `Tab` — по полям,
`←→` — по вариантам селектора, `Enter` — далее и подтвердить, `Esc` — закрыть
без изменений. Правая панель при этом не трогается. Открываются они только из
фокуса списков: пока ввод идёт агенту, ничто не выпрыгивает.

Запуск идёт через тот же PTY-менеджер: команда и аргументы берутся из реестра
провайдеров, стартовым промптом становится бриф (`.harnas/works/<id>/briefs/`),
который перечитывается с диска при запуске — правьте его своим редактором.
Сессия, запущенная вне харнесса (`harnas-core work session new`), к панели не
подключается: у харнесса нет её PTY, и правая панель это прямо говорит.

Нижняя строка терминала — строка статуса: единственное место уведомлений в обоих
режимах (включая предупреждение о параллельных агентах). `⚑N` — сколько событий
ещё не просмотрено; событие гаснет, когда фокус побывал на его строке в списках.

`HARNAS_ASCII=1` заменяет Unicode-глифы списка работ (`● ◌ ✓ ✉ ▾ …`) на
ASCII-запасные — для терминалов и шрифтов, которые их не рисуют. То же
происходит само, когда локаль терминала (`LC_ALL`, `LC_CTYPE`, `LANG`) задана и
не UTF-8.

Пока в правой панели работает живой агент, **весь ввод принадлежит ему** — включая
`q`, `Tab` и `Ctrl+C`. Забрать фокус обратно можно только escape-клавишей; она
настраивается: `HARNAS_ESCAPE_KEY=w` сделает ею `Ctrl+W`.

## Что где лежит

- `packages/core` — чтение истории: потоковый разбор `.jsonl`, версионированные
  адаптеры схем, индекс сессий, watcher и CLI. Наружу отдаёт JSON и типы,
  про UI ничего не знает.
- `packages/tui` — Ink-приложение: списки, PTY-менеджер, VT-парсер
  (`@xterm/headless`), маршрутизация ввода.
- `.ralph/specs/` — спецификации слоя данных, UI, PTY и раннеров.
- `docs/schema/` — снимки реальных схем обоих провайдеров, по которым сверяется парсер.

## Провайдеры

|             | История сессий           | Запуск в панели        |
| ----------- | ------------------------ | ---------------------- |
| Claude Code | да, `~/.claude/projects` | `claude --resume <id>` |
| Codex       | да, `~/.codex/sessions`  | `codex resume <id>`    |
| GLM         | нет                      | `glm`                  |

У GLM нет своего формата истории: он ходит через OpenAI-совместимый эндпоинт
внутри чужих харнессов. Поэтому в списке сессий его нет — но выбрать его в
переключателе провайдеров можно, и `n` запустит новую сессию.

## Известные ограничения

- **Мышь** пробрасывается только в SGR-кодировании (`?1006`). Древние форматы
  X10 (`?1005`) и urxvt (`?1015`) не поддерживаются.
- **Поведение живого `claude` внутри панели** проверяется вручную: настоящий
  бинарь в автотестах не запускается никогда — лимиты подписки и недетерминизм,
  тесты идут против stub-бинаря. Проверено 2026-09-02: полноэкранный интерфейс,
  навигация по его меню и возврат фокуса по Ctrl+Q работают. Прокрутка scrollback
  и мышь на живом агенте пока не проверялись.
- **Формат `.jsonl` недокументирован** и меняется между релизами. Расхождение
  ловится сверкой со снимком схемы, см. ниже.
- Запуск нескольких агентов сразу расходует лимиты подписки — харнесс предупреждает,
  но не блокирует.

## Разработка

```bash
pnpm -r test                          # все тесты
pnpm --filter @harnas/core test:coverage
pnpm lint
pnpm format
```

После обновления Claude Code или Codex стоит пересверить схему:

```bash
node tools/claude-export.mjs --full
node tools/scrub-export.mjs claude-export docs/schema
node tools/observe-schema.mjs --root ~/.codex/sessions --out docs/schema/codex-schema-report.json
git diff docs/schema/
```

Непустой diff означает, что формат поехал и нужен новый адаптер схемы.

Фикстуры для тестов делаются из реальных сессий с полной анонимизацией:
`node tools/make-fixtures.mjs <session-id> ...`.
