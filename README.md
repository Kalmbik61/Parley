# my-harnas

Терминальный харнесс поверх агентских CLI. Слева узкий сайдбар: работы проекта,
строка `new` и дерево сессий выбранной работы с цветной точкой состояния агента.
Справа — вся оставшаяся площадь под настоящего агента, запущенного во встроенном
псевдотерминале: там его экран целиком, в рамке харнесса и без единого его
заголовка или подписи. Внизу одна строка статуса.

```
╭─ работы ───────────────╮
│ + new                  │
│ 1 Авторизация        ● │   (панель Claude Code — PTY целиком его:
│   ~/dev/shop · main    │    ни заголовков, ни подписей харнесса)
│ 2 Платежи            ● │
│   ~/dev/shop · feat/pay│
│ 3 Релиз 1.2          ✓ │
╰────────────────────────╯
╭─ сессии · Авторизация ─╮
│ ● план         working │
│   ↑1.2к ↓845 · 12м · ⋮1│
│ ● бэкенд       blocked │
│   └ ● ревью     unseen │
│ ○ тесты         exited │
│ ◌ доки         pending │
╰────────────────────────╯
 ⚑ ревью ждёт ответа — не подключена                            ctrl+q ?
```

Работы пронумерованы 1..9 в порядке создания (`ctrl+q 1..9` выбирает работу и сразу
подключает панель к той её сессии, к которой вы подключались последней), под
заголовком — хвост пути проекта и ветка git, справа точка состояния работы:
максимум по её сессиям. `done`-работы
свёрнуты в одну строку и уходят вниз, `archived` не показываются. Под **выбранной**
сессией одна компактная строка: токены вход/выход, длительность, `▤N`
непрочитанных сообщений, `⋮N` живых субагентов. Порядок строк стабильный (дерево
по `createdAt`): при событиях меняются глифы и слова, а не расположение.

Точка сессии — две оси. Жизненный цикл: `◌` pending, `○` exited, `✓` done,
`✗` failed. У живой (`●`) сессии точка показывает, чем занят агент:

| Точка              | Слово     | Что значит                                      |
| ------------------ | --------- | ----------------------------------------------- |
| серая, мигает 1 Гц | `working` | думает или выполняет инструменты                |
| жёлтая             | `blocked` | ждёт разрешения, ответа на вопрос или ввода MCP |
| синяя              | `unseen`  | ход закончен, вы к панели ещё не подключались   |
| тусклая            | `idle`    | ждёт ввода, и вы это видели                     |

Мигание — единственный таймер в интерфейсе, и он существует, только пока есть хотя
бы одна `working` сессия; всё остальное перерисовывается по событиям watcher.
Сайдбар шириной 26 колонок; на терминале уже 80 он сжимается до 18 (слово
состояния заменяется буквой `w`/`b`/`u`/`i`), уже 60 — прячется и открывается
оверлеем по `ctrl+q b`.

Работает строго локально, в вашем собственном терминале. Это не сервер и не веб-приложение.

## Архитектура

Три слоя, каждый отдельно тестируется и общается с соседями только данными:

```
   ~/.claude/projects/*.jsonl      <проект>/.harnas/works/<id>/       ~/.harnas/
   ~/.codex/sessions/*.jsonl         map.json  briefs/  events/        providers.json
            │  только чтение         settings.json  artifacts/         works-index.json
            ▼                                ▼  пишет только харнесс      config.json
   ┌──────────────────────── packages/core ───────────────────────────────┐
   │ адаптеры схем → индекс сессий → watcher     хранилище карты (lock,   │
   │ метрики: токены, длительность, инструменты   .bak, переходы статусов) │
   │ журнал хуков → activity, живость по pid     harnas-core CLI (JSON)    │
   │ harnas-mcp: get_map · report · spawn · wait_for · send/inbox · guide  │
   │             звонок адресату через channel, когда письмо в карте       │
   └──────────────┬───────────────────────────────────────┬───────────────┘
                  │ типы и JSON                           ▲│ stdio MCP
                  ▼                                       │▼ channel: звонок агенту
   ┌──────── packages/tui ────────┐            ┌── claude (стоковый бинарь) ──┐
   │ Ink: сайдбар, панель, оверлеи│  node-pty  │ --session-id --mcp-config    │
   │ PTY-менеджер + @xterm/headless│◀─────────▶│ --settings (наши хуки)       │
   │ префикс и мышь, строка статуса│            │ агент видит карту через MCP  │
   └──────────────────────────────┘            └──────────────────────────────┘
```

- **core** ничего не знает про UI: читает логи провайдеров, ведёт карту работы,
  считает метрики, сворачивает журнал хуков в состояние агента, поднимает
  MCP-сервер и печатает JSON в stdout. Всё, что читает `~/.claude` и `~/.codex`,
  делает это только на чтение.
- **tui** — тонкий потребитель core: рисует сайдбар и панель, спавнит агента в
  псевдотерминале, маршрутизирует ввод. Перерисовка по событиям watcher, не по таймеру.
- **агент** — немодифицированный `claude` (или `codex`), запущенный под вашим
  логином. Про харнесс он узнаёт только из брифа и MCP-инструментов; ни один
  токен и ни один файл учётных данных через харнесс не проходит.

Карта работы — единственное общее состояние: кто что делает, что сделано, где
результат. Агенты её не редактируют, а отчитываются через `report`; читатели
(TUI, `get_map`) выводят из неё всё остальное.

## Юридическая рамка

Проект держится на одной границе, и она не обсуждается:

- запускается **только немодифицированный официальный бинарь** (`claude`, `codex`)
  из вашего `PATH`, под вашим же логином;
- харнесс **никогда не читает, не хранит и не подставляет учётные данные**:
  `~/.claude/.credentials.json` и `~/.codex/auth.json` не открываются ни при
  каких условиях;
- каталоги истории (`~/.claude/projects`, `~/.codex/sessions`) открываются
  **только на чтение**; в `~/.claude` харнесс не пишет ничего — хуки передаются
  флагом `--settings` из файла в каталоге работы;
- никакого своего клиента к API и никаких обёрток над токенами подписки;
- `--dangerously-load-development-channels` — документированный флаг самого
  Claude Code (research preview, `code.claude.com/docs/en/channels`): он включает
  штатный механизм клиента, а не меняет бинарь.

Окно (`packages/desktop`) и его хост добавляют к рамке ещё пять правил
(спека `docs/specs/2026-09-26-desktop-design.md`, раздел 9.1):

- Keychain `Claude Code-credentials` не читается; запросов к API Anthropic и
  OpenAI нет, лимиты подписки окно не показывает;
- в `~/.claude.json` ничего не пишется, включая доверие к папкам;
- скрытых запусков нет: каждый процесс агента виден в окне как сессия;
- хост не отвечает на диалоги агента. Печатает он только указатель на письма и
  только после хука `Stop`; флаг dev-канала окно не передаёт;
- `--dangerously-skip-permissions` — только явный выбор человека; телеметрии и
  автообновления нет.

Это соответствует политике Anthropic (перечитано 2026-09-02): бинарь не должен
модифицироваться, а вход конечного пользователя в неизменённый Claude Code под
своей подпиской прямо допускается. Подробности — в
`code.claude.com/docs/en/legal-and-compliance`.

## Требования

- Node.js >= 20 (проверено на 22)
- pnpm >= 9
- `claude` и/или `codex` в `PATH` — те, что вы уже используете
- для звонка через channel (см. «Разговор сессий») — `claude` не ниже 2.1.211

## Установка и запуск

```bash
pnpm install
pnpm build
pnpm --filter @harnas/tui dev
```

`pnpm install` доустанавливает бит исполнения вспомогательному бинарю node-pty:
pnpm распаковывает его без прав, и без этого PTY не стартует.

### Окно

```bash
pnpm install
pnpm build
pnpm dev:desktop
```

Окно — Electron-приложение над отдельным процессом `harnas-host`. Хост держит
PTY агентов, карту, будильник и комнаты. Он живёт в `~/.harnas/host/`
(`host.sock`, `host.token`, `host.pid`, `host.log`) и переживает закрытие окна:
открыли заново — терминалы восстанавливаются из снимков экрана. Окно поднимает
хост само, системным `node` из `PATH` вашей login-shell. Второй запуск окна
фокусирует первое.

Облик окна — в стиле Orca: шрифт Geist, примитивы shadcn/ui, палитра терминала
Ghostty Dark / Tango Light. Тема (тёмная/светлая) следует за системной темой
macOS и переключается на лету, без перезапуска окна; «Система», «Тёмная» или
«Светлая» выбираются в настройках (⌘,) на вкладке «Вид» — там же живут
уведомления, а поля терминала и агентов остались на прежнем месте.

Чем окно отличается от TUI:

- у каждой работы своя раскладка: дерево сплитов из групп вкладок (терминал
  сессии, почта, комната, изменения). Пока группа одна, её вкладки стоят прямо
  в заголовке окна. Раскладка работы запоминается и переживает перезапуск окна;
  при старте открывается последняя активная работа;
- сайдбар слева — карточки работ: сверху «Закреплённые» (Pinned), дальше группы
  по проектам с цветным чипом, числом работ, «+» и меню «⋯» («Show done»).
  Внутри секции выше та работа, где нужен вы: сессия ждёт разрешения или
  ответа, потом — с непросмотренным итогом, потом — где агент работает; при
  равенстве — свежее событие. Пока указатель над сайдбаром или открыто его меню, порядок
  не прыгает. На карточке — название, ветка, время, счётчик писем и комнат и
  строки сессий со значком состояния; клик по строке открывает вкладку её
  терминала. Правый клик по карточке — закрепить, новая сессия или комната,
  почта, переименование на месте (или двойной клик по названию), «Показать в
  Finder», копировать путь, завершить, архивировать, удалить. Свёрнутые
  проекты, закреплённые работы и «Show done» переживают перезапуск окна;
- центр показывает активную работу: клик по карточке делает её активной, клик
  по строке сессии ещё и открывает вкладку сессии. ⌘1…⌘9 выбирают работу по
  видимому порядку сайдбара (закреплённые первыми), ⌘⇧↑ и ⌘⇧↓ — соседнюю;
  стрелки ходят по карточкам и строкам, когда фокус в сайдбаре. Терминалы трёх
  последних работ остаются живыми, переключение их не пересоздаёт;
- новая работа — ⌘N, «New workspace» вверху сайдбара или «+» в заголовке
  проекта (тогда проект уже выбран). Форма создаёт работу и сразу её первую
  сессию: проект, название (1–120 символов), цель, агент (по умолчанию —
  последний выбранный, иначе Claude Code), ярлык (пустой — имя агента), задача
  и свой worktree, если проект — git-репозиторий. ⌘Enter — создать. Если
  сессия не запустилась, работа уже есть, и «Retry» повторяет только запуск
  сессии. С галочкой «Create more» форма после создания очищает название, цель
  и задачу и остаётся открытой;
- вкладку и строку сессии из сайдбара перетаскивают мышью: в строку вкладок или
  в середину группы — вкладкой туда, к краю группы — новой группой рядом.
  Терминал переезжает между группами без пересоздания и без потери экрана;
- мышь, меню и сочетания на ⌘ вместо префикса: ⌘T — новая сессия в активной
  работе, ⌘D и ⇧⌘D — новая группа справа или снизу с выбором сессии, ⌘W —
  закрыть вкладку, ⌘⇧T — вернуть закрытую, ⌘[ и ⌘] — соседняя группа, ⌃Tab и
  ⌃⇧Tab — недавние вкладки работы, ⌘⌥← и ⌘⌥→ — назад и вперёд по истории
  переходов (и кнопки в заголовке), ⌘J — палитра, ⌘K — очистить терминал,
  ⌘F — поиск, ⌘, — настройки;
- внимание: вкладка терминала сессии, которая ждёт вас или закончила ход,
  подсвечена; в строке статуса — «N need you · M unseen», клик ведёт к следующей
  такой сессии; бейдж Dock — число «ждут вас» и писем вам. «Не просмотрено»
  гаснет, только когда вы секунду видите терминал в окне с фокусом; письмо вам
  отмечается прочитанным, когда оно видно в почте;
- уведомления macOS: сессия ждёт вас или закончила ход, пришло письмо вам,
  сессия не запустилась, не возобновилась или ждёт доверия к папке. Когда вы и
  так смотрите на эту вкладку, уведомления нет; после перезапуска окна или хоста
  пачки уведомлений о прежних состояниях нет. Клик открывает окно (и при
  закрытом окне тоже) прямо на вкладке: рамка вспыхивает, у терминала — фокус
  ввода. Что уведомлять и со звуком ли — в настройках, раздел «Notifications»;
  если уведомления не приходят, их разрешают в Системных настройках →
  Уведомления → Harnas. Тексты уведомлений — по-английски, как и всё окно;
- файлы: правый сайдбар (⌘L) — вкладка «Files» с деревом папки сессии (её
  worktree) или проекта; корень выбирается сверху, скрытые git файлы — по
  галочке. Клик по файлу открывает его во вкладке редактора Monaco, ⌘-клик — в
  новой группе справа. ⌘S сохраняет; вкладка с несохранённой правкой — с
  точкой, и закрыть её (или окно) без вопроса «Save / Don't save / Cancel»
  нельзя. Правка агента на диске молча не перетирается: без ваших правок файл
  перечитывается сам («Reloaded from disk»), с правками — баннер «File changed
  on disk (probably by the agent)» с «Reload», «Compare» и «Keep mine», а запись
  поверх чужой правки сначала спрашивает «Overwrite». Файлы до 2 МБ правятся,
  до 20 МБ — только читаются, больше — не открываются. В терминале «Open in
  editor» в меню ссылки открывает путь во вкладке на нужной строке;
- ⌘P — быстрый переход к файлу по нескольким буквам имени, ⌘⇧F — поиск строки
  по содержимому файлов (с учётом регистра, целым словом, регулярным
  выражением); клик по совпадению открывает файл на этой строке;
- превью прямо во вкладке файла: Markdown — по умолчанию превью, «Code» в шапке
  вкладки — редактор того же текста; ссылки `http(s)` открываются в системном
  браузере, относительные — вкладкой файла, картинки берутся только из папок
  работы; сырой HTML не исполняется. Картинки (`png jpg jpeg gif webp svg`) —
  «Fit / 100%» и размер в пикселях. PDF — прокрутка страниц, ⌘F по тексту,
  ссылки — только `http(s)` и только в системном браузере; скрипты PDF не
  исполняются, pdf.js и его шрифты — локальные, без сети. CSV и TSV — таблица
  (первые 10 000 строк), «Code» — редактор;
- «вся почта работы» и комнаты в markdown, письма человека из окна;
- обычные выделение, копирование и прокрутка терминала. Правый клик по
  терминалу — меню: копировать, вставить, выделить всё, очистить экран (агенту
  ничего не уходит), поиск и сплит;
- ссылки в выводе терминала: адреса и пути к файлам (`src/a.ts:12`, в том
  числе с кириллицей) подчёркиваются под указателем. Клик — меню ссылки,
  ⌘-клик — сразу действие: путь открывается приложением по умолчанию (только
  внутри папок работы; скрипты и исполняемое — лишь показываются в Finder),
  адрес — в системном браузере;
- ⌘F — полоса поиска по экрану и прокрутке терминала: с учётом регистра,
  регулярным выражением, Enter и ⇧Enter — следующее и предыдущее, Esc —
  закрыть;
- файл из Finder, брошенный на терминал сессии, вставляется путём в поле ввода
  агента — в одинарных кавычках shell, через пробел, Enter не нажимается:
  человек дописывает промпт сам;
- скриншот: ⌘⌃⇧4 и ⌘V в терминале (или «Paste» меню терминала), когда в
  буфере картинка без текста. Окно сохраняет PNG в `~/.harnas/desktop/drops`
  (права 0600, через 7 дней файл удаляется при старте) и вставляет путь к нему —
  Claude и Codex читают его как вложение. Если в буфере есть текст, вставляется
  текст;
- ответ агента на такую вставку окно показывает тостом: «Sent to S02», «…
  without Enter» (в поле ввода уже был черновик, вы печатали или сессия
  перезапустилась), «S02 is waiting for your answer — text not inserted» (агент
  ждёт разрешения или ответа — текст не вставлен совсем, есть «Copy» и
  «Open S02»), «busy» с «Retry», «isn't running» с «Resume». Повтор — только
  кнопкой; успешная вставка без Enter тоста не даёт. Со старым хостом без
  `pty.send` вставка идёт как обычно, а бросок файлов не принимается.

**Клавиши окна** (спека 9.6). Все сочетания — в одной таблице
`packages/desktop/src/shared/keybindings.ts`: по ней строятся системное меню, обработчик
клавиш окна и строки действий палитры. Сочетание ловит окно с учётом фокуса: в терминале
всё без ⌘ уходит агенту (кроме ⌃Tab, ⌃⇧Tab и ⌃1–9), в поле ввода остаётся правка текста
(⌘A, ⌘C, ⌘V, ⌘Z, ⌘←/→, ⌘⇧↑/↓), за модальным диалогом сочетания окна не действуют.

| Действие | Клавиши | Меню |
|---|---|---|
| Палитра | ⌘J | View |
| Быстрый переход к файлу | ⌘P | View |
| Найти в файлах | ⌘⇧F | View |

Палитра ⌘J ищет вкладки, работы, сессии, комнаты и действия (2–4 буквы ярлыка
хватает: «исп» находит `S02 исполнитель`), Enter открывает строку и отдаёт фокус её
вкладке, ⌘Enter — в новой группе справа, ⌘1–9 выбирают строку по номеру. Пустой
результат предлагает «Create workspace "…"» — форму с этим названием; сама палитра
работ и сессий не создаёт и в терминал не пишет, «Restart host…» спрашивает
подтверждение. «Show archived workspaces» до перезапуска окна показывает архивные
работы приглушёнными в конце своей секции; вернуть работу — «Reopen» в её меню. В
счётчики, бейдж и «Next session that needs you» архивные не входят и при показе.

Будит агентов сам хост, без dev-канала: печатает указатель
«Новые письма (N). Вызови check_inbox.», когда агент закончил ход и вы ничего не
набираете. Поэтому сессия, порождённая агентом, стартует сама, без диалога
канала. TUI заморожен и работает по-старому, с каналом; работу, которую держит
хост, он не запускает повторно (аренда `host.lease`).

Ядро можно использовать и отдельно от UI — оно печатает в stdout только JSON:

```bash
node packages/core/dist/cli.js index
node packages/core/dist/cli.js session <id>
```

## Клавиши

Пока в панели работает живой агент, **весь ввод принадлежит ему** — включая `q`,
стрелки, `Tab`, `Esc` и `Ctrl+C`. Харнесс слушает только префикс `ctrl+q` и одну
клавишу действия после него. Неизвестная клавиша молча отменяет префикс и агенту
не уходит; `ctrl+q ctrl+q` отправляет сам `Ctrl+Q` агенту.

| Клавиша          | Действие                                                             |
| ---------------- | -------------------------------------------------------------------- |
| `ctrl+q c`       | новая сессия Claude в выбранной работе (работы нет — заведётся)      |
| `ctrl+q C`       | дочерняя сессия выбранной: её резюме контекстом, ждёт ваш запрос     |
| `ctrl+q w`       | пикер работ, включая работы других проектов                          |
| `ctrl+q g`       | пикер истории `~/.claude` для возобновления                          |
| `ctrl+q i`       | детали выбранной сессии; `e` в них правит цель работы                |
| `ctrl+q j` / `k` | следующая / предыдущая сессия сайдбара, по кругу через все работы    |
| `ctrl+q 1`..`9`  | выбрать работу и подключиться к её последней сессии                  |
| `ctrl+q s`       | фокус в сайдбар: `↑↓`/`j k` ходят, `Enter` подключает, `Esc` — назад |
| `ctrl+q b`       | спрятать / показать сайдбар (на узком терминале — оверлеем)          |
| `ctrl+q t`       | комната: переписка агентов работы на месте панели; повторно — назад  |
| `ctrl+q x`       | закрыть выбранную сессию (SIGHUP) с подтверждением                   |
| `ctrl+q d`       | удалить выбранную сессию с подтверждением: запись, бриф и журнал     |
| `ctrl+q D`       | удалить выбранную работу целиком: каталог с артефактами и индекс     |
| `ctrl+q r`       | возобновить `○` / `✓` / `✗` сессию через `--resume`                  |
| `ctrl+q R`       | дозаказать авто-резюме для сессии, вышедшей без отчёта               |
| `ctrl+q ,`       | настройки: `Enter` переключает или правит, пишется в `config.json`   |
| `ctrl+q ?`       | справка по всем привязкам с фильтром                                 |
| `ctrl+q q`       | выйти (с подтверждением, если харнесс держит живые сессии)           |
| `ctrl+q ctrl+q`  | отправить `Ctrl+Q` агенту                                            |

Ключи, занятые самим Claude Code (`ctrl+b`, `ctrl+c`, `ctrl+d`, `ctrl+l`,
`ctrl+o`, `ctrl+r`, `ctrl+t`, `Esc`), харнесс без префикса не использует.

Оверлеи (детали, пикеры, справка, запуск `pending`, возобновление, дозаказ
резюме, закрытие, удаление сессии и выход) рисуются рамкой поверх панели: `↑↓` — прокрутка
и выбор, набор текста — фильтр в пикерах, `Enter` — подтвердить, `Esc` — закрыть
без изменений. Одновременно открыт максимум один; пока он открыт, ввод идёт ему,
а не агенту. Живой агент за оверлеем не тронут — его PTY продолжает работать.

**Мышь** (`mouseCapture`, по умолчанию включена). Клик по строке работы выбирает
её, по строке сессии — выбирает и подключает, по `new` — заводит сессию. Клик и
колесо в области панели уходят агенту с пересчётом колонок, если он сам запросил
отслеживание мыши; иначе колесо листает скроллбэк нашего буфера. Выделение текста
— родное терминальное, через `option`/`shift`-клик, как у Claude Code. Пока открыт
оверлей, мышь не делает ничего: клик не выбирает строк и в поля ввода не попадает.

## Настройки

Все настройки правятся и из TUI, по `ctrl+q ,`: `Enter` переключает булевы
и открывает ввод для остальных, значение пишется в файл и применяется без
перезапуска. Значение, заданное переменной окружения, показано тусклым — файл
его не перекроет.

`~/.harnas/config.json` (или в `HARNAS_HOME`), необязательный:

```json
{
  "prefix": "q",
  "sidebarWidth": 26,
  "mouseCapture": true,
  "ascii": false,
  "theme": "mocha",
  "silenceThresholdMs": 30000,
  "channelPush": true,
  "messageRate": 20,
  "autoLaunch": true
}
```

Переменные окружения перекрывают файл: `HARNAS_PREFIX`, `HARNAS_SIDEBAR_WIDTH`,
`HARNAS_MOUSE`, `HARNAS_ASCII`, `HARNAS_THEME`, `HARNAS_SILENCE_MS`, `HARNAS_CHANNEL_PUSH`,
`HARNAS_MESSAGE_RATE`, `HARNAS_AUTO_LAUNCH`. Битый файл
запуску не мешает:
работают значения по умолчанию, а причина уезжает в строку статуса событием `⚑`.

`prefix` — буква, которая станет `ctrl+<буква>`. Меняйте её, если `ctrl+q`
перехватывает ваш терминал (в справке `ctrl+q ?` это написано первой строкой).
`ascii: true` (или `HARNAS_ASCII=1`) заменяет Unicode-глифы на ASCII-запасные;
то же происходит само, когда локаль терминала задана и не UTF-8.
`theme` (`mocha` по умолчанию, или `HARNAS_THEME`) — палитра интерфейса: `mocha`,
`latte`, `gruvbox`, `nord`, `tokyo-night`, `terminal`. `terminal` — отказ от своей
палитры в пользу цветов терминала, как было раньше. Тёмная тема рассчитана на
тёмный терминал, светлая — на светлый: у Ink нет фона у рамки, и на контрастном
фоне между блоками видны линии цвета терминала (дизайн темы, 5.2).
`autoLaunch` (по умолчанию включён) — `pending` сессию, которую породил агент через
`spawn_session`, харнесс поднимает сам, в фоне: панель остаётся у вас, в строке
статуса — «запускается». Запускаются только записи, появившиеся при живом TUI;
найденные при старте ждут `Enter` как раньше. С `autoLaunch: false` (или
`HARNAS_AUTO_LAUNCH=0`) любую `pending` запускаете вы через диалог с брифом — так
его можно поправить до старта. Сессии, заведённые вами (`prefix c`, `prefix C`,
CLI), настройка не трогает.

Ещё две — про переписку сессий («Разговор сессий»): `channelPush` будит
адресата письма звонком, `messageRate` — потолок писем одной сессии за час.
Прежний ключ `threadWidth` больше не нужен: панель треда заменила комната, и
старый файл с ним читается без жалобы.

## Состояние агента: хуки и живость

Каждой сессии харнесс передаёт `--settings <работа>/settings.json` — файл с
восемью хуками Claude Code (`UserPromptSubmit`, `Notification`,
`PermissionRequest`, `Stop`, `SubagentStart`, `SubagentStop`, `SessionStart`,
`SessionEnd`). Хук не содержит логики: он одной командой дописывает пришедший
на stdin JSON в журнал сессии.

```
cat >> "$HARNAS_WORK_DIR/events/$HARNAS_SESSION_ID.jsonl" || true
```

Журнал читается инкрементально, с запомненного смещения, и сворачивается в
`working` / `blocked` / конец хода чистой функцией core. `--settings` мержится с
вашими настройками, чужие хуки не трогает, в `~/.claude` ничего не пишется. Если
бинарь этот флаг не принял или каталог недоступен для записи, состояние ведёт
страховка — тот же jsonl-watcher истории, что и раньше: новая запись ассистента
значит «работает», тишина дольше `silenceThresholdMs` — «ход закончен». Про
отсутствующий журнал в строке статуса появляется разовое предупреждение.

**Живость.** При старте сессии в карту пишутся `pid`, время старта процесса и
`launchedBy`. При запуске харнесса и на каждое событие watcher (не по таймеру)
каждая `active` сессия сверяется с ОС: процесс жив и время старта совпало —
сессия остаётся живой, но панель показывает карточку «запущена вне харнесса»,
потому что её PTY у другого процесса; иначе сессия уходит в `exited`. Сессии,
поднятые командой CLI без известного pid, считаются живыми, пока обновляется лог.

## Координация агентов

Работа — единица координации внутри проекта: заголовок, цель и сессии разных
провайдеров, которые знают друг о друге через одну общую карту. Пишет карту
только харнесс; агенты читают её и отчитываются через MCP-сервер.

```
<проект>/.harnas/works/<work-id>/
  map.json            карта работы: сессии, статусы, метрики, резюме, сообщения
  map.json.bak        предыдущая версия — обновляется при каждой записи
  settings.json       хуки Claude Code для всех сессий работы (--settings)
  events/<id>.jsonl   журнал хуков сессии: из него выводится состояние агента
  briefs/<id>.md      стартовый промпт сессии; правится своим редактором
  mcp/<id>.json       конфиг MCP-сервера для этой сессии
  artifacts/          планы, отчёты и прочее, что кладут агенты

~/.harnas/
  config.json         настройки харнесса (необязателен)
  providers.json      необязательные переопределения реестра провайдеров
  works-index.json    глобальный индекс работ: проект, id, заголовок, статус
```

`HARNAS_HOME` переносит `~/.harnas` в другое место — этим же тесты держатся
подальше от вашего настоящего каталога. Коммитить `.harnas/` проекта или
добавить его в `.gitignore` — ваш выбор, харнесс это не решает.

Сессия заводится тремя путями. `ctrl+q c` открывает Claude сразу, без диалога:
работа при необходимости создаётся сама и получает заголовок из первой реплики,
бриф такой сессии не пишется. `spawn_session` от агента создаёт `pending` с
брифом — её запускает человек (`Enter` в сайдбаре, с показом брифа). `ctrl+q g`
регистрирует в текущей работе сессию из истории `~/.claude` и продолжает её
через `--resume`.

Убирается сессия из работы одним путём: `ctrl+q d` с подтверждением. Живой
процесс, чей PTY держит харнесс, сначала закрывается — SIGHUP, ожидание выхода
до трёх секунд, потом SIGKILL, — и только после выхода исчезает запись. Живую
сессию, поднятую мимо харнесса, удалить нельзя: закрыть её нечем, и оверлей
предлагает сделать это там, где она запущена. Из карты уходят запись, ссылки на
неё в `contextFrom` и файлы `briefs/<id>.md`, `events/<id>.jsonl`, `mcp/<id>.json`;
дочерние сессии поднимаются к родителю удалённой, письма остаются с пометкой
`deleted`, а `artifacts/` и транскрипт в `~/.claude` не трогаются. Id удалённой
не переиспользуется, и `wait_for` по нему отвечает агенту `state: deleted`.
Инструмента удаления у агентов нет — это решение человека.

Работа целиком убирается по `ctrl+q D`: процессы её сессий, чьи PTY у харнесса,
закрываются так же, затем уходит весь каталог `.harnas/works/<id>` вместе с
артефактами и запись в глобальном индексе; транскрипты в `~/.claude` остаются.
Живая сессия мимо харнесса блокирует и это. Если каталог работы всё же снесли
руками, мёртвую запись индекса снимает `harnas-core work prune`.

### Что видит агент

Каждой запускаемой сессии харнесс генерирует свой конфиг stdio-сервера
`harnas-mcp` и передаёт через окружение `HARNAS_WORK_DIR` и `HARNAS_SESSION_ID` —
представляться агенту не нужно, сервер знает, кто звонит. Инструменты:

| Инструмент                                          | Что делает                                                     |
| --------------------------------------------------- | -------------------------------------------------------------- |
| `get_map()`                                         | вся карта плюс провайдеры реестра с пометкой доступности       |
| `report(status, summary, artifacts)`                | `done` / `failed` — итог, `progress` — промежуточное резюме    |
| `spawn_session(provider, label, task, contextFrom)` | новая `pending` сессия с брифом; её откроет пользователь       |
| `wait_for(target, timeoutSec)`                      | ждать завершения сессии или сообщения; по таймауту — `running` |
| `send_message(to, text, kind)`                      | письмо другой сессии: `note`, `question` или `decision`        |
| `check_inbox()`                                     | непрочитанные входящие с их видом; помечает прочитанными       |
| `read_guide()`                                      | подробный гид по харнессу; без аргументов                      |

Пути артефактов — всегда относительно корня проекта. Сессия, запущенная с нашим
конфигом, но без `HARNAS_SESSION_ID`, получает только `get_map` и `read_guide`.

Гид агенту выдаётся двумя слоями, от дешёвого к подробному.

Первый слой — короткая системная вставка (`--append-system-prompt`, не больше
двенадцати строк): в какой работе и какой сессии агент находится, цель работы,
семь инструментов по строке на каждый и правило — подзадачу этой темы, которая
живёт дольше одного хода или должна идти параллельно, отдавать в
`spawn_session`, а собственных субагентов держать для коротких разведок и
правок. Её получают все запуски харнесса и команда `harnas-core work session
new`; системный промпт не хранится в транскрипте, поэтому вставка идёт заново
и при `--resume`. Провайдеру, у которого такого флага нет, она не достаётся:
подстановка отбрасывается молча, как файл настроек.

Второй слой — `read_guide()`: сущности и жизненный цикл сессии, что класть в
резюме и артефакты, как устроен бриф, как ждать подчинённую сессию, чего не
делать. Он инструмент, а не MCP-ресурс: у модели в Claude Code нет инструмента
чтения ресурсов, и ресурс остался бы мёртвым слоем.

### Разговор сессий

**В окне комнаты — по участникам** (спека `2026-09-26-desktop-design.md`, раздел 6).
Агент заводит комнату для своих подчинённых инструментом
`create_room(title, members)`, человек — пунктом «Создать комнату с…» в меню
сессии. Комната стоит в сайдбаре под сессией-создателем, комнаты человека —
прямо под работой; в работе их может быть несколько. Лента комнаты видна всем
участникам. Письмо без адресата будит всех, адресное — только адресатов:
`send_message(to?, text, kind, room)`. `read_room(room)` читает ленту для
контекста, не трогая отметок. Человек пишет в комнату из поля ввода внизу
ленты — всем или выбранным участникам.

**Жизнь сессии — две оси.** Процесс: `pending` → `active` → `sleeping`
(процесса нет, но сессия на связи) → `closed`. Итог из `report`: `done` или
`failed`, и он сессию не закрывает. Письмо спящей сессии поднимает её:
`claude --resume` с указателем в аргументе, не больше `resumeRate` раз в час
(по умолчанию 6). «Остановить» в меню переводит сессию в `sleeping`,
«Закрыть…» — в `closed`, и писем она больше не получает. Агент закрывает
сессию инструментом `close_session` только после явного согласия человека.
Если хост упал посреди хода, окно покажет прерванные сессии с кнопкой
«Поднять всех». Пауза будильника в строке статуса копит письма и никого не
будит.

**Worktree на сессию.** В диалоге новой сессии (⌘T) есть флажок «в своём
worktree», у агента — параметр `worktree: true` у `spawn_session`. Хост делает
`git worktree add` в `~/harnas/worktrees/<проект>-<хеш>/<работа>-<S03>` с веткой
`harnas/<работа>/<s03>` от ветки родителя (настройка `worktreeRoot`). Путь
закреплён за сессией: `--resume` идёт из того же каталога. Пункт «Изменения» в
меню сессии показывает дифф ветки и незакоммиченного против базы. Там же
кнопки «Закоммитить всё», «Влить в <базу>» (merge-коммит `--no-ff`, только при
чистой базе; собственный `.harnas/` харнесса не считается грязью) и «Отбросить»
(worktree и ветка удаляются, сессия закрывается). Конфликт слияния можно
поручить агенту одной кнопкой. Если Claude ждёт доверия к новой папке, хост
пришлёт уведомление: доверие в `~/.claude.json` харнесс не пишет, нужен один
клик в панели.

**В TUI** (заморожен) всё как раньше:

Сессии одной работы переписываются письмами: `send_message(to, text, kind)`
кладёт письмо в карту, `check_inbox()` его забирает. Адресат у письма один, но
читается переписка целиком. Для агентов **тред** выводится из карты, а не
хранится — это письма поддерева одного родителя: у сессии с родителем тред
общий с ним и сёстрами, у корня с детьми — свой, у одинокого корня — вся
работа. Человек читает всю переписку работы сразу — в **комнате**: строка
`▤ комната` внизу блока сессий или `ctrl+q t`. Комната встаёт на место панели
агента: участники подписаны номером сессии и моделью (`S03 (Codex) → S01
(Opus 5.5)`), решения собраны сверху, `▤` помечает письма, которые адресат ещё
не забрал. Агенты при этом работают в фоне, а ввод, пока открыта комната, не
уходит никому: стрелки, `j`/`k`, `PgUp`/`PgDn`, `End` и колесо листают ленту.
Номер `S03` виден и в сайдбаре, перед ярлыком сессии.

Видов письма три: `note` — к сведению, `question` — жду ответа, `decision` — мы
договорились. Этикет одинаков для всех сессий и повторён в брифе, гиде и
`instructions` сервера: отвечать только на `question`, на `note` и `decision` не
отвечать, договорённость фиксировать одним письмом `decision`. Карты, написанные
до 2026-09-08, читаются с видом `note`.

**Звонок.** Письмо будит адресата само: `harnas-mcp` получателя следит за картой
и на непрочитанное письмо шлёт Claude Code уведомление
`notifications/claude/channel` — «новое письмо от <ярлык> (<вид>): позови
check_inbox». Агент, сидящий у промпта, начинает ход сам. Звонок ничего не
доставляет и карту не трогает: текст приносит `check_inbox`, поэтому `readAt`
по-прежнему значит «агент прочитал», а не «мы отправили». Отсюда и запасной
путь: канал молчит — письмо просто висит непрочитанным, как раньше, и его
забирают `check_inbox` или `wait_for("inbox")`.

Включает звонок `channelPush` (по умолчанию `true`): в конфиг MCP сессии
добавляется `HARNAS_CHANNEL=1`, а в команду запуска — пара
`--dangerously-load-development-channels server:harnas`. Флаг документирован, но
скрыт из `claude --help` и принимается начиная с **2.1.211** (проверено на
2.1.276), поэтому при старте харнесс один раз зовёт `claude --version` и на
версии ниже выключает звонок, сказав об этом строкой статуса. То же делает свой
`args` в `providers.json` без подстановки `{channel}` — про него предупреждение
тоже разовое. Codex и GLM звонка не получают: у них остаётся pull.

Набранная, но не отправленная строка звонок переживает: событие начинает ход
агента, а текст остаётся в поле ввода — его можно допечатать и отправить
(проверено на `claude` 2.1.276).

В стартовом баннере агента рядом с «Channels (experimental) messages from
server:harnas» видна жёлтая строка `server:harnas · no MCP server configured with
that name`. Это ожидаемо: Claude Code проверяет имя до загрузки серверов из
`--mcp-config`, регистрация всё равно состоялась и события доходят.

**Потолок.** Два вежливых агента способны переписываться, пока не кончится лимит
подписки, поэтому `send_message` считает письма отправителя за скользящий час:
сверх `messageRate` (по умолчанию 20) письмо не создаётся, а агенту сказано
отчитаться через `report` и обратиться к человеку. Окно отличает петлю от
честной долгой работы и восстанавливается само.

### Без TUI

Слой работает и из обычного терминала — ядро печатает в stdout только JSON
(в установленном виде это бинарь `harnas-core`):

```bash
node packages/core/dist/cli.js work new --title "Авторизация" --goal "логин по e-mail"
node packages/core/dist/cli.js work list
node packages/core/dist/cli.js work prune
node packages/core/dist/cli.js work map --work w-0001
node packages/core/dist/cli.js work session new \
  --work w-0001 --provider claude --label тесты --task "прогнать e2e"
```

Последняя команда создаёт `pending`-запись, пишет бриф, MCP-конфиг и файл
настроек с хуками и печатает готовую команду запуска (`command`, `args`, `cwd`,
`env`). Запущенный ею стоковый `claude` видит карту, отчитывается и может
породить свои сессии; к панели харнесса такая сессия не подключается — её PTY не
у него, и карточка сессии это прямо говорит.

Сессия, вышедшая без отчёта (`○`), резюме не оставляет. `ctrl+q R` на такой
сессии дозаказывает его: харнесс достаёт транскрипт из логов провайдера (для Codex —
своим адаптером) и один раз зовёт стоковый `claude -p` командой из реестра.
Готовый текст попадает в карту как `summary` с пометкой `авто`
(`summarySource: "auto"`) и всплывает в строке статуса. У GLM истории нет —
дозаказ ему недоступен.

Нижняя строка терминала — строка статуса: единственное место уведомлений
(pending от агента, новое сообщение, сессия вышла без отчёта, агент ждёт
разрешения или ответа, готово авто-резюме, ошибка конфига). `⚑N` — сколько
событий ещё не просмотрено; событие гаснет, когда вы подключились к его сессии.

## Что где лежит

- `packages/core` — чтение истории: потоковый разбор `.jsonl`, версионированные
  адаптеры схем, индекс сессий, watcher и CLI. Наружу отдаёт JSON и типы,
  про UI ничего не знает.
  - `src/work/` — карта работы: типы, хранилище с блокировкой, бриф, метрики,
    MCP-конфиг, файл настроек с хуками, журнал событий и `activity`, живость по
    pid, дозаказ резюме.
  - `src/config.ts` — `config.json` и `HARNAS_*` с дефолтами и валидацией.
  - `src/mcp/` — сервер `harnas-mcp` и его инструменты.
  - `src/providers.ts` — реестр провайдеров: чем запускать, как передать id,
    MCP-конфиг, файл настроек и промпт.
- `packages/tui` — Ink-приложение: сайдбар, панель, оверлеи, PTY-менеджер,
  VT-парсер (`@xterm/headless`), префиксный ввод с мышью, строка статуса.
- `docs/specs/` — спецификации слоя координации (`2026-09-02-coordination-design.md`)
  и интерфейса (`2026-09-05-tui-v2-design.md` с отчётом инженерного ревью и
  `2026-09-05-tui-v2-mockups.md` с макетами всех экранов).
- `.ralph/specs/` — спецификации v0–v2: слой данных, старый UI, PTY, раннеры.
- `docs/schema/` — снимки реальных схем обоих провайдеров, по которым сверяется парсер.
- `TODOS.md` — отложенная работа с причинами и точками входа.

|             | История сессий           | Запуск в панели        |
| ----------- | ------------------------ | ---------------------- |
| Claude Code | да, `~/.claude/projects` | `claude --resume <id>` |
| Codex       | да, `~/.codex/sessions`  | `codex resume <id>`    |

## Известные ограничения

- **Мышь** пробрасывается только в SGR-кодировании (`?1006`). Древние форматы
  X10 (`?1005`) и urxvt (`?1015`) не поддерживаются.
- **Экран агента при возврате в панель** перерисовывается не сразу: буфер
  показанной панели создаётся заново, и до первого нового байта от агента она
  пуста — любая нажатая клавиша заставляет его перерисоваться.
- **Поведение живого `claude` внутри панели** проверяется вручную: настоящий
  бинарь в автотестах не запускается никогда — лимиты подписки и недетерминизм,
  тесты идут против stub-бинаря.
- **Формат `.jsonl` недокументирован** и меняется между релизами. Расхождение
  ловится сверкой со снимком схемы, см. ниже.
- Запуск нескольких агентов сразу расходует лимиты подписки — харнесс предупреждает,
  но не блокирует. Два харнесса на одном проекте не поддерживаются.

## Разработка

```bash
pnpm -r test                          # все тесты
pnpm --filter @harnas/core test:coverage
pnpm lint
pnpm format
```

После обновления Claude Code или Codex стоит пересверить схему:

```bash
node tools/claude-export.mjs --full
node tools/scrub-export.mjs claude-export docs/schema
node tools/observe-schema.mjs --root ~/.codex/sessions --out docs/schema/codex-schema-report.json
git diff docs/schema/
```

Непустой diff означает, что формат поехал и нужен новый адаптер схемы.

Фикстуры для тестов делаются из реальных сессий с полной анонимизацией:
`node tools/make-fixtures.mjs <session-id> ...`.
